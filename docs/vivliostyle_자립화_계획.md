# Vivliostyle 조판 자립화 — 계획과 진행

**목표: 클로드 세션 없이도 비블리오 조판을 굴린다.**
지금은 사소한 수정 하나에도 대화를 열어야 하고, 컨텍스트가 차면 새 세션에서
메모리를 받아 이어가야 한다. 그 의존을 끊는 것이 이 작업이다.

작업 브랜치 `vivlio-studio` (2026-08-29 시작). 단계마다 태그를 단다.

## 진단 — 문제는 셋이다

**① 터미널 문제 (인터넷 문제가 아니다)**
`bin/viv` 는 지금도 100% 로컬·오프라인으로 돈다. `@vivliostyle/cli` 11.1.0 과
뷰어가 `core/render_vivlio/node_modules` 에 이미 있고 서체·원고·assets 전부
로컬이다. 막는 건 인터넷이 아니라 **터미널과 "어디를 고쳐야 하는지 모름"** 이다.

**② 손잡이가 선언되어 있지 않다**
계열마다 그때그때 필요한 것만 즉흥적으로 뚫려 있다.

| 계열 | 색 손잡이 | 치수 손잡이 | 테마 생성 |
|---|---|---|---|
| `vocaunit` (광문보카) | 20여 개 + 파트별 | 계열 기본값 오버라이드 | `theme.py` 완전 파라미터화 |
| `vocabook` (상일보카) | common + sections | 5개 | 일부 |
| `special` (특강) | 파트별 7색 | **0개** | 없음 (CSS 고정) |
| `blackbook` | **0개** (CSS에 박힘) | 레이아웃 8개 | 없음 |

가장 최근에 만든 `special` 이 `vocaunit` 보다 후퇴했다 — 급히 만들었기 때문.
선언이 없으니 ⑴사용자는 뭘 만질 수 있는지 모르고 ⑵편집기를 만들 수 없고
⑶클로드조차 매번 코드를 읽어 확인해야 한다(컨텍스트 소모).

**③ 디자인 수정이 여러 번인 이유는 두 종류인데 해법이 다르다**
- **취향 조정**("칙칙하다", "톤을 올려라", 헤더 시안 A/B/C) → 손잡이로 해결된다.
- **컨셉 오류**("빈약하다", "미러링 하지 마라", "글리프 쓰지 마라", "손가락 같다")
  → 손잡이로 해결 안 된다. **규칙을 게이트로 굳혀야** 1차 시안 품질이 올라간다.
  광교관 10차 시안의 대부분이 이 부류였다.

## S0 — 안전망 (진행 중)

**autosync 브랜치 가드** (`scripts/autosync.sh`, main 에 커밋 `697cad7`)
180초마다 도는 autosync 가 **브랜치를 보지 않고** 언제나 `origin main` 으로
pull/push 했다. 작업 브랜치를 체크아웃한 채 두면 그 커밋이 main 으로 밀려나가
브랜치를 판 의미가 사라진다. 커밋은 어느 브랜치에서든 그대로 하고 동기화
대상만 현재 브랜치로 맞췄다. 원격에 없는 새 브랜치는 `-u` 로 만든다.
→ 이건 나 때문에 생긴 게 아니라 **원래 있던 잠복 결함**이다(누가 브랜치를 파도
   조용히 main 으로 샜다).

**전체 백업** — `조판/_backup_vivlio_20260829/`
10권 교재 폴더 통째 사본(config·원고·산출 PDF·build). 교재 폴더는 git 이 아니라
파일 사본이 유일한 되돌리기 수단이다.

**회귀 기준선** — `scripts/vivlio_baseline.py` → `tests/baseline/vivlio/<키>.json`
면별 **픽셀 해시 + 텍스트 해시 + 판형**. 손잡이를 뚫으며 CSS 를 파라미터화할 때
기본값이 현재값과 정확히 같은지는 눈으로 확인할 수 없어서 기계가 잰다.

```bash
python3 scripts/vivlio_baseline.py list
python3 scripts/vivlio_baseline.py capture --books special
python3 scripts/vivlio_baseline.py compare          # 0 = 불변
```

⚠ 픽셀 해시는 MuPDF 판본에 딸린다. 판본이 바뀌면 `tx`(글자)만 신뢰하고 다시 뜬다.

**재현성 확인(필수)** — 기준선은 "지금 파일"에서 떴다. 그런데 지금 코드가 그
파일을 **재현하는지**는 별개다. 재빌드가 납품본과 다르면 기준선의 뜻이 바뀌므로
(=이미 코드와 산출물이 어긋나 있다는 뜻) 각 교재를 한 번씩 재빌드해 대조한다.
⚠ 재빌드는 산출 PDF 를 덮어쓴다 — **교재 폴더 사본을 만들어 거기서 빌드**한다.

### ⚠⚠ 동시 세션 — 이 작업의 가장 큰 함정 (2026-08-29 01:46 실증)

**리포의 워킹트리는 하나인데 클로드 세션은 여럿이 붙는다.**
`git checkout -b` 로 브랜치를 파면 **다른 세션까지 그 브랜치로 끌려간다.**
여기서 실제로 벌어진 일:

1. `vivlio-studio` 를 파자 다른 세션(특강 `G-밑줄` 게이트 작업 중)이 모르는 사이
   그 브랜치 위에서 일하게 됐다.
2. autosync 가 180초마다 `git add -A` 를 하므로 **그 세션의 미완성 편집이
   내 브랜치로 커밋됐다**(`766b0ae`, `d9866a6` — `special.css`·`special/__init__.py`).
3. 그 세션이 특강을 재빌드해 `광교관_예비고1특강_내지.pdf` 47면의 픽셀이 바뀌고
   `_인쇄.pdf` 가 새로 생겼다 — **기준선을 뜬 지 1분 만에 무효가 됐다.**
4. 같은 이유로 중등부 `_backup` ditto 가 `Operation timed out` 으로 실패했다
   (복사 중에 상대가 그 파일을 쓰고 있었다).

**대응 — 워크트리로 격리한다.**
```
~/dev/yone-design-web    main            ← 다른 세션·autosync 의 자리. 건드리지 않는다
~/dev/yone-web-vivlio    vivlio-studio   ← 이 작업 전용
```
- `node_modules` 는 gitignore 라 워크트리에 안 따라온다 → 원본을 심볼릭 링크로
  빌려 오고 워크트리의 `.git/info/exclude` 에 넣는다.
- autosync 는 `cd $REPO` 가 박혀 있어 **워크트리는 자동 커밋되지 않는다** —
  여기서는 손으로 커밋한다(그게 더 안전하다).
- 복구 절차: 상대 작업물을 `git show <커밋>:<경로>` 로 뽑아 main 워킹트리에
  되돌려 놓고, 내 브랜치는 오염 전 커밋으로 `git branch -f` 한 뒤 내 파일만 다시 얹는다.

**⚠ 교재 폴더는 워크트리로 못 가른다.** 특강·중등부는 상대가 만지는 중이므로
이번 밤 작업에서 **뺀다**(기준선도 특강만 무효). 손대는 순간 서로의 결과가 섞인다.

## S1 — 라이브 미리보기 (`watch`) ✅

```bash
bin/viv --list                    # 책 목록
bin/viv 광문보카 watch             # 이름 일부로 가리켜도 된다
bin/viv 광문보카 knobs             # 만질 수 있는 값
```

**책을 가리키는 말**은 ①실제 경로 ②`--list` 가 찍는 스튜디오 기준 상대경로
③**책 이름 일부** 셋 다 받는다. 목록에 보이는 것을 붙여 넣을 수 없으면 목록이
무슨 소용인가 — 처음엔 절대경로만 받아서 `<책폴더>` 를 그대로 친 사용자가
역추적을 봤다. 이름이 여러 권에 걸리면 후보를 보여 주고 멈춘다.

⚠ `bin/viv` 는 `python3 **-u**` 로 띄운다. 버퍼링을 끄지 않으면 **오래 도는
명령이 아무 말도 안 한다** — `watch` 가 찍는 미리보기 주소가 버퍼에 갇혀
빈 화면만 보였다(실제로 그랬다).

**재렌더 0.4초.** 전권 조판(20~50초) + PDF 뷰어 다시 열기 왕복이 사라진다.
완전히 오프라인(`@vivliostyle/cli` 와 뷰어가 이미 `node_modules` 에 있다).

설계·함정은 `docs/vivliostyle_엔진.md` 의 "라이브 미리보기" 절에. 요약:
- 렌더는 **자식 프로세스**(`bin/viv <책> render`) — 계열 `.py` 를 고쳐도 새 코드로 돈다.
- 주소를 조립하지 말고 CLI 가 찍는 `Preview URL:` 줄을 읽는다. stdout 을 안 비우면
  파이프가 차서 **서버가 멎는다**(데몬 스레드로 계속 비운다).
- **"조판 건너뛰기"는 최종 조판에만 건다.** 블랙북은 본 조판 앞에 높이 측정 PDF 를
  두 번 굽는데 거기서 멈추면 **측정용 HTML 을 미리보기로 삼는 사고**가 난다
  → `cli.run_build(..., final=False)` + 블랙북 `render_opts={"nomeasure": True}`.

### 첫 판에서 걸러낸 오탐 다섯 — 게이트를 만들 때 반드시 겪는 부류

1. **엔진 표식**(`§A1§`·`DAYOPEN`)이 0.1pt 글자로 잡혔다 → 이름 목록으로는 못 막는다
   (표식 이름이 계열마다 다르다). **크기로 가른다** — 1pt 미만은 읽을 글자가 아니다.
2. **머리말·꼬리말 6pt** 가 "본문 7pt 미만"으로 잡혔다 → 러닝 요소는 원래 작다.
   `verify.frame` 이 있으면 그걸로 본문을 가르고, 없으면 위아래 8% 를 러닝 띠로 본다.
3. **본문 최소 크기 7pt 를 기본값으로 두면 안 된다** — A4 중등부 규칙이지 A5 단어장은
   본문이 원래 6pt 다. 상일보카 한 권에서 **34,241건**이 나왔다. → 기본은 **끔**,
   분포만 적어 두고 책이 자기 바닥값을 정한다.
4. **대비를 WCAG 4.5 하나로 재면** 하우스 색이 흰 바탕에 얹힌 것까지 다 걸려
   광문보카에서 20줄이 나오고, 정작 **흰 글자가 파스텔 위에 얹힌 1.8:1** 이 묻힌다.
   → 3.0 미만만 경고, 3.0~4.5 는 **참고 한 줄**로 요약. 색 조합으로 묶어 세고
   (헤더는 매 면 반복되므로 안 묶으면 결함 2개가 "272곳"이 된다) 심한 순 8가지만 편다.
5. **평평한 색 띠는 장식이 아니다** — 광문보카는 위아래에 단색 분홍 띠를 두는데
   단색이니 좌우가 같은 게 당연하다. 채도로 "장식 있음"을 재면 64개 펼침면이 전부
   미러링으로 걸린다 → **경계선 밀도**(`_edge_density`)로 모양이 있을 때만 따진다.

### 기존 3권 첫 판정 — **고치지 않는다(납품 중). 목록만 남긴다**

- **블랙북01** — 해설 간지 헤더 `Unit 01`: 흰 글자가 카키 캡슐 위 **1.8:1**,
  올리브 `Unit` 이 같은 캡슐 위 2.2:1 (84·100면). 2면 머리 올리브/짙은회색 2.7:1.
- **상일보카01** — **헤더 워드마크 `SANGIL VOCA` 흰 글자가 파스텔 띠 위 1.7:1**
  (32면). 이건 우리 규칙 "**흰 글자는 deep 위에만**" 위반이 그대로 잡힌 것이다.
  `MEMO` 회색 1.9:1. `·` 를 머리 기호로 66번(152~159면) — 글리프 장식 금지 위반.

## S3 — 손잡이 선언 ✅ (blackbook · vocabook · vocaunit)

`core/render_vivlio/knobs.py` + 계열의 `knobs(cfg)` 선언.

```bash
bin/viv "<책폴더>" knobs                              # 무엇을 만질 수 있나
bin/viv "<책폴더>" knobs --set="palette.gold=#c0392b" # 값 바꾸기(config.json 에 쓴다)
bin/viv "<책폴더>" knobs --reset="palette.gold"       # 기본값으로
bin/viv "<책폴더>" knobs --json                       # 편집기가 읽을 형태
```

| 계열 | 손잡이 | 방식 |
|---|---|---|
| blackbook | 19 | 테마가 **고정 CSS** → `build/knobs.css` 로 `:root` 덮어쓰기 |
| vocaunit | 20 | `theme.py` 가 config 를 이미 읽는다 → 선언만 |
| vocabook | 34 | 같음. 섹션 색은 **config 에서 읽어** 손잡이를 만든다(6섹션×3색) |

**핵심 계약 — 손잡이는 덮어쓰기만 한다.** config 에 없는 키는 아무것도 내보내지
않으므로, 손잡이를 뚫는 것만으로는 지면이 한 픽셀도 안 바뀐다. 블랙북을 다시
빌드해 확인했다(116면 지면 불변).

### 되돌리기(reset)는 **기본값을 아는 손잡이만**

- `blackbook` 은 기본값이 `themes/blackbook.css` 의 `:root` 에 있다 → 지우면 그 값.
- `vocabook`·`vocaunit` 의 팔레트는 **config 가 곧 원본**이다 → 지우면 계열 코드의
  임시 폴백으로 떨어져 디자인이 달라진다. 그래서 `resettable=False` 로 막았다.
  모르는 기본값을 아는 척하지 않는 것이 요점이다.
- 치수는 계열의 `DEFAULT_METRICS` 가 진짜 기본값이라 되돌릴 수 있다.

### 계약 검사 — `tests/test_render_vivlio_knobs.py` (12건, 오프라인)

손잡이에서 사람이 절대 못 잡는 결함은 하나다: **선언한 기본값 ≠ 실제 기본값.**
그러면 값을 바꿨다 되돌렸을 때 원래대로 안 돌아온다. 그래서
`css` 손잡이의 기본값 = `themes/<계열>.css` 의 `:root` 값,
치수 손잡이의 기본값 = 계열 `DEFAULT_METRICS` 를 기계가 대조한다.

### 여기서 실제로 물린 것 둘

1. `knobs.write(cfg, BlackbookSeries, …)` 로 **클래스를 넘겨** `knobs()` 가 터졌는데,
   **빌드가 죽었는데도 폴더에 먼저 만든 PDF 가 남아 회귀 대조가 통과**했다.
   → `of()` 가 클래스도 받게 고치고, `compare --newer-than <분>` 을 신설해
   **다시 만들어지지 않은 PDF 로는 통과할 수 없게** 했다. 이건 손잡이보다
   중요한 교훈이다 — 회귀 게이트는 "무엇을 쟀는가"만큼 "그게 새 결과인가"를 봐야 한다.
2. 손잡이가 34개가 되자 목록이 안 읽혔다 → 묶음에 `섹션` 을 더해 갈랐다.

## S4 — `overrides.css` 탈출구 ✅

책 폴더에 `overrides.css` 를 두면 **맨 마지막에** 얹힌다(무엇이든 이긴다).

손잡이를 아무리 잘 뚫어도 "이번 한 번만 여기를 이렇게" 하고 싶은 자리는 반드시
생긴다. 그때 계열 CSS 를 고치면 다른 책까지 바뀌고, `build/` 안을 고치면 다음
렌더에 사라진다 — 결국 클로드를 부르게 된다. 그 자리를 책 폴더의 파일 하나로 연다.

- 계열 코드를 안 건드리므로 다른 책에 영향 없음
- `build/` 가 아니라 **책 폴더**라 재빌드해도 살아남음
- `watch` 가 지켜보므로 저장하면 바로 보임
- 자주 쓰는 것이 보이면 **손잡이로 승격**한다 (그게 이 파일의 쓸모다)

⚠ 계열이 모르는 규칙이라 계열이 바뀌면 어긋날 수 있다. 임시 처방이지 살림집이 아니다.

## S5 — 내지 작업대 (`/book-studio`) ✅

`routes/book_studio.py` + `templates/book_studio.html`.
표지 작업대(`/cover-studio`)의 내지 판이고 같은 뼈대를 따른다 — 목록은 폴더에서
찾고(`bin/viv list --json`), **조절판은 계열이 선언한 손잡이로 저절로 그려진다.**
계열에 손잡이를 더하면 화면을 안 고쳐도 거기 나타난다.

- 왼쪽: 손잡이 폼(색은 컬러픽커+hex, 치수는 슬라이더) + `overrides.css` 편집칸
- 오른쪽: **Vivliostyle 뷰어가 직접 조판**한 지면 (PDF 를 굽지 않는다)
- 저장 → `config.json` 갱신 → 다시 렌더 → 화면 갱신

### 미리보기는 **견본**이다

전권(116~259면)을 브라우저 안에서 조판시키면 렌더러가 버거워 화면이 멎는다
(실제로 겪었다 — 블랙북 전권은 1면 그리는 데도 수십 초). 그래서 기본이 견본이고
`전권으로 보기` 체크박스로 넘길 수 있다.

⚠ **`--sample` 이 블랙북에서는 산출 파일 이름만 `_견본` 으로 바꾸고 내용은 전권
그대로였다**(그래서 화면이 멎었다). 진짜 견본(1과·어휘 2·문항 8, 해설은 번호가
맞는 것만)을 구현했다 → HTML 393KB → 31KB.

### 여기서 실제로 걸린 것 넷 — 전부 "빈 상자"로만 보인다

1. **`frame-ancestors 'none'`** — 우리 화면이 우리 뷰어를 iframe 으로 못 문다.
   → `/book-studio/viewer|doc` 에만 `'self'` 로 연다(다른 화면은 그대로 DENY).
2. **뷰어 번들이 `eval` 을 쓴다** → CSP `script-src` 에 막혀 `EvalError`,
   지면이 영원히 안 그려진다. → `'unsafe-eval'` 을 **뷰어 경로에만** 준다.
   이 번들은 우리가 node_modules 에 고정해 둔 정적 파일이고 사용자 입력이
   들어가지 않는다. 앱의 다른 화면은 그대로 eval 금지.
3. **`src=` 를 URL 인코딩하면 안 된다** — 뷰어가 상대 경로로 보고
   `/book-studio/viewer/%2Fbook-studio%2F…` 를 찾다 404.
4. **책을 가리키는 URL 조각은 하나여야 한다** — 키(`조판/교재/…`)를 그대로 쓰면
   슬래시 때문에 `assets/`·`fonts/` 하위가 404. → sha1 앞 10자리 `bid`.

이 넷은 증상이 전부 "미리보기가 비어 있다"라 콘솔을 봐야 원인이 나온다.

### config.json 서식을 지키며 고친다

작업대는 값을 바꿀 때마다 `config.json` 을 쓴다. 통째로 다시 쓰면(`json.dump`)
값은 맞지만 **손으로 맞춘 서식이 사라진다** — 빈 줄 묶음, `"page": { … }` 처럼
한 줄로 쓴 것, 주석 구실을 하는 `_note` 의 자리. 실제로 블랙북 config 를 한 번
뒤집어 놓고 백업에서 되돌렸다.

→ `knobs.patch_text()` 가 **바뀐 값의 자리만** 갈아 끼운다(최소 JSON 훑개로 값
스팬을 찾아 치환·삽입·삭제). 실제 책 config 로 **값을 바꿨다 되돌리면 원문과
바이트까지 같다**(`test_patch_real_configs_roundtrip`). 못 하는 모양이면 통째
쓰기로 물러서되 그 사실을 로그로 알린다. 어느 쪽이든 `.bak` 을 남긴다.

## S6 — 시안 매트릭스 ✅

```bash
bin/viv "<책폴더>" variants --knob=palette.gold \
        --values="#908400,#c0392b,#1e88e5" [--pages=4]
```

→ `<책폴더>/_시안_gold.pdf` — 같은 견본 앞면들을 **값마다 한 줄씩** 붙인 한 장.

시안은 지금까지 **순차**였다(헤더 시안 A → 지적 → B → …). 값 하나만 다른
시안이라면 동시에 뽑아 한 장에 놓고 고르는 편이 빠르다. 손잡이가 선언돼 있으니
"어느 값을 어떻게 바꿀지"를 기계가 안다.

⚠ 값은 **메모리에서만** 갈아 끼운다 — 시안을 뽑다가 `config.json` 이 바뀌면 안 된다
(끝나면 원래대로 되돌리고, 되돌림은 `finally` 에 둔다).

## S7 — 클릭 편집 ✅ (blackbook 우선)

지면의 글을 **클릭하면 그 자리에서 고친다.** "오타 하나 고치는 데 클로드"가
사라지는 지점이라 이 작업에서 값어치가 가장 큰 조각이다.

```
지면 클릭 → 자리표(lessons.0.problems.3.stem) → 글 상자 → 저장
        → errata.json → 다시 렌더(0.4초) → 화면
```

### ① 고친 것은 `data.json` 이 아니라 **정오표**에 쌓인다

`data.json` 은 원고에서 만들어진다. 거기 직접 손대면 `bin/viv <책> data` 를 한 번
돌리는 순간 **말없이 되돌아간다.** 그래서 `<책폴더>/errata.json` 에 쌓고
`errata.load_data()` 가 **읽는 자리에서** 얹는다 — 조판도 검수도 같은 글을 보므로
게이트와 어긋날 자리가 없다(중등부 `book.py` 의 `errata` 와 같은 생각).
자리가 사라지면(원고가 바뀌면) **조용히 넘기지 않고 경고**한다.

### ② 서식을 잃지 않는다 — `**굵게** __밑줄__ //기울임//`

원고 글은 조각으로 서식을 들고 있다(`[{t:"밑줄 친", u:true}, …]`). 민글로 받았다
되돌리면 **밑줄이 사라지는데**, 어법 문제는 밑줄이 곧 문제라 그건 글자를 고치는
게 아니라 문제를 망가뜨리는 것이다. `richtext.py` 가 표시로 폈다 되접는다.
민글로 들어온 것은 민글로 돌려준다(모양이 바뀌면 data.json 이 달라진다).

### ③ ⚠ Vivliostyle 은 **임의 속성을 조판 결과로 옮기지 않는다**

`data-ref` 만 심으면 화면에서 클릭해도 아무것도 못 찾는다(실제로 그랬다 —
`data-vivliostyle-*` 와 `data-adapt-eloff` 만 남는다). 반면 **class 는 남는다**
(CSS 가 거기 걸려 있으니 당연하다).
→ 자리표를 `vrefN` **클래스 토큰**으로 싣고, 번호↔경로 표는 `build/refs.json`
으로 따로 낸다. `data-ref` 는 원본 HTML 을 사람이 읽을 때를 위해 같이 남긴다.
→ 클릭 훅은 **뷰포트가 생기면** 건다. "자리표가 보일 때까지" 기다리면 첫 면이
간지인 책에서 영영 안 걸린다.

### ④ ⚠ 클래스를 하나 얹었더니 지면이 바뀌었다 (게이트가 잡았다)

자리표를 붙이면서 **대화문 줄에 `.t` 를 같이 얹었는데**, 원래 대화문 줄에는
클래스가 없었다. `<보기>` 상자 안 대화문의 줄바꿈이 달라져 **26·61면이 어긋났다.**
회귀 대조가 아니었으면 못 봤다 — 글자는 하나도 안 틀렸기 때문이다.
자리표만 붙이고 클래스는 원래대로 두어 해결(116면 지면 불변 재확인).

### ⑤ ⚠ 견본이 `heights.json` 을 덮어썼다

시안을 뽑은 뒤 전권 렌더가 "문항 높이 8" 로 돌았다 — 견본(8문항)의 측정값이
전권 표를 덮었기 때문. 견본은 `heights_견본.json` 을 따로 쓰게 고쳤다.

### 남은 것

지금 자리표는 **blackbook 의 발문·지문·선지·보기**에 있다. 어휘·해설과 다른
계열(vocabook·vocaunit)은 같은 방식으로 넓히면 된다 — `index_refs()` 로 객체→경로
표를 만들고 `_mark()` 로 클래스를 얹는 것이 전부다(계열당 반나절).

값만 만지던 조절판을 **인디자인 배치**로 갈아엎었다: 위에 도구줄 · 왼쪽에 툴 ·

| 찾기 · 바꾸기(전권) | `edits.json` `set` 연산 다발 | ○ |
| 쪽 나눔 | `[data-ref="…"]{break-before:page}` | 같은 버튼 다시 |
| 그림 배치 | `assets/` + `[data-ref="…"]::after{content:url(…)}` | 규칙 삭제 |

### 왜 그림도 CSS 로 앉히는가

원고에 없던 도표를 한 자리에만 넣으려고 **계열 코드를 고치면 그 계열 책이 전부
흔들린다.** 그래서 그림은 파일로 넣고 규칙 한 줄로 앉힌다. 계열 코드가 안 바뀌니
이미 납품한 책은 그대로다. Vivliostyle 이 `content: url()` 을 대체 요소로 조판해
블록으로 흘려 주는 것을 실측으로 확인했다(블랙북 8면, 지정한 60.0mm 그대로).

⚠ `[data-ref=…]` 규칙은 **그 자리**를 가리킨다. 원고가 바뀌면 딴 곳을 잡는다 —
  편집 연산과 같은 성질이라 화면에도 그렇게 적어 두었다.

### 자리표는 셋을 심는다 (`refs.py`)

    class     조판 결과 DOM 에 **남는다** → 클릭한 자리를 되짚는다
    id        결과에 남는다 → 검색 결과에서 그 자리로 이동한다
    data-ref  결과엔 없지만 **조판하는 동안 있다** → CSS 선택자로 쓴다

### 이번에 드러난 것

색을 바꿔도 그 책만 아무 일도 안 일어났다(조용히). 네 계열이 같은 길을 지나는지

## 화면이 고장 나 보이던 것 (2026-08-31 저녁)

"이렇게 뜨는데?" — 작업대를 열면 **빈 흰 면**이 나왔다. 재현해 보니 세 가지가
겹쳐 있었다.

### ⚠ ①`id` 는 조판 결과에 안 남는다 — 찾기 이동이 여태 안 됐다

`refs.mark()` 가 `class`·`id`·`data-ref` 셋을 심는데, **남는 것은 `class` 뿐**이다.
`id` 는 원본 HTML 에만 있고 조판 결과 DOM 에는 없다(실측: `[id^=vref]` 0개).
그래서 `navigateToInternalUrl('#vrefN')` 은 **아무 일도 안 한다** — 문서 URL 을
붙여도, 쿼리까지 붙여도 안 움직인다.

그 API 로 만든 **찾기 결과 클릭 → 그 자리로 이동은 처음부터 안 되고 있었다.**
계획서에 "id 도 남는다" 고 적어 둔 것이 틀렸다(고쳤다).

지금은 **면을 넘기며 `.vrefN` 클래스를 찾는다**. 한 면에 1~2초가 들어 열 몇 면을
가면 30초가 넘으므로, 몇 면째인지 계속 알리고 Esc 로 멈출 수 있게 했다.

### ⚠ ② `navigateToPage()` 는 비동기다 — 세면서 넘기면 안 된다

"빈 면이면 한 장 더" 를 되풀이했더니 **1면을 아홉 번 다시 보고 아홉 번 넘겼다**
(그러고도 엉뚱한 데 섰다). 함정이 셋 겹쳐 있다.

  ① 지나온 면이 `display:none` 으로 DOM 에 쌓인다 → 앞에서 집으면 언제나 1면
  ② 넘긴 **직후에는 새 면이 아직 안 그려져** 폭이 0이고 글이 비어 있다
  ③ 그때 **옛 면이 아직 보인다** → "보이는 것 중 맨 뒤" 로도 옛 면을 집는다

**맨 뒤 칸이 다 그려졌을 때만** 인정하고(`pageEl()`), 쪽 번호가 실제로 바뀔
때까지 기다린 뒤 다음 판단을 한다(`afterRender()` · `seek()`).

### ⚠ ③ 껍데기 높이를 96px 로 못 박아 두었다

실제 머리띠는 **73px** 이라 23px 짜리 죽은 틈이 생기고, 그만큼 문서가 길어져
**화면이 12px 스크롤**됐다. 스크롤되는 조판 프로그램은 쓸 수가 없다.
이제 머리띠를 **재서** `--ide-top` 에 넣고(창 크기가 바뀌면 다시 잰다),
작업대가 떠 있는 동안은 문서를 못 스크롤하게 한다.

### 그밖에

- 블랙북 1면은 `§DIV1§` 표식뿐인 **간지 자리**다(마감 때 진짜 간지 PDF 로 바뀐다).
  열자마자 그 흰 면이 나와 고장 난 것처럼 보였다 → 이제 내용부터 편다.
- `MARK` 라는 이름을 새로 지었다가 **굵게/밑줄 표시 상수와 부딪혀** 서식 버튼이
  조용히 죽었다. 이 파일은 한 IIFE 안에 다 들어 있어 이름이 겹치기 쉽다.
- 오른쪽 팔레트가 잘려 보인 것은 캡처가 잘린 것이었다(실측: 창 안에 정확히 들어간다).

### 남은 것

- **찾아가기가 느리다**(면당 1~2초). `renderAllPages` 를 잠깐 켜고 뛰는 길을
  재 볼 만하다 — 지금은 진행 표시와 Esc 로 버틴다.

## ⚠ 미리보기가 조판본과 달랐다 (2026-08-31 밤)

"왜 왼쪽으로 쏠렸어? 조판본이랑 전혀 다르잖아" — 본문 단이 **167mm 여야 하는데
118mm** 로 나왔다. 폭만 좁은 게 아니라 **줄바꿈도 면 나눔도 달라졌다**
(지문이 3줄 → 7줄, `amazed`·`randomly` 두 항목이 다음 면으로 밀렸다).
디자인을 보라고 만든 화면이 **다른 판을 보여 주고 있었다.**

### 원인 — 우리 앱 CSS 가 조판에 얹혔다

지면이 이제 **우리 문서 안**에 있다(뷰어 앱 iframe 을 벗은 대가다). 그래서
`main.css` 첫 줄의 전역 리셋이 그대로 조판에 걸린다:

```css
*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }
```

Vivliostyle 은 **내용 요소**에는 계산한 값을 인라인으로 박지만, 자기가 만든
**판면 래퍼**에는 안 박는다. 그 래퍼는 `width` 에 `padding`(=판면 여백)을 얹어
쓰는데 `border-box` 가 되면 여백이 **두 번** 깎인다:

    216mm − 23 − 26 = 167mm   (한 번, 옳다)
    167mm − 23 − 26 = 118mm   (두 번, 우리가 보던 것)

같은 문서를 **뷰어 앱**(`/book-studio/viewer/`)으로 열면 167mm 가 나온다 —
그 앱은 자기 문서라 우리 리셋이 없다. 그 대조가 범인을 확정했다.

### 고침

```css
#ide-stage, #ide-stage *, #ide-stage *::before, #ide-stage *::after {
  box-sizing: content-box;          /* 내용 요소는 인라인이 이긴다 */
}
#ide-stage { font: initial; color: initial; line-height: normal; … }
body.ide-on .site-footer { display: none; }
```

- **전칭 선택자를 지면에 대지 말 것.** 내가 쓴 `.ide *` 도 같은 죄였다.
- 물려받는 것(서체·글자색·행간)도 끊는다 — Vivliostyle 이 값을 안 박은 자리에서
  조용히 다른 판이 된다.
- 앱 푸터(`© 2026 Y.ONE DESIGN · All rights reserved`)가 **지면 위로 비쳤다.**
  작업대는 화면을 꽉 채우므로 그 아래 문서는 감춰도 된다.

### 확인

블랙북 2면 — 지면 본문 단 **167mm**(PDF 와 같다), 지면 글과 PDF 2면 글이
같은 자리에서 끝난다(`… on purpose(의도적으로)`). 광문보카·특강도 정상.

`test_render_vivlio_studio.py` 에 다섯 건을 못박았다(고침을 되돌리면 빨간불인
것까지 확인했다). 전역 리셋이 실제로 있는지도 같이 본다 — 리셋이 없어졌는데
시험만 남으면 무엇을 지키는지 모르게 된다.

### 교훈

**미리보기는 "비슷해 보이면 된다" 가 아니다.** 이 화면을 보고 디자인을
판단하므로, 판면·줄바꿈·면 나눔이 조판본과 **같아야** 한다. 앞으로 이 화면에
CSS 를 더할 때는 반드시 `#ide-stage` 밖으로 범위를 좁힐 것.

## 지면을 딴 문서로 격리했다 (2026-08-31 밤, 이어서)

앞 절에서 앱 CSS 오염을 **보상용 규칙**으로 막았는데, 그건 앱 스타일시트에
규칙 하나 더할 때마다 같은 사고가 난다는 뜻이다. 그래서 **문서를 갈랐다.**

    작업대 화면  ─┐
                  ├─ 같은 출처(same-origin) 이지만 **다른 문서**
    지면 iframe  ─┘   `/book-studio/frame`  (routes/book_studio.py: FRAME_HTML)

지면 문서가 싣는 것은 **조판 엔진 하나와 표식용 CSS 몇 줄**뿐이다.
`main.css` 도 `book_studio.html` 의 스타일도 거기 안 닿는다.
보상용 규칙(`#ide-stage` 의 `box-sizing`·서체 초기화)은 **걷어냈다** —
격리만으로 167mm 가 나오는 것을 확인했다.

### 잃은 것이 없다 (같은 출처라서)

    클릭 편집   프레임 문서에 이벤트를 건다 (`hookStage()` → `stageEl()`)
    글자 편집   `contenteditable` 은 그 문서 안에서 그대로
    굵게·밑줄   ⚠ **선택 영역은 프레임 창의 것**이다.
                `getSelection()`·`createRange()` 를 화면 문서 것으로 쓰면
                지면 안 글을 몰라 서식이 조용히 안 먹는다 → `fwin()`·`fdoc()`
    단축키      ⚠ 고치는 동안 커서가 **프레임 안**에 있다. 화면 문서에만 걸면
                ⌘↵·⌘B·Esc 가 전부 안 먹는다 → 두 문서 모두에 건다
    커서 표시   `tool-text` 같은 상태 클래스를 **양쪽 body** 에 건다

### ⚠ 엔진은 프레임 것만 쓴다

화면 문서에도 번들을 실으면 그쪽 기준으로 계산돼 판이 또 달라진다.
`<script src="…vivlio-core.js">` 는 **프레임 문서에만** 둔다.

### ⚠ 프레임 문서 안에서도 전칭 선택자는 금물

조판 결과가 그 문서에 그려지므로 `*` 규칙 하나가 판면을 바꾼다.
`FRAME_HTML` 의 규칙은 전부 **우리가 심은 표식**(`vrefN`·`ide-editing`)에만
건다. 시험이 이걸 못박는다(주석은 빼고 선택자만 본다).

### 확인

블랙북 본문 단 **167mm**, 2면 글이 PDF 2면과 같은 자리에서 끝난다.
상일보카·광문보카·특강·중등부 모두 정상. 클릭 → 선택, T → 편집,
⌘B → `**굵게**`, Esc → 취소, 찾기 → 8면 이동까지 프레임 너머로 확인했다.
워터마크 없음. 시험 8건 신설(격리를 되돌리거나 전칭 규칙을 넣으면 빨간불).

## 알아볼 수 있게 · 고를 수 있게 (2026-08-31 밤, 이어서)

써 보고 나온 지적들. 기능이 아니라 **알아볼 수 있느냐**의 문제가 많았다.

### ⚠ 문장이 안 잡히고 단락만 잡혔다

누를 때마다 다시 골라서 편집기를 새로 열었고, 그때마다 커서가 **글 끝으로
튀었다.** 그래서 드래그도 더블클릭도 소용이 없었다.
→ **고치고 있는 글 안을 누른 것이면 손대지 않는다.** 글을 고르는 것은
브라우저가 알아서 한다.

### 자리표 이름의 머리글자가 곧 **출처**다

지면의 글이 전부 원고에서 오는 것은 아니다. 그걸 구분 안 하니 머리 띠를
눌러도 "원본에 없는 자리" 만 떴다.

    lessons.…   원고(data.json)   → 글자 편집은 edits.json 에 쌓인다
    book.…      책 설정(config)   → 글자 편집은 config.json 을 고친다
    #…          조판이 만든 것    → 고를 수만 있다(스타일·색·쪽 나눔)

머리 띠·탭·제목·기입칸에 자리표를 달았다. 제목은 `book.subject` 라, 고치면
그 책의 같은 자리가 모두 바뀐다는 것도 알려 준다. 조판이 만든 자리는
"모양은 오른쪽 단락 스타일에서 바꿉니다" 라고 이유를 말한다.

### 스타일에 사람 이름을 붙였다

`.pbox`·`.vunit` 만 보여 주면 무엇을 고르는지 알 수 없다. 계열마다
`style_names` 를 두었다(블랙북 31 · 단어장 30 · 광문 15 · 특강 18 · 중등부 24).
목록에는 **「지문 상자 (.pbox)」** 처럼 사람 이름을 앞에 세운다.

### 색은 CMYK 로 읽힌다

내지는 종이에 찍힌다. 화면의 `#908400` 이 인쇄에서 몇 %인지 모르면 색을
정할 수가 없다.

⚠ **눈대중 공식을 쓰지 않는다.** 마감(`prepress.py`)이 실제로 쓰는 그 ICC
  프로파일(Japan Color 2001 Coated)로 서버가 바꾼다 — 공식으로 낸 숫자는
  인쇄물과 달라서 없느니만 못하다.

⚠ **먹으로 빠지는 색은 CMYK 가 아니라 K 단색**이다(`DEFAULT_GRAY_MAP`).
  본문 먹·품사·발음기호는 마감 때 DeviceGray 로 바꾼다 — 리치 블랙으로 4도가
  겹치면 글자가 번지기 때문이다. 그런 색은 `K100 (먹 단색)` 이라고 적는다.

### 화면 설명을 달았다

- **직접 손보기(CSS)** — 여기 적은 CSS 가 이 책 조판에 그대로 얹힌다.
  `overrides.css` 에 저장되고 다른 책은 안 바뀐다. 임시 처방이라는 것까지.
- **왼쪽 도구** — 선택(V)은 스타일·색만 본다 / 글자(T)는 그 자리에서 글을
  고친다 / 문단(P)은 글자와 같되 나누기·넣기·합치기·지우기를 함께 쓴다.
- **견본 · 전권** — 견본은 앞부분만 빠르게(색·여백 볼 때), 전권은 책 전체라
  느리지만 면수·면 나눔이 실제와 같다.

### 남은 것

- 중등부·단어장 계열의 **머리 띠에도** 같은 자리표를 달 것(지금은 블랙북만).
- CMYK 를 **입력**으로도 받을 것(지금은 보여 주기만 한다).

## 클로드 칸 · 머리 띠 자리표 (2026-08-31 밤, 이어서)

### 「직접 손보기(CSS)」는 사실상 빈 칸이었다

CSS 를 쓸 줄 아는 사람만 쓸 수 있는 칸이었다. 사람이 하고 싶은 말은
"머리 띠를 좀 더 진하게" 이지 `.sechdr{background:#…}` 가 아니다.
그 자리를 **클로드에게 한국어로 시키는 칸**으로 바꿨다.
(CSS 칸은 「고급」으로 접어 남겨 뒀다 — 아는 사람에게는 여전히 가장 빠르다.)

### ⚠ 모델에게 리포를 열어 주지 않는다

계열 코드를 고치면 **그 계열 책이 전부 흔들리고**, 원고를 고치면 납품본과
글이 달라진다. 그래서 손댈 수 있는 곳을 셋으로 못 박았다 — 셋 다 **그 책
폴더 안 파일**이라 다른 책은 어떤 경우에도 안 바뀐다.

    knobs           config.json 의 손잡이 값 (계열이 선언한 key 만)
    styles          config.json 의 `styles` 절 → build/knobs.css
    overrides_css   그 책의 overrides.css

**모델이 준 것을 그대로 쓰지 않는다.** `assist.vet()` 이 전부 다시 검사한다 —
없는 손잡이, 색이 아닌 색, min~max 밖 숫자, `{`·`}` 든 선택자, `@import`·
바깥 `url(` 든 CSS 를 걸러 내고 **왜 걸렀는지 화면에 적는다.** 조용히 반만
먹는 것이 제일 나쁘다. 모델에게는 "인쇄물이다 · 8pt 아래로 내리지 마라 ·
확실하지 않으면 고치지 말고 무엇이 필요한지 적어라" 를 못박아 둔다.

**되돌릴 수 있다.** 고치기 전에 `config.json`·`overrides.css` 를 `.bak` 으로
남긴다. ⚠ 원래 **없던** 파일이면 `.bak` 이 없어 되돌릴 방법이 사라진다 —
'원래 없었다' 도 되돌릴 상태라 `.none` 표식을 남겨 도로 없앤다(실측으로 잡았다).

키는 `ANTHROPIC_API_KEY` 환경변수에서 읽는다. 없으면 단추를 막고 **무엇을
하면 되는지** 화면에 적는다(그냥 실패하면 원인을 알 수 없다).

### 머리 띠 자리표를 네 계열 모두에

머리·꼬리도 지면이다. 예전엔 어느 계열에서도 안 잡혔다.

| 계열 | 단 것 |
|---|---|
| blackbook | 머리 띠 · 유닛탭 · 제목(`book.subject`) · 기입칸 · 본문 라벨 칩 |
| vocabook | 탭 · 브랜드(`book.brand`) · 머리 라벨 · 꼬리말 좌우 · DAY 머리 |
| vocaunit | 머리 탭 · 브랜드 · 꼬리 좌우 · 단원 머리(3칸은 **원고**라 편집 가능) |
| special | 머리말 좌우 · 책 이름(`book.running`) · 큰 제목 |
| middle | 머리말 좌우 · 구역 머리 |

### 시험을 방법이 아니라 **지켜야 할 것**에 걸 것

`_refs.index(` 를 시험하고 있었는데 `index_paths(` 로 옮기자마자 깨졌다.
바뀐 것은 방법이지 지켜야 할 것이 아니었다 — "자리표를 만들고 표를 낸다" 로
고쳤다.

### 회귀

```
blackbook 116p · gwangmun 160p · special 148p · sangil 259p → 683면 불변 ✓
클로드 칸 — 모델 응답을 대신 넣어 끝까지 확인:
  · 옳은 것만 반영(손잡이 1 · 스타일 1 · CSS 1), 엉뚱한 것 3건은 이유와 함께 거름
  · 되돌리기 뒤 config.json 이 **바이트까지 같고**, 새로 생긴 overrides.css 는 사라짐
시험 1344 passed (신규 75건 중 이번 12건). 새로 실패 0.
```

### 남은 것

- 클로드 칸은 **디자인만** 고친다. 원고 오타는 지금처럼 지면에서 직접 고친다
  (그쪽은 되돌리기가 편집 이력에 있다).
- CMYK 를 **입력**으로도 받기(지금은 보여 주기만).

## 에디터로 다시 짰다 (2026-09-01)

"변경도 전혀 안 되고 에디터로의 기능이 하나도 없는데 뭘 만든 거야?" —
맞는 말이었다. 지적을 하나씩 확인하고 고쳤다.

### ⚠ 스타일이 "전혀 안 변한" 진짜 이유 — 단위

`font-size: 20` 이 저장돼 있었다. **단위가 없으면 CSS 는 그 선언을 통째로
무시한다.** 그런데도 "✓ 스타일 저장" 이 떴다. 조용히 아무 일도 안 하는 것이
제일 나쁘다.

  · 화면은 이제 **숫자와 단위를 따로** 받고 우리가 붙인다(`20` + `pt`).
  · 서버도 `_needs_unit()` 으로 막고 **무엇을 붙이라고** 말해 준다.

(조판 자체는 멀쩡했다 — 단위를 붙여 심으니 11pt 칩이 20pt 로 나왔다.
 안 되던 것은 값을 만드는 자리였다.)

### ⚠ 패널이 **책마다 달랐다** — 그건 에디터가 아니다

계열이 선언한 손잡이를 그대로 늘어놓았더니, 어떤 책은 "헤더 간격", 어떤 책은
"보는 권" 이 떴다. 인디자인은 어떤 파일을 열어도 문자·단락 패널이 같고
**값만** 문서에서 온다. 그렇게 바꿨다.

| 패널 | 내용 | 책마다 다른가 |
|---|---|---|
| 문자 | 글꼴·크기·행간·자간·굵기·기울임·밑줄·글자색·바탕색 | **아니오** |
| 단락 | 정렬·들여쓰기·좌우 여백·앞뒤 간격·쪽 나눔·덩어리 유지 | **아니오** |
| 단락 스타일 | 이 책의 스타일 목록 | 목록만 |
| 페이지 | 면 목록·이동·낱쪽/펼침 | 아니오 |
| 색상 견본 | 이 책이 쓰는 색 | 목록만 |
| 문서 설정 | 판면·간격 | 목록만 |

계열 손잡이는 **색상 견본**과 **문서 설정** 두 패널로 들어갔다.

### 고른다는 것 — 인디자인의 규칙을 그대로

    한 번  → **덩어리**(가장 바깥 자리표). 지문 상자면 상자 전체
    두 번  → 그 안으로 한 단계
    빈 곳  → 선택을 푼다

그러려면 덩어리에도 자리표가 있어야 한다 — `.vunit`·`.pbox`·`.q` 에 달았다
(전에는 안쪽 단락에만 있어서 늘 한 단락씩만 잡혔다).

### ⚠ 실시간은 스타일시트로 안 된다

두 번 막혔다.
  ① 저장용 선택자 `[data-ref="…"]` 는 **조판 결과 DOM 에 없다** — 그래서
     저장하면 되는데 미리보기만 안 바뀌었다.
  ② `<style>` 을 프레임 head 에 넣었더니 규칙이 **0개**로 들어갔다
     (조판 엔진이 head 를 자기 식으로 다룬다).

그래서 **요소에 직접** `important` 로 얹는다. 값을 만지면 그 자리에서 바로
보이고(14.66px → 26.67px 확인), 잠시 뒤 저장하고 다시 조판해 **정확한 판**으로
바꾼다(줄바꿈·면 나눔은 다시 조판해야만 맞다).

### 고치는 중에도 지면은 그대로

바탕을 노랗게 칠하고 글꼴을 고정폭으로 바꾸던 것을 걷었다 — 누를 때마다 글이
딴것처럼 보이면 조판을 보는 눈이 흐트러진다. 이제 얇은 테두리와 커서만 바뀐다.
원본 표시(`**굵게**`)로 갈아 끼우는 것도 **보이는 글과 원본이 다를 때만**
하고, 그때는 이유를 말한다.

### 남은 것 — 아직 인디자인이 아니다

정직하게 적어 둔다.

- **글자 단위 서식이 없다.** 지금 문자 패널은 **문단/덩어리 전체**에 걸린다.
  고른 몇 글자만 굵게는 ⌘B 로 되지만(원고에 표시가 들어간다), 크기·색은 안 된다.
- **페이지 패널에 썸네일이 없다.** 전권을 다 그려야 해서 몇 분이 든다 —
  지금은 번호를 눌러 간다.
- **되돌리기가 갈라져 있다.** 글은 편집 이력, 디자인은 `.bak`.
- **면 이동이 느리다**(한 면씩 넘긴다). 뷰어에 '몇 면으로' 가 없다.

## 인디자인에 맞춰 나가기 (2026-09-01 밤)

"인디자인과 99.9% 동일해질 때까지" 라는 지시로 밤새 이어 만든 것.

### ① 글자 단위 서식 — 편집 방식을 바꿔야 했다

가장 큰 구멍이었다. 예전 방식(글 안에 `**굵게**` 표시를 끼움)은
굵기·밑줄·기울임 셋뿐이고 크기·색은 담을 자리가 없었다. 게다가 편집기를 열
때마다 글이 딴것처럼 보였다.

→ 편집기에 **HTML** 을 준다. 보이는 그대로 고치고, 저장할 때
  `richtext.from_html()` 이 세그먼트로 되접는다.

    {"t": "글", "b": 1, "st": {"font-size": "12pt"}, "cs": "강조"}

  · **민글은 민글로** 돌려준다(형태가 바뀌면 회귀가 시끄럽다)
  · 빈칸(`_____`)은 `data-raw` 로 실어, 편집기에선 빈칸처럼 보이고 정확히 돌아온다
  · 붙여넣기로 들어온 남의 태그는 글자만 남긴다
  · 실측: 고른 12글자만 PDF 에 **12.00pt #cc0000** 으로 찍혔다

문자 패널은 **글자를 골라 두었으면 그 글자에**, 아니면 덩어리 전체에 건다
(인디자인과 같다). 어디에 걸리는지 늘 화면에 적는다.

### ② 되돌리기를 하나로

글은 편집 이력, 디자인은 `.bak` 으로 갈라져 있었다. 이제 디자인도 같은 이력에
연산으로 쌓는다(`design_ops.py` — style·knob·css). 실측: 스타일→글→스타일 세 번
뒤 ⌘Z 세 번이면 config 가 **바이트까지** 원래대로.

가는 길에 잡은 것 둘:
  · `patch_text` 가 최상위 새 키를 못 만들었다(루트 스팬이 `".{}"` 로 기록됐다)
  · `palette` 절이 없던 책에서 되돌리면 `"palette": {}` 가 남았다

### ③ 조판 엔진이 어디까지 되는지 **실측**했다

일곱 가지를 하나씩 구워 봤다 — 전부 된다.

    표(면 넘어가면 머리 반복) · 자동 번호 · 글머리표 · 단락 경계선 ·
    드롭캡 · 세로쓰기 · 각주 · 여러 단

그중 여섯을 「단락 옵션」 패널로 붙였다(가상 요소 `::before`·`::first-letter`
까지 묶음으로 건다). 실제 책에 걸어 PDF 에 경계선과 드롭캡이 찍히는 것을 봤다.

### ④ 서체는 **책이 임베드한 것만**

브라우저에도 설치 서체를 훑는 길(`queryLocalFonts`)이 있지만 쓰지 않는다 —
크로미움 데스크톱 전용인 데다, **설치돼 있다고 PDF 에 들어가는 것이 아니다.**
화면에서는 되는데 인쇄물이 딴 글씨가 되는 것이 제일 나쁘다. 서버가 이 책이
싣는 서체와, 이 기계에 있어 더 실을 수 있는 서체를 갈라 준다.

### ⑤ 레이어 — 뜻을 옮겼다

인디자인 레이어는 겹쳐 놓은 판이라 z-순서까지 있다. 우리 조판은 글이 흐르는
구조라 겹치는 판이 없다. 대신 레이어가 **실제로 쓰이는 방식**(갈래를 끄고
켜며 보기)을 옮겼다 — 해설만 끄고 문제만 보는 식.
⚠ **보기일 뿐 조판을 바꾸지 않는다.**

### ⑥ 그밖에

- 페이지 패널에 **실제 지면 썸네일**(마지막 PDF 에서 뽑는다 — 면당 수 ms)
- 판면·재단선·기준선 보기(덧그리기만)
- 정규식 찾기·바꾸기(GREP). 틀린 식은 무엇이 틀렸는지 말한다
- 단축키: ⌘Z/⇧⌘Z(어디서든) ⌘F ⌘S ⌘B/U/I ⌘+/-/0/1 ⌘; ←/→ V/T/P
- 배율을 %로 보여 주고 ⌥휠로 확대·축소

### 아직 인디자인이 아닌 것 — 아래 「지금 어디까지 왔나」로 갱신됨

(이 절의 옛 표는 그 뒤 대부분 만들어져서 아래로 옮겼다.)

### ⑦ 표 넣기 — 만들었다

앞 절에서 "못 하는 것" 으로 적었던 표를 넣었다. 웹의 한계가 아니라 **우리
구조**의 일이었으므로.

`core/render_vivlio/table.py` 한 곳에 자료 모양과 HTML 을 둔다 — 계열은
`elif t == 'table':` 한 줄이면 된다.

    {"t":"table", "head":[…], "rows":[[…]], "align":[…], "widths":[…]}

  · 칸 하나하나가 **rich** 라 굵게·글자 서식이 그대로 들어간다
  · **칸마다 자리표**가 있어 그 칸만 고칠 수 있다(`…blocks.3.rows.1.0`)
  · 표가 길어 면을 넘으면 **머리줄이 다음 면에도** 나온다(실측 확인)
  · 넣기·줄/칸 늘리고 줄이기·지우기가 전부 **편집 이력**에 쌓인다(⌘Z)
  · 검수 전수 대조에 들어가도록 `plain()` 도 둔다 — 표도 글이다

⚠ 표 CSS 를 넣을지 판정할 때 `data.json` 만 보면 안 된다. 작업대에서 넣은 표는
  `edits.json` 에 있어서, 그러면 표가 **괘선 없이 글자만** 늘어선 채로 나간다
  (실제로 그렇게 나왔다).

실측: 3칸 3줄 표를 넣고 칸을 채워 구웠더니 8면에 머리줄·괘선까지 제대로 찍혔다.

### ⑧ 내보내기

인디자인의 「내보내기」 자리. 도구줄의 **PDF**(조판본)와 **인쇄용**(CMYK)이
그것이다. 지금까지는 통합웹 조판 카드에서만 됐는데, 작업대에서 고치고 곧바로
뽑아 볼 수 있어야 한다.

### ⑨ 서체 기능(OpenType) · 면 이동

조판 엔진이 어디까지 하는지 또 실측했다 — **커닝 · 합자 · 옛숫자 · 표숫자 ·
작은대문자 · 하이픈 · 트래킹 · 위아래첨자 전부 된다.** 문자 패널 아랫단에
붙였고(인디자인 문자 패널과 같은 자리), 단락 패널에는 하이픈·줄바꿈 다듬기·
외톨이 줄(widows/orphans)을 넣었다.

**면 이동** — 세 가지를 잡았다.

  ⚠ `navigateToPage('epage', N)` 은 **다 그리기 전에는 어림값**이다
    (실측: epage 24 → 10면, epage 9 → 5면). 빗나가면 옛 길(한 면씩)로 마저 간다.
  ⚠ `renderAllPages` 는 **문서를 실을 때** 주는 값이다. 만들 때만 주거나
    `setOptions` 로 바꾸면 안 먹어, 그대로 두 면만 그렸다.
  ⚠ `renderAllPages` 를 켜면 `loaded` 가 한참 뒤에 오거나 안 온다. 그동안
    면을 못 넘겨 "아직 조판 중" 만 떴다 → `readystatechange` 의 `interactive`
    에서도 쓸 수 있게 했다.

도구줄의 **모두 그리기**가 그 손잡이다. 여는 데 오래 걸리는 대신 그다음
이동·찾기가 즉시다.

  ⚠ 브라우저는 **창이 뒤에 있으면 그리기를 크게 늦춘다.** 여기 잰 수치
    (면당 ~3초)는 숨은 창에서 잰 것이라 실제로는 훨씬 빠르다 — 같은 책을
    CLI(헤드리스)는 5.5초에 116면을 굽는다. 창을 앞에 두고 쓸 것.

⚠ **페이지 패널은 보고 있는 것과 맞춰야 한다.** 썸네일은 전권 PDF 에서 뽑는데
  견본(40면)을 보면서 25번 썸네일을 누르면 13면으로 갔다. 견본일 때는 번호만
  보여 주고 그 사실을 적는다.

### ⑩ 자유 배치 · 문서 설정 · 눈금자

**"흐르는 조판이라 좌표 배치는 못 한다" 는 내 판단이 틀렸다.** 실측해 보니
흐름 한가운데 둔 `position:absolute` 상자가 **그 면을 기준으로** 앉는다
(둘째 면 top 20mm·right 6mm). 그래서 만들었다 — `core/render_vivlio/box.py`.

  · 좌표 상자(본문 위에 얹힌다) / 감싸기 상자(본문이 피해 흐른다)
  · 좌표 값은 길이만 통과(`url(evil)` 같은 것은 버린다)
  · 상자 안 단락에도 자리표, 넣기·옮기기·지우기가 편집 이력에
  · 실측: 실제 책 8면에 top 30mm·right 12mm 로 정확히 앉았다

⚠ **어느 면에 앉는지는 넣은 자리가 정한다.** 앞 문단이 밀리면 상자도 따라간다.
  인디자인처럼 "3면 여기" 로 못 박으려면 그 면에 앉는 자리에 넣어야 한다.

**문서 설정** — 판형·도련은 어느 책에나 있으므로 계열이 아니라 `Series.base_knobs()`
가 준다. 그래야 어느 교재를 열어도 「문서 설정」이 같다.
⚠ 판형을 바꾸면 책이 통째로 다시 흐른다 — 만지려 하면 화면이 말해 준다.

**눈금자·안내선** — 지면 위에 덧그린다(인쇄에 안 나간다). 안내선은 끌어 놓는
대신 **mm 로 적는다** — 지면 좌표계가 면마다라 끌어 놓으면 배율에 따라 흔들린다.

### ⚠ 다른 세션과 한 워킹트리를 쓴다

`git add -A` 로 커밋했다가 다른 세션의 진행 중 파일(`series/final`,
`engines/mockexam_v2/parser.py` 등)까지 쓸어 담았다. 내용은 안 바뀌었지만
**앞으로는 파일을 지정해서 add 할 것.** 시험 실패 수가 갑자기 늘면 먼저
`git status` 로 남의 작업이 섞였는지 볼 것 — `final` 계열 2건, `mockexam_v2`
4건이 그랬다.

### ⑪ 마스터 페이지 · 색상 견본

**마스터 페이지** — 단락 스타일로는 **면**을 못 건드린다(여백·머리·꼬리).
CSS 조판에서 `@page` 가 그 자리다. `config.page_rules` 에 담고 `knobs.css` 로
내보낸다 — 계열 테마 **뒤**라 한 줄만 적어도 그 값만 바뀐다.

    "page_rules": { ":left": {"margin-left":"23mm"}, ":right": {…} }

실측: `:left` 왼쪽 여백을 23 → 33mm 로 바꾸니 짝수 면 본문이 33.0mm 에서
시작하고 면수가 116 → 122 로 늘었다. 같은 이력에 쌓여 ⌘Z 로 되돌아간다.

**색상 견본** — 값 칸만 있으면 "이 색이 어디 쓰이나" 는 알아도 **칠할 수가
없다.** 색을 누르면 고른 자리(⇧누르면 바탕색)에, 글자를 골라 두었으면 그
글자에 칠한다. CMYK 도 함께 보인다.

⚠ 색 팔레트를 두 곳에서 그리면 나중 것이 견본을 지운다 — `drawPalettes()` 는
  색을 `drawSwatches()` 에 넘기고 치수만 그린다.

### ⑫ 끌어서 옮기기 · 표·상자를 전 계열로

**"끌어 놓으면 배율에 따라 흔들린다" 는 것도 틀렸다.** 재 보니 면 상자에서
mm 로 정확히 되돌릴 수 있다(지문 상자 왼 23mm·폭 167mm — 실제 값과 같다).
그래서 상자를 **끌어서** 옮긴다.

⚠ 어느 변에 붙여 두었는지를 지킨다. 오른쪽·아래에 붙인 상자를 끌었다고
  왼쪽·위 기준으로 바꾸면 판형이 바뀔 때 딴 데로 간다.
⚠ 판형은 책마다 다르다 — `216mm` 로 못 박으면 딴 책에서 어긋난다.
  손잡이에서 받은 `page.width + 2×bleed` 를 쓴다.

**넣을 자리** — 예전에는 `blocks` 목록만 찾아서 어휘부·단어장에서는 "넣을
자리가 아니다" 만 떴다. 이제 **어느 목록이든** 받되, **든 것으로** 가른다.

    글·서식 조각·`t` 가진 블록·낱말  → 넣을 수 있다
    문항(`stem`·`blocks`)·단원(`vocab`·`problems`) → 못 넣는다

⚠ 이름으로 가르면 안 된다. `…problems.0.stem` 을 고르면 위로 올라가다
  `problems` 를 만나는데, 거기 끼우면 **문항 자리에 상자가 들어가** 조판이 깨진다.

네 계열(블랙북·상일보카·광문보카·특강) 모두 표·상자를 받는다. 실측으로
블랙북 어휘부·문항부, 광문보카 낱말 목록에 넣어 PDF 까지 확인했다.


### ⑬ 화면을 직접 몰아 보고 나온 것들

코드로는 다 되는데 **사람이 쓰면 안 되는** 자리가 여럿 있었다. 인증만 뗀
사본 서버(5099)를 띄워 브라우저로 직접 눌러 보며 잡았다.

| 무엇이 | 어땠나 | 어떻게 고쳤나 |
|---|---|---|
| ⌘Z | 스타일을 바꿔도 **회색** | 고친 것을 알리는 응답이 이력을 안 실었다 → `_hist(st)` 한 곳 · 화면은 `api()` 한 곳에서 받는다 |
| 다시 조판 | 몇 초 동안 **빈 회색 판** | 직전 면을 복제해 덮고, 새 면이 서면 걷는다 |
| 안내선 | `prompt()` 로 **적어 넣기** | 눈금자에서 **끌어다 놓는다**(두 번 누르면 지움) |
| 눈금자+안내선 | 같이 켜면 눈금자가 사라짐 | 같은 `::before` 를 다퉜다 → 안내선은 진짜 요소로 |
| 상자 끌기 | 잡으면 **여백만큼 튐** | 기준점을 짐작하지 말고 **적힌 값 + 움직인 만큼** |
| 상자 크기 | 적어 넣어야 했다 | 모서리 손잡이 8개 — 붙여 둔 변을 지킨다 |
| 상자 고르기 | 바깥 덩어리가 잡힘 | 상자는 글이 아니라 **물건** — 한 번 누르면 상자 |

**⚠ `offsetParent` 를 믿지 말 것.** 상자를 담고 있는 것이 면인지 본문 상자인지
조판이 정하는데, `offsetParent` 는 면이라고 답하면서 실제 기준은 본문 상자였다
(`left:20mm` 짜리를 잡으면 42.99mm 로 튀었다). **기준을 찾지 말고** 지금 적힌
mm 에 움직인 mm 을 더하면 기준이 무엇이든 맞는다. 1mm 가 몇 px 인지는 면 안에
100mm 짜리를 잠깐 넣어 **잰다**(화면 맞춤 배율 때문에 96dpi 계산은 어긋난다).

### ⑭ 중등부도 같은 도구로 고쳐진다

이 계열만 자료도 조판도 3계층 밖(automation)에 살아서, 작업대가 책 폴더에 쌓아
둔 것을 **아무도 읽지 않았다.** 클릭은 되는데(자리표는 있었다) 고치면 "저장됨"

### ⑮ 면 번호는 조판 엔진 말고 **끝에 닿아서** 안다

작업대를 브라우저에서 몰아 보며 "면 넘기기가 몇 분 걸린다" 고 판단했는데,
**둘 다 틀린 관찰이었다.**

1. 재는 자리가 틀렸다 — 브라우저 **패널이 숨겨져 있으면**(`document.hidden`)
   브라우저가 그 화면을 스로틀링한다. 한 면 넘기는 데 12초가 걸리고 60초씩
   본줄이 멈춘 것처럼 보였다. **보이는 창**(puppeteer)에서 재니
   전권 30면 2.0초 · 60면 2.0초였다.
   → 앞으로 작업대 성능은 `scratchpad/hop4.mjs` 같은 실제 창에서 잰다.
2. "끝까지 못 간다" 도 틀렸다 — 견본은 **원래 15면**인데 엔진이 40면이라고
   했다(`epageCount` 는 다 그리기 전 어림값이다. 116면짜리 전권은 508 이라
   했다). 15면에서 안 움직인 게 맞다.

그래서 면수는 이렇게 안다.

    전권   마지막 조판본(PDF)의 면수 — 그게 실제로 인쇄될 면수다
    견본   끝에 닿으면 그 자리를 참으로 삼는다("이 판은 15면까지입니다")

⚠ 넘기라는 말이 **무시되는 동안**(엔진이 그 면을 그리는 중) 세어 둔 횟수로
  뛰면 모자라게 간다(8면 → 4면). 반대로 반영을 안 기다리고 연달아 넘기면
  지나친다(8면 → 9면). **반영을 기다렸다가 다시 본다.**
⚠ 다만 무거운 면은 몇 초씩 걸린다 — `readyState === 'loading'` 이면 계속
  기다린다(3초로 자르면 15면에서 "여기까지" 하고 멈춘다).
⚠ 면이 바뀔 때마다 페이지 패널 116칸을 다시 만들면 안 된다(표시만 옮긴다).
  같은 이유로 갈래 패널·알림도 면마다 새로 쓰지 않는다.

먼 면으로 뛸 때는 **마지막 조판본의 그 면 그림**을 지면 자리에 깔아 둔다
(`/book-studio/thumb/<bid>/<n>.png?dpi=140`). 조판은 앞에서부터 흐르니
그 면에 닿는 데 시간이 걸리는데, 그동안 빈 판을 보여 주지 않는다.
⚠ **견본을 보는 중이면 깔면 안 된다** — 면 번호가 PDF 와 달라 엉뚱한 면이 된다.


### ⑯ 개체답게 다루기 — 표 모양 · 상자 모양 · 밀기 · 특수문자

| 인디자인의 | 작업대의 |
|---|---|
| 표 스타일 | 괘선·칸 여백·줄 높이·머리줄 바탕/글자색·세로 맞춤·글자 크기 |
| 셀 병합 | 처음 칸 → 마지막 칸을 눌러 합치기(먹힌 자리는 `null` 로 남긴다) |
| 개체 속성 | 바탕·테두리·둥근 모서리·그림자·투명도·**회전**·안 여백·글 맞춤 |
| 프레임 손잡이 | 모서리 8개(붙여 둔 변을 지킨다) |

  (`table.STYLE` · `box.STYLE_KEYS`). `position: fixed` 같은 것이 들어오면
  조판이 통째로 흔들린다.
⚠ **모양을 안 정한 표는 한 글자도 달라지면 안 된다.** 그래서 표 모양은 CSS
  변수로 받고, 정한 것이 없으면 `style` 속성 자체를 안 단다(회귀 대조).
⚠ **누를 때마다 저장하면 못 쓴다.** 화살표로 밀 때는 지면에서 먼저 움직이고
  손을 뗀 뒤(0.6초) 한 번만 저장한다.
⚠ 라우트에서 블록을 고칠 때는 **사본**에 고친다(`json.loads(json.dumps(block))`).
  원본을 고치면 되돌리기가 값을 잃는다.

### ⑱ 커닝 쌍은 웹의 한계가 아니었다 — 그리고 그걸 찾다 조판이 죽었다

"커닝 쌍은 못 한다(CSS 에는 자간과 `font-kerning` 켜기/끄기뿐)" 고 적어 두었는데
틀렸다. **두 글자만 골라 자간을 주면 그게 커닝 쌍이다** — 글자 단위 서식이
`letter-spacing` 을 싣고 조판본에 그대로 나간다.

그걸 확인하다 **훨씬 큰 것**이 나왔다. 라벨 칩 두 글자에 자간을 줬더니

    AttributeError: 'list' object has no attribute 'replace'   ← 책 전체가 안 나온다

계열 렌더러들이 `html.escape(값)` 을 쓰는 자리가 있는데, 작업대에서 그 자리
글자에 서식을 걸면 값이 **서식 조각 목록**이 된다. 그러면 조판이 통째로 죽는다.
겉으로는 "저장했는데 갑자기 조판이 안 된다" 로 보인다.

여섯 계열의 이스케이프를 **너그럽게** 고쳤다(평문은 한 글자도 안 바뀐다).

    blackbook.esc1 · whitebook.esc1 · pocketbook.ESC · vocabook.esc
    vocaunit.esc · special.esc

⚠ 화이트북은 서식 조각의 `st`(크기·색·자간)를 **버리고 있었다** — 죽지는 않지만
  저장은 되는데 지면은 그대로다(조용해서 더 나쁘다). `seg_attr` 를 붙였다.

회귀: 블랙북·광문보카·특강·상일보카 683면 + 포켓북 204면 **전부 불변** ✓


### ⑲ 최악을 미리 해 본다 — `richfuzz.py`

⑱ 의 사고("라벨 칩에 자간을 줬더니 책 전체가 안 나왔다")가 **한 자리만의 일이
아닐 것** 같아, 작업대가 고를 수 있는 자리 **전부**에 서식을 걸어 놓고 한 번
조판해 보는 것을 만들었다.

    python3 scripts/studio_check/richfuzz.py            # 전 계열

### ㉒ 진짜 단락 스타일 — 이름을 고치면 걸린 곳이 전부 바뀐다

여태 스타일 패널이 하던 일은 두 가지였다.

    "이 자리에만"   `[data-ref="…"]` 선택자 — 그 한 곳만
    계열 클래스      `.pbox`·`.q` — 그 계열이 쓰는 곳 전부

없던 것이 **인디자인의 단락 스타일**이다. 이름을 만들어 문단에 걸고, 이름
하나를 고치면 걸린 문단이 전부 바뀌는 것.

막던 것: 조판 결과의 `class` 는 **계열 렌더러가 정한다.** 사람이 클래스를
더 달 자리가 없었다.

    편집 이력에 `cls` 연산 → `refs.set_classes()` → `refs.mark()` 가 얹는다

`edits.load_data()` 한 곳에서 넘기므로 **계열 코드를 하나도 안 고치고** 아홉
계열 모두에서 된다.

⚠ 스타일 이름은 `ps-` 로 시작한다 — 계열 클래스와 섞이면 어느 쪽이 사람
  것인지 알 수 없다(라우트가 막는다).
⚠ `refs.clear()` 가 스타일까지 지우면 안 된다. 자리표 표는 렌더할 때마다 새로
  만드는데 스타일은 원고를 읽을 때 정해진다 — 같이 지우면 **적용했는데 지면은
  그대로**가 된다.
⚠ `cls` 는 글이 아니다 → `apply_all` 이 건드리면 안 된다.

실측: `.ps-강조` 를 두 문단에 걸고 색을 한 번 고쳤더니 **둘 다** 빨강→초록.


### ㉓ 표를 인디자인처럼 — 자리 지정 · 칸 모양

| 인디자인의 | 작업대의 |
|---|---|
| 위/아래에 줄 넣기 · 이 줄 지우기 | 고른 칸을 기준으로(없으면 맨 뒤) |
| 왼쪽/오른쪽에 칸 넣기 · 이 칸 지우기 | 〃 |
| 셀 스타일 | 칸 하나의 바탕·글자색·가로/세로 맞춤·굵기·괘선 |

⚠ **합친 칸을 가로지르는 줄·칸 조작은 거절한다.** 넣거나 빼면 칸 수가 어긋나
  표가 통째로 밀린다(되돌리기도 어렵다).
⚠ 칸 모양은 **합친 칸과 같은 그릇**(`{"v":…, "c":2, "st":{…}}`)에 담는다 —
  모양을 줘도 글과 합침을 안 잃는다. 모양도 합침도 없어지면 **민 글로** 돌아간다
  (찌꺼기를 남기면 회귀 대조가 시끄러워진다).
⚠ 칸 모양은 **열 정렬보다 뒤**에 붙는다(칸에 준 것이 이긴다).
⚠ 받을 항목을 못 박았다(`CELL_STYLE`) — `position` 같은 것이 들어오면 표가
  통째로 흔들린다.

### ㉕ 단락 스타일 살림 — 몇 곳에 걸렸나 · 이름 바꾸기 · 지우기

만들기만 되고 치우지 못하면 이름이 쌓여 어느 것이 쓰이는지 알 수 없다.
인디자인의 단락 스타일 패널이 하는 일을 그대로 둔다.

⚠ **이름을 바꾸면 걸린 자리도 같이** 바꾼다. 스타일만 바꾸면 걸린 곳은 없는
  이름을 가리켜 **조용히 모양을 잃는다.**
⚠ 지울 때는 **떼고 지운다.** 규칙부터 지우면 잠깐 "없는 이름이 걸린" 상태가 생긴다.

실측: `ps-머리` 를 두 곳에 걸고 → `ps-큰머리` 로 이름 바꾸기(두 곳 따라옴,
색 유지) → 지우기(둘 다 떨어짐) → 되돌리기로 복구.


### ㉖ 상자 여러 개 — ⇧누르고 더 고르기 · 서로 맞추기 · 고르게 벌리기

인디자인처럼 ⇧를 누르고 더 고른다. 고른 것끼리 왼/가운데/오른·위/중간/아래로
맞추고, **가로로 · 세로로 고르게** 벌린다(양 끝은 그대로 두고 사이를 나눈다).

⚠ 그냥 누른 것도 **묶음의 시작**이다. 안 담아 두면 ⇧로 하나를 더 골라도
  "1개" 가 되어 정렬 단추가 안 나온다(실제로 그랬다).
⚠ 상자마다 저장을 부르면 다시 조판이 그만큼 돈다 → **마지막 하나가 끝나면
  한 번만** 굽는다.
⚠ **`key` 라는 이름을 함수 안에서 쓰면 안 된다.** 고르게 벌리기에서 축 이름을
  `key` 에 담았더니 그 함수 안에서 **책 이름을 가려**, 저장이 통째로
  "모르는 책"(404)이 됐다. 화면에는 "맞췄습니다" 만 뜨고 아무 일도 안 일어났다
  — 서버 로그를 안 봤으면 못 잡았다.
