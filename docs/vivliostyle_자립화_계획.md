# Vivliostyle 조판 자립화 — 계획과 진행

**목표: 클로드 세션 없이도 비블리오 조판을 굴린다.**
지금은 사소한 수정 하나에도 대화를 열어야 하고, 컨텍스트가 차면 새 세션에서
메모리를 받아 이어가야 한다. 그 의존을 끊는 것이 이 작업이다.

작업 브랜치 `vivlio-studio` (2026-08-29 시작). 단계마다 태그를 단다.

## 진단 — 문제는 셋이다

**① 터미널 문제 (인터넷 문제가 아니다)**
`bin/viv` 는 지금도 100% 로컬·오프라인으로 돈다. `@vivliostyle/cli` 11.1.0 과
뷰어가 `core/render_vivlio/node_modules` 에 이미 있고 서체·원고·assets 전부
로컬이다. 막는 건 인터넷이 아니라 **터미널과 "어디를 고쳐야 하는지 모름"** 이다.

**② 손잡이가 선언되어 있지 않다**
계열마다 그때그때 필요한 것만 즉흥적으로 뚫려 있다.

| 계열 | 색 손잡이 | 치수 손잡이 | 테마 생성 |
|---|---|---|---|
| `vocaunit` (광문보카) | 20여 개 + 파트별 | 계열 기본값 오버라이드 | `theme.py` 완전 파라미터화 |
| `vocabook` (상일보카) | common + sections | 5개 | 일부 |
| `special` (특강) | 파트별 7색 | **0개** | 없음 (CSS 고정) |
| `blackbook` | **0개** (CSS에 박힘) | 레이아웃 8개 | 없음 |

가장 최근에 만든 `special` 이 `vocaunit` 보다 후퇴했다 — 급히 만들었기 때문.
선언이 없으니 ⑴사용자는 뭘 만질 수 있는지 모르고 ⑵편집기를 만들 수 없고
⑶클로드조차 매번 코드를 읽어 확인해야 한다(컨텍스트 소모).

**③ 디자인 수정이 여러 번인 이유는 두 종류인데 해법이 다르다**
- **취향 조정**("칙칙하다", "톤을 올려라", 헤더 시안 A/B/C) → 손잡이로 해결된다.
- **컨셉 오류**("빈약하다", "미러링 하지 마라", "글리프 쓰지 마라", "손가락 같다")
  → 손잡이로 해결 안 된다. **규칙을 게이트로 굳혀야** 1차 시안 품질이 올라간다.
  광교관 10차 시안의 대부분이 이 부류였다.

## S0 — 안전망 (진행 중)

**autosync 브랜치 가드** (`scripts/autosync.sh`, main 에 커밋 `697cad7`)
180초마다 도는 autosync 가 **브랜치를 보지 않고** 언제나 `origin main` 으로
pull/push 했다. 작업 브랜치를 체크아웃한 채 두면 그 커밋이 main 으로 밀려나가
브랜치를 판 의미가 사라진다. 커밋은 어느 브랜치에서든 그대로 하고 동기화
대상만 현재 브랜치로 맞췄다. 원격에 없는 새 브랜치는 `-u` 로 만든다.
→ 이건 나 때문에 생긴 게 아니라 **원래 있던 잠복 결함**이다(누가 브랜치를 파도
   조용히 main 으로 샜다).

**전체 백업** — `조판/_backup_vivlio_20260829/`
10권 교재 폴더 통째 사본(config·원고·산출 PDF·build). 교재 폴더는 git 이 아니라
파일 사본이 유일한 되돌리기 수단이다.

**회귀 기준선** — `scripts/vivlio_baseline.py` → `tests/baseline/vivlio/<키>.json`
면별 **픽셀 해시 + 텍스트 해시 + 판형**. 손잡이를 뚫으며 CSS 를 파라미터화할 때
기본값이 현재값과 정확히 같은지는 눈으로 확인할 수 없어서 기계가 잰다.

```bash
python3 scripts/vivlio_baseline.py list
python3 scripts/vivlio_baseline.py capture --books special
python3 scripts/vivlio_baseline.py compare          # 0 = 불변
```

⚠ 픽셀 해시는 MuPDF 판본에 딸린다. 판본이 바뀌면 `tx`(글자)만 신뢰하고 다시 뜬다.

**재현성 확인(필수)** — 기준선은 "지금 파일"에서 떴다. 그런데 지금 코드가 그
파일을 **재현하는지**는 별개다. 재빌드가 납품본과 다르면 기준선의 뜻이 바뀌므로
(=이미 코드와 산출물이 어긋나 있다는 뜻) 각 교재를 한 번씩 재빌드해 대조한다.
⚠ 재빌드는 산출 PDF 를 덮어쓴다 — **교재 폴더 사본을 만들어 거기서 빌드**한다.

### ⚠⚠ 동시 세션 — 이 작업의 가장 큰 함정 (2026-08-29 01:46 실증)

**리포의 워킹트리는 하나인데 클로드 세션은 여럿이 붙는다.**
`git checkout -b` 로 브랜치를 파면 **다른 세션까지 그 브랜치로 끌려간다.**
여기서 실제로 벌어진 일:

1. `vivlio-studio` 를 파자 다른 세션(특강 `G-밑줄` 게이트 작업 중)이 모르는 사이
   그 브랜치 위에서 일하게 됐다.
2. autosync 가 180초마다 `git add -A` 를 하므로 **그 세션의 미완성 편집이
   내 브랜치로 커밋됐다**(`766b0ae`, `d9866a6` — `special.css`·`special/__init__.py`).
3. 그 세션이 특강을 재빌드해 `광교관_예비고1특강_내지.pdf` 47면의 픽셀이 바뀌고
   `_인쇄.pdf` 가 새로 생겼다 — **기준선을 뜬 지 1분 만에 무효가 됐다.**
4. 같은 이유로 중등부 `_backup` ditto 가 `Operation timed out` 으로 실패했다
   (복사 중에 상대가 그 파일을 쓰고 있었다).

**대응 — 워크트리로 격리한다.**
```
~/dev/yone-design-web    main            ← 다른 세션·autosync 의 자리. 건드리지 않는다
~/dev/yone-web-vivlio    vivlio-studio   ← 이 작업 전용
```
- `node_modules` 는 gitignore 라 워크트리에 안 따라온다 → 원본을 심볼릭 링크로
  빌려 오고 워크트리의 `.git/info/exclude` 에 넣는다.
- autosync 는 `cd $REPO` 가 박혀 있어 **워크트리는 자동 커밋되지 않는다** —
  여기서는 손으로 커밋한다(그게 더 안전하다).
- 복구 절차: 상대 작업물을 `git show <커밋>:<경로>` 로 뽑아 main 워킹트리에
  되돌려 놓고, 내 브랜치는 오염 전 커밋으로 `git branch -f` 한 뒤 내 파일만 다시 얹는다.

**⚠ 교재 폴더는 워크트리로 못 가른다.** 특강·중등부는 상대가 만지는 중이므로
이번 밤 작업에서 **뺀다**(기준선도 특강만 무효). 손대는 순간 서로의 결과가 섞인다.

## S1 — 라이브 미리보기 (`watch`) ✅

```bash
bin/viv "<책폴더>" watch          # 주소를 찍어 준다. 브라우저로 열어 두고 작업
```

**재렌더 0.4초.** 전권 조판(20~50초) + PDF 뷰어 다시 열기 왕복이 사라진다.
완전히 오프라인(`@vivliostyle/cli` 와 뷰어가 이미 `node_modules` 에 있다).

설계·함정은 `docs/vivliostyle_엔진.md` 의 "라이브 미리보기" 절에. 요약:
- 렌더는 **자식 프로세스**(`bin/viv <책> render`) — 계열 `.py` 를 고쳐도 새 코드로 돈다.
- 주소를 조립하지 말고 CLI 가 찍는 `Preview URL:` 줄을 읽는다. stdout 을 안 비우면
  파이프가 차서 **서버가 멎는다**(데몬 스레드로 계속 비운다).
- **"조판 건너뛰기"는 최종 조판에만 건다.** 블랙북은 본 조판 앞에 높이 측정 PDF 를
  두 번 굽는데 거기서 멈추면 **측정용 HTML 을 미리보기로 삼는 사고**가 난다
  → `cli.run_build(..., final=False)` + 블랙북 `render_opts={"nomeasure": True}`.

### 첫 판에서 걸러낸 오탐 다섯 — 게이트를 만들 때 반드시 겪는 부류

1. **엔진 표식**(`§A1§`·`DAYOPEN`)이 0.1pt 글자로 잡혔다 → 이름 목록으로는 못 막는다
   (표식 이름이 계열마다 다르다). **크기로 가른다** — 1pt 미만은 읽을 글자가 아니다.
2. **머리말·꼬리말 6pt** 가 "본문 7pt 미만"으로 잡혔다 → 러닝 요소는 원래 작다.
   `verify.frame` 이 있으면 그걸로 본문을 가르고, 없으면 위아래 8% 를 러닝 띠로 본다.
3. **본문 최소 크기 7pt 를 기본값으로 두면 안 된다** — A4 중등부 규칙이지 A5 단어장은
   본문이 원래 6pt 다. 상일보카 한 권에서 **34,241건**이 나왔다. → 기본은 **끔**,
   분포만 적어 두고 책이 자기 바닥값을 정한다.
4. **대비를 WCAG 4.5 하나로 재면** 하우스 색이 흰 바탕에 얹힌 것까지 다 걸려
   광문보카에서 20줄이 나오고, 정작 **흰 글자가 파스텔 위에 얹힌 1.8:1** 이 묻힌다.
   → 3.0 미만만 경고, 3.0~4.5 는 **참고 한 줄**로 요약. 색 조합으로 묶어 세고
   (헤더는 매 면 반복되므로 안 묶으면 결함 2개가 "272곳"이 된다) 심한 순 8가지만 편다.
5. **평평한 색 띠는 장식이 아니다** — 광문보카는 위아래에 단색 분홍 띠를 두는데
   단색이니 좌우가 같은 게 당연하다. 채도로 "장식 있음"을 재면 64개 펼침면이 전부
   미러링으로 걸린다 → **경계선 밀도**(`_edge_density`)로 모양이 있을 때만 따진다.
