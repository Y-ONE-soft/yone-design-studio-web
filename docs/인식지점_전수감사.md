# 인식 지점 전수 감사 (W32, 2026-07-20)

W31이 워크북 v2 계열의 **지문 헤더 인식**을 구조 우선(`core/structure/header_detect.py`)으로
교체한 데 이어, "다른 교재도 이런 문제가 있는지 전면 확인 — 구조로 인식하지 않는 것들을
구조 우선 인식으로" 지시에 따라 **전 엔진의 인식 지점을 전수 감사**했다. 이 문서가
후속 전환 배치의 로드맵이다. (본 감사는 읽기 전용 — 코드 무변경, pytest 647/647 통과로 확인.)

"인식 지점" = 입력(파일명·폴더명·원고 텍스트·문서 구조)을 보고 무언가를 판정하는 코드.
방식 분류:

| 방식 | 정의 | 특성 |
|---|---|---|
| **구조** | 형식 열거 없이 구조 신호(길이·토큰 밀도·문맥·문서 내 자기 유사·유사도)로 판정 | 토씨 변화에 강함. W31 header_detect, passage_match가 대표 |
| **데이터룰** | 판정 로직은 고정, 지식은 데이터 테이블(taxonomy·style_map·step_map)에 — 새 표기 = 테이블 추가 | 열거이긴 하나 수리 지점이 한 곳, 게이트와 눈 공유 가능 |
| **리터럴** | 코드에 박힌 토큰/정규식 열거 단독 | 토씨 하나에 깨짐. 실패가 대부분 침묵(누락/오라우팅) |

리스크 = 실사용 빈도 × 침묵 여부 × 취약도. **침묵**(실패 시 조용히 누락·오라우팅되고 로그/게이트가
못 봄)이 가장 위험 — W12 지문 유실, W18 D4 빈 사이클 250p "성공", W31 동기 사건(376b34d0
통짜+경고 0)이 전부 침묵 부류였다.

## 1. 공통 인식 백엔드 (도달 목표 상태 — 이미 구조/데이터룰)

| 위치 | 무엇 | 방식 | 비고 |
|---|---|---|---|
| `core/structure/header_detect.py` | 지문 헤더 (문서 단위 2패스: 구조 앵커 + 자기 유사 전파 + 순번 단조성) | **구조** | 침묵 금지(`HeaderSilenceError`). legacy 정규식은 프라이어로 강등(하위호환 하한). 인식률 89.71%→96.39% (전수 인벤토리 20,982문서/190,970헤더) |
| `core/structure/rules.py` + `paragraph_kind.py` | 단락 종류(GH/A/Box/Cond/Q/C/P/K/Word/Ans/SRC…) | **데이터룰** (taxonomy 09 구현) | "단어 리터럴은 시그니처의 한 층일 뿐 단독 판정 근거가 아니다" 원칙 명문화 |
| `core/structure/style_map.json` + `style_resolver` | kind→인쇄 스타일 | **데이터룰** | 실물 인벤토리 가드 테스트 |
| `engines/_taxonomy/` (classify) | 발문 텍스트→(code,label,q_kind) | **데이터룰** | paragraph_kind가 1선으로 사용, mockexam_v2 직접 사용 — "미연결" 상태 해소됨 |
| `core/passage_match/` (matcher+segment) | 지문 동일성 (shingle w=3 + IDF 토큰 + 앵커, 허브 배제) | **구조(유사도)** | passage_remove가 사용. 임계 미달 시 조용한 미매칭 |
| `engines/workbook/parser._find_manuscript_file` | 스텝 파일명 유사 매칭 (정규화+subsequence+LCS≥0.70+답안 토큰 가드) | **구조(유사도)+리터럴 가드** | 탐색기 중 유일하게 유사도 기반 — 다른 탐색기의 전환 모델 |

## 9. 전환 배치 계획 (배치당 1~3지점)

원칙 (W31 방법론 계승): ① 구조/데이터룰 1선 + 기존 리터럴은 프라이어(하위호환 하한 —
기존 인식분 diff 0), ② **침묵 금지** — 후보는 있는데 소비 0이면 [오류]/critical, ③ 골든 코퍼스
diff 0 + 결손 주입 테스트(본 실증 재사용) + 실서비스 job 재플랜 sweep으로 검증.

### 배치 A — 파일 라우팅 침묵 금지 (리스크 1·2) — 최우선
- **전환 방식**: (a) `_parse_step3_folder`에 쌍방 대조 — 기대 문항 집합 vs 매칭 파일 집합, 매칭
  안 된 원고 파일(hwp/hwpx/docx)이 남으면 숫자 토큰 유사 매칭 시도 후 실패 시 **[오류]**
  (textbook 폴백은 명시 로그). (b) `_routes_to_step3`/v1 `_is_step3_name` 4벌/sero 파일명
  정규식을 공용 라우터로 통합 — 토큰 정규화(공백·0패딩·NFC) 후 판정, 미라우팅 원고 파일은
  G9 critical 승격(정답/답지 제외).
- **검증**: 골든 33케이스 parse diff 0 + 실증 #1/#4 입력이 [오류]/critical로 전환되는 테스트 +
  실서비스 144 job 재파스 오차단 0.
- **규모**: 파서 1함수+엔진 라우터 5곳 통합, 테스트 ~10개. 1~2일.

### 배치 B — 정답부 시작 데이터룰 합류 (리스크 3)
