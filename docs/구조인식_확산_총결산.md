# 구조 인식 확산 총결산 (W37, 2026-07-20)

W32 전수 감사(`docs/인식지점_전수감사.md`)가 수립한 전환 배치 A~G의 완주 결산이다.
출발점은 "원고 구조를 읽어야 한다 — 토씨 하나 바뀌면 못 읽는 구조는 한계"(W31)였고,
감사 시점의 실태는 **인식 지점 약 120곳 중 리터럴 84곳, 그 70%가 실패 시 침묵**이었다.

핵심 원칙 (전 배치 공통, W31 방법론):
1. **구조/데이터룰 1선 + 기존 리터럴은 프라이어** — 기존 인식분 diff 0 (하위호환 하한).
2. **침묵 금지** — 인식 실패·강등·건너뜀은 반드시 로그에 흔적([경고] + 무엇을 못 읽었는지
   + 후보/근거). [오류] 승격은 운영 판단 기록이 있는 곳만.
3. **실물 검증** — 골든 코퍼스 diff 0 + 결손 주입 테스트 + 실서비스 job 재현 sweep.

## 3. 전/후 분포 (감사 §5 재집계 — 실제 코드 기준)

감사와 동일한 논리 지점 단위(~120곳). "유연 매칭" = 리터럴 1선 유지 + 정규화/숫자 토큰
구조 2차 + 침묵 금지 리포트 (배치 E·F의 방식 — 순수 리터럴과 구분).

| 방식 | 감사 시점 (W32) | 현재 (W37) | 변화 내역 |
|---|---|---|---|
| **구조** | 14 | **17** | +C 화이트북 섹션(1) +D v1 파서 헤더 계층·sero(2) |
| **데이터룰** | 22 | **30** | +A 라우팅 공용화·routing_rules(5) +B 정답부 rules 공유(2) +G seseo 프로필(1) |
| **유연 매칭** (신설 분류) | 0 | **9** | +E find_* 8종→공용 4행(4) +F merge 매처 5곳(5) |
| **리터럴 단독** | 84+ | **~64** | 상기 전환분 차감 (가시화 22지점은 방식 유지 — 침묵만 제거) |

침묵 재집계: 감사 시점 리터럴의 ~70% ≈ **59지점 침묵** →
- A~F가 전환과 함께 제거한 침묵 ≈ 20 (쌍방 대조 [오류]·G9 critical·[오류] 섹션 결손·warn_zero·후보 동봉)
- G가 가시화로 제거한 침묵 = 22
- **잔여 침묵 ≈ 17지점** (아래 §4 전수 — 전부 사유 있음). 침묵 비율 **70% → 약 20%**,
  그나마 대부분 하류 게이트가 감시하는 반침묵.

## 6. 판단 기록 (배치 G)

- **[오류] 승격 안 한 이유**: 감사 §9 G가 "대수술 전에 침묵부터 제거"로 규정. 특히
  pocketbook 폴더 매칭 0건을 missing_tb_cats에 추가하면 RuntimeError로 승격되는데,
  이는 운영 판단 기록 없는 동작 변경이라 배제 (경고+후보만). 파이널 canon/scope도
  동일 — 파이널은 다중 소스 부분 부재가 정상일 수 있다는 W36 판단 계승.
- **cover를 [알림]으로 한 이유**: '그 외 → 프리미엄북'은 문서화된 의도적 기본값(인식
  실패가 아님) — 다만 목적지가 어디로 갔는지는 남긴다. final_cover는 이미 템플릿
  선택을 로그함(수정 불요).
- **hanyoung 경고를 '역할 자체 미검출'로 한정한 이유**: 종전 호출부 `not
  col_map.get('word')`는 word가 0열에 감지돼도 참(인덱스 0 falsy) — 그 경로에 경고를
  달면 정상 파일마다 울린다. 결함 자체는 배치 중 별도 태스크로 즉시 수리(4곳
  `is None` — 감지 매핑 보존), 경고 가드는 방어적으로 유지.
- **`_strip_manuscript_headers` 경고를 '실제 제거 시'로 한정한 이유**: 코퍼스 실측에서
  세로 C2 'NN번' 원고(정상 형식)가 무마커 no-op 폴백을 타는 것을 확인 — 아무것도 안
  버리는 폴백은 유실 위험이 없으므로 소음 배제.
