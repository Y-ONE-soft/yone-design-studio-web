# 워크북 Vivliostyle 전환 계획 (2026-09-01)

InDesign 템플릿(`[원본]워크북(모의고사)_내지.indd`)에 부기하는 현행 조판을
**HTML/CSS → @vivliostyle/cli → PDF** 로 옮긴다.

대상 순서(사용자 확정): **① 본가 모의고사(`workbook_v2`) → ② 부교재(`workbook_supp_v2`)
→ ③ 교과서(`textbook_workbook_v2`)**. 디자인 기준은 **최신 완성본 실측 이식**,
오늘 밤 완료 기준은 **실전 잡 1건 납품급**.

---

## 1. 왜 옮기는가 — 병목의 실제 위치

사용자가 든 병목 4가지를, 저장소의 수정 이력으로 검증했다(2026-01-01 이후).

| 층 | 커밋 수 |
|---|---|
| 파서 `engines/workbook/parser.py` | 75 |
| InDesign 렌더층 `workbook_flow.body.jsx` + `workbook/jsx` + `plan.py` | **211** |
| 두 층을 함께 고친 커밋 | 16 |
| 범위·선별 후처리 `workbook_select`/`passage_remove`/`slim_merge` | 92 |

워크북 관련 커밋은 397건으로 전체(1,561)의 25%다. 그중 **파서는 1/4이고 인디자인
쪽이 2.8배**다. 체감("파서를 100번 넘게 고쳤다")과 이력이 어긋난다.

렌더층 수정의 성격은 `engines/workbook_v2/step_map.json` 주석이 그대로 말해 준다:

> "[원본]워크북_C p114의 page.textFrames 순서가 [발문, 하단, 상단]이라 프레임수
> 동률에서 rank 선택이 상단/하단을 뒤바꾸는 상하반전"

이건 원고 문제도 디자인 문제도 아니라 **.indd 안을 더듬는 비용**이고, CSS에는 이
층 자체가 없다.

실물 조판 로그(`jobs/f8fb2fd2/조판_로그.txt`)도 같은 이야기를 한다 — 298면 템플릿에
부기한 뒤 **176면을 지운다**. 필요한 면만 만드는 방식이면 존재하지 않는 작업이다.

## 2. 문제별 판정

| 사용자 문제 | 판정 | 근거 |
|---|---|---|
| ① 구버전 .indd 의존 | **해결** | 디자인이 `themes/workbook.css` 1파일 + config 토큰이 된다. 템플릿 사본(모의고사/세종/C/세로/마더텅 5벌)이 config 분기 하나로 접힌다 |
| ② 원고 제각각 → 파서 수정 | **해결 안 됨** | 파서는 그대로 쓴다(공유). 다만 조판 437초→수초로 회귀 그물이 매번 돌아가고, 파서가 지던 레이아웃 판단이 CSS로 빠진다 |
| ③ 학교마다 범위 다름 | **해결** | `select.passages:[2,4,6]` → 그것만 렌더. 삭제·번호정렬·빈면제거 후처리가 사라진다 |
| ④ 학교마다 스텝 다름/슬림 | **해결** | `select.steps:[...]` → 그것만 렌더. 고정 페이지(4/13/22/40/…) 못박기가 사라진다 |

②의 처방은 이 전환이 아니라 별도 트랙(원고 정규화 중간층 + 인식 회귀 코퍼스)이다.
**전환이 그것을 싸게 만들지만 대신하지 않는다.**

## 3. 무엇을 건드리지 않는가 (경계)

- **파서 무변경.** `engines/workbook/parser.py`, `_taxonomy`, `manuscript_noise` 그대로.
- **v1/v2 InDesign 경로 무변경.** 기존 잡은 그대로 돈다. 병행 운영이 전제다.
- **InDesign 무접촉.** 이 작업은 InDesign을 한 번도 켜지 않는다(1·2차 파일럿과 동일).
  기준 실측은 이미 나와 있는 완성본 PDF에서 뽑는다.
- **입력 계약 재사용.** 렌더 플랜 `wb-flows-v1`(`jobs/<id>/render_plan.json`)을
  그대로 소비한다. 파서 → 플랜까지는 두 렌더러가 공유한다.

```
원고 ─(parser.py, 무변경)─→ content.json ─(plan.py)─→ render_plan.json (wb-flows-v1)
                                                        ├─→ [기존] run.jsx → InDesign → PDF
                                                        └─→ [신규] series/workbook → HTML → PDF
```

## 5. 구조 — 3계층에 어떻게 얹는가

```
core/render_vivlio/series/workbook/
  data.py    render_plan(wb-flows-v1) → data.json   (역할 해석 + 선택 필터)
  render.py  data.json → HTML                        (스텝별 시트 빌더 + STEP3 흘림)
  theme.py   팔레트·치수 → themes/workbook.css 주입   (토큰화)
  assets.py  아이콘·서체 배치
themes/workbook.css
```

### 5.1 역할 해석은 구조로 — 리터럴 화이트리스트 금지

단락 스타일 이름은 계열마다 꼬리가 다르다. 실측:

```
STEP 01 > A1_어휘 선택          (본가)
STEP 03 > S_선지 올림포스        (본가 step3 — '올림포스' 꼬리)
STEP 03 > 실전 문제 지문 올림포스_
```

파일럿은 이 이름을 **리터럴 상수**로 박았다(`S3_Q = "STEP 03 > S_실전문제 번호 수정 올림포스"`).
그러면 계열이 바뀔 때마다 상수를 늘려야 한다 — 지금 파서에서 반복된 그 실패다.

대신 **구조 판정**한다: `STEP NN > ` 접두 제거 → 변종 꼬리(올림포스/리딩파워/수특…)와
`_`·`S_` 잡음 제거 → 역할 어휘로 정규화. 새 방언은 코드가 아니라 `ROLE_ALIASES`
데이터에 한 줄 추가로 끝난다. 못 알아본 스타일은 **조용히 넘기지 않고 게이트에서 세운다.**

### 5.2 지면 규칙은 CSS가 아니라 데이터로

`docs/워크북_섹션_지면규칙.md` 의 상단/하단 규칙(본문정리=상단 카드/하단 문제,
문장배열=상단 순서배열/하단 순서삽입)은 시트 빌더의 **선언 테이블**로 옮긴다.
"칸이 비었는가 / 상하가 뒤바뀌었는가"는 텍스트 대조로 안 잡히므로 **면 검수 게이트**로 만든다.

### 5.3 범위·스텝 선택 (③④가 죽는 지점)

책 `config.json`:

```jsonc
"select": {
  "passages": [2, 4, 6],          // 지문 번호. 생략 = 전부
  "steps": ["step1_a1", "step1_c1", "step3"],   // 생략 = 플랜에 있는 전부
  "renumber": true                 // 남은 지문을 1..N 으로 다시 매김
}
```

플랜을 렌더 **전에** 거른다. 만들지 않은 면은 지울 필요가 없다.

## 7. 정직한 한계 (전환해도 남는 것)

1. **장평** — 실물 하단 박스류는 ~86% 장평. CSS에 장평이 없다. `scaleX` 근사는
   고정 시트에선 되지만 2단 흘림 구간엔 위험하다. 정공법은 wdth 가변축 서체.
   **사용자 눈 승인이 필요한 유일한 항목.**
2. **상용 서체** — TTMamablock(스텝 로고)·URWDIN. 라이선스 확보 또는 대체 확정 전까지
   내부 검증 한정.
3. **행 단위 파리티 비목표** — 기존 완성본과 줄바꿈이 같아지지 않는다. 신규 조판부터
   쓰고, 기존 책의 "차이 0" 개정은 InDesign 경로에 남긴다.
4. **원고 인식(②)** — 이 전환의 사정권 밖이다.
