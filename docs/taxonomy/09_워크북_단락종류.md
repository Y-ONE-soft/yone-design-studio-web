# 09. 워크북 단락 종류 식별 시그니처 (Tier 1 — 워크북-A)

작성일: 2026-05-26
대상: 워크북 STEP1~STEP3 모든 단원

## 목적

원고의 각 단락이 **무엇인지** (발문/지문/선지/조건/보기/정답/한글해석/그룹헤더 등)를 **단어가 아닌 구조**로 판정.

기존 방식의 문제:
- `"이 단어가 들어가면 → 발문"` 식 → 단어 한 글자만 달라도 깨짐
- 예: `_RE_STEP3_NON_CHOICE`는 "어형 변화"만 매칭, "어형 변형"은 못 잡음
- 예: `"<보기>"` 정확 매칭, `"[보기]"`는 못 잡음

새 방식 (제안):
- **위치 + 마커 + 컨텍스트 + 언어 + 길이**의 조합으로 단락 종류 판정
- 어떤 한 시그니처가 깨져도 다른 시그니처로 보정 (다층 방어)

## 단락 종류 카탈로그 (10종)

| 코드 | 단락 종류 | 워크북 예시 스타일 |
|---|---|---|
| **GH** | 그룹 헤더 (`※`/`[Gateway]`/`[N과]`/`[유형 N]`) | (제거 대상) |
| **Q** | 발문 (문항 번호 + 발문) | S1_HADAN_SEO / S2_C2_NUM / S3_NUM |
| **Q-INTRO** | 묶음 도입 발문 ("다음 글을 읽고 물음에...") | S3_INTRO |
| **P** | 지문 (영어 통문장 본문) | S1_A2_BOX / S1_C1 / S3_DEFAULT / S3_PASSAGE |
| **P-CONTEXT** | 배경/씨앗 지문 (순서배열 X 단락, 문장삽입 주어진 문장) | S3_BG |
| **K** | 한글 해석 (영어 본문의 한글 번역) | S1_C2_KOR |
| **C** | 선지 (`①②③④⑤` 5개) | S1_A1 / S2_A1 / S3_CHOICE |
| **Cond** | 조건 박스 (`<조건>` / `[조건]` / 단독 "조건") | S3_COND |
| **Box** | 보기 박스 (`<보기>` / `[보기]` / 단독 "보기") | S3_VIEW |
| **Word** | 영단어 박스 (어휘 강조, `*` 마커) | S3_WORD |
| **A** | 정답 (`①` 또는 `①: 해설...` 단답형) | (제거 대상) |

## 단락 종류별 식별 시그니처 (다층 방어)

### GH — 그룹 헤더

| 우선순위 | 시그니처 | 정규식 / 룰 |
|---|---|---|
| 1 | 묶음 마커 단독 라인 | `^\[(Gateway|gateway|\d+)\]$` |
| 2 | 글 시작 ※ 문장 | `^※\s*다음` |
| 3 | 유형 라벨 | `^\[\s*유형\s*\d+\s*\]` |
| 4 | 유형 부제 (괄호 안 한글 콤마 나열) | `^\(\s*[가-힣\s,/&·]+\s*\)$` (한글 토큰 2개+) |
| 5 | 책 헤더 | `^\d{4}\s*년?\s*수능특강` 등 |
| 6 | `[N과]` / `[N번]` | `^\[\s*\d+(과|번)\s*\]$` |

→ **처리**: 본문 외부 정보. 단락스타일 매핑 대상 아님. 파서가 grouping 결정 후 출력에서 제거.

### Q — 발문

| 우선순위 | 시그니처 | 정규식 / 룰 |
|---|---|---|
| 1 | **분류기 leaf 코드 매칭** (가장 강력) | `OBJ-*` / `SRV-*` 코드 부여 가능 |
| 2 | 번호 + 발문 | `^(\d+\.)\s` 시작 + 끝이 `?` 또는 `시오.`/`것은?`/`것을 ...` |
| 3 | 서술형 헤더 | `^서술형\d+\.` 시작 |
| 4 | 한글 + 종결어미 | `[가-힣](?:시오|것은|것을|것)\??\s*$` |

→ **처리**: 매칭 시 leaf 코드 부여. leaf 코드로 부속 단락 구조 결정 (B 문서).

### Q-INTRO — 묶음 도입 발문

| 우선순위 | 시그니처 |
|---|---|
| 1 | 분류기: `OBJ-LNG-HEADER` 코드 |
| 2 | `^(※\s*)?다음 글을 읽고\s*(,\s*)?물음에 답하시오` |
| 3 | `^\[\d+~\d+\]\s*다음 글` |

→ **처리**: 다음 단락(보통 지문)부터 묶음 시작. 묶음 내 발문들 grouping.

### P — 지문 (영어 본문)

| 우선순위 | 시그니처 |
|---|---|
| 1 | 영어 알파벳 시작 + 한글 미포함 + 길이 80자+ | `^[A-Za-z]` + `not /[가-힣]/` + `len ≥ 80` |
| 2 | 위 + 인라인 마커 (`①②③④⑤` / `(A)(B)(C)` / 빈칸 ____ / `_____`) → 마커 보존 |
| 3 | 영어 단락 + 종결 마침표 | `[.!?]\s*$` |

→ **변형**:
- P-NOUL: 밑줄 없는 지문 (S3_PASSAGE_NOUL) — 본문에 underline run이 없음
- P-WITH-UL: 밑줄 있는 지문 (S3_PASSAGE) — 본문에 underline run 1개+

→ **처리**: 영어 + 한글 미포함 단락은 기본 P. 발문 직전/직후 위치 + 컨텍스트로 P/P-CONTEXT 구분.

### P-CONTEXT — 배경 / 씨앗 단락

| 우선순위 | 시그니처 (현재 STEP3 jsx의 로직 일반화) |
|---|---|
| 1 | 발문이 `OBJ-FLW-INSERT` / `OBJ-FLW-ORDER` 코드 → 발문 다음 첫 비빈 단락 = P-CONTEXT |
| 2 | 발문이 `OBJ-FLW-INSERT-MARK` / `OBJ-FLW-ORDER-NEXT` 등 변형 → 동일 |
| 3 | 발문 다음 두 번째 비빈 단락이 `^(A)\s+[A-Za-z]` 시작 (순서배열 (A)(B)(C) 구성) → 첫 비빈 단락이 P-CONTEXT |

→ **처리**: 발문 + 첫 단락(X) + 둘째 단락(Y) 패턴 검사. Y가 `(A)` 시작 또는 발문이 삽입형이면 X = P-CONTEXT.

### K — 한글 해석

| 우선순위 | 시그니처 |
|---|---|
| 1 | 한글 비율 70%+ + 길이 30자+ | 한글/전체 ≥ 0.7 |
| 2 | 영어 본문 단락 직후 위치 | 위 단락이 P |
| 3 | 종결어미 `다.`/`다.` 으로 끝 | `[가-힣]+다\.\s*$` |

→ **처리**: 빈칸 워크북(C2_빈칸 어휘 한글)에서 한글 해석을 별도 단락스타일로.

### C — 선지

| 우선순위 | 시그니처 |
|---|---|
| 1 | `^[①②③④⑤]` 시작 | 가장 명확 |
| 2 | 5개 연속 단락이 `①②③④⑤` 시작 (블록 검출) | 정답 마커 분리 |
| 3 | `(A)` + 공백 2개+ 또는 `(A)` + 탭 시작 (어법 매칭 헤더) | `/\(A\)\s{2,}/` 또는 `/\(A\)\t/` |
| 4 | `\(?[①②③④⑤]\)?\s*$` 단독 라인 (정답 라인) → A로 재분류 |

→ **처리**: 5개 묶음 인식. 5개 묶음의 마지막 다음에 빈 줄 또는 발문이면 선지 블록 종료.

### Cond — 조건 박스

| 우선순위 | 시그니처 (정규화 후) |
|---|---|
| 1 | 트림 후 정확히 `<조건>` | `^\s*<조건>\s*$` |
| 2 | 트림 후 정확히 `[조건]` | (정규화 단계에서 `<조건>`으로 변환) |
| 3 | 트림 후 정확히 `조건` (꺾쇠/대괄호 없는 단독) | `^\s*조건\s*$` |
| 4 | `<조건>` 이후 propagation: 다음 한글 단락이 `•`/`-`/`①~⑤` 시작 | 조건 항목 |

→ **처리**: Cond 마커 라인 → 그 이후 한글 단락이 ★ 조건 항목. 다음 발문/Box/빈칸 만나면 종료.

### Box — 보기 박스

| 우선순위 | 시그니처 (정규화 후) |
|---|---|
| 1 | 트림 후 정확히 `<보기>` 또는 `[보기]` 또는 단독 `보기` |
| 2 | 단락 시작에 `<보기>` + 뒤가 한글 X | `^<보기>\s*[^가-힣]` (있으면 영문 보기) |
| 3 | propagation: 다음 영문 단락이 슬래시 포함 또는 쉼표 3개+ | 보기 단어 나열 |

→ **처리**: <보기> 마커 → 영문 단어/구 나열이면 Box 그룹. 한글 단락 만나면 종료.

### Word — 영단어 박스

| 우선순위 | 시그니처 |
|---|---|
| 1 | `*` 마커 포함 단락 | `/\*/` |
| 2 | 단어 + 품사 + 뜻 패턴 (영어 단어 + 한글 ":") | `^[a-z]+\s*[:：]` |
| 3 | 발문/지문 외부에서 어휘 강조 | 짧은 라인 (< 50자) + 영단어 위주 |

→ **처리**: 영단어 단독 라인 또는 어휘 강조 박스. STEP3의 어휘 박스에 S3_WORD 적용.

### A — 정답

| 우선순위 | 시그니처 |
|---|---|
| 1 | `^\s*[①②③④⑤](?:\s*,\s*[①②③④⑤])*\s*$` 단독 라인 |
| 2 | `^\s*[①②③④⑤]\s*(?:,\s*[①②③④⑤]\s*)*:\s*.+` (정답 + 해설) |
| 3 | `^\s*\[\s*정답\s*\]\s*$` / `정답 및 해설` 헤더 이후 단락 |
| 4 | 한글 해설 (긴 한글 문장) — `①` 또는 마크 + 한글 | 해설 |

→ **처리**: 자동화 출력에서 **제거** 대상. 별도 정답지 스토리에 따로 배치 가능.

## 우선순위 규칙

같은 단락이 여러 시그니처에 매칭되는 경우:

1. **GH (그룹 헤더)** > 다른 모든 종류 — 출력 제거 대상이므로 먼저 빼냄
2. **A (정답)** > 본문 단락 — 정답이면 본문 단락스타일 부여 X
3. **Q (발문)** > P (지문) — 발문은 leaf 코드 매칭 우선
4. **Q-INTRO** > Q — `OBJ-LNG-HEADER`가 더 구체적
5. **P-CONTEXT** > P — 발문 컨텍스트 기반 결정이 더 구체적
6. **Box / Cond / Word** > P — 박스 마커가 더 강력한 시그널
7. **C (선지)** > P — `①` 시작이 더 명확
8. **K (한글)** > P — 한글 비율로 명확히 구분

## 시그니처 룰 정리 (의사 코드)

```python
def classify_paragraph(para, idx, paragraphs, leaf_code_of_prev_question):
    text = para.text.strip()

    # 1. 빈 단락
    if not text: return "BLANK"

    # 2. 그룹 헤더 (먼저 빼내야 다른 룰에 안 걸림)
    if is_group_header(text): return "GH"

    # 3. 정답 단독 라인
    if is_answer_only(text): return "A"

    # 4. 박스 마커 (단독 라인)
    if text in ("<보기>", "<조건>", "보기", "조건"): return text_to_box_kind(text)

    # 5. 발문 (분류기 leaf 코드 우선)
    code, label, kind = classify(text)
    if code:
        if code == "OBJ-LNG-HEADER": return "Q-INTRO"
        return "Q"  # leaf code = code

    # 6. 선지 (① 시작)
    if text.startswith(("①","②","③","④","⑤")): return "C"

    # 7. 영어 본문
    if is_english_passage(text):
        # 컨텍스트 검사
        if is_p_context(idx, paragraphs, leaf_code_of_prev_question):
            return "P-CONTEXT"
        return "P"

    # 8. 한글 해석
    if korean_ratio(text) > 0.7 and len(text) > 30:
        return "K"

    # 9. 영단어 강조
    if "*" in text and len(text) < 100:
        return "Word"

    # 10. fallback
    return "UNKNOWN"
```
