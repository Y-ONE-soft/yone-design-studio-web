# 04. 유형별 식별 시그니처

각 leaf 유형(분류 코드)에 대해 파서가 무엇을 보고 그 유형으로 판정해야 하는지 정리.

기본 식별 흐름:
1. **컨텐츠 분기 (Level 0)**: 발문이 있는지 → 없으면 A군(본문/분석), 있으면 B군(문제)
2. **묶음 헤더 인식**: `[N~M]` 또는 `다음 글을 읽고 물음에 답하시오` → 장문 묶음
3. **발문 정규식 매칭**: `RULES` 적용 → leaf 코드 부여
4. **변형 차원 부착**: 보기 표기, 정답 개수, 출처 마커 등

## 0) 식별 우선순위

같은 발문에 여러 룰이 매칭될 수 있으므로 **구체적 → 일반** 순서.

| 우선순위 | 영역 | 예시 |
|---|---|---|
| 1 | 묶음 헤더 (장문 시그니처) | `^[\d+~\d+] 다음 글` |
| 2 | 복합 룰 (~끼리/두 개/모두) | `OBJ-GRM-UND-WRONG-MULTI` 우선 |
| 3 | 단일 룰 | `OBJ-GRM-UND-WRONG` |
| 4 | 폴백 (기본 분류) | 분류 안되면 unclassified로 보관 |

## 3) 단락 구조 패턴 (Block Structure)

각 leaf 유형에 부속되는 단락의 표준 구조. JSX/파서가 어떤 단락을 어떤 역할로 인식해야 하는지.

### 표준 블록 구조

```
[Q-block]
├── header_marker      (예: "[20~21]", "서술형1.", "5.")
├── question_text      (발문 본문, 위에서 매칭한 정규식)
├── source_marker      (예: "[24년 10월 20번]", "[EBS 강좌명 N강]")
├── point_marker       (예: "[3점]")
├── instruction_box    (조건 박스 — 서술형 일부에만)
├── stimulus           (본문 / 지문 / 도표 / 안내문)
│   ├── inline_marks   (밑줄 ①~⑤, ⓐ~ⓔ, (A)(B)(C), 빈칸 등)
│   └── multi_blocks   (장문 묶음의 경우 여러 stimulus)
├── given_text         (주어진 문장 / 한글 해석 / 보기 박스 — 일부)
├── choices            (보기 ①~⑤ / 한글 단답 / 영문 단답 / 조합)
└── answer_marker      (정답 표시 — 정답지 첨부 시)
```

## 4) 출처 마커 식별

발문 또는 헤더에 부착되는 출처 표시.

| 패턴 | 의미 | 예시 |
|---|---|---|
| `\[\d{2}년 \d+월 \d+번\]` | 모의고사 출처 | `[24년 10월 20번]` |
| `\[\d{2}년 \d+월\]` | 모의고사 시점만 | `[23년 11월]` |
| `\[EBS .{1,30}\]` | EBS 강좌 | `[EBS 수능특강 8강]` |
| `\[\d+과\]` | 교과서 단원 | `[3과]` |
| `\[\d+번\]` | 단순 문항 번호 | `[20번]` |
| `\[\d+점\]` | 배점 | `[3점]` |
| `\[Read More\]` | 보충 텍스트 | (가끔) |
