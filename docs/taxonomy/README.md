## 핵심 아이디어 (사용자가 원한 것)

**기존 방식 (문제)**:
```
"이 단어가 들어가면 → 발문 단락스타일"
"❮…❯ 마커 → 본문 박스"
"<조건> 매칭 → 조건 박스"
↓ 원고에서 단어 한 글자만 달라져도 깨짐
```

**제안 방식 (해결)**:
```
원고 단락 → [단락 종류 식별 시그니처]
            (위치 + 마커 + 컨텍스트 + 언어 + 길이)
                ↓
        Q(발문)이면 → [분류기 leaf 코드]
                ↓
        leaf 코드 + 단락 종류 + 교재 유형 → [단락스타일 결정]

→ 단어 변화에 둔감. 결정론적.
```

## 구체적 적용 시나리오

### 1. 원고 처음 받았을 때 (즉시)
```bash
python3 -m engines._taxonomy.cli file "원고.hwp"
```
→ "발문 32개, 객관식 26 + 서술형 6, 미분류 2개" 즉시 확인. Claude가 작업 시작 전 자동 호출.

### 2. 워크북 STEP3 새 변형 처리 (점진적)
현재 STEP3 파서의 fragile한 `_RE_STEP3_NON_CHOICE` (5 키워드 OR) → 분류기 `classify() == "서술형"` 한 줄로 대체 가능.
파서 수정 없이 룰 한 줄만 추가하면 새 변형 흡수.

### 3. 신규 엔진 (동형/배N제 등)
처음부터 분류 체계 기반 설계. `engines/_taxonomy.classify()` → leaf 코드별 단락 dispatch → 단락스타일 매핑.

### 4. 학교별 패턴 통계
누적 분류 결과로 학교별 leaf 코드 분포 → 출제 기획 보조 + 비정상 검출.

### 5. 결과물 검수 자동화
원본 원고 분류 (N발문) vs 자동화 결과 PDF (M문항) → 누락 자동 탐지.
