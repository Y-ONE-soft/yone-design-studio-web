# 05. 파서 룰 매핑표

각 leaf 유형 코드를 실제 파서가 다룰 수 있는 구조로 매핑.
출력 형태는 **공통 스키마 + 유형별 필드**.

## 1) 공통 출력 스키마

모든 문제는 다음 공통 스키마로 직렬화.

```json
{
  "id": "문항 ID (자동 부여)",
  "type": "leaf 코드 (예: OBJ-FLW-ORDER)",
  "kind": "객관식 | 서술형",
  "label": "한국어 라벨 (예: '순서 배열')",
  "header": {
    "marker": "[20~21] | 서술형1. | 5. | null",
    "group_id": "장문 묶음 그룹 ID (null 또는 'G-N')",
    "source": "[24년 10월 20번] | null",
    "score": 3
  },
  "question": "발문 본문 텍스트",
  "stimulus": {
    "type": "passage | dialogue | chart | notice | empty",
    "blocks": [
      { "kind": "text", "content": "...", "marks": [ {"type": "underline", "id": "①", "span": [12,18]} ] },
      { "kind": "para", "label": "(A)", "content": "..." }
    ]
  },
  "given": {
    "type": "sentence | summary_box | condition_box | word_box | null",
    "content": "주어진 문장 또는 요약문 박스 내용"
  },
  "choices": {
    "format": "circled | letter_combo | text_combo | none",
    "items": [
      { "label": "①", "content": "..." }
    ]
  },
  "constraints": [
    "본문 단어 활용",
    "N단어 이내",
    "어법에 맞게 변형 가능"
  ],
  "answer": "정답 (정답지에서 추출)",
  "level3_variants": {
    "choice_format": "V1-CIRCLE",
    "answer_count": "V2-SINGLE",
    "polarity": "V3-NEG",
    "source_marker": "V4-MOCK",
    "bundle": "V5-SINGLE",
    "inline_marker": "V6-INLINE",
    "choice_origin": "V7-INDEP"
  },
  "_source": {
    "file": "한영고1 동형 1회 원고_최종.hwp",
    "school": "한영고1",
    "year": "2026년",
    "exam": "26-1-중간",
    "category": "동형모의고사"
  }
}
```

## 2) leaf 유형 × 출력 필드 매핑표

### 2.1 객관식 - 어휘

| 코드 | 필수 필드 | 선택 필드 | 출력 예시 |
|---|---|---|---|
| `OBJ-VOC-SYN` | choices.items × 5 (문장 + 동의어 부호) | - | `{type: "OBJ-VOC-SYN", choices: [{label: "①", content: "He was reluctant... (=unwilling)"}]}` |
| `OBJ-VOC-DEF` | given.content (영영풀이 N개), choices.items × 5 (단어) | - | `{type: "OBJ-VOC-DEF", given: "1. opposed to..."}` |
| `OBJ-VOC-APPLY` | given.content (대상 단어), choices.items × 5 (빈칸 포함 문장) | - | `{type: "OBJ-VOC-APPLY", given: "remarkable"}` |
| `OBJ-VOC-PAREN` | stimulus.marks (`(A)/(B)/(C)`), choices.items × 5 (조합) | - | `{type: "OBJ-VOC-PAREN", stimulus.marks: [{label: "(A)", options: ["accept", "expect"]}]}` |
| `OBJ-VOC-UND-WRONG` | stimulus.marks (밑줄 ①~⑤), choices.items × 5 | - | inline mark = ① ~ ⑤ |
| `OBJ-VOC-UND-MEAN` | stimulus.marks (ⓐ~ⓔ), choices.items × 5 | - | mark format = mark_circle |
| `OBJ-VOC-COMMON-FILL` | given.content (보기 문장들 with 빈칸), choices.items × 5 | - | given.type = "sentence_box" |

### 2.2 객관식 - 어법

같은 패턴, given/stimulus.marks 구성만 다름.

| 코드 | 마크 유형 | 보기 |
|---|---|---|
| `OBJ-GRM-PAREN` | `(A)/(B)/(C)` 본문 안 | ①~⑤ 조합 |
| `OBJ-GRM-UND-WRONG` | 밑줄 ①~⑤ | ①~⑤ |
| `OBJ-GRM-UND-WRONG-MULTI` | 밑줄 ①~⑤ 또는 ⓐ~ⓕ | ①~⑤, 정답 2개 |
| `OBJ-GRM-MARK-CORRECT` | 마크 ⓐ~ⓕ | ①~⑤ 마크 묶음 |

### 2.3 객관식 - 내용

| 코드 | choices 형식 | 비고 |
|---|---|---|
| `OBJ-CTN-TITLE` | 영문 제목 5개 | - |
| `OBJ-CTN-TOPIC` | 영문 주제구 5개 | - |
| `OBJ-CTN-GIST` | 한글 요지 5개 | - |
| `OBJ-CTN-MATCH` | 한글 진술 5개 | polarity = NEG (불일치) 대부분 |
| `OBJ-CTN-COUNT` | 한글 진술 N개, 정답 = 숫자 | choices.format = "count" |
| `OBJ-CTN-PROVERB` | 한글 속담 5개 | - |
| `OBJ-CTN-INFO` | 한글 진술 5개 + 도표/안내문 stimulus | stimulus.type = "chart" or "notice" |
| `OBJ-CTN-INFER` | 한글 진술 N개 (모두 고르기) | answer_count = MULTI |

### 2.4 객관식 - 흐름

| 코드 | stimulus 특이사항 | choices |
|---|---|---|
| `OBJ-FLW-ORDER` | stimulus.blocks: 주어진 글 + (A)(B)(C) 단락 | ①~⑤ 조합 ((A)-(C)-(B) 등) |
| `OBJ-FLW-INSERT` | stimulus.blocks: 본문 + ①~⑤ 위치 마커 / given: 주어진 문장 | ①~⑤ |
| `OBJ-FLW-IRRELEVANT` | stimulus: 본문 (①~⑤가 문장으로 표시) | ①~⑤ |
| `OBJ-FLW-BLANK-SENT` | stimulus.marks: 빈칸 1개 (보통 본문 후반) | ①~⑤ (영문 단어/구/문장) |
| `OBJ-FLW-BLANK-AB` | given: 요약문 박스 with (A)/(B) | ①~⑤ 짝 |
| `OBJ-FLW-BLANK-ABC` | stimulus: 본문 안 (A)(B)(C) 빈칸 | ①~⑤ 세 짝 |
| `OBJ-FLW-BLANK-VOC-EXCL` | stimulus: 본문 안 (A)~(E) 빈칸 + 어휘 보기 풀 | ①~⑤ (활용 안 되는 어휘) |

### 2.5 장문 묶음

`OBJ-LNG-MULTI`, `OBJ-LNG-AB`, `OBJ-LNG-DLG`은 일반 문항을 묶는 그룹.

```json
{
  "type": "OBJ-LNG-MULTI",
  "header": { "marker": "[20~21]", "group_id": "G-001" },
  "stimulus": {...},   // 공유 본문
  "questions": [
    { "id": "Q-20", "type": "OBJ-CTN-TITLE", ... },
    { "id": "Q-21", "type": "OBJ-VOC-UND-MEAN", ... }
  ]
}
```

`OBJ-LNG-AB`은 stimulus가 두 개(글 A, 글 B):
```json
{
  "type": "OBJ-LNG-AB",
  "stimulus_a": {...},
  "stimulus_b": {...},
  "questions": [...]
}
```

### 2.6 서술형 - 단어

| 코드 | 출력 |
|---|---|
| `SRV-WRD-BOX` | given: 보기 박스 (단어 리스트) |
| `SRV-WRD-FROM-TEXT` | constraints: ["본문 발췌"] |
| `SRV-WRD-FROM-TEXT-VAR` | constraints: ["본문 발췌", "어법 변형 가능"] |
| `SRV-WRD-START-LETTER` | constraints: ["첫 글자 주어짐"], stimulus.marks: 첫 글자 힌트 |
| `SRV-WRD-N-WORDS` | constraints: ["N단어 이내"] (N = 정규식 캡처) |

### 2.7 서술형 - 어법 수정

| 코드 | stimulus.marks | constraints |
|---|---|---|
| `SRV-GRM-FIX-ALL` | (없음 - 글 전체) | - |
| `SRV-GRM-FIX-ALL-LIMIT` | (글 전체) | ["N개 이내"] |
| `SRV-GRM-FIX-MARKED` | ⓐ~ⓔ 밑줄 | ["각각 하나씩"] |
| `SRV-GRM-FIX-FIND-K` | (밑줄 없음 - 직접 찾기) | ["N곳 찾기"] |

### 2.8 서술형 - 영작

| 코드 | given | constraints |
|---|---|---|
| `SRV-WRT-COND` | 조건 박스 | 조건 박스의 모든 항목 |
| `SRV-WRT-COND-VAR` | 조건 박스 | ["변형 가능"] + 기타 |
| `SRV-WRT-SUMM` | 요약문 박스 with (A)~(C) | ["본문 단어 활용"] |
| `SRV-WRT-SUMM-BOX` | 보기 박스 + 요지 | ["보기 단어 모두 포함", "한 문장"] |
| `SRV-WRT-ORDER` | 단어 배열 | - |
| `SRV-WRT-KO-EN` | 한글 문장 | - |
| `SRV-WRT-BOX-WORDS` | 보기 박스 (단어들) | ["보기 활용"] |
| `SRV-WRT-MULTI-BLANK` | (A)~(E) 빈칸 | ["각 빈칸 완성"] |

## 3) 단락 구조 인식 룰 (Block Parser)

파서가 raw 텍스트 → 구조화된 블록으로 변환할 때 사용하는 룰.

### 3.1 블록 경계 식별

| 트리거 | 블록 종료 / 시작 |
|---|---|
| 발문 정규식 매칭 | 이전 Q-block 종료, 새 Q-block 시작 |
| `[N~M]` 헤더 | 장문 묶음 시작 |
| `※` 또는 `다음 글을 읽고 물음에 답하시오` | 묶음 헤더 |
| `서술형\d+\.` | Q-block 시작 (kind=서술형) |
| 빈 줄 1개 + 다음 문단이 발문 | Q-block 경계 |
| `①~⑤` 5개 라인 연속 | choices 블록 |
| `<보기>` ~ `</보기>` 또는 박스 모양 | given 블록 |
| `<조건>` ~ `</조건>` | instruction 블록 |
| `[24년 10월 20번]` 또는 `[YY년 M월 N번]` | source marker (현재 Q에 부착) |

### 3.2 inline mark 인식

본문 안에서 마크된 부분 식별:

| 패턴 | 마크 종류 | 처리 |
|---|---|---|
| `①`, `②`, `③`, `④`, `⑤` (본문 안) | numbered mark | stimulus.marks.id = "①" |
| `ⓐ`, `ⓑ`, ... | marked circle | stimulus.marks.id = "ⓐ" |
| `(A)`, `(B)`, `(C)` (본문 안 괄호) | paren mark | stimulus.marks.label = "(A)" |
| 밑줄 (hwpx/hwp의 UnderlineStyle) | underline mark | mark.style = "underline" |
| 굵게 (Bold) | bold mark | mark.style = "bold" |
| 빈칸 `_____` 또는 `(           )` 또는 `▭` | blank slot | mark.kind = "blank" |

### 3.3 hwpx/hwp 서식 보존 추출

raw 텍스트만으로는 밑줄/볼드/빈칸 식별이 불가능하므로 XML 단위로 처리.

hwpx (section0.xml):
- `<hp:run>` 안의 `charPr` 속성에서 underline/bold 확인
- 빈칸은 종종 `<hp:t>          </hp:t>` (공백) 또는 별도 도형 처리

hwp:
- `pyhwp`의 `BodyText/Section\d` 스트림에서 record 단위 처리
- charShape의 underline 플래그 사용

## 6) 파서 구현 단계 (권장)

### Phase A. Block Parser (구조 인식)

1. 입력: hwpx / hwp / docx (raw)
2. 추출: 문단별 텍스트 + 서식 메타 (밑줄/볼드/빈칸)
3. 출력: 블록 시퀀스 `[ {type, text, marks}, ... ]`

### Phase B. Question Detector (발문 추출)

1. 입력: 블록 시퀀스
2. 처리: `RULES` 정규식 매칭 → leaf 코드 부여
3. 출력: `Q-block`들 (with type, header, source)

### Phase C. Structure Resolver (단락 구조 해석)

1. 입력: Q-block + 인접 블록
2. 처리: Q-block 앞뒤 블록을 stimulus / given / choices / instruction로 분류
3. 출력: 공통 스키마

### Phase D. Variant Tagger (변형 차원 부착)

1. 입력: 공통 스키마
2. 처리: V1~V7 변형 차원 분석
3. 출력: 최종 JSON

### Phase E. Renderer (조판 출력)

1. 입력: 최종 JSON
2. 처리: 유형 코드별 InDesign 스타일 적용 (JSX)
3. 출력: InDesign 페이지

## 8) 미해결 / 후속 결정 사항

- [ ] 듣기 문제(`OBJ-LST-*`) 처리: mp3 파일 + 스크립트 텍스트가 별개. 분류 체계에 포함할지 별도 트랙으로 둘지.
- [ ] 정답 추출 룰: 발문 끝의 정답 표기(`① ~ ⑤`)와 정답지 별도 파일의 매칭 방법.
- [ ] 학교 특이 발문: 한 두 학교만 사용하는 특이 발문은 학교 코드를 부착한 별도 분류로 보관.
- [ ] 출처 추적: 모의고사 출처 마커 + 학교 워크북 매핑표 (`Google Sheets`)와 연동.
