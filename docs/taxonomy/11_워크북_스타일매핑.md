# 11. 워크북 단락스타일 매핑 매트릭스 (워크북-C)

작성일: 2026-05-26
대상: 워크북 STEP1A1 ~ STEP2C2 + STEP3

## 목적

`(단락 종류 × leaf 코드 × STEP 단원)` 입력에 대해 어떤 InDesign 단락스타일을 적용할지 결정론적으로 답.

기존 자동화의 패턴 매칭 휴리스틱(괄호 마커, "어휘2단계_Hard" 단어, ❮T/F❯ 등)을 완전히 대체할 수 있는 룩업 테이블.

## 0) STEP 단원과 leaf 코드 매핑 (STEP이 어떤 leaf를 다루는가)

| STEP | leaf 코드 (이 STEP의 표준 처리 대상) | 변형 |
|---|---|---|
| **STEP1A1** | `OBJ-VOC-PAREN` (괄호 선택 → 어휘 변형) | 본문에 ❮…❯ 마커 → `[…]` 치환 |
| **STEP1A2** | `OBJ-VOC-UND-WRONG` 또는 OX형 (본문 + T/F) | ❮T/F❯ 토큰 → TF 버튼 |
| **STEP1B1** | 내용 정리 (한글 정리 박스 — 분류 체계 외) | 자동 생성 단락 |
| **STEP1B2** | 내용 종합 (한글 정리 + 선지) | 분류 체계 외 |
| **STEP1C1** | `OBJ-FLW-ORDER` + `OBJ-FLW-INSERT` (혼합) | 본문 (A)(B)(C) 또는 ①~⑤ |
| **STEP1C1_New** | `OBJ-FLW-ORDER` (간소) | 하단 처리 X |
| **STEP1C2** | `OBJ-FLW-BLANK-SENT` + `OBJ-VOC-PAREN` (혼합 — 빈칸 어휘) | 본문 + 한글 해석 |
| **STEP2A1** | `OBJ-GRM-PAREN` (괄호 어법 선택) | 본문에 {…} 마커 |
| **STEP2A1Practice** | `OBJ-GRM-PAREN` (실전, 하단) | 헤더 삭제만 |
| **STEP2B1** | `OBJ-GRM-UND-WRONG` (어법 OX) | TF 버튼 |
| **STEP2C1** | `OBJ-FLW-BLANK-SENT` (빈칸 어법) | 본문 + 한글 |
| **STEP2C2** | `OBJ-FLW-BLANK-AB` 또는 `SRV-WRT-ORDER` (영작 배열) | 보기 단어 |
| **STEP3** | **다양한 leaf 코드** (객관식 + 서술형 혼합 — 모의고사/EBS 기출 단일 문항) | 변형 다수 |

## 1) STEP3 단락스타일 매핑 (가장 풍부)

STEP3는 분류 체계의 거의 모든 leaf 코드를 다룬다. 단락 종류 → 스타일 매핑.

| 단락 종류 | InDesign 단락스타일 | 적용 조건 (leaf 코드 무관, 단락 위치 기반) |
|---|---|---|
| GH | (출력 제거) | 그룹 헤더 — `_strip_step3_book_markers()`로 제거 |
| A | (출력 제거) | 정답 — `_strip_step3_answers()`로 제거 |
| **Q** | **S3_NUM** (`S_실전문제 번호 수정 올림포스`) | 발문 (모든 leaf 코드 발문) |
| **Q-INTRO** | **S3_INTRO** (`다음 글을 읽고`) | `OBJ-LNG-HEADER` 매칭 발문 |
| **P** | **S3_DEFAULT** (`실전 문제 지문 올림포스_`) | 기본 지문 (밑줄 무시) |
| **P-NOUL** | **S3_PASSAGE_NOUL** (`지문 밑줄 없음`) | 본문에 underline run 0개 |
| **P-WITH-UL** | **S3_PASSAGE** (`지문 밑줄 있음`) | 본문에 underline run 1개+ |
| **P-CONTEXT** | **S3_BG** (`배경 올림포스`) | `OBJ-FLW-INSERT` 발문의 주어진 문장, `OBJ-FLW-ORDER` 발문의 씨앗 문장 |
| **C** | **S3_CHOICE** (`S_선지 올림포스`) | `①~⑤` 시작 또는 `(A)\s{2,}` |
| **Cond** | **S3_COND** (`조건 올림포스`) | `<조건>` 마커 + propagation |
| **Box** | **S3_VIEW** (`보기 올림포스`) | `<보기>` 마커 + propagation (슬래시/쉼표 3+) |
| **Word** | **S3_WORD** (`영단어`) | `*` 마커 포함 |
| **K** | (지원 X — STEP3에 한글 해석 없음) | (해당 없음) |

### STEP3의 분기 휴리스틱 (현재 jsx 로직 정규화)

```python
def determine_step3_style(para, idx, paragraphs, leaf_code_of_prev_q):
    """
    원본 로직 (engines/workbook/jsx/run.jsx:2106~2237) 정규화
    """
    text = para.text.strip()

    # 1. 기본값
    style = S3_DEFAULT

    # 2. 분류기로 발문 leaf 코드 확인
    code, _, kind = classify(text)
    if code == "OBJ-LNG-HEADER":
        return S3_INTRO
    if code:  # 분류기 매칭 = 발문
        return S3_NUM

    # 3. 선지
    if text.startswith(("①","②","③","④","⑤")):
        return S3_CHOICE
    if re.match(r"\(A\)\s{2,}", text) or re.match(r"\(A\)\t", text):
        return S3_CHOICE

    # 4. 영단어 박스
    if "*" in text:
        return S3_WORD

    # 5. 박스 (정규화 후 <보기> / <조건>)
    if text in ("<보기>", "보기"):
        return S3_VIEW
    if text in ("<조건>", "조건"):
        return S3_COND

    # 6. P-CONTEXT 결정 (블록 단위)
    if is_p_context(idx, paragraphs, leaf_code_of_prev_q):
        return S3_BG

    # 7. 지문 (default)
    return S3_DEFAULT
```

이 흐름은 **사용자의 "단어가 한 글자 달라져도 인식 못 함"** 문제를 해결한다:
- 발문 판정은 `classify()` 결과로 (단어 변화에 둔감)
- 박스 판정은 정규화 후 매칭 (`[보기]` → `<보기>` 자동 변환)
- 선지 판정은 `①` 마커만 보면 됨 (단어 무관)

## 2) STEP1 단락스타일 매핑

STEP1A1 (어휘 선택):

| 단락 종류 | 스타일 | 조건 |
|---|---|---|
| (특수) `[…]` 단락 | (프레임 브레이크 + 제거) | ❮…❯ → […] 치환 후 마커 단락 |
| **P (본문, 인라인 ()(A)(B)(C)** | **S1_A2_BOX** (`A2_본문 박스`) | `[…]` 다음 첫 영어 단락 |
| **C (선지 — 어휘 변형으로 생성)** | **S1_A1** (`A1_어휘 선택`) | `[…]` 단락 직후 (자동 생성) |
| 번호 라벨 (자동 생성) | **S1_A_NUM** | C 앞 번호 라벨 |

STEP1A2 (OX 문제):

| 단락 종류 | 스타일 | 조건 |
|---|---|---|
| `[…]` 다음 영어 본문 | **S1_A2_BOX** | bracket idx 다음 첫 영어 |
| ❮T/F❯ 토큰 라인 | **S1_A2_OX** (`A2_OX문제`) | findGrep `❮\s*T\s*/\s*F\s*❯` 매칭 + TF 버튼 인라인 삽입 |

STEP1B1 (내용 정리):

| 단락 종류 | 스타일 | 조건 |
|---|---|---|
| 모든 단락 (기본) | **S1_B1** (`B1_내용 정리`) | everyItem 적용 |
| 주제/제목 헤더 | **S1_B1_SUBJ** / **S1_B1_TITLE** | `{주제}` `{제목}` 치환 후 라인 |
| 하단 문제 | **S1_HADAN** (`하단 문제`) | "다음" 시작 발문 |
| 하단 지문 | **S1_HADAN_JIM** | 발문 다음 단락 |
| 하단 선지 | **S1_HADAN_SEO** | ①~⑤ 단락 |

STEP1B2 (내용 종합):

| 단락 종류 | 스타일 | 조건 |

## 4) 결정 함수 (의사 코드)

```python
def resolve_paragraph_style(para, idx, paragraphs, step_unit, leaf_code, prev_question_code):
    """
    워크북 단락스타일 결정.

    Args:
        para: 단락 객체
        idx: 단락 인덱스
        paragraphs: 전체 단락 배열
        step_unit: "STEP1A1" / "STEP1A2" / ... / "STEP3"
        leaf_code: 이 단락의 leaf 코드 (발문인 경우)
        prev_question_code: 이 단락 위의 마지막 발문 leaf 코드 (컨텍스트)

    Returns:
        InDesign 단락스타일 이름 (예: "STEP 01 > A1_어휘 선택")
    """
    # 단락 종류 결정 (워크북-A 시그니처)
    kind = classify_paragraph(para, idx, paragraphs, prev_question_code)

    # STEP 단원별 매핑 룩업
    if step_unit == "STEP3":
        return STEP3_MAP[kind]
    if step_unit == "STEP1A1":
        return STEP1A1_MAP[kind]
    if step_unit == "STEP1A2":
        return STEP1A2_MAP[kind]
    # ... (다른 STEP들)
```

## 5) 기대 효과

| 기존 (단어 기반) | 제안 (구조 기반) |
|---|---|
| "다음 글을 읽고 물음에" 정확 매칭 → S3_INTRO | `classify() == OBJ-LNG-HEADER` → S3_INTRO. 변형 발문도 자동 |
| `<조건>` 정확 매칭 → S3_COND | `[조건]` / `조건` / `〈조건〉` 모두 정규화 후 매칭 |
| "어휘2단계_Hard" 단어로 삭제 | leaf 코드 기반: A (정답) 또는 GH (그룹헤더)는 항상 제거 |
| `\\(A\\)\\s{2,}` 정확 매칭 | 같은 패턴 + leaf 코드의 보기 구조 결합 |

원고 단어 한두 글자가 달라져도:
- 발문 → leaf 코드 분류기가 흡수
- 단락 종류 → 다층 시그니처가 흡수
- 단락스타일 → 룩업 테이블 결정론적

## 6) 적용 시 검증 절차 (수정은 별도 작업)

이 매핑을 실제 워크북 파서/JSX에 적용하기 전:

1. **Dry-run 도구**: 원고 → 단락 종류 결정 → 스타일 매핑 결과를 JSON으로 출력. 실제 InDesign 무변경
2. **현재 파서/JSX 결과와 diff**: 광범위 추출 데이터로 dry-run 결과 vs 현재 결과 비교
3. **불일치 케이스 검토**: 어느 쪽이 맞는지 사람 확인
4. **회귀 안전 확인**: 95%+ 일치 시 적용 검토 (이건 별도 작업)

이 검증 자체도 분석 단계라 코드 수정 X.
