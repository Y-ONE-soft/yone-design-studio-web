# 포켓북 Vivliostyle 전환 — 분석과 계획

**목표: 포켓북에서 "완성본에서 가져오기"와 "분석본을 포켓북으로 변환"을 없앤다.**
사람이 조판 후에 손대는 일이 0 이 되는 것이 성공 조건이다.

작성 2026-09-01. 파일럿 코드 `pilot/pocketbook/`.

---

## 0. 결론 먼저

1. **막는 것은 조판이 아니라 데이터다.** 포켓북에서 값이 가장 비싼 내용
   (구문분석 주석·플로우노트·동반의어)은 지금 **완성 .indd 안에만** 있다.
   그래서 매 학기 "가져오기"를 해야 한다. 가져오기는 게으름이 아니라
   **유일한 저장소를 읽는 행위**였다.
2. 따라서 전환의 본체는 CSS 가 아니라 **지문 DB(passage corpus)** 다.
   DB 가 생기는 순간 가져오기는 "DB 조회"가 되고, 코드 조판은 몇 번을 다시
   돌려도 같은 지면을 내므로 **재사용을 위해 스프레드를 복제할 이유가 사라진다.**
3. 가장 무섭던 기술 위험 — *낱말 위·아래에 붙은 구문분석 주석을 HTML 로 그릴 수
   있는가* — 는 **파일럿으로 해소했다.** 실측 그리드(9pt / 행간 24pt)와 주석
   기준선(위 −9.4pt · 아래 +8.6pt)이 소수점까지 맞고, 자간 상수 하나로 원본과
   행바꿈까지 일치시켰다. §4 참조.
4. 결정 완료(2026-09-01): 동반의어는 **완성본 하베스트 + 신규는 교재팀 원고**
   (§3-C·E), 도련 **사방 3mm**(§9-2), 행바꿈은 **맞추지 않는다**(§10).

## 1. 지금 구조 — 무엇이 자동이고 무엇이 수동인가

엔진: `engines/pocketbook/` (`engine.py` 1,700줄 + `jsx/run.jsx` 3,763줄).
입력은 **분석본 .indd 폴더**, 출력은 포켓북 .indd + PDF (A5 148×210mm).

> ⚠ **현재 산출 PDF 에는 도련이 없다.** MediaBox·TrimBox·BleedBox 가 전부
> 148×210 으로 같다(실측). 위·아래 띠는 InDesign 안에서 재단선 밖 3mm 까지
> 그려져 있는데 **내보내기에서 잘려 나간다.** 고품질 인쇄가 최종 출력물이므로
> 이건 지금도 결함이다 → §9-2 에서 사방 3mm 로 확정.

### 지면 구성 (고등 지문형, 반복 단위 = 지문 1개)

| 면 | 마스터 | 내용 |
|---|---|---|
| 짝(왼쪽) | A(교과서)·C(모의고사, 삽화)·I(EBS) | 지문번호 배지 · **구문분석 영어 지문** · PICTURE(삽화) · TRANSLATION(한글) |
| 홀(오른쪽) | 같은 스프레드 | **FLOW NOTE** · 주제/요약문 · **동반의어 카드 9칸**(보통 6장) |
| 짝 | B/D/F/L | 암기 TEST (빈칸) |
| 홀 | 〃 | 암기 TEST 정답 |

짤지문은 pair 마스터(G/H)로 한 스프레드에 둘. 어휘 J, 듣기 K.
중등·교과서 문제형 포켓북(어휘노트·대화문·문법·5분점검·실전문제)은 별도 계보로
`automation/lesson4`·`donga2`·`miraen2` 빌더가 만든다 — **이번 범위 밖**(§8).

### run.jsx 가 실제로 채우는 것 / 채우지 않는 것

`grep` 으로 확인했다. `flownote`·`동반의어`(`동반...`)를 다루는 코드가
**한 줄도 없다.**

| 요소 | 지금 | 출처 |
|---|---|---|
| 영어 지문(주석·색·형광펜 포함) | 자동 | 분석본 스토리를 **서식 유지 복제** |
| 한글 해석 | 자동 | 분석본 |
| 지문번호·단원명 | 자동 | 파일명/커버 파싱 |
| 삽화 | 자동 | GDrive `포켓북 삽화정리/<학년>/<회차>/<번호>.jpg` (949개) |
| 암기 TEST 문제·정답 | 자동 | 리뷰테스트 해설지 .docx (`parser.py`) |

그 손댄 결과를 **완성본에서 스프레드째 복제**해 가져온다. 이것이 "가져오기"의
정체다.

## 2. 그래서 비블리오로 옮기면 무엇이 사라지는가

| 지금 하는 일 | 비블리오 후 |
|---|---|
| 완성본 파일 탐색·[완] 판정·passageNo 맵 구축(`buildSpreadPnoMap`, `copySpreadByPassageNo`, canon 매칭 …) | **전부 삭제.** 지문 키로 DB 조회 |
| 스프레드 복제 후 마스터 교정(`correctCopiedMasters`) | 삭제. 면 종류는 데이터가 정한다 |
| 오버플로우 수습(`resolveOverflow`, 글자 축소) | 삭제. 지면이 CSS 로 늘고 준다 |
| InDesign 유휴 대기·강제종료·복구 대화상자 | 삭제. Node 프로세스 하나 |
| 조판 후 FLOW NOTE·동반의어 손입력 | **DB 에서 자동**(또는 없으면 게이트가 막는다) |

"IDML 로 내보내기" 한 줄이다(§3-A).

## 3. 없어서 막히는 것 = 필요한 데이터

### A. 구문분석 지문 — **정본은 IDML, 백카탈로그는 PDF**

분석본 .indd 안의 표현을 실측했다(포켓북 완성 PDF 기준, 9pt 본문):

| 표현 | 실제 구현 |
|---|---|
| 위 주석 (`conceivably (X)`, `명접`) | 앵커된 텍스트 프레임, 7pt, baseline **−9.4pt** |
| 아래 주석 (`S` `V` `C` `진 S` `관계부사`) | 〃, baseline **+8.6pt** |
| 강조색 | 글자색 파랑 `#224E8E` · 빨강 `#D2232A` (본문 `#231F20`) |
| 형광펜 | **굵기 9pt 밑줄 스트로크**(노랑 `#FDF598` 등). 색 스와치 참조라 [[analysis_swatch_edit_breaks_body]] 사고의 그 구조 |
| 밑줄 표시 | 굵기 0.4pt 스트로크 |

`.indd` 는 바이너리지만 **IDML(=zip+XML)** 은 이 전부를 그대로 담는다 —
`CharacterStyleRange` 의 색·밑줄 오버라이드, 앵커 프레임의 `AnchoredObjectSetting`
(어느 **글자**에 붙었는지까지). 실제 IDML 을 열어 확인했다.

- **정본 경로**: 분석본 .indd → (InDesign 이 IDML 내보내기 — 로직 없음) →
  **순수 파이썬 파서** → 지문 JSON. 이후 조판에 InDesign 은 관여하지 않는다.
- **백카탈로그**: GDrive 완성 포켓북 **262개 .indd** 는 한 번 배치로 IDML 을
  내보내 흡수한다. 로컬 완성 PDF 72권은 PDF 에서 바로 뽑을 수 있다(아래 검증).

**PDF 하베스트도 실증했다** (`pilot/pocketbook/harvest_pdf.py`).
한 면에서 **줄 10 · 낱말 137 · 주석 50 · 미부착 0**. 낱말 색·형광펜·밑줄·
위/아래 주석이 전부 복원된다.

> ⚠ PDF 하베스트의 한계 두 가지.
> ① 서로 다른 앵커 프레임의 글자가 0.3pt 만 떨어져 붙는다(`S` 와 `V`) —
>   **글자 간격으로 끊으면 안 되고 PDF span 경계로 끊어야 한다**(그렇게 고쳤다).
> ② 주석이 낱말 **안의 어느 글자**에 붙었는지는 PDF 에 없다(`It’s` 아래
>   `가 S`+`V`). IDML 에는 있다. → **IDML 이 정본인 이유.**

### B. 플로우노트 — **이미 텍스트 DB 가 있다**

`콘텐츠 관리/내신대비/플로우노트DB/<학년>/<회차>.hwp(x)`.
구조가 매우 규칙적이다:

```
24-9 23번 Flow
<흐름 줄 …>          ← 그대로 FLOW NOTE
<빈칸 처리본 …>       ← 학생용
주제: …
주제문: …
```

키(`24-9 23번`)가 포켓북 지문번호(`240923`)와 1:1 이다. 파서 하나면 끝난다.
고3 은 `분석본 원고 작성 가이드.hwpx` 에 규칙이 문서화돼 있다(주제 120자 이하,
요약 120~180자, 플로우 4문장, 상세해설 `①.` …).

### C. 동반의어 — 하베스트 + 신규는 교재팀 원고 (2026-09-01 결정)

`콘텐츠 관리` 전체에 동반의어 DB 가 없다. 지금은 교재팀이 **완성 포켓북 .indd
안에 직접** 타이핑한다.

- **과거 지문** — 완성본 262권에서 하베스트한다. 카드 격자는 **3열 × 3행 = 9칸**
  고정이고 내용은 `표제어 뜻` / `= 유의어…` / `↔ 반의어…` 세 줄. 칸 색은 열이
  정한다(1열 크림 `#F8F6E2` · 2열 라벤더 `#ECE1EB` · 3열 하늘 `#D6E3EF`) —
  **내용이 아니라 자리가 색을 정하므로 DB 에는 색을 넣지 않는다.**
- **신규 지문** — 교재팀이 원고로 준다. 받는 그릇은 §3-E.

> **지금 이게 새는 것을 실측했다.** 명일2 포켓북(동아박3과 외) 동반의어 면
> **26면 중 12면이 카드 9칸 전부 비어 있고, 플로우노트도 같은 12면이 비었다.**
> 주제/요약문이 영어로 들어간 면도 있다. 사람이 채우는 자리라서 새는 것이고,
> 조판이 이걸 못 잡는 이유는 **비어 있어도 조판은 성공하기 때문**이다.
> DB + G-P2 게이트는 정확히 이 사고를 막는다.

### D. 삽화·암기테스트·주제요약 — 이미 있다

- 삽화 949개 jpg/png. **웹에 그대로 쓸 수 있다**(.ai 변환 불필요).
  캡션은 이미지 안에 구워져 있다.
- 암기테스트: 리뷰테스트 해설지 .docx → 기존 `parser.py` 가 이미 판다.
- 주제/요약문: 분석본 + 플로우노트DB 양쪽에 있다(교차검증 가능).

### E. 신규 지문 원고를 어떻게 받을까 — **플로우노트 원고에 블록 하나만 더**

교재팀은 이미 플로우노트를 `.hwp(x)` 로 쓰고 있고, **그 안에 키·주제·주제문이
이미 들어 있다.** 실제 블록(`플로우노트DB/고2/2409.hwpx`, 24-9 21번):

```
24-9 21번 Flow                     ← 키. 이미 있다
정보화시대 – 목표 = 오류 방지, 반복 가능성 X
[반대로] 목표 = 창의성, 속도, 그리고 명민함
…                                  ← 흐름 줄. 이미 있다
정보화시대 – 목표 = 오류 방지, _____________ X
…                                  ← 빈칸 처리본. 이미 있다(포켓북은 안 쓴다)
주제: 현대 기업에서의 혁신과 창의성의 중요성                ← 이미 있다
주제문: 정보화 시대의 기업들은 …                          ← 이미 있다
```

→ **교재팀이 새로 쓸 것은 동반의어 블록 하나뿐이다.** 양식도 새로 만들지 않는다.

```
동반의어                            ← 이 줄만 추가하고
expensive 비싼 = costly ↔ cheap, inexpensive, affordable
collapse 폭락 = crash, fall, breakdown ↔ rise, boom, flourish
…                                  ← 한 줄 = 카드 한 장, 위에서부터 좌→우, 최대 9줄
```

- 표제어와 뜻은 **첫 한글이 나오는 자리**로 가른다(`depend on ~ ~에 달려 있다`
  같은 구도 안전하다). 구분 기호를 새로 만들지 않는다.
- 카드 격자는 3열×3행 9칸이고 실측 분포가 3~9장으로 제각각이니 **6장 강제는 하지
  않고 0장을 막는다**(G-P2).
- 칸 색은 열이 정한다 — 원고에 색을 쓰지 않는다.

> ⚠ **`=` 를 전역 구분자로 쓰면 안 된다.** 플로우 줄 자체에 `=` 가 흔하다
>   (`목표 = 오류 방지`, `(=일관성 X, 빠르게 변화)`). `동반의어` **블록 헤더로
>   먼저 가른 뒤**에만 `=`·`↔` 를 읽는다.

**키가 없는 지문**(학교별 외부지문·교과서 본문)은 회차 키가 없다. 지금 분석본
파일명·헤더에 쓰는 표기를 그대로 쓴다 — `명일2 4과 본문2`, `외부지문 01`,
`p86-Gateway`. 파서는 형식을 강요하지 않고 지문에 붙여 보되, **안 붙은 블록은
조용히 버리지 않고 목록으로 보고**한다([[feedback_parser_structural_not_pattern]]).
업로드 즉시 `지문 N개 중 M개 매칭 / 미매칭 / 빈 항목` 을 돌려준다.

#### 최종형 — 통합웹 '포켓북 원고' 화면

지금 통합웹(`templates/typeset_pocketbook.html`)은 **조판 실행 화면**이다.
폴더를 고르고 돌리면 .indd 가 나온다. 여기에 **원고 입력 화면**을 하나 더 붙인다.

```
┌ 상일2 26-2-중간 · 지문 24개 ───────────────────────────────┐
│ ✓ 250923  ✓ 250924  ● 250925 ← 지금 편집  ○ 미래엔4과-본문1 │
├──────────────────────┬───────────────────────────────────┤
│ (읽기 전용)          │ 플로우 ① ______________________   │
│ 지문 원문 + 번역     │        ② ______________________   │
│ 삽화 미리보기        │ 주제 ______  요약 ______          │
│                      │ 동반의어  [expensive][비싼]        │
│                      │   = [costly] ↔ [cheap, …]         │
│                      │   … 9칸                            │
└──────────────────────┴───────────────────────────────────┘
                                    [저장] → corpus 에 바로 기록
```

hwpx 를 거치지 않고 **DB 에 바로** 쓰는 것이 요점이다. 얻는 것 셋:

1. 지문을 **클릭해서 들어가므로 키가 어긋날 수 없다**(hwpx 는 키를 손으로 쓴다).
2. 교재팀이 지금 InDesign 에서 하던 것 — 지문을 보면서 단어를 고른다 — 을
   그대로 한다. 빈 문서에 쓰라고 하는 것보다 품질이 유지된다.
3. 게이트가 **입력 시점에** 걸린다. 지금은 조판까지 가서야 빈 것을 아는데,
   그게 §3-C 의 12면 사고가 납품까지 간 이유다.

순서는 **hwpx 양식 먼저, 화면은 P5 이후**. 화면이 없다고 전환이 막히면 안 된다.

| 아래 주석 기준선 | 84.6pt | 84.7 (0.1pt) ✓ |
| 1~3행 행바꿈 | — | **일치**(자간 −0.022em 보정 후) |
| 형광펜·강조색·밑줄 | — | 재현 |
| 삽화·번역·칩·띠·폴리오 | — | 재현 |

핵심 기법:

```html
<mark style="--hl:#FDF598">          <!-- 형광펜은 낱말이 아니라 연속 구간 -->
  <span class="w blue">conceivable
    <i class="up">conceivably (X)</i>
    <i class="dn">C</i>
  </span> …
</mark>
```
`.w{position:relative;display:inline-block}` + `i{position:absolute;left:50%}`.
**줄바꿈은 브라우저가 하고 주석은 낱말을 따라간다** — 원고가 길어져도 사람이
손볼 곳이 없다. 이것이 InDesign 앵커 프레임과 결정적으로 다른 점이다.

> 발견한 함정
> - 형광펜을 낱말마다 칠하면 어절 사이가 비어 **줄무늬**가 된다 → 연속 구간을
>   `<mark>` 로 묶는다.
> - 주석 오프셋을 baseline 기준으로 쓰려면 인라인 박스의 half-leading 을
>   거쳐야 해서 서체 의존이다 → **실측 1회 보정 상수**로 잡는다(기존 계열과 동일).
> - 첫 행 기준선이 InDesign('어센트' 기준)과 7.7pt 다르다 → 블록 top 보정.

### 실제로 세운 것

- **입력 세 갈래** — 코퍼스(school/term) · 분석본 IDML(신규 지문) · 교재팀
  원고 hwpx(플로우노트·동반의어). 원고가 어느 지문에도 안 붙으면 **목록으로**
  알린다(조용히 버리지 않는다).
- **실측 후 맞춤** — 지문이 길면 행간(24→14pt)부터, 그다음 글자(9→7.5pt).
  원본 InDesign `resolveOverflow` 와 같은 순서다. 플로우노트·주제요약·암기TEST
  도 같은 방식으로 잰다. **행간을 줄여도 첫 기준선과 주석 위치는 안 변한다**
  (기준선이 상자 바닥에서 L/2−3.925pt 라 L 이 상쇄된다).
- **도련 3mm** — MediaBox 154×216 / TrimBox 148×210. 판면 좌표는 재단선 기준
  그대로 두고 `.trim` 을 3mm 민다. 띠만 도련까지 뺀다.
- **표지** — `.ai` 가 이미 154×216(도련 포함) PDF 라 그대로 붙는다. 디자인이
  바뀌면 config 경로만 갈아 끼운다.

### 이 밤에 밟은 함정 (전부 코드 주석에 남겼다)

1. **구문분석 주석은 앵커 프레임이 아니라 루비였다.** 위=`AboveRight`(범위
   오버라이드) · 아래=`BelowLeft`(스타일 기본). 어느 **글자**에 붙었는지까지 남아
   PDF 하베스트보다 훨씬 정확하다.
2. **`.w` 에 line-height 를 다시 주면** 낱말마다 24pt 로 되돌아가 행간 축소가
   통째로 무효가 된다.
3. **`calc(24mm + -7.7pt)` 는 잘못된 CSS** — 속성이 조용히 버려지고 첫 기준선이
   8.5pt 어긋난다. 부호를 연산자로 써야 한다.
4. **암기테스트 스토리는 스레드**라 스토리 단위로 집으면 책 전체가 한 면에
   들어간다. 지문 첫머리(알파벳만 남긴 지문)로 잘라야 한다.
5. **암기테스트 본문에는 문자 스타일이 없다**(런 2개에 1,761자). 위첨자·주황은
   로컬 서식이라 IDML 런에 안 남는다 → `숫자[낱말]` **표기에서 되만든다**.
   그래야 문제면과 정답면이 반드시 달라진다.
6. **짤지문 스프레드의 둘째 지문이 조용히 사라지고 있었다**(광문1 70→50).
   지문번호 배지 개수로 가른다.
7. **지문번호에 학년이 없어 고1·고2가 43건 겹친다.** 키에 학년·학기를 넣는다.
8. **`osascript -e` 는 AppleEvent 60초 타임아웃** — 262권 배치가 109번째에서
   20분 멎었다. `.applescript` 파일 + `with timeout`, 무응답이면 InDesign 자동
   재시작(복구 폴더도 비운다), 두 번 죽은 파일은 영구 스킵.
9. **작업 사본을 `/private/tmp` 에 두면 안 된다.** InDesign 을 강제 종료했다가
   다시 띄우면 그 경로의 문서를 전부 "손상되었습니다(오류 4)" 로 거부한다.
   같은 파일이 `~/Documents` 아래에서는 정상으로 열린다.
10. **G-P7 은 글자 개수로 본다.** 루비 낱말이 inline-block 이라 PDF 추출 순서가
    뒤섞이고 인접 span 이 붙어 낱말이 엉킨다 — 순서로 대조하면 거짓 결함이
    쏟아진다.

### 밤새 더 나온 함정

11. **암기 TEST 원고는 docx 가 아니다.** `리테 모음` 363개 중 docx 는 12개뿐이고,
    PDF 정답지에는 `숫자[낱말]` 표기가 아예 없다 — **정답 낱말만 굵게** 찍혀 있고
    그 굵기가 곧 표시다. 정답지인지 `(앞글자)` 판인지도 굵은 낱말 평균 길이로
    가른다(6~8자 vs 1자, 363개가 2.5자 경계에서 깨끗이 갈렸다).
12. **지문 차례가 통째로 뒤섞이고 있었다** — 쪽 번호를 글자로 정렬해
    `"10-11" < "12-13" < "2-3"`. 교과서와 모의고사가 섞여 나왔다.
13. **같은 분석본의 판본이 둘이면 지문이 두 배로 실린다**(`…_내지` + `…_내지 제목수정`).
    조판은 성공하고 쪽수만 늘어 눈으로 잡기 전까지 모른다.
14. **분석본 주제/요약 경계는 세대마다 다르다** — 구세대는 `주제/요약:상단제목`
    빈 run, 신세대는 줄바꿈(453/532면에 구분자가 아예 없다). 빈 구분자가 하나라도
    있으면 그것이 경계다.
15. **1,850자를 넘는 지문은 상자 밖으로 밀려 글자가 사라진다** → 문단 경계에서
    나눈다. 완성본도 `본문7-1/7-2` 로 나눠 싣는다.
16. **루비가 낱말 일부에 걸리면 낱말 한가운데서 줄이 바뀐다**(`everyon / e`) —
    inline-block 경계이기 때문. 낱말 덩이를 `nowrap` 으로 묶는다.

17. **마스터 글자(B/D/F/L)만 보고 암기테스트 면으로 넘기면 지문이 통째로 사라진다.**
    마스터 이름은 책마다 달라서 지문면을 B 마스터에 얹은 책이 있다(광문2 36→79,
    한영2 14→54). 같은 결함이 `read_sequence`·`read_book`·`corpus.py` **세 곳에
    따로** 있었다. ⚠ 계열 게이트로는 절대 못 잡는다 — 지문이 빠지면 면 수도 같이
    줄어 G-P1 이 통과한다. 그래서 원본 IDML 에서 지문 스프레드를 파서와 무관하게
    세는 **G-P9** 를 뒀다.
18. **자동화가 남의 InDesign 문서를 닫을 뻔했다.** 내보내기 정리 코드가 열린
    문서를 **전부** 닫았다 — 다른 세션이 열어 둔 워크북이 열려 있었다.
    경로가 우리 작업 사본과 같은 것만 닫고, 남의 문서가 있으면 **시작을 거부**한다.

## 10. "행바꿈을 맞춘다"가 무슨 말이었나

**구문분석 영어 지문 본문 한 곳** 얘기다. 같은 글·같은 폭인데 **한 줄에 들어가는
낱말 수가 InDesign 과 브라우저가 다를 수 있다** — InDesign 은 양끝정렬에서
어간을 줄이고 글자 폭까지 미세하게 늘렸다 줄였다 하는데(글리프 스케일),
브라우저는 어간만 늘린다.

파일럿 실물:

| | 원본 | 파일럿(자간 보정 전) | 자간 −0.022em |
|---|---|---|---|
| 1행 끝 | … expensive **and** | … expensive | … expensive **and** ✓ |
| 2행 끝 | … to space, **you might** | … to space, | … to space, **you might** ✓ |
| 3행 끝 | … above the **atmosphere.** | … them above | … above **the** ✗ |

상수 하나로 1~3행이 맞았고 문단 마지막 줄에서 어긋난다.

**중요한 것 셋.**

1. 이건 **책마다 손보는 일이 아니다.** 계열 CSS 상수 하나(자간)이고 전 권에
   같이 걸린다. "사람이 손댄다"와 무관하다.
2. **하베스트 검증 게이트(G-P7)는 영향을 안 받는다.** 글자 해시로 비교하므로
   줄이 어디서 나뉘든 통과·불통과가 달라지지 않는다.
3. 그래서 **신간에는 신경 쓸 필요가 없다.** 옛 줄 나눔을 아무도 모른다.
   맞춰야 하는 경우는 딱 하나 — **이미 납품한 책을 그대로 증쇄**할 때다.
   그때는 옛 PDF 를 그대로 쓰면 되고, 엔진으로 다시 뽑을 이유가 없다.

다만 줄 수가 늘면 지문이 삽화·번역 영역을 침범할 수 있다 → **G-P6(오버플로우 0)**
가 잡는다. 사람이 눈으로 볼 일이 아니다.

## 11. 남은 확인거리


1. 제본 방식 — 안쪽 여백을 키워야 하는지는 실물 한 권 보고 정한다.
2. 신규 지문 원고 양식(§3-E)을 교재팀에 언제 내릴지. **첫 비블리오 조판보다
   먼저**여야 한다.
3. 표지·마지막 면은 **PDF 로 받기로 확정**됐고 디자인이 바뀔 예정이다 →
   지금은 기존 것으로 세우고, 새 디자인이 나오면 config 경로만 갈아 끼운다.
