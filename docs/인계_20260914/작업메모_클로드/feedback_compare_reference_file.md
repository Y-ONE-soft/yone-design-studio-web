포켓북을 새 출판사로 조판할 때, **결과를 사용자가 검수하기 전에 기준 완성본과 직접 비교해 스타일 차이를 전부 잡아라.** 사용자가 "왜 할 때마다 매번 지적해야 돼"라고 강하게 불만(2026-06-15). 특히 **어휘 표**가 매번 어긋남.

**Why:** 새 출판사 파일은 직전 출판사(예: 동아/능률김 계열) 완성본의 복사본으로 시작하는데, 그 템플릿이 정작 기준이 되는 완성본(예: 천재소)과 스타일이 다를 수 있다. 빌더가 그 차이를 그대로 답습하거나 더 망가뜨려서, 매 출판사마다 같은 지적이 반복된다.

**How to apply:**
- 사용자가 검수용으로 **기준 완성본을 InDesign에 열어둔다**. "기존 파일이랑 비교" = 그 열린 파일. ⚠️**어떤 파일인지 매번 확인**(중간에 바뀜: 처음 천재소→나중 능률김으로 교체됨. 추정 금지).
- ⚠️ 문서 식별 함정(여러 번 당함): 빌더는 `nm.indexOf("3,4")`로 잡는데 **기준 파일도 "3,4"**라 충돌. 파일명 한글은 **NFD**라 `indexOf("미래엔")` 실패. 푸터 findGrep "중3"/"중2"도 작업본에 두 문자열 혼재해 오판. → **페이지수로 확실히 구분**(미래엔121·능률김133·백업119 등). 빌더 "3,4"매칭이 첫 매칭 문서를 잡으니 **기준 파일이 목록 앞이면 기준 파일을 수정해버림**→위험할 땐 페이지수 지정한 직접 스크립트로 작업, 기준 파일 절대 수정 금지.
- ⚠️ **표 종류별로 스타일이 다름**: 어휘 단어표=테두리 없음, 영영풀이=전 행 테두리. 일괄 처리하면 한쪽이 망가짐. probe로 표별 확인 후 개별 적용.
- 비교 기준 3종: ①현재 작업본 ②`_조판작업전_백업`(빌더 돌리기 전 = 복사 직후 원본 스타일) ③기준 완성본(천재소). 백업 vs 현재 = 내 빌더가 바꾼 것. 현재 vs 기준 = 템플릿/디자인 차이.
- **어휘 표 필수 체크**(셀 속성 probe): 열너비(품사열 폭), 행 테두리(cell strokeWeight), 품사 셀 채움 여부. [[pocketbook-miraen-combined]]에 미래엔 사례 상세.
- 차이 발견 시 **현재 문서 직접 수정 + 빌더도 수정**(다음 출판사 재발 방지). 단독-overset/빈셀 등은 내용 확인 후 처리.
