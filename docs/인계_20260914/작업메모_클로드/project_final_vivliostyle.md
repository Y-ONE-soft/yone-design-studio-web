파이널 직전보충을 Vivliostyle 로 옮긴 계열 `final`(2026-09-01 신설). 기준 학교
광문2 26-1-기말이 완성본과 **쪽수 동일**(Vol1 40p · Vol2 62p, Vol2 는 면별 지문
배치 62/62 일치), 두 권 6.4초. 고1·고2·고3 다섯 학교 열 권 게이트 전부 통과.
설계·함정은 `docs/final_vivliostyle_전환계획.md` §8 과 `docs/vivliostyle_엔진.md`
"파이널(final)" 절. 오프라인 계약은 `tests/test_render_vivlio_final.py` 19건.

**병목의 본체는 렌더가 아니라 소스다.** 렌더는 Vivliostyle 이 없앴지만(오버플로우
7건 → 0건), 워크북 `.indd` 역수확은 계열 **바깥**의 일이다.

**B6 원고 직독 — 교체까지 완료.** `engines/final/manuscript.py`(원고 docx 직독) +
`manuscript_locate.py`(범위 토큰→폴더, 라벨 규칙) +
`scripts/final_manuscript_diff.py`(대조) + `scripts/final_manuscript_build.py`
(**원고 직독 content.json 빌더** — 스키마 같아 계열은 무수정). 계약 29건.
라벨 규칙 **173/174(99.4%)**, 원고 직독본 자기대조 61/61 글자까지 동일.
원고 파일 이름은 출처 불문 같고(`Step1 C1 문장배열.docx`, 고3 수특만
`3. 문장배열.docx`), 폴더는 **숫자와 낱말**로 찾는다(연도 묶음
`고1 23년(3,6,9,10,11월)/고1 23년 9월` 주의). **시험범위 = 섹션 합집합**
(어법·어휘·영작은 다른 출처라 한 곳에서 빠진 게 다른 곳에 산다) — 시트 재조회 불필요.
안 맞는 것이 곧 되수확 결함이었다 — **리딩파워 14강 문장배열 6지문 통째 누락**
(어법·영작엔 있다), 15강 Ex 두 지문씩 뭉침, 하이픈 잔재 42건,
**서술형영작 지문번호가 통째로 어긋남**(광문2 64블록 중 35개만 맞음 — 교과서
묶음과 리딩파워 19강 묶음이 자리를 바꿔 들어갔다. 고3도 48중 33).
⚠**"문장삽입만 원고 출처가 없다"는 내 오판이었다** — 하단 문제는 같은
`Step1 C1 문장배열.docx` 의 **표 안의 표**에 있다(깊이 1=항목, 깊이 2=주어진 문장).
겉 표만 읽던 리더 탓. 발문만 원고에 없어 유형(① 유무)으로 얹는다.
단 중첩까지 읽히면 arrange/writing/vocab 이 하단 항목을 상단 카드에 붙여
지문이 두 배로 길어진다 → 이 셋은 **깊이 0 만**. 대조 광문2 21/21·상일1 34/35·명일1 10/10.
하단 문제가 없는 출처(되수확 유지)=23년 9·11월 모의, 리딩파워 유형편(계열이 안 만듦),
고3(섹션 자체 없음), 외부지문, 딥러닝 4과.

**완성본이 정답이 아니다** — 납품본은 사분면을 넘친 지문의 뒷부분을 잘라
버렸다(리딩파워 15강 Ex02 항목 4개 소실). 넘침 정책(사용자 확정): **활자 크기는
책 전체에서 8.5pt 하나로 고정**하고 ①한두 줄 넘치면 **행간만** 조이고(하한 10%,
두 점 실측으로 정확히 푼다 — `H(L)=F+(H1−F)·L`) ②그보다 길면 **두 칸**
③한 단보다 길면 흘림. 전부 리포트에 남긴다. ⚠`html` 의 line-height 는 거기서
`--lead` 가 이미 풀려 내려오므로 **상자에서 다시 선언**해야 먹는다.

실측으로 굳힌 값: 자간 **−40/1000 em**(장평 모델은 잔차 6배), 단 **83.7mm** ·
단 사이 3.3mm, 빈칸 밑줄 = **정답 글자수 × 0.684em**, 전권 무채색(K 단색 인쇄).

쓰는 법: `python3 scripts/final_viv_book.py jobs/<job>` → 책 두 권 →
`bin/viv "<책>/Vol1" all`. 산출은 **Vol 폴더 안**(학교 폴더에는 인디자인 납품본이
같은 이름으로 있다 — 덮어쓰면 안 된다).
