포켓북(A5 148×210, 고등 지문형)을 Vivliostyle 로 옮기는 작업. 2026-09-01 분석·
파일럿 완료, 구현 전. 계획서 `yone-design-web/docs/vivliostyle_포켓북_전환계획.md`,
파일럿 `pilot/pocketbook/`(README 먼저).

**핵심 진단**: `run.jsx` 3,763줄에 flownote·동반의어를 채우는 코드가 **한 줄도
없다**. 신규 지문은 오른쪽 면이 빈 채로 나가고 사람이 채우며, 기존 지문은 그
손댄 결과를 완성본에서 스프레드째 복제해 온다. 즉 **'완성본에서 가져오기'는
게으름이 아니라 유일한 저장소를 읽는 행위**였다. 그래서 전환의 본체는 CSS 가
아니라 **지문 DB(passage corpus)** 다. DB 가 생기면 코드 조판은 몇 번 돌려도
같은 지면을 내므로 재사용을 위해 복제할 이유 자체가 사라진다.

**데이터 출처 전수**: 구문분석 지문·번역·주제요약=분석본(.indd) · 플로우노트=
`콘텐츠 관리/내신대비/플로우노트DB/<학년>/<회차>.hwp(x)`(`24-9 23번 Flow`+빈칸본+
주제/주제문, 키가 지문번호와 1:1) · 삽화=`포켓북 삽화정리` 949개 jpg(캡션이 그림에
구워져 있어 변환 불필요) · 암기테스트=리뷰테스트 해설지 docx(기존 parser.py) ·
**동반의어=출처 없음** → 결정(2026-09-01): 완성본 하베스트 + 신규는 교재팀이
**플로우노트와 같은 hwpx 그릇**에 얹어 준다(지문1개=1블록, `표제어 뜻 = 유의어 ↔ 반의어`
한 줄=카드 한 장, 최대 9줄). **플로우노트 hwpx 에 키·주제·주제문이 이미 있어서
교재팀이 새로 쓸 것은 `동반의어` 블록 하나뿐**(2409.hwpx 실측). ⚠`=` 를 전역
구분자로 쓰지 말 것 — 플로우 줄에 `목표 = 오류 방지` 처럼 흔하다. 블록 헤더로
먼저 가른 뒤에만 `=`·`↔` 를 읽고, 표제어/뜻은 **첫 한글 자리**로 가른다.
표지 1P·마지막P 는 **PDF 로 받기로 확정**(디자인 교체 예정 → config 경로 한 줄로
갈리게, 파일명 코드에 박지 말 것). 지금 교재팀은 완성 .indd 에 직접 타이핑 중 —
**비블리오로 돌리면 완성 .indd 가 안 나오므로 새 입력 그릇이 첫 조판보다 먼저** 서야 한다.
카드 격자 3열×3행=9칸, 색은 열이 정한다(내용 아님 → DB 에 색 넣지 말 것).

**IDML 이 정본**: .indd→IDML(zip+XML)에 `CharacterStyleRange` 색·밑줄 오버라이드와
앵커 프레임의 `AnchoredObjectSetting`(어느 **글자**에 붙었는지)이 그대로 있다.
GDrive 완성 포켓북 262 indd 를 한 번 배치 내보내면 백카탈로그가 흡수된다
(InDesign 은 '내보내기' 한 줄만, 로직 없음).

**완성·검증 완료(2026-09-01 새벽)**: 조판 준비 **23권**(26-2-중간 20개 학교 +
26-1-기말 3권) 전권 검수 **23/23 통과**, **회귀 183권 재조판 12,708면 결함 0**,
코퍼스 **1,352지문**(184권), 26-2-중간 분석본
IDML 67권 전부. 완성본 IDML 225/263(남은 38개는 옛 아카이브).

**엔진 완성(2026-09-01 밤)**: `core/render_vivlio/series/pocketbook/`.
`bash bin/viv "조판/교재/포켓북/26-1-기말/세종1" all` → 47지문 96면 약 40초, 게이트 통과.
입력 세 갈래 = 코퍼스(`options.school`/`term`) · 분석본 IDML(`analysis`, 신규 지문) ·
교재팀 원고 hwpx(`manuscript`). 인계는 `조판/교재/포켓북/HANDOFF.md`, 양식 샘플은
`_원고양식/`. 코퍼스 `_corpus/` 1,111지문(동반의어 0개는 **1지문**뿐), 수확 도구는
`tools/pocket_harvest/`(idml·analysis·manuscript·corpus·export_idml·regress).

**구문분석 주석은 앵커 프레임이 아니라 루비**였다 — 위=범위 오버라이드
`RubyPosition=AboveRight`, 아래=스타일 기본 `BelowLeft`. 어느 **글자**에 붙었는지까지
IDML 에 남아서 이식이 정확하다.

**맞춤은 실측 뒤 행간 먼저, 그다음 글자**(24→14pt, 9→7.5pt — 원본 resolveOverflow 와
같은 순서). 행간을 줄여도 첫 기준선·주석 위치는 안 변한다(기준선이 상자 바닥에서
L/2−3.925pt 라 L 이 상쇄).

**G-P7(원문 대조)은 글자 개수로 본다** — 루비 낱말이 inline-block 이라 PDF 추출
순서가 뒤섞이고 인접 span 이 붙어 낱말이 엉킨다. 63지문 전수 누락 0.

**파일럿 실측(재현 확인)**: 완성 PDF 한 면 → JSON(줄10·낱말137·주석50·미부착0)
→ HTML/CSS → Vivliostyle 4초. 본문 기준선 76/100/124pt·위 주석 66.6·아래 84.7 이
원본과 일치, 자간 −0.022em 에서 행바꿈까지 일치. 형광펜은 **굵기 9pt 밑줄
스트로크**(#FDF598)이고 강조는 글자색(#224E8E/#D2232A).

**도련 사방 3mm 확정**(고품질 인쇄가 최종물). ⚠ **현재 납품 PDF 는 도련이 0** —
MediaBox·TrimBox 가 전부 148×210 이고 띠가 재단선에서 잘린다(지금도 결함).
파일럿을 154×216 / TrimBox 148×210 으로 바꿔 검증했다: 판면 좌표는 재단선 기준
그대로 두고 `.trim` 을 3mm 밀고, 띠만 `.pg`(154mm) 기준으로 빼야 흰 줄이 안 생긴다.

**행바꿈은 맞추지 않기로 했다** — InDesign 은 양끝정렬에서 글리프 폭까지 조정하고
브라우저는 어간만 늘려서 줄 나눔이 달라진다. 계열 상수 1개(자간)이고 책마다 손보는
일이 아니며, 하베스트 검증 게이트는 **글자 해시**라 무관. 증쇄는 옛 PDF 를 쓰면 된다.

**실측 증거**: 명일2 포켓북 동반의어 면 26개 중 **12개가 카드 9칸 전부 비고
플로우노트도 같은 12면이 비었다**(주제/요약이 영어인 면도 있음). 사람이 채우는
자리라 새고, **비어 있어도 조판은 성공**하기 때문에 안 잡힌다 → G-P2 게이트의 근거.

⚠ 밤새 밟은 함정 (전부 조용히 틀리는 종류): **`.w` 에 line-height 재지정**→행간
축소 무효 · **`calc(24mm + -7.7pt)`** 는 잘못된 CSS 라 속성이 통째로 버려짐 ·
**암기테스트 스토리는 스레드**라 스토리 단위로 집으면 책 전체가 한 면에 ·
**암기테스트 본문엔 문자 스타일이 없어**(런 2개/1761자) `숫자[낱말]` 표기에서
서식을 되만들어야 문제면·정답면이 달라짐 · **짤지문 둘째 지문이 조용히 유실**
(배지 개수로 가름) · 지문번호에 학년이 없어 고1·고2 43건 충돌 ·
**`osascript -e` 는 AppleEvent 60초 타임아웃**(→.applescript+with timeout, 무응답 시
InDesign 자동 재시작+복구폴더 비움) · **작업 사본을 `/private/tmp` 에 두면**
InDesign 재시작 후 전부 "손상(오류 4)" 로 거부(→`~/Documents` 아래로).

⚠ PDF 하베스트 함정 ①주석 런을 **글자 간격으로 끊지 마라** — 다른 앵커 프레임의 `S`와 `V`가
0.3pt 만 떨어져 있다. PyMuPDF **span 경계**로 끊는다. ②형광펜을 낱말마다 칠하면
어절 사이가 비어 줄무늬 → 연속 구간을 `<mark>` 로 묶는다. ③낱말 **안의** 글자
앵커는 PDF 에 없다 → PDF 하베스트는 백카탈로그용, 정본은 IDML.

**밤새 더 나온 것**: ①**암기 TEST 원고는 docx 가 아니다** — `리테 모음` 363개 중
docx 12개뿐이고 PDF 정답지에는 `숫자[낱말]` 표기가 없다. **정답 낱말만 굵게** 찍혀
있고 그 굵기가 곧 표시다(`series/pocketbook/memtest.py`). 정답지 판정도 굵은 낱말
평균 길이(정답지 6~8자 vs 앞글자 1자)로 가른다. G-P8 = 문제면·정답면은 글자가 같으니
**쓰인 색**으로 검사. ②**쪽 번호를 글자로 정렬해 지문 차례가 통째로 뒤섞이고 있었다**
(`"10-11" < "12-13" < "2-3"`). ③**같은 분석본의 판본이 둘이면 지문이 두 배로 실린다**
(`분석본01…_내지` + `…_내지 제목수정`) — 조판은 성공하고 쪽수만 는다. ④분석본은
회차를 **책 머리**에, 번호를 지문에 나눠 적는다 → 합쳐 `260620` 을 만들어야 삽화가
붙고, 배지도 완성본 표기(`1과 01`·`11강 02`)로 맞춰야 한다. ⑤1,850자 넘는 지문은
상자 밖으로 밀려 글자가 사라진다 → 문단 경계에서 나눈다(`longsplit.py`).
⑩**자동화가 남의 InDesign 문서를 닫을 뻔했다** — `export_idml._cleanup_docs` 가
열린 문서를 **전부** 닫았고, 다른 세션이 열어 둔 워크북이 열려 있었다. 경로가 우리
작업 사본(`work.indd`)과 같은 것만 닫고, 남의 문서가 있으면 **배치 시작을 거부**한다.
⑨**마스터 글자(B/D/F/L)만 보고 암기테스트 면으로 넘기면 지문이 통째로 사라진다**
— 마스터 이름은 책마다 달라서 지문면을 B 마스터에 얹은 책이 있다(광문2 36→79,
한영2 14→54, 고2 올포14~16강 0→44). **그 면에 지문이 있으면 지문면**으로 내용 판정.
같은 결함이 `read_sequence`·`read_book`·`corpus.py` **세 곳에 따로** 있었다.
⚠ 계열 게이트로는 절대 못 잡는다 — 지문이 빠지면 면 수도 같이 줄어 G-P1 이 통과한다.
그래서 `tools/pocket_harvest/regress.py` 가 원본 IDML 에서 '긴 영어 본문이 있는
스프레드' 수를 **독립적으로** 세는 R1 게이트를 둔다.
⑦**검수 계측 캐시 열쇠에 `id(문서)` 를 쓰면 안 된다** — 앞 책 문서가 닫히면 그 주소를
다음 문서에 다시 줘서 **멀쩡한 책이 "글자 유실 24지문"으로 떨어진다**(세종1). 파일
경로로 잡고 검수 시작 때 비운다. (캐시 자체는 필요하다 — 없으면 그림 많은 책 검수가
18분, 있으면 2.5초.) ⑧**병합된 지문이 학교 선택에서 통째로 빠진다** — 코퍼스는 원문이
같으면 하나로 합치는데(402건) `school`/`term` 은 먼저 만난 책 것만 남는다. `books`/
`where` 의 **모든 책 경로**로도 봐야 한다(세종1 31→52). ⑥분석본 주제/요약 경계는 **세대마다 다르다** — 구세대는 `주제/요약:상단제목` 빈 run,
신세대는 줄바꿈. 빈 구분자가 하나라도 있으면 그것이 경계다.

**수록 범위 = Y.OS 시험범위(2026-09-02 정정)**: 카드에 두었던 `기존 지문도 넣기`
체크박스를 없앴다 — 범위는 고르는 게 아니라 **정해져 있다**(사용자 지적). 범위는
`engines/final/scope_source.py`(파이널 공용)로 읽고, 그 범위 지문을 분석본+코퍼스에서
모아 전부 싣는다. `core/render_vivlio/series/pocketbook/scope.py` 신설. 예전엔 코퍼스가
딸려 오는 걸 막으려고 `options.term` 을 일부러 비워 둔 책이 22권이었는데 그 회피가 없어짐
(학기는 책 폴더에서 되찾는다).
⚠ 23권 A/B 로 잡은 함정 다섯: ①**범위로 지문을 빼면 안 된다** — 범위 밖을 버리게 했더니
한영1 이 72→12. 분석본은 그 시험용 원고이고 시험범위 표가 덜 찬 것일 뿐이다. 범위는
**넣기와 차례**에만 쓴다. ②**남의 학교에서 끌어올 수 있는 건 모의고사뿐** — `260620` 은
회차·번호로 하나뿐이지만 `13강 01` 은 광문1 25-2-기말과 26-1-기말에 각각 있고 **다른 글**,
강동2 `1과 01` 은 1학기 영어Ⅰ. ③**머리말(chapter)은 묶음 첫 지문에만 있다** —
`Exercise 02`·`MR4`·`22번` 만 남아 헛경보(서울여고1·명일2·한영2). 라벨은 안 건드리고
범위 읽을 때만 이어받는다. ④**한 지문이 두 이름을 가진다** — 마더텅 11강 2번 =
고1 23년 11월 33번(`label` 은 기출, `chapter` 는 강). pno 를 먼저 잡으면 강을 못 본다 →
토큰을 **짝 목록**으로 돌려준다. ⑤**겹친 지문이 실제로 인쇄되고 있었다** — 창현1 8지문
(분석본 원본+학교본, 글자까지 동일)·한영1 20지문. 라벨 말고 **글 앞 300자**로 판정하고
바탕은 분석본 것을 두고 **빈 곳만** 코퍼스로 채운다(플로우노트·동반의어). G-P9 는 합친
수를 되돌려 세야 한다(안 그러면 79%로 "유실" 오판).
**G-P10 신설**: 범위에 있는데 없는 지문. 단원이 통째로 비면 fail, 번호만 어긋나면 warn.
⚠ 이것 없이는 아무도 못 잡는다 — 지문이 빠지면 면·글자도 같이 줄어 G-P1·G-P7 이 통과하고
G-P9 는 분석본 기준이라 분석본에 없는 것은 못 본다. 실제 검출: 한영1·한영2 교과서 1과
분석본 없음, 상일1 26년 9월 없음, 이의2 수특 11·12강 없음, 광문1 분석본04 는 **파일 이름이
'올포6강'인데 안에 6강 지문이 없다**.
