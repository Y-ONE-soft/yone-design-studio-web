워크북/교재 원고 파서(engines/workbook/parser.py 등)는 단락의 역할(지문번호·본문·선지·원고정보값·답지)을 **형식(정규식 화이트리스트)으로 매칭하면 안 되고, 구조/의미로 인식**해야 한다.

**Why:** 형식 매칭은 글자 하나만 바뀌어도 깨진다. 사용자 실증 예:
- 지문번호가 `1. L1-본문1`(기존)에서 `1. PROJECT 2-본문1`(YBM김)으로 바뀌자 `_RE_HEADER_NUM`이 못 잡아 → 헤더(책제목/Q/READING) 제거 실패 + 지문번호 인식 실패 + 본문 스타일 어긋남.
- `정답`→`정답지`, `[정답]`→`<<해설>>`로 바뀌면 답지 인식 실패 → 답지를 본문으로 조판.
- 거기에 정규식을 또 추가(`PROJECT` 패턴 등)하는 건 같은 땜질의 반복일 뿐. 사용자가 강하게 거부함: "글자 하나 바뀐다고 로직이 인식 안 되면 어쩌냐… 이런 방식은 한계가 너무 많아서 안 된다."

**How to apply:** 원고 구조는 어느 교재나 동일하다(지문번호 → 본문 → 선지 → 답지). "본문"을 형식-불변 앵커(긴 영어 지문)로 먼저 잡고, 나머지를 상대 위치/특징으로 분류:
- 본문 = 긴 영어 단락(앵커)
- 지문번호 = 본문 바로 앞의 짧은 줄(앞에 숫자·기호·단원명 뭐가 오든)
- 원고정보/헤더 = 첫 본문 이전 전부(책제목·발문·섹션라벨 일괄 제거)
- 선지 = ①②③/ⓐⓑ 시작
- 답지 = 정답/해설의 *의미*(정답/정답지/[정답]/<<해설>> 다 포함)

파서 핵심을 바꾸는 작업이므로 **회귀 안전 필수**: 기존 교재 원고들로 현재 파서 출력 스냅샷(기준선) → 재작성 → 기존 교재 동일 + 새 형식도 되는지 대조. 무작정 갈아엎으면 잘 되던 수십 교재가 깨진다.
