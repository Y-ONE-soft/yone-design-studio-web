2026-08-25 (능률(민) SL1). 사용자: "아니 이걸 내가 왜 하나씩 알려줘야 되냐고.
**기존 파일을 보고 거기서 어떻게 들어갔는지를 보고 거기에 맞추면 된다니까?**
이것도 벌써 몇 번째 알려주냐?"

**Why**: 조판 관행의 정본은 사양서도 사용자의 구두 지시도 아니라 **이전
완성본**이다. 무엇을 인쇄하고 무엇을 빼는지, 어떤 스타일을 쓰는지 전부
거기 있다. 항목별로 확인 질문을 던지는 것은 사용자에게 검수를 떠넘기는
것이고, 같은 지적을 반복하게 만든다.

**How to apply**:
1. 결과물 판단이 필요하면 **먼저 같은 계열 완성본을 찾아 열어 대조**한다
   (같은 과목·출판사의 다른 과, 같은 계열 우선 SL1↔SL2). 질문은 대조로도
   못 가르는 것만.
2. 대조는 내용이 아니라 **구조**로 — 단락스타일 인벤토리 / 무스타일
   ([기본 단락]) 줄의 형태 / 지시문 집합. 과가 다르면 내용은 당연히 다르다.
3. 완성본은 **여러 권**을 보고 교집합만 신뢰한다(한 권 사정 = 오탐).
4. 구현 완료(교과서 워크북 v2): `core/inspect/reference_diff.py` +
   `TextbookWorkbookV2Engine._reference_findings` → verify 단계에서 자동
   실행, 결과는 `🔎 [기준대조]` 경고. 완성본 덤프는 mtime 캐시.
   **다른 계열 엔진에도 같은 훅(`_reference_findings`)만 구현하면 붙는다** —
   base `WorkbookV2Engine.verify`가 훅이 있으면 호출한다.

이 건에서 대조로 드러난 사실: 사용자가 지적한 3종(파이프 머리글/원고 발문/
기입란)은 완성본에 **전부 없었다** — 물어볼 필요가 없던 것들이다. 반대로
'어법 안내문'은 완성본에 **있었고**(템플릿 상주), 그건 사용자가 명시적으로
삭제를 지시한 예외다. 관련: [[feedback_compare_reference_file]],
[[workbook_v2_manuscript_noise_gate]], [[feedback_typeset_compare_real_exam_details]]

**2026-09-03 후속 (워크북 A2 발문, [[workbook_v2_w82_step3_title_named]]
W86/W87)**: 완성본 없이 **추측으로 고쳤다가**("섹션 머리 띠에 프레임이
없으니 복제해 한 번만 넣자") 사용자가 다른 완성본 화면을 다시 보여주며
반려당함 — 실제로는 유닛마다 반복되는 문구였다. 정정은 사용자가 "지금
인디자인에 열어놨어"라고 알려준 그 파일을 `doc.findText()`로 검색해
**단락 스타일 이름을 직접 읽어서** 확정했다(추측 0). **완성본이 로컬에 없어도
사용자가 이미 인디자인에 열어둔 파일이 있으면 그게 최선의 기준본** —
스크린샷 대조보다 `findText`로 스타일 이름을 읽는 게 훨씬 정확하고 빠르다.
단, 열려 있는 파일은 읽기만(app.open() 재오픈 시도 금지 — GDrive 원본을
직접 열려다 대화상자 30486에 걸려 InDesign 전체가 잠깐 멎은 사고 있음,
사용자의 실제 미저장 작업까지 위험할 뻔했다).
