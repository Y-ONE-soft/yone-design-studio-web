파이널 직전보충의 **시험범위 정본을 Y.OS `/work/exam`** 으로 옮기는 중
(2026-09-01 착수). 코드: `engines/final/scope_source.py`.

**워크북 파일 이름은 범위의 대역이었다.** 괄호(`…(리딩파워12강,14강)…`)를 읽은 건
워크북이 필요해서가 아니라 범위를 적어 둔 곳이 거기뿐이어서다. 새는 데 실증:
- **명일1** `외부지문 본문1~7` = 사실 **공통영어2 YBM(김) 4과**(원고와 100% 일치).
  파일 이름에 그 교과서가 없어 업로드 외부지문으로 들어왔고, 라벨이 틀리니
  하단 문제 원고도 못 찾고 있었다. 원고 8번째 `p.99 Reading` 은 시트 `추가본문X` 라 정상 제외.
- **명일3** 파일 이름의 `20강` 은 시트에 없다 — 없는 폴더를 뒤지고 있었다.

**모양은 토큰 하나로 좁혔다** — `("lesson",4) ("olpo",15) ("rp",12) ("teuk",18)
("bare",18) ("test",2) ("mock",25,3)`. `manuscript_locate` 가 이걸 받아 원고 폴더를
찾으므로 **정본이 바뀌어도 아래는 그대로**. 출처 셋: `from_yos`(정본) →
`from_workbook_names`(폴백) → `from_labels`(교차검증), 어긋나면 `cross_check()` 가 말한다.

**범위 글은 형식 아닌 자리로 읽는다**(파일 이름 파서 재사용 불가):
괄호는 범위가 아니라 **출판사**(`미래엔(김)`) · 계열과 숫자 사이에 교재 이름이 낌
(`올림포스 독해기본1 15~18강`) → **`강` 으로 끝나는 숫자 묶음만** 강 · `25년 3월 18~45`
의 18~45 는 문항번호 · **`*` 가 항목 머리**(한 도막으로 보면 뒤 교과서 출판사 소실) ·
계열은 한 번 적고 `/` 로 이어 씀 → 승계.

**26-1-기말 5학교 검증**: 범위 글만으로 폴더 결정 → 광문2 8=8, 광문3 13=13,
상일1 12vs11(＋26년6월, 듣기만이라 지문 0), 명일1 5vs4(＋YBM 4과), 명일3 7vs8(−20강).
문장배열·삽입·영작 지문 수는 다섯 학교 **불변**.

✅**남은 한 겹은 Y.OS 안에 이미 있었다.** `/work/exam` 은 범위를 글이 아니라
**항목**으로 받는다 — `교과서 | 공통영어2_NE능률민병천 | Lesson 1. … 1~9, Lesson 2. … 1~12 | 21지문`,
`모의고사 | 고1_2024_09월(인천시) | 15~18, 20~24 | 9지문`, `부교재 | 수능특강 Light… | 08 1~5, 09 1~5`,
`프린트 | EBS 연계 외부지문 | 1~20`. 구조화 라인은 글을 안 읽어도 되고 `직접 입력`만 `parse()`.
`from_yos_entries()`/`normalize_book()`/`lesson_ranges()`/`unit_ranges()` 구현·검증 완료.
⚠`NE능률민병천`의 NE는 상표라 버리지만 `YBM박준언`의 YBM은 출판사 — **앞에서 걸리는 것**이 진짜.
⚠회차 학년≠반 학년(고2 반이 고1 회차). RSC 모양: `lines[].weeks[].seriesScopes[]`
(scopeText·scopeStatus·volNo·weekCovers 등). **REST 없음**(서버 컴포넌트) — 읽기 엔드포인트/
서비스 토큰/DB 직독 중 하나 필요, `from_yos()` 한 함수만 바뀐다.

⚠**곁가지 버그 2**: `L1-p. 17 본문 1` — 쪽 표시가 **이름 자리**에 오는 원고를 `parse_label` 이
못 읽어 `to_final_label` 이 None → **그 과가 통째로 빠졌다**. 이름 앞 `p.N` 제거. 5학교 재빌드 불변.

⚠**곁가지 버그**: `공통영어2 능률(민) 1과` 에 든 숫자 2 때문에 **2과를 찾으면 1과가 걸렸다**
(`_pick` 이 아무 숫자나 셈) → `num_unit="과"`. 공통영어2 계열 2과는 전부 틀렸을 자리.

옛 기록(글로만 받던 시절):
⚠**지문 수준 제한.** 범위 글엔 강·과뿐 아니라 어디까지인지도 있다
(`23년 9월 32,34,35,41~42` · `Test1 20~25` · `분석~3` · `(24-3,27-3 제외)` ·
`(추가본문X)` `(Read More 제외)` `(MR만)` `(Practice 1만)`). 안 걸면 범위 밖이 쏟아진다
(명일1 23→65, 명일3 19→55). 지금은 `parse()` 가 괄호 단서를 **버리지 않고 붙여만** 둔다.
거는 판정은 이미 엔진에 있다(`fetch_high3_scope` 의 lecture_details/lecture_exclude,
모의 문항범위) — 이 자리로 옮기면 범위 글 하나로 책이 선다.

## 자립 ③ 통합웹 카드 (2026-09-01 완료)

`engines/final_viv` — 카드 **「파이널 직전보충 (Vivliostyle)」**. FinalEngine 상속
(같은 원고·같은 parse), `render_backend="vivliostyle"` **한 값으로만** 분기하므로
부모의 JSX 경로는 호출되지 않는다. 기존 `final` 카드 무변경(opt-in).

흐름: parse → `_read_manuscripts`(시트 범위 → 원고 직독 빌더) → 교재 폴더에
`config.json`+`원고/content.json` 생성 → `core.render_vivlio.book` 의
data/build/print/verify → 내지·인쇄본 PDF 를 job_dir 로 복사.

- **이미 있는 `config.json` 은 덮지 않는다**(손잡이를 손봐 뒀을 수 있다).
- 원고를 못 읽으면 **되수확본으로 조판하되 로그로 말한다**(조용히 넘어가면
  겉으로 멀쩡한 책이 나온다).
- `scope_source.from_sheet(school, exam_period, grade)` 신설 — Y.OS 가 열리면
  **이 함수 하나만** 갈아 끼운다. 학교 이름 짝짓기(`광문2`↔`광문고2`)는
  `vocab_fetcher._find_scope_row` 가 이미 안다.
- 등록 3곳: `engines/registry.py` · `data/subjects.json` · `templates/`.
  **`routes/pages.py` 의 `material_id == "final"` 특례**(학교·시험기간 드롭다운)에
  `final_viv` 도 넣어야 한다 — 안 그러면 학교 목록이 빈다.
- `tests/test_render_vivlio.py` 의 `VIVLIO_OPT_IN` 에 카드 이름을 적어야 통과.

⚠빌더 import 는 `config.BASE_DIR + "/scripts"`. `__file__` 두 단계 위는
`engines/` 라 `scripts` 를 못 찾는다(조용히 폴백돼 되수확본이 나갔다).
⚠`YONE_STUDIO_ROOT` 없으면 `MATERIALS_ROOT` 가 **`~/dev/조판/교재`**(개발 샌드박스).
운영에선 env 가 Documents 를 가리킨다.
