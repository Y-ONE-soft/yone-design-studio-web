# 중등 내신 정규 교재 — 조판 파이프라인
## 1권 「같이새김」(개념·기본) · 2권 「홀로새김」(응용·실전)

**백엔드 = Vivliostyle 코드 조판. InDesign 아님.**
A4(210×297) + 도련 사방 3mm = 216×303mm, TrimBox 각인. 한 권 빌드 약 20초.

**교재가 몇 권이 되든 코드는 한 벌이다.** 교재마다 다른 것은 **원고 파일과 산출
파일명뿐**이다 — 내지 색은 교재가 아니라 **권**(「같이새김」/「홀로새김」)을 따르므로
`automation/book.py` 의 `VOLUME_STYLE` 에 한 벌씩 두 벌만 둔다.
간지·속표지에 들어가는 글(원고에 없는 조판의 글)은 `copy_kr.py` 가 **권 단위**로
가지고 있고 교재를 가리지 않는다 — 1권·2권의 구조가 같기 때문이다.

### 폴더

```
내신 정규 교재/
  README.md              ← 이 파일. 파이프라인·게이트·디자인 규칙 전부
  automation/            ← 코드 한 벌. 모든 교재가 공유한다
    book.py              ← 권별 팔레트 + 교재 표. 교재를 늘릴 곳
    work/<교재키>/       ← 중간 산출(raw·data·build). 손댈 일 없다
    assets/v1, v2/       ← 면 배경 아트워크(권 단위, 자동 생성)
  중2_천재소_L5/  원고/ + 산출 PDF
  중2_동아윤_L5/  원고/ + 산출 PDF
```

교재 폴더에는 **`원고/` 와 산출 PDF 만** 둔다.

### 돌리는 법

```bash
cd "automation"
python3 extract.py  donga 1   # 원고 docx → raw1.json (굵기·밑줄만 보존)
python3 gen_data.py donga 1   # raw1.json → data1.json (구조 파싱 + 3중 게이트)
python3 build.py    donga 1   # 렌더 → Vivliostyle → 면 패리티 2패스 → TrimBox
python3 verify.py   donga 1   # 원고 ↔ PDF 전수 대조 게이트
python3 press.py    donga 1   # 인쇄 납품본 — CMYK 변환 + 도련/재단 상자 + 프리플라이트
```

첫 인자가 **교재 키**(`cheonjae`·`donga`), 둘째가 **권**이다. `--book donga --vol 1`
로 길게 써도 같다. 교재를 빼면 기본 교재(천재소), 권을 빼면 그 교재의 첫 권이다.
원고를 바꿨을 때만 `extract` + `gen_data` 를 먼저 돌리고, 평소에는 `build.py` 하나로
render → 조판 → 면 패리티 확정 → 재조판 → 마감까지 간다.

### 교재를 늘릴 때

`book.py` 의 `BOOKS` 에 한 칸을 더한다 — 폴더 이름·이름표·산출 파일명·시리즈 호수와
`allow`(조판이 일부러 원고와 다르게 찍은 자리). **색은 잡지 않는다**(권에 딸려 온다).
**코드를 복사하지 않는다.** 교재별 분기가 필요해지면 그것은 파서를 형식이 아니라
구조로 고칠 자리라는 신호다(아래 「파서에서 실제로 물린 곳」 참고).

**손을 댔으면 기존 교재가 그대로 나오는지 먼저 확인한다.** 천재소 1·2권 PDF 를
`중2_천재소_L5/_backup/` 에 떠 두었고 `fingerprint.json` 에 면 수·본문 해시·
면별 픽셀 해시가 들어 있다. 다시 빌드해 셋이 전부 같아야 한다.

## 표기

- 출판 브랜드 = **새김북스**. (Y.ONE 관련 문구는 쓰지 않는다.)
- 과목 표기는 줄여 쓴다 — 원고 `중학 영어 2  천재(소영순)` → 지면 **`중2 천재(소)`**.
  `render.short_subject()` 가 자동으로 줄인다.

| `pagecheck.py` | 납품 PDF ↔ 원고 구조 대조 — 묶음이 어느 면에서 시작해 어디서 끝나는가. `build.py`·`verify.py` 공용 |

## 인쇄 납품본

`python3 press.py donga 1` → `중2_동아윤_L5_1권(같이새김)_내지_인쇄용(CMYK).pdf`

- **Ghostscript 를 쓰지 않는다.** 이 책은 이미지·그러데이션·투명이 하나도 없고 전부
  단색 벡터라 gs 로 넘길 이유가 없다. 오히려 서체를 다시 심으면서 **글리프↔유니코드
  대응이 깨진다**(실측: `대` → `눀` 85곳). 그래서 내용 스트림의 색 연산자만 직접 바꾼다
  — 서체·글리프·텍스트는 원본 그대로다.
- **무채색은 K 단색**(`GRAY_MAP`). 9pt 본문 먹이 4도 리치블랙이 되면 핀 어긋남으로
  글자가 뭉갠다. 본문 먹 K100 / 한글 해석 K72 / 빈칸 밑줄 K63 / 보조 글자 K42 …
  미색·파트 틴트 같은 **유채색 틴트는 표에 넣지 않는다**(넣으면 따뜻한 기가 빠진다).
- **유채색만 ICC 변환** — sRGB → Japan Color 2001 Coated, 상대 색도 + 검은점 보정.
- MediaBox = BleedBox = 216×303, **TrimBox = 사방 3mm 안쪽(210×297)**, ArtBox = TrimBox.
  PyMuPDF `set_bleedbox` 는 MediaBox 와 같은 크기를 거부하므로 xref 에 직접 쓴다.
- **OutputIntent(GTS_PDFX)** 로 ICC 를 심는다 — 인쇄소 프리플라이트가 묻지 않게.
- ⚠ 저장할 때 **`clean=True` 를 쓰지 말 것.** mupdf 정리기가 Type3 글리프 안에 `q` 를
  넣어 `d0/d1` 앞에 오게 만든다(규격 위반, poppler 경고 1,263건). 게이트가 잡는다.

### 프리플라이트 (press.py 가 자동으로 본다)
면 수 · 남은 RGB 0 · 본문 K 단색 · MediaBox/BleedBox/TrimBox · **글자가 원본과 동일**
(글리프 매핑 깨짐 검출) · 잉크 총량 300% 이하 · 서체 전부 임베드 · OutputIntent ·
**다른 렌더러(poppler)로 열리는지 + Type3 규격 경고 0건**

## 게이트 (셋 다 통과해야 납품)

1. `gen_data.py` — 원고 단락 100% 소비 + `(N개)` 표기와 실제 항목 수 일치
2. `verify.py` — ① **원고 단락이 전부 PDF 안에 있음**(data.json 을 거치지
   않는 직접 대조. 파서가 조용히 버린 단락은 여기서만 드러난다) ② data.json 문자열
   전수 대조 ③ 재단선 넘침 0 ④ 6pt 미만 글자 0 ⑤ **서체 폴백 0**(우리 서체에
   없는 글자가 시스템 서체로 떨어지지 않았는가) ⑥ 파트 간지가 전부 왼쪽(짝수) 면 /
   마지막 면 짝수 ⑦ **장을 넘겨 가며 푸는 지문 묶음 0건** ⑨ **본문이 하단 여백
   (꼬리말 자리)으로 내려온 곳 0건**(재단선 안쪽이라 판면 게이트로는 안 잡힌다)
   ⑩ **머리말·꼬리말만 있는 빈 면 0건** ⑧ **발문이 가리키는
   기호에 지문 쪽 밑줄이 붙어 있는가**(형제 기호엔 있는데 하나만 없는 자리 — 글자는
   다 있어서 누락 게이트로는 안 잡힌다)
3. 육안 — 대수(contact sheet)로 전 면 확인

## 조판 규칙

- **파트 = 6개**(원고는 PART 6 결번 → 순서대로 1~6 재번호). 파트마다 색이 다르다.
- **파트 간지 = 2면 펼침, 문구 없이 깔끔하게.** 전면 파트 색 한 장이고,
  **원 하나가 두 면에 걸쳐 이어진다** — 왼쪽 면 오른쪽 재단선(213mm)과 오른쪽 면
  왼쪽 재단선(3mm)에 같은 원의 중심을 두면 펼쳤을 때 하나로 맞물린다.
  왼쪽에 PART 번호·파트명·영문명, 오른쪽에 흐린 큰 숫자. 설명 문구·학습 목록·분량
  통계는 넣지 않는다. 간지 A 는 `break-before:left` 로 반드시 짝수 면에서 시작한다.
- **마지막 면은 판권 면**(`.ep`) — 아래 색 띠 안, 발행처 줄 바로 위에 **새김어학원
  마크를 흰색**으로 앉힌다(사용자 지시). 파스텔 위의 흰 마크는 읽는 글자가 아니라
  조용한 표식이라 간지의 흐린 숫자와 같은 쓰임이다. **메모 면으로 끝내지
  않는다**(사용자 지시). 속표지를 위아래로 뒤집은 꼴이다 — 속표지는 색 띠가 위,
  판권 면은 아래. 판권 면이 늘 한 장 붙으므로 **본문이 짝수 면에서 끝나야** 전체가
  짝수가 된다(모자라면 그 앞에 MEMO 면을 끼운다).
  - 마크는 표지(`디자인/표지/새김중등부/_에셋/logo_bk.png`)와 같은 것을 **벡터 패스로
    딴 SVG**(`assets/logo_saegim.svg`)다. **이 책에는 이미지가 하나도 없다** — press.py
    의 색 변환이 그 전제 위에 서 있으므로 로고도 래스터로 넣지 않는다(인쇄본 이미지 0개).
- **파트가 왼쪽 면에서 끝나면 다음 오른쪽 면은 MEMO 면**. `build.py` 1패스가
  파트 끝 면의 홀짝을 재서 2패스에 메모 면을 끼운다. 마지막 면도 짝수로 맞춘다.
- **섹션(1-0, 1-1 …)은 언제나 새 면에서 시작**한다(학습 면과 문제 면 분리).
- **빈칸은 언더스코어 문자가 아니라 고정 길이 인라인 룰** — 18·34·70mm.
- **답란(`→ 정답 ____`)은 제 줄에 세우고 빈칸을 길게 준다.** 문제 문장 뒤에 붙이면
  줄이 넘쳐 빈칸만 다음 줄로 흘러내린다. `→` 는 선지·문법 설명에도 흔하므로
  **뒤에 빈칸이 있고 앞이 30칸 넘게 길 때만** 가른다(한글은 두 칸으로 센다).
  홀로 선 빈칸은 그 줄에서 길게(70mm) 잡는다.
- **긴 빈칸이 공백만 두고 잇달아 오면 하나로 잇는다.** 원고가 한 칸을 잘못 넣은
  것이지 답이 둘인 게 아니다(짧은 빈칸이 잇달아 오는 것은 낱말 슬롯이라 그대로 둔다).
- **지문 한 줄에 화자가 두 번 들어오면 뒤 화자 앞에서 나눈다.** 한 줄로 두면 두 사람이
  한 사람처럼 읽힌다. 선지(`① A: … B: …`)는 한 줄이 맞으므로 **지문 줄에만** 적용한다.
- **밑줄은 한 권 안에서 굵기가 같다 — 전부 0.5pt**(사용자 지시). 원고 밑줄(`<u>`) ·
  빈칸(`.blk`) · 답란(`.ansline`·`.abl`·`.sl`)이 각각 다른 굵기를 쓰고 있었다.
  문항마다 굵기가 달라 보이면 같은 문제인데 다른 규칙처럼 읽힌다.
- **마지막 한 문항만 넘치면 여백을 조여 한 면에 담는다**(`.qs.tight`). 세 개 넘게
  넘치는 것은 어쩔 수 없지만 하나만 떨어지는 자리는 대개 들어간다. 어느 블록을
  조일지는 `build.py` 가 재서 붙이므로 **필요한 데만** 좁아진다.
- **품사는 한글 한 글자 회색 원배지**(명·동·형·부). `[명]` 같은 표기를 그대로 찍지 않는다.
- **형광(`--hl`)은 핵심 표현에만.** 파트당 유채색 면적은 학습면 3~8%, 문제면 1~3%.
- **`<보기>` 항목은 낱개 칩**으로 나눈다. 한 줄로 이어 붙이면 어디서 끊기는지 안 보이고,
  긴 목록은 상자가 판면을 넘는다. `<조건>` 은 문장이라 칩 대신 줄 단위로 쌓는다.
  - **`<보기>` 가 라벨인지 문장 속 낱말인지는 조사로 가른다.** `<보기>에서 알맞은 말을 …`
    은 발문이고 `<조건>주어, 동사가 …` 는 라벨이다. 공백 유무로 가르면 붙여 쓴 라벨을
    놓치고, 안 가르면 **발문이 통째로 사라진다**(실측: 천재소·동아윤 2권 C. 발문).
  - **번호가 붙은 조건은 번호로 나눈다.** 공백 두 칸으로만 나누면 원고가 한 칸만 띄운
    자리에서 두 조건이 한 줄에 붙는다.
  - **라벨만 한 줄로 적은 원고는 뒤따르는 줄을 제 항목으로 데려간다.** `<보기>` 만
    쓰고 항목을 다음 줄부터 늘어놓은 원고가 있다 — 안 그러면 빈 라벨 상자와 항목이
    따로 논다.
  - **`<보기>` 상자와 `<조건>` 상자는 색으로 가른다** — 보기는 미색(고를 거리),
    조건은 중립 회색(지켜야 할 규칙).
  - **꺾쇠가 없어도 라벨은 라벨이다.** `보기 …` · `조건 •…` 처럼 적은 원고가 있다.
    항목은 `•` 가 있으면 `•` 로, `ⓐ ⓑ …` 가 둘 이상이면 기호로, 번호가 붙었으면
    번호로, 그 밖에는 공백 두 칸으로 나눈다.
  - **보기 상자는 자료 상자와 따로 세운다.** 한 상자에 뭉치면 어디까지가 보기인지
    안 보인다. 자료 줄 다음에 오는 첫 ⓐ 앞에는 구분선을 넣는다.
  - **보기 항목 안의 굵기·밑줄을 살린다.** 발문이 "밑줄 친 부분"을 묻는데 보기의 그
    낱말에서 밑줄이 사라지던 자리가 있었다.
- **지문 묶음의 기호는 ⓐ 부터 다시 매긴다.** 원고가 긴 지문에서 잘라 온 토막을 그대로
  써서 ⓑ·ⓓ 로 시작하는 자리가 있다(발문도 그 기호를 부른다). 기호는 자리 이름일 뿐이라
  앞으로 당긴다 — **끊긴 채로 시작하는 경우만** 손대고, 같은 기호가 두 번 나오는 것은
  내용 문제라 건드리지 않는다.
- **답란이 두 벌이면 마지막 한 벌만 남긴다.** 원고가 같은 답란을 형식만 달리해 두 번
  적어 둔 자리가 있다(기호가 되돌아가면 새 벌로 본다).
- **docx 의 줄바꿈(shift+enter)은 줄 경계로 본다.** 발문과 `<보기>` 를 한 단락에
  붙여 놓은 원고가 있다.
- **답 쓰는 칸이 있는 문항에는 아래 구분선을 넣지 않는다**(`.qi.ans`). 빈칸 밑줄과
  구분선이 겹쳐 줄이 두 개로 보인다.
- **우리말이 문제인 줄은 작게 쓰지 않는다**(사용자 지시). 영문 뒤에 오는 한글은
  해석이라 작고 흐려도 되지만, **앞줄이 영문이 아닌 한글 줄은 그걸 보고 푸는 문제**다
  (영작·배열). 해석체로 쓰면 정작 풀어야 할 문장이 가장 안 보인다.
- **대화 지문 안의 ⓐ~ⓔ 는 대화 글줄에 맞춘다.** 화자 이름 칸만큼 들여쓰되 기호는
  그 칸에 걸쳐 둬, ⓐ 뒤의 문장이 화자가 말하는 문장과 같은 자리에서 시작하게 한다.
- **영문 지문에 한글 절이 섞여도 영문 줄이다.** 한 글자라도 한글이면 해석 줄로 보면
  지문이 통째로 해석 글자꼴(8.6pt 회색)로 떨어져 **같은 상자 안에서 줄마다 크기가
  달라 보인다.** 그렇다고 글자 수를 단순히 견주면 `우리가 ____ 장소는 Shoreditch입니다.`
  처럼 고유명사가 낀 해석 줄이 영문으로 넘어간다 — **영문이 네 배 넘게 많을 때만** 영문.
- **지문 묶음의 지문과 첫 문항은 갈라 놓지 않는다**(`.setq{break-after:avoid}`).
  지문 상자만 면 아래에 남고 문항이 다음 면으로 통째로 넘어가면 지문을 보며 풀 수 없다.
- ⚠ **두 단 덩어리에 `display:flex` + `break-inside:avoid` 를 함께 걸지 말 것.**
  Vivliostyle 이 그 덩어리를 다음 면으로 **못 옮기고 판면 밖으로 흘려 버린다**
  (실측: 끊어읽기 해석 줄이 꼬리말 위에 포개졌다). **`display:table` 로 짠다.**
- **★ 주의점의 영문 예문은 제 줄에 세운다.** 원고가 `한글 설명.  영문 예문` 을
  두 칸 띄어 한 줄로 적어 어디부터가 예문인지 안 보였다.
- **지문 안 `Q: …` 는 묻는 말이라 색을 달리한다**(진한색). 화자의 말과 갈라 보이게.
- **잇단 예문 줄 사이에 숨통**(`.qi .en + .en`, 1.9mm). 붙여 놓으면 한 문장처럼 읽힌다.
- **역할이 바뀌는 자리에서 간격을 벌린다**(`.rgap`, 4.2mm — 사용자 지시).
  자료(대화·지문) → 묻는 말(`Q:`) → 선지 → 답란. 전부 같은 간격이면 **어디까지가
  자료이고 어디부터가 질문인지 한 눈에 안 들어온다.** 같은 몫끼리(1.9mm)의 두 배
  넘게 벌려야 눈에 걸린다. ⚠ `.qi .en + .en` 이 명시도에서 이기므로 클래스를 겹쳐 적는다.
- **묶음을 밀어 앞 면이 비면 메모 면으로 채운다.** 빈 면은 인쇄 사고처럼 보인다.
- **답란(`→ …`) 밑줄은 낱말 뒤에서 끊지 않고 단 오른쪽 끝까지 긋는다**(사용자 지적).
  고정폭 빈칸을 쓰면 줄마다 끝나는 자리가 달라 답란이 들쭉날쭉해 보인다. 대신
  **마지막 빈칸 뒤 꼬리말**(`.` · `was expensive.`)은 오른쪽 끝으로 보낸다 —
  안 그러면 줄 한가운데 뜬다. 칸 나누기는 `display:table`(flex 금지).
- **빈칸 폭은 「얼마나 쓰는가」로 정한다.** 원고가 준 밑줄 길이(s/m/l)를 기본으로 쓰되,
  발문에 **낱말 보따리**(`(I / the cookies / baked / which)`)가 있으면 문장 하나를
  통째로 쓰는 문제이므로 그 칸만 줄 끝까지 늘린다. 한 낱말 쓰는 칸을 늘리면
  "몇 자 쓰는 자리인지 알 수 없다"는 지적이 온다. **칸이 여럿이면 하나로 합치지 말 것**
  (조건이 "빈칸에 한 단어씩"인 문제가 있다).
- **답란(`→ …`)은 한 갈래로만 그린다.** 앞말 길이로 모양을 갈랐더니 같은 묶음
  안에서 화살표 색·들여쓰기·밑줄이 제각각이 됐다. 밑줄은 **빈칸 자리에만** 긋고
  (줄 전체에 그으면 글자 밑까지 선이 지나간다), 줄에 남는 자리를 **빈칸들이 똑같이
  나눠 가져** 오른쪽 끝을 맞춘다. 칸 나누기는 `flex` — `display:table` 은 글자를
  최소 폭으로 눌러 낱말을 세로로 쪼갠다.
- **⚠ `.mk` 는 묶음 제목의 표식 막대가 쓰는 이름이다.** 계측용으로 같은 이름에
  `position:absolute` 를 얹었더니 막대가 제자리를 벗어나 **모든 묶음 제목의 첫 글자**를
  덮었다(세 교재 다섯 권 전부). 새 규칙을 넣을 때는 이름 충돌부터 확인할 것.
  verify 에 **제목 가림 게이트**를 신설했다.
- **표처럼 칸이 정해진 자리는 한 줄에 담는다**(사용자 지시). build 가 조판본을 재서
  **간발의 차로** 넘친 칸만 골라 자간을 줄인다(-.028em, 모자라면 -.055em 한 단계 더).
  뒤 줄이 길면 건드리지 않는다 — 자간을 줄여 봐야 안 들어가고 글자만 답답해진다.
  같은 칸이 여러 자리에 나오면(어휘 정리·확인) **한 군데라도 넘쳤으면** 줄인다.
- **문항 하나만 다음 면에 남기지 않는다.** 둘 넘게 넘어가는 건 어쩔 수 없어도 하나만
  남는 건 조여서 당긴다(사용자 지시). ⚠ 조임 값이 일반 간격과 **같으면 아무 일도 하지
  않는다**. 2단 목록은 원래 간격이 더 좁아(1.4mm) 조임 값을 그대로 두면 **오히려 넓어진다**
  — `.qs.two.tight` 를 따로 잡을 것. 안 잡히면 한 단계 더(`tight2`).
- **면을 먼저 보고 블록을 찾는다.** 문항 글자를 앞에서부터 찾아 면을 매기면 짧은 항목
  (`많이`·`도마`)이 앞쪽 어휘 목록 면에 먼저 걸려 블록 전체가 한 면에 있는 것처럼 보인다.
- **스크립트 안의 `[어구 · 어법]` 은 대화 줄과 다르게 그린다.** 같은 두 칸 줄로 찍으면
  스크립트인지 개념 정리인지 구분이 안 된다.
- **문항 하나가 홀로 넘어가면 자간·행간까지 조인다**(`tight3`). 여백만으로 안 되면
  글자를 조금 좁혀서라도 앞 면에 넣는다(사용자 지시). 세 단계로도 안 들어가면
  자리가 정말 없는 것이다 — 억지로 밀지 않는다.
- ⚠ **꼬리 판정은 "블록의 마지막 항목"이 넘어왔는지로 한다.** 그냥 몇 개 걸린 것으로
  보면 어휘 목록 낱말이 다른 면에 우연히 겹쳐 **멀쩡한 표를 세 단계나 조인다**.
- **머리(발문 바)만 앞 면에 남기지 않는다.** 묶음이 면 끝에서 시작해 문항 하나만 걸치면
  통째로 다음 면에서 시작한다(`.grp.nb`). build 가 발문 글자로 면을 찾아 잰다.
- **밑줄만 있는 줄은 화살표가 없어도 답란이다.** 답이 길어 두 줄을 준 원고는 둘째 줄에
  화살표를 안 붙인다 — 인라인 빈칸으로 잡히면 앞 줄과 길이가 다른 짧은 줄이 하나 더 생긴다.
- **`① ② ③ ④ ⑤` 답 줄은 고르게 벌린다.** 원고의 공백은 들쭉날쭉하다.
- **작은 글자에 연한 보조색(`--sub`)을 쓰지 않는다.** 8pt 곁설명(`← so 뒤는 …`)은
  인쇄하면 흐려 보인다 — 같은 색상환의 **진한 쪽(`--subdeep`)** 을 쓴다.
- **한 대화에 함께 나오는 화자는 색이 달라야 한다.** 표기별 고정색을 쓰되 **같이
  나오는 짝**(A–B, B–G, M–W, G–M, B–W)이 전부 갈리게 배정한다(A1 B2 G3 M1 W4).
  그리고 같은 대화에서 색이 겹치면 **자동으로 비켜 준다** — 새 표기가 들어와도 안전하다.
- **문장 성분 표(`svo`)** — 원고가 문장을 토막 내고 **표의 아래 행에 S·V·O·C** 를 단다.
  평평하게 펴면 어느 토막이 무슨 성분인지 사라지므로 `extract` 가 **행·열 번호를 남기고**,
  파서가 열로 맞물린다. 긴 문장은 원고가 표를 **둘로 쪼개고 사이에 빈 단락**을 둔다 —
  거기서 끊으면 안 된다. 4-0 은 `parse_reading`, 5-0 은 `build_readgroup` 으로 들어가므로
  **양쪽 다** 붙여야 한다. `est_mm` 에 크기를 안 알려 주면 통째로 `keep` 이 걸려 빈 면이 난다.
- **`→` 답란은 문제 문장과 같은 자리에서 시작한다.** 한 단 들여쓰면 문제와 답란의
  시작점이 어긋난다. 들여쓰기로 층을 만들지 말 것 — 층은 간격(`rgap`)으로 낸다.
- **`→` 답란도 줄 끝까지 간다 — 그리고 블록 단위로 정한다.** 발문 끝 괄호가 낱말을
  둘 이상 주면(`(buy, a book)` · `(I / the cookies / …)`) 답이 한 낱말이 아니므로 빈칸이
  줄 끝까지 늘어난다. **한 문항이라도 그러면 그 블록 전부** 그렇게 한다 — 같은 묶음에서
  어떤 줄만 짧고 어떤 줄만 길면 그게 바로 정렬이 안 맞는 모습이다.
- **답란(빈 밑줄)의 자리는 하나뿐이다.** 왼쪽 끝은 **그 문항 본문의 왼쪽 끝**(번호 칸
  다음), 오른쪽 끝은 **판면 끝**. 원고의 밑줄 개수로 길이를 정하지 않는다(`.half` 폐기).
  `→` 줄이 있는 문항만 그 줄에 맞춰 한 단 더 들여쓴다(`.ansrow.deep`).
  ⚠ `.ansrow` 는 번호 칸 바깥이라 같은 값을 주면 번호 칸 폭만큼 왼쪽으로 밀린다.
- **`① 문장 ② 문장 …` 은 선지가 아니라 지문 안 위치 표시다.** 선지로 두면 지문 상자
  밖으로 떨어져 지문이 두 동강 난다. 기호만 늘어선 답 줄과는 **글자 양**으로 가르고,
  선지로 잡히며 떼어 낸 첫 기호(①)는 돌려놓는다.
- **답란은 화살표 줄과 같은 자리에서 시작한다.** `.ansrow` 는 번호 칸 바깥이라 같은 값을
  주면 번호 칸 폭만큼 왼쪽으로 밀린다. 빈칸이 없는 꼬리(`→ (부정문)`)에는 괘선을 붙이지
  않는다 — 아래 진짜 답란과 길이도 자리도 어긋난 짧은 줄이 하나 더 생긴다.
- **섹션 번호에 글자가 붙는다**(`2-2b`·`3-4b`). 숫자만 받으면 그 섹션이 통째로 앞
  섹션 본문에 묻혀 제목도 STEP 배지도 사라지고 원고 번호가 본문으로 인쇄된다.
- **묶음 안내문 앞에 머리기호가 붙기도 한다**(`▸ [09-12] 다음 대화를 …`). 그대로 두면
  안내문이 문항처럼 찍히고 **지문 묶음이 통째로 0개**가 된다. 배지의 `~` 와 원고의 `-` 는
  같은 것이므로 대조에서 함께 지운다.
- **빈 자리를 메우는 메모 면은 바로 다음 면에 앉힌다**(`break-before:page`). 오른쪽 면을
  요구하면 메우려던 그 면이 그대로 빈다. 그리고 **넣고도 앞 면이 비면 걷어낸다** —
  넣기만 하고 못 빼면 필요 없어진 메모가 남아 또 빈 면을 만든다.
- **묶음 안내문은 문항이 하나뿐이면 범위가 없다**(`[09] 다음 글을 읽고 …`). 범위를
  필수로 두면 안내문이 문항처럼 조판되고 지문이 문제 본문이 된다. 배지도 `09~09` 가
  아니라 `09` 로 찍는다.
- **`<조건>` 은 라벨이 제 줄에 서기도 한다.** `조건 •a •b •c` 한 줄만 보면 상자가
  **비어 나온다**(실측: 비상(황) 2권). 라벨 다음 머리기호 줄은 그 상자 안이고,
  머리기호가 끊기면 상자도 닫힌다(안 그러면 뒤 대화문까지 삼킨다).
- **발문이 「밑줄 친 space」 라고 약속하면 조판이 밑줄을 넣는다.** 원고에 없으면 문제가
  성립하지 않는다 — 교재별 정오표가 아니라 발문·지문 대조로 판정한다.
- **괄호 선택형은 품사 배지보다 먼저 가른다.** 배지를 먼저 HTML 로 바꾸면 닫는 태그의
  `/` 가 선택 구분자로 읽혀 `(freedom 명 자유)` 같은 파생어 힌트가 굵게 나간다.
- **대화 스크립트의 화자 줄은 `display:table`.** flex 덩어리에 `break-inside:avoid` 가
  걸리면 면에 안 들어갈 때 다음 면으로 못 가고 꼬리말을 침범한다.
- **PART 6 묶음은 제목 낱말이 아니라 생김새로 잡는다.** 교재가 새 묶음을 하나 넣으면
  (비상(황) 「본문에 나온 그 밖의 어법」) 화이트리스트로는 통째로 떨어져 나간다.
  `·` 머리기호가 뼈대면 `notes` 로 받는다.
- **표식 없는 줄은 앞 `▸`/`★` 항목의 이어진 줄이다.** 원고에 따라 설명과 예문이
  한 단락이기도, 두 단락이기도 하다. 버리면 예문이 통째로 사라지는데 **단락은 소비돼
  있어 gen_data 게이트로는 안 잡히고** 원고→PDF 대조에서만 드러난다.
- **조판 계측은 나가는 판 그대로 한다.** 흰 글자 표식(`§E1§`)을 심어 재던 때는
  표식이 든 판과 실제 판의 쪽나눔이 달라(93p vs 91p) 메모 면이 엉뚱한 자리에 붙고
  빈 면이 남았다. 지금은 **파트 간지를 찾아** 파트 끝을 재고, 그 뒤에 붙은 메모
  면·빈 면은 빼고 센다.
- **문항 사이는 벌린다**(`.qi` 2.2mm · `.qs.boxed` 3.2mm). 한 문제가 어디서 끝나고
  다음이 어디서 시작하는지 눈에 걸려야 한다. **여백 조임(`tight`)도 2.2mm** — 한 문항을
  앞 면으로 당기는 값이지 문항을 붙이라는 뜻이 아니다. 1mm 로 눌러 두면 조인 면만
  유독 답답해진다(사용자 지적: 아래 여백이 100mm 넘게 남는데도 문항이 붙어 있었다).
- **지문 속 화자 줄은 우리말이라도 지문이다.** 언어로만 가르면 영작 문제의 우리말
  대사(`B: (B)그렇게 멀어?`)가 해석처럼 흐려진다. 화자 표시가 없는 우리말 줄만 해석.
- **원고의 밑줄 길이는 답을 쓸 칸의 크기가 아니다.** 원고는 그저 밑줄 문자를 몇 개
  찍어 둔 것뿐인데 그대로 옮기면 영어 단어 한 개도 못 쓰는 20mm 칸이 나온다.
  답란(`.abl`)은 **줄에 남는 자리를 다 차지**하고, 원고에서 온 s/m/l 은 최소 폭으로만
  남긴다(사용자 지적).
- **발문이 '위 대화…' 인데 그 지문을 문항이 스스로 달고 있으면 '다음'으로 고친다.**
  지문이 발문 아래에 찍히므로 가리킬 '위'가 없다. 묶음(setq)은 지문이 정말 위에
  있으므로 건드리지 않는다. 고친 원문은 `data.json` 의 `meta.allow` 에 남아
  verify 의 원고→PDF 대조가 그대로 엄격하다.
- **기호만 늘어놓은 줄(`ⓐ ⓑ ⓒ ⓓ ⓔ`)은 원고 잔재**라 지운다. 이음표로 엮인
  `ⓒ-ⓐ-ⓓ-ⓔ-ⓑ` 는 배열 답이므로 남긴다.
- **대화 스크립트는 한 면에 들어가면 쪼개지 않는다**(`.scr.keep`, 추정 높이 ≤168mm).
  대신 세로 리듬을 조여 되도록 한 면에 담는다.
- **머리말은 좌·우가 서로 다른 것을 한 번씩 인다**(사용자 지시).
  왼쪽 = `PART 1 어휘 WORDS ● 실전`(지금 어디를 보고 있는가),
  오른쪽 = `중2 천재(소) · Lesson 05`(어느 교과서의 몇 과인가).
  양쪽에 같은 것을 찍으면 펼침면에 같은 글이 네 번 보인다. 꼬리말도 같다 —
  왼쪽 `홀로새김 Vol.1`, 오른쪽 `중2 천재(소) · Lesson 05`.
  **Vol. 은 권(1권/2권)이 아니라 시리즈 호수**다 — 「같이새김」·「홀로새김」 각
  시리즈에서 몇 번째 책인가(과 순서). 6과가 나오면 그 책이 Vol.2. `book.py` 의
  교재별 `vol_no`.
- **밑줄 굵기는 서체 기본값에 맡기지 않는다.** 기본값(0.84pt)은 PDF 안에서는
  어느 줄이나 같지만 줄마다 y 소수점이 달라 **화면 뷰어에서 굵기가 달라 보인다**
  (같은 낱말인데 ①은 얇고 ②는 굵어 보이는 이유 — 인쇄물에서는 안 나타난다).
  `text-decoration-thickness:.5pt` + 고정 offset + `skip-ink:none` 로 못 박는다.
- **지문 묶음은 장을 넘겨 가며 풀지 않게 한다**(사용자 지시). 묶음(지문 상자 +
  범위 안 문항)이 **왼쪽 → 오른쪽**으로 이어지는 것은 한 펼침면이라 괜찮고,
  **오른쪽 면에서 시작해 다음 장 왼쪽으로** 넘어가면 통째로 다음 왼쪽 면으로 민다.
  `build.py` 가 재서 `.grp.bl{break-before:left}` 를 붙이고, `verify.py` 가
  납품본에서 다시 잰다(둘 다 `pagecheck.py` 라는 **같은 자**를 쓴다).
- **머리말은 배경 SVG 가 그린다**(`gen_art.py`). 마진 박스는 도형을 못 그리고 도련까지
  닿지도 못한다. `@page bookN:left/right` 배경으로 깔린다.
  **SVG 에 글자는 넣지 않는다**(서체 의존 제거).
  - **왼쪽 면과 오른쪽 면은 거울 반전이 아니라 서로 다른 구성이다**(사용자 지시).
    왼쪽 = 연한 띠 + 바깥쪽 톤 슬래브(안쪽 아래 모서리만 둥글게).
    오른쪽 = 연한 띠 + 아래쪽 두꺼운 톤 바 + 바깥 위 모서리 사분원.
  - 바깥 날개에 **색인 막대 1개**. 파트마다 높이가 달라 엄지 색인이 된다.
    (여러 개를 층층이 쌓은 형태는 "손가락 같다"는 지적으로 폐기)
- **발문과 문항 번호는 형태를 다르게.** 발문 = 연한 바탕 띠 + 진한 사각 배지 + 굵은 글자,
  문항 번호 = 배경 없는 진한 색 글자. 같은 배지 모양을 쓰면 구분이 안 된다.
- **괄호 선택형 `(happy / happily)` 는 굵게**, `(○)`·`(×)` 는 앞 낱말에 NBSP 로 붙여
  줄 끝에서 떨어지지 않게 한다.
- **그룹 머리에 개수(`45개`)를 찍지 않는다.**
- **회차(`N회`)는 제목 뒤**(`실전 모의고사 1회`), **단계(`STEP N`)는 제목 앞**이다.
  섹션 표제와 머리말이 같은 규칙을 쓴다 — 한쪽만 앞에 붙이면 같은 섹션이 면마다
  다른 이름으로 읽힌다.
- **속표지도 간지처럼 설명 문구를 넣지 않는다**(사용자 지시). 권 이름·권 표기·
  CONTENTS 목록까지만이고, 책 소개문도 목차 줄의 파트 설명도 찍지 않는다.
  문구를 뺀 만큼 블록을 아래로 내려 색면 아래와 꼬리말 위 여백을 맞춘다.
  `copy_kr.py` 의 `line`·`toc`·`lead`·`tip`·`sec` 는 **지면에 나가지 않는다** —
  되살릴 때를 대비해 글만 남겨 둔 것이라 고쳐도 지면은 그대로다.
- **조판이 쓰는 글에 수를 손으로 적지 않는다.** 게이트는 조판이 쓴 글을 보지 않으므로
  "모의고사 **네** 회" 같은 표기는 원고가 5회로 늘어도 조용히 남는다. 지금은 그런
  문구 자체를 지면에서 뺐지만, 되살릴 때는 원고에서 세어 채울 것.
- 최소 글자 7pt. 영문 본문(9.8~10pt)을 한글(8.3~9.4pt)보다 크게 잡는다.

## 팔레트 — 뮤트 파스텔

**완성본(상일보카·블랙북·포켓북·워크북 v2)에서 실측한 하우스 색감**을 기준으로 잡았다.
우리 책들의 유채색은 **채도 C 0.06~0.10 / 밝기 L 0.68~0.85** 구간에 몰려 있다. K 를 섞어
어둡히지 않고 **채도만 낮춘 밝은 톤**이다. 밝기까지 같이 내리면 탁해진다(아래 금지색). 톤(L·C)은 여섯 파트가 같고 **색상만 돈다**.

| 역할 | L / C | 쓰는 곳 |
|---|---|---|
| `main` | 0.815 / 0.095 | 색면 — 간지 색면, 머리말 띠, 표제 배경 |
| `mid` | 0.660 / 0.110 | 얇은 괘선·작은 마크 (파스텔은 선으로 쓰면 사라진다) |
| `deep` | 0.500 / 0.120 | **흰 글자를 얹는 배경**, 진한 글자, 쪽번호, 문항 번호 |
| `soft` / `pale` / `tint` | 0.890 / 0.945 / 0.975 | 도형, 상자 바탕, 면 바탕 |
| `sub` / `subdeep` | 0.790 / 0.530 (C 0.10) | 보조색 — 다른 색상환의 액센트 |

**흰 글자는 `deep` 위에만 얹는다.** `main` 은 파스텔이라 흰 글자가 안 읽힌다.

**내지 색은 교재가 아니라 권을 따른다**(사용자 지시, 2026-08-27) — 「같이새김」과
「홀로새김」만 갈리면 되고, 교과서가 달라도 같은 색이다. 그래서 팔레트는
`book.py` 의 `VOLUME_STYLE` 에 **한 벌씩 두 벌**뿐이고, 교재는 원고와 산출 파일명만
갖는다. 배경 아트워크도 `assets/v1`·`assets/v2` 한 벌씩을 모든 교재가 함께 쓴다.

> 교재마다 색을 새로 잡던 때는 네 권 24개 파트로 **노랑(60~110)을 뺀 색상환이 거의 차**
> 다른 책의 파트와 10° 안팎까지 붙기 시작했다. 권으로 묶으면 그 문제가 사라진다.

**1권 「같이새김」**

| 파트 | 주색(main) | 진한색(deep) | 보조색(sub) |
|---|---|---|---|
| 1 어휘 | `#F6B08D` 애프리콧 | `#394F67` 차콜슬레이트 | `#69CAE7` 스카이 |
| 2 대화 | `#BFB9FD` 라벤더 | `#6156A3` 인디고 | `#E5AE73` 골드 |
| 3 문법 | `#A2D297` 연두 | `#297C3D` 리프그린 | `#ECA0C4` 핑크 |
| 4 본문 | `#86CCF9` 스카이 | `#006B9F` 오션 | `#F2A58A` 애프리콧 |
| 5 기타 지문 | `#F0AAD1` 로즈 | `#914373` 플럼 | `#73D0B1` 민트 |

**2권 「홀로새김」** — 톤(L·C)은 1권과 똑같고 색상만 다르다.

| 파트 | 주색(main) | 진한색(deep) | 보조색(sub) |
|---|---|---|---|
| 1 어휘 | `#F3A9C9` 로즈 | `#933F7B` 베리 | `#6ED0B7` 민트 |

| 6 실전 모의고사 | `#D5B2F1` 라일락 | `#784D96` 플럼 | `#8BCD99` 민트 |

`deep` 을 뉴트럴 잉크로 받는 파트(`'slate'`)는 **괘선·작은 마크(`mid`)에 쓸 색상환이
없어진다** — 기본값은 주황(40)이라 주색이 애프리콧일 때만 맞는다. 주색이 다른 색상환이면
`('slate', H)` 로 mid 색상환을 따로 준다.

**진한 보조색(`subdeep`)은 글자·배지에 쓰지 않는다.** 따뜻한 보조색이 어두워지면
갈색이 되기 때문이다. 배지·번호·라벨은 전부 `deep`, 작은 마크·괘선은 `mid` 를 쓴다.
1파트(애프리콧)만 `deep` 을 **뉴트럴 잉크(차콜슬레이트)** 로 받는다 — 따뜻한 파스텔은
어두워지면 벽돌·갈색으로 빠지기 때문이다.

**대화 화자 구분색** — 파트 색과 무관한 공통색. 한 대화 안에서 두 사람이 확실히
갈리도록 `spk1 #2E6EA6` 파랑 / `spk2 #B2456A` 베리 / `spk3 #2F7D57` 초록 /
`spk4 #7A56A8` 보라 를 쓴다. **`G`·`B`·`A`·`W`·`M` 같은 역할 표기는 책 전체에서 색이
고정**이고(같은 G 가 대화마다 색이 바뀌면 더 헷갈린다), 사람 이름(Chris·Ms. Ali …)은
그 대화 안에서 나온 순서대로 돈다. 스크립트의 화자 칸뿐 아니라 **지문 상자 안의
인라인 화자(`G: We have …`)에도 같은 색**이 붙는다.

**공통 바탕색** — 본문 상자는 파트 색으로 물들이지 않는다.
`ivory #FAF6EF`(대화·개념·카드·형식) / `ivory2`(보기·LEVEL UP) / `ivory2 #F5F0E6`(보기 상자·핵심 문장 포인트) /
`gray1 #F3F4F6`(비교표·주어진 글·단어 칩). 파트 색은 **머리말 띠·간지·칩·괘선**에만.

> ⚠ **쓰지 않기로 한 색** (사용자 지시, 2026-08-26 — 해제 전까지) — 더스티 모브코럴
> `#DB9488` 계열, 세이지 그린 `#81B98C` 계열. "칙칙하고 예쁘지 않다".
> 원인은 색상환이 아니라 **밝기**다. 채도를 낮추면서 밝기까지 내리면 이 두 색상환은
> 흙빛으로 빠진다. **채도만 낮추고 L 0.80 이상을 유지**하면 같은 색상환이 애프리콧·민트가
> 된다. 색상환 60~110(노랑)은 진한 색이 올리브로 빠져 주색으로 부적합하다.

속표지는 파트에 매이지 않는 책 고유색(뮤트 인디고 + 살구).

- **■ 의 두 얼굴.** ■ 는 개념 서술의 머리(`■ 개념`·`■ 형식`·`■ 의사소통 기능 2`)이기도 하고
  그룹 안의 표제어(다의어 `■ field`, 상하위어 `■ sports`, 문법 공식 `■ make/keep …`)이기도
  하다. 그룹 종류로 가르려다 **문법 공식 상자가 통째로 빠졌다**(내용은 남고 스타일만 빠져서
  누락 게이트를 통과했다). 지금은 **■ 뒤에 오는 말**로 가른다(`RE_CONCEPT_HEAD`).
- 앞의 두 사고는 **원고 단락 100% 소비 게이트를 통과했다** — 단락을 읽기는 했지만 빌더가
  버렸기 때문이다. 그래서 `verify.py` 에 **원고 → PDF 직접 대조**와 **빈 블록 게이트**
  (그룹은 잡았는데 항목이 0개)를 넣었다. 파서를 고칠 때는 이 둘을 먼저 돌릴 것.

**원고 개정으로 물린 것(2026-08-27, 2권)** — 섹션 머리가 `실전 모의고사  1회   기본`
에서 `실전 모의고사  1회` 로 바뀌자 **회차 배지가 통째로 사라지고 제목에 눌러앉았다**
(`실전 모의고사  1회` 가 제목 한 덩어리가 됐다). 난이도 꼬리를 **필수**로 잡는
정규식이었기 때문이다. 꼬리를 선택으로 바꿔 꼬리 유무와 무관하게 회차를 잡는다.
게이트 셋은 이걸 못 잡는다 — 글자는 전부 PDF 안에 있었다. **육안 검수의 몫이다.**

- **지문 묶음** `[04~06] 다음 대화를 읽고 물음에 답하시오.` — 범위 배지 + 지문 상자.

  (1권의 `우리말 → 영문 빈칸` 처럼 선지가 없는 문항은 그대로 둔다)
- **［서술형］·［고난도］** — 배지로 옮기고 본문 글자에서는 지운다.
- **`<조건>` 상자** — `<보기>` 와 같은 꼴.
- **`ⓐ ____  ⓑ ____` 답 칸**, **`(  )(  )( ★ )` 괄호 칸**, **`*G: Girl, B: Boy` 각주**.
- **내용이 있는 답란** — `→ A__________ a__________, I love ice hockey.` 처럼 답란 줄에
  글자가 섞여 있으면 빈 밑줄로 지우지 않고 그대로 찍는다. (1권은 밑줄만 있어 드러나지 않던 자리)

## 원고에 관해 (교재팀 확인 필요)

### 천재(소)

1. **⚠ PART 번호 충돌 — 결정 필요.** 1권 원고는 PART 5 다음 PART 7(시험 직전 5분 점검)
   로 건너뛰고, **2권 원고의 PART 6 이 실전 모의고사**다. 즉 원고의 결번은 실수가 아니라
   2권 자리를 비워 둔 것으로 보인다. 지금 조판은 1권을 지시대로 1~6 으로 재번호해
   두었으므로 **두 권에 PART 6 이 각각 다른 이름으로 존재한다.**
   `book.py` 의 1권 파트 목록에서 6 → 7 로 고치면 원고대로 돌아간다(한 줄).
   섹션 번호(1-2 → 1-3, 2-3 → 2-4 …)가 두 권에 걸쳐 이어지는 것도 같은 근거다.
2. **1권에 정답이 없다** — 빈칸·배열·영작 문제의 답이 원고에 없어 조판에도 없다.
   정답지 원고가 나오면 별도 파트로 조판해 뒤에 이어 붙인다.
3. `10. different [형] 다른, 여러 가지의 (difference 차이) (difference 차이)` — 같은
   괄호가 두 번 적혀 있다. 조판에서는 한 번만 찍었다.

**2권 원고 개정(2026-08-27)** — `…_2권(응용·실전).docx` → `…_2권(홀로새김).docx`.
모의고사가 **4회 → 5회**로 늘고 섹션 머리의 난이도 꼬리(`1회   기본`)가 빠졌다.
단락 1,619 → 1,736, 면 82 → 88. 이전 원고는 `원고/_이전본/` 에 있다.
⚠ **같은 권 원고를 두 벌 두지 말 것** — `book.manuscript()` 가 이름 순 마지막을 고르므로
어느 쪽으로 조판됐는지가 파일 이름에 걸린다. 두 벌이면 경고를 찍지만, 애초에
안 쓸 원고는 `원고/_이전본/` 으로 옮긴다.

### 동아(윤)

1. 5분 점검이 원고에 **PART 6** 으로 적혀 있다(천재(소)는 PART 7). 조판은 원고
   순서대로 재번호하므로 결과는 두 교재가 같다 — 고칠 것 없다.
2. 대화 스크립트 라벨이 `Watch and Talk` / `Speak Up` / `Talk and Play` / `Review`
   다(천재(소)는 `LISTEN AND TALK`). 파서는 라벨 글자를 보지 않고 구조로 읽으므로
   그대로 통과했다. **여기서 막히면 문자열 화이트리스트가 남아 있다는 뜻이다.**
3. 1권에 정답이 없는 것은 천재(소)와 같다.
4. 2권 `실전`(1-3·2-6·3-7·4-6·5-3) 섹션에는 **지문 묶음이 없다** — 문항마다 짧은
   지문이 붙는 형식이다(천재(소) 2권은 `[01~04]` 묶음이 있었다). 원고를 확인했고
   파서가 놓친 것이 아니다. 묶음 25개는 전부 PART 6 모의고사에 있다.

### 지면 스윕에서 고친 것 (2026-09-02)

1. **문항 블록 번호가 render 와 pagecheck 사이에서 어긋나 있었다.**
   `split_setq_tail()` 이 원고 한 블록을 머리·꼬리 두 조각으로 자르면서 조각마다
   번호를 매겨, 자르기가 한 번 일어난 뒤로는 "여백 조임"·"머리 넘김" 지시가 **엉뚱한
   블록**에 걸렸다(그래서 세 단계까지 조여도 고아 문항이 안 잡혔다). 이제 번호는
   **자르기 전 원고 순서**로 매기고(`_qgi`), 조각은 그 번호를 같이 쓴다.
2. **섹션의 첫 묶음을 왼쪽 면으로 밀면 표제만 앞 면에 덜렁 남았다.** 끊김을
   `.sechd` 에 걸면 부모 `.sec{break-before:page}` 에 먹히므로 **`.sec.bl` 로 섹션째**
   민다. 그래서 비는 앞 면의 메모 면도 섹션 **앞**에 세운다.
3. **하나만 남은 마지막 문항** — 세 단계까지 조여도 안 담기면 바로 앞 문항까지 같이
   넘긴다(`.qi.pb`). 둘이 넘어가는 건 괜찮고 하나만 남으면 안 된다는 규칙.
4. **조임이 지나쳐 본문이 꼬리말 자리로 내려오면 그 조임을 되돌린다.**
   `pagecheck.spills()` 를 스윕 안에서도 잰다(전에는 verify 에서만 잡혀 손으로 풀었다).
5. **유형 글자를 A~H 로 못 박아 둔 탓에 `I.`·`J.` 발문이 통째로 본문으로 인쇄됐다**
   (동아윤 6과 1권 16·17면, 검수 지적). 글자 목록이 아니라 **뒤에 오는 것이 한글
   지시문인가**로 가른다. verify 에 `발문이 본문 글자로 인쇄됐다` 게이트를 넣었다 —
   납품한 여섯 교재를 다시 재 보니 이 자리 말고는 없었다.
6. **`조건` 라벨만 한 줄로 적은 원고**(꺾쇠도 없고 항목은 다음 줄부터)에서 상자가
   안 만들어져 조건이 맨 글자로 인쇄됐다(검수 반복 지적). 라벨만 있는 줄도 라벨로
   본다. ⚠ 같은 자리가 **납품본 세 권에 남아 있다** — 천재소 L5 2권 87면 · 중1
   천재소 L4 2권 94면 · 천재소 L6 2권 59면(재조판은 사용자 승인 후).
7. **발문 라벨 칩이 접혔다**(`Dr.` / `Schofield`) — 발문이 두 줄이면 flex 가 칩을
   줄여 버린다. `flex:0 0 auto; white-space:nowrap`.
8. **`____ (the light, look, bright)` 처럼 힌트 앞에 붙은 군더더기 빈칸**은 걷어낸다
   (뒤에 진짜 답란이 또 있을 때만). 원고가 밑줄을 겹쳐 적은 자리다.
9. **원고가 강조를 겹화살괄호로 적은 자리**(`«틀린» 부분을 찾아`)는 책 관행대로
   **밑줄**로 바꾼다(`render.guill()`), 대조에서는 괄호를 무시한다. verify 게이트
   `강조 표시(«»)가 글자 그대로 인쇄됐다` 신설.
10. **화자가 있는 지문 줄은 이름 칸 + 말 칸 두 칸으로 세운다** — 말이 두 줄이 되면
    다음 줄이 이름 밑으로 내려가 들여쓰기가 어긋났다(검수 지적). `.setq .pass` ·
    `.qpass` 공통. 첫 줄 자리는 그대로다(칸 너비 = 이름 그대로).
11. **지문 상자는 양쪽 정렬**(`text-align:justify`) — 왼쪽 정렬이라 오른쪽 끝이
    들쭉날쭉했다(검수 지적).
12. **회색 잔글씨(해석)와 본문이 한 목록 안에서 섞였다**(검수 지적). 마커가
    이어지는 줄 묶음(ⓐⓑⓒ · (1)(2)(3) · ①②③)은 **한 몫**이다 —
    `render._series_kinds()` 가 묶음 안에 본문 줄이 하나라도 있으면 전부
    본문으로, 아니면 전부 굵은 한글로 맞춘다. 한글만 있다고 해석으로 낮추면
    같은 목록에서 크기·색이 갈린다.
13. **대화는 양쪽 정렬하지 않는다** — 낱말 사이가 벌어져 어수선했다. 양쪽 정렬은
    줄글 지문에만(`.tx{text-align:left}`).
14. **선지 하나에 대화가 통째로 들어온 자리**는 말차례마다 줄을 나눈다
    (`render.dlg_lines()`, 말차례 둘 이상일 때). 한 줄로 이으면 누가 무슨 말을
    했는지 안 보인다.
15. **`<예시>` 는 보기 조각이 아니다** — 상자 아래 `예시` 라벨을 달아 따로 세운다
    (`.egrow`). 같은 칩으로 세우면 고를 거리로 읽힌다.
16. **역할이 다른 것을 한 상자에 담지 않는다** — `<보기>` 안에 `(A)___ (B)___`
    답란이 조각처럼 섞여 있었다. 기호와 밑줄뿐인 조각은 답란으로 보고 상자 밖에
    세운다(`.bankans`).
17. **답란 줄은 글 시작점을 본문(7mm)에 맞추고 화살표만 왼쪽에 건다** — 화살표째
    왼쪽 끝에 붙어 있어 위의 `(1) …` 줄과 어긋나 보였다.
18. **혼자 말하는 지문(화자 하나)의 이름 없는 줄은 그 말의 이어지는 줄** — 상자
    왼쪽 끝으로 나가지 않고 이름 칸만큼 들여쓴다. 화자가 둘 이상이면 손대지 않는다
    (그런 지문의 이름 없는 줄은 서술이다).
19. **`(     )` 는 기호 써 넣는 칸** — HTML 이 잇단 빈칸을 하나로 줄여 손톱만 한
    괄호가 됐다. 8mm 칸으로 세운다(`.pslot`).
20. **라벨+빈칸 줄(`(1) 기호: ___`)은 본문이 아니라 답란** — 역할이 바뀌는 자리라
    앞에서 간격을 벌린다. 답란 바로 앞의 안내 줄(`<기호> → <바르게 고친 문장>`)도
    답란과 한 몫이다.
21. **지문 없이 문항 범위에만 걸친 안내문**(`[10~11] 다음 우리말을… 각각
    7단어로 영작하시오.`)은 지문 상자를 안 낸다 — 바로 뒤가 지문 없이 번호
    문항으로 곧장 이어지면(비상(황) 6과 2권) 파서가 만든 `setq` 는 지문이

    건드리면 이 책 다른 곳(2권에만 55곳)의 멀쩡한 자리까지 흔들리므로,
    **이 자리 하나만** `book.py` 의 `errata` 로 칸을 줄였다(30자→10자,
    답 `Jo could water the plants alone` 은 여전히 다 들어간다) — 문단이
    세 줄로 고르게 다시 짜였다. ⚠ **`build.py` 는 `gen_data.py` 를 부르지
    않는다** — `errata`/원고를 고쳤으면 `extract.py` 뒤에 **`gen_data.py`
    를 손으로 한 번 더 돌려야** 새 raw.json 이 data.json 에 반영된다(안
    돌리고 build 만 하면 조용히 옛 데이터로 찍는다 — 이번에 한 번 걸렸다).
38. **문항 사이 간격을 한 번 더 벌렸다**(사용자 지적: "문제들끼리 너무
    붙어있어"). 처음엔 `.qi{padding:2.2mm→2.6mm}`·`.qs.boxed .qi{3.2mm→3.6mm}`
    (일반 간격)만 올렸는데 **57쪽은 하나도 안 넓어졌다** — 그 구간은 이미
    `여백 조임(tight/tight2/tight3)` 이 걸려 있어서, 일반 간격을 아무리
    올려도 조임 값(1.5/1/.7mm)이 그대로 이겨 버렸다(조임 값은 일반 간격과
    무관한 별도 상수). **조임 3단계 값도 다 같이 올렸다**(1.5→1.8·1→1.2·
    .7→.8mm, 2단 목록도 비례해서). build 의 여백 조임 스윕이 늘어난 만큼을
    두 번 다 자동으로 흡수해 **면수는 그대로**(92p, 2026-08-28 지시 때
    총 14쪽 늘었던 것과 다르다). ⚠ **이 값들도 전역 상수라 15권 전부에
    적용된다** — 1권도 뒤이어 다시 뽑아 함께 적용했고(104p 그대로), 나머지
    14권은 재조판하지 않았다.
39. **비교 카드(`compare`, 「비교」)에서 라벨·값으로 안 갈리는 줄(`tall -
    tallest / quiet - quietest / …` 처럼 원고에 두 칸 띄어쓰기가 없는 예시
    줄)이 통째로 라벨 칸(`.k`, 진한 파트색)에 들어가 값 칸이 비었다**
    (사용자 지적: "하단의 개념이라 검은색 글씨로"). ⚠ 처음엔 칸이 하나면
    무조건 `cont` 로 냈다가 **`-est 를 붙일까, most 를 앞에 둘까` 같은
    진짜 소제목 줄까지 예시체로 눌러 카드 정렬이 뒤죽박죽** 됐다(재지적:
    "정렬이 너무 이상하잖아"). 칸이 하나인 줄도 **영문이 대부분이면
    예시**(`cont`, 값 색) · **우리말이 대부분이면 다음 줄들을 여는
    소제목**(라벨색 그대로)으로 한글·영문 글자 수로 가른다(아래 "잠복
    자리" 정정 참고 — 첫 시도 때 비상(황) L5 1권도 결함으로 잘못 짚었다).
40. **빈출 불규칙 변화 표에서 뜻(`.k`)이 유난히 긴 자리(`can - could
    ~할 수 있다; ~해도 된다 ( could 는 can 의 과거형 )`)가 활용형(`.f`)까지
    같이 눌러 `can -` 다음 줄에 `could` 로 줄바뀜됐다**(사용자 지적:
    "can - could로 위치하도록"). `.irow` 가 `display:flex` 라 뜻이 길면
    짧은 활용형까지 같이 눌린다 — 활용형은 안 줄어들게(`flex:0 0 auto;
    white-space:nowrap`) 고정하고 뜻만 준다. 그래도 뜻이 워낙 길어 괄호
    `)` 하나만 다음 줄로 떨어졌다(재지적: "자간 줄여서... 한 줄로") —
    `.irow .k` 자간을 `-.03em` 줄였다.
41. **영문 글자 바로 뒤에 한글 조사·어미가 공백 없이 붙는 자리(`the를`·
    `A가` 등, 원고가 늘 이렇게 붙여 쓴다)가 활자가 붙어 보였다**(사용자
    지적: "글씨가 붙어서... 간격 조금 넓게"). 얇은 공백(U+2009)을 끼우는
    구조 규칙을 **모든 텍스트 출력 경로**(`t()`/`runs()`)에 넣었다 — 이
    패턴은 문법 설명에서 책 전체에 아주 흔하다(이 책 1권에만 345곳). ⚠ verify 대조(`pagecheck.norm` 이 모든 공백을 지운다)에는
    걸리지 않아 원고 대조는 그대로 엄격하다 — 15개 볼륨 재확인 결과
    게이트 전부 통과. **이미 납품한 15권도 다음에 다시 뽑으면 전부
    적용된다**(재조판은 승인 후 — 전부 좋아지는 방향이라 위험은 없지만
    면수가 미세하게 늘 수 있다).
42. **비교 카드 안에서 규칙마다 "라벨+값 한 줄" · "라벨만 있고 값은 다음
    줄에 들여쓰기" 가 섞여 있어 정렬이 들쭉날쭉해 보였다**(항목 39 정정
    이후 재지적: "정렬이 들쭉날쭉해서 이상하다... 도대체 무슨 기준으로
    맞추는 건데"). 사용자가 기준을 정해 줬다 — **값이 한 줄뿐이면 라벨과
    한 줄에, 예시 줄이 따로 딸려 값이 사실상 2줄 이상이면 라벨을 떼어
    값도 예시와 나란히 들여쓴 줄로**. 다음 줄이 예시(`cont`)인지 미리
    한 줄 보고 결정한다. ⚠ **이미 납품한 책에도 같은 자리 있다** — 재조판
    승인 후: 중2 천재(소) L5 1권 2곳 · 중2 동아(윤) L5 1권 2곳.
    ⚠ 재지적("두 줄짜리는 들여쓰기 없애") — 두 줄 구조로 뗀 값·예시 줄의
    들여쓰기(`padding-left:8mm`)를 없애 라벨과 같은 왼쪽 끝에 맞췄다.

## 비교 카드 예시 줄이 라벨색으로 찍힘 (2026-09-05 발견, 잠복 아님으로 정정)

`compare`(「비교」) 카드에서 칸이 하나뿐인 줄(라벨·값으로 안 갈리는 줄)이
라벨 칸(`.k`, 진한 파트색)에 통째로 들어가 값 칸이 비었다(항목 39 참고).
처음엔 "칸이 하나면 전부 예시"로 보고 고쳤다가, **오히려 진짜 소제목
줄까지 예시체로 눌러 카드 전체 정렬이 뒤죽박죽 됐다**(사용자 재지적:
"정렬이 너무 이상하잖아"). 실제로는 칸이 하나인 줄에도 두 갈래가 있다 —
`tall - tallest / …` 처럼 **영문이 대부분이면 예시**(값 색), `-est 를
붙일까, most 를 앞에 둘까` 처럼 **우리말이 대부분이면 다음 줄들을 여는
소제목**(라벨색 그대로가 맞다). 한글·영문 글자 수로 가르게 고쳤다.
⚠ **이전 항목에 "비상(황) L5 1권에도 잠복" 이라고 적었던 것은 정정한다**
— 그 줄(`배수사는 첫 번째 as 앞에…`)은 우리말 문장이라 애초에 결함이
아니었다(다시 재보니 라벨색이 맞는 자리).
