## 1. 최소 실행 예제 — HTML + CSS 한 벌 → A4+도련3mm PDF ✅검증됨

새 교재 폴더에 파일 셋(`index.html`·`theme.css`·`build.py`)만 두면 된다.
아래 그대로 돌려 **3쪽 / MediaBox 216×303 / TrimBox 210×297** 을 확인했다.

### `theme.css`

```css
/* A4(210×297) + 도련 3mm = 216×303mm */
@font-face { font-family:"Pre"; src:url("fonts/Pretendard-Regular.otf"); font-weight:400; }
@font-face { font-family:"Pre"; src:url("fonts/Pretendard-Bold.otf");    font-weight:700; }
@font-face { font-family:"HN";  src:url("fonts/HelveticaNeueLTStd-Lt.otf"); font-weight:400; }

@page {
  size: 216mm 303mm;              /* 재단 210×297 + 사방 3mm */
  margin: 23mm;                   /* 재단선 기준 20mm + 도련 3mm */
  background: linear-gradient(#0b5,#0b5) no-repeat 0 0 / 216mm 13mm;  /* 재단선까지 닿는 색면 */
  @bottom-right-corner {
    content: counter(page);
    vertical-align: top; padding-top: 9mm; padding-left: 4mm;
    font: 7pt/1 "HN"; color: #666;
  }
}
@page :left  { margin-left: 20mm; margin-right: 26mm; }   /* 바깥 17 / 안쪽 23 + 도련 3 */
@page :right { margin-left: 26mm; margin-right: 20mm; }

html, body { margin: 0; padding: 0; }
body { font: 400 10pt/1.6 "Pre"; color:#231f20;
       line-break: strict; hyphens: none; word-break: keep-all; }
.pagebreak { break-before: page; }
```

### `index.html`

```html
<!DOCTYPE html>
<html lang="ko"><head><meta charset="utf-8"><title>최소예제</title>
<link rel="stylesheet" href="theme.css"></head>
<body>
<h1>A4 + 도련 3mm 최소 예제</h1>
<p>본문…</p>
<div class="pagebreak"><h1>둘째 면</h1></div>
</body></html>
```

### `build.py` — 서체 스테이징 → CLI → TrimBox 각인

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import os, shutil, subprocess, sys
import fitz

HERE  = os.path.dirname(os.path.abspath(__file__))
BUILD = os.path.join(HERE, "build")
CLI   = os.path.expanduser(
    "~/dev/yone-design-web/core/render_vivlio/node_modules/.bin/vivliostyle")
FONTS = ["Pretendard-Regular.otf", "Pretendard-Bold.otf",
         "HelveticaNeueLTStd-Lt.otf"]
OUT   = os.path.join(HERE, "최소예제.pdf")
BLEED, PT = 3.0, 72 / 25.4

os.makedirs(os.path.join(BUILD, "fonts"), exist_ok=True)
for n in FONTS:                                   # ① 서체 스테이징
    src = os.path.expanduser(f"~/Library/Fonts/{n}")
    if not os.path.exists(src):
        sys.exit(f"서체 없음: {src}")
    shutil.copy2(src, os.path.join(BUILD, "fonts", n))
for n in ("index.html", "theme.css"):             # ② HTML/CSS 배치
    shutil.copy2(os.path.join(HERE, n), os.path.join(BUILD, n))

r = subprocess.run([CLI, "build", "index.html", "-o", OUT], cwd=BUILD)   # ③ 조판
if r.returncode:
    sys.exit(f"vivliostyle 실패({r.returncode})")

doc = fitz.open(OUT)                              # ④ TrimBox 각인
for pg in doc:
    mb = pg.mediabox
    pg.set_trimbox(fitz.Rect(mb.x0 + BLEED*PT, mb.y0 + BLEED*PT,
                             mb.x1 - BLEED*PT, mb.y1 - BLEED*PT))
tmp = OUT + ".tmp"
doc.save(tmp, garbage=3, deflate=True); n = doc.page_count; doc.close()
os.replace(tmp, OUT)                              # 임시 → replace (반쪽 저장 방지)
```

```bash
python3 build.py
#  SUCCESS Finished building ../최소예제.pdf
#  ■ 3p  Media [0.0, 0.02, 216.0, 303.02]  Trim [3.0, 3.02, 213.0, 300.02]
```

**핵심 3줄**
1. `cd <html 있는 폴더> && vivliostyle build index.html -o <절대경로>.pdf`
2. 서체는 `build/fonts/` 에 복사하고 `@font-face src:url("fonts/…")` 로 물린다.
3. TrimBox 는 CSS 가 못 찍는다 — **PyMuPDF 로 마지막에** 찍는다.

## 2. A4 + 도련 3mm 정확한 레시피

### 원칙 — 도련은 옮기는 게 아니라 **늘리는 것**

판형 210×297 + 도련 3mm → 페이지는 **216×303mm**, 재단선 원점 (3,3).
본문 위치는 **재단선 기준으로 그대로** 두고 여백에 도련만 더한다.
재단선에 닿는 **색면만 3mm 더 그린다**.

| 값 | 계산 | A4+3mm |
|---|---|---|
| `@page size` | (W+2b) × (H+2b) | `216mm 303mm` |
| 여백 | 재단선 기준 여백 + b | 20mm → `23mm` |
| TrimBox | MediaBox 원점 + b … − b | 210×297 |

`config.py` 의 `cfg.page` 가 `media_w = width + 2*bleed` 를 자동으로 만든다
(계열 테마 생성기는 이 값만 쓰면 된다 — `series/vocaunit/theme.py: prelude()` 참고).

### TrimBox 각인 코드 (공용)

`core/render_vivlio/bleed.py: stamp_trimbox()` 가 정본이다.

```python
PT = 72 / 25.4

def stamp_trimbox(doc, bleed=3.0, trim=None, log=None):
    """전 면에 TrimBox 지정. MediaBox **원점 기준**으로 찍는다."""
    import fitz
    n = 0
    for pg in doc:
        mb = pg.mediabox
        if trim:                        # trim=(x0,y0,x1,y1) mm 직접 지정
            r = fitz.Rect(mb.x0 + trim[0]*PT, mb.y0 + trim[1]*PT,
                          mb.x0 + trim[2]*PT, mb.y0 + trim[3]*PT)
        else:
            r = fitz.Rect(mb.x0 + bleed*PT, mb.y0 + bleed*PT,
                          mb.x1 - bleed*PT, mb.y1 - bleed*PT)
        pg.set_trimbox(r); n += 1
    return n
```

- ⚠ **`set_cropbox` 를 먼저 부르면 TrimBox 가 되돌아간다.** TrimBox 만 찍는다.
- ⚠ **MediaBox 원점이 0 이 아닐 수 있다.** 실측에서 `y0 = 0.02mm` 가 나왔다
  (위 검증 로그). 절대좌표 `fitz.Rect(3*PT, 3*PT, 213*PT, 300*PT)` 로 찍으면
  0.02mm 어긋난다 — 반드시 `mb.x0 + …` 형태로.
- 인쇄 원고까지 갈 거면 BleedBox 도 같이 (`prepress.stamp_boxes()`).
- ⚠ **Ghostscript(CMYK 변환)는 TrimBox/BleedBox 를 흘려버린다** → 변환 뒤 다시 찍는다.
- ⚠ 마감 저장은 **항상 임시 파일 → `os.replace`**. 교재 폴더는 클라우드 동기화
  경로라 큰 저장이 `Operation timed out` 으로 끊길 수 있고, 목적지에 직접 쓰면
  납품본이 반쪽짜리로 덮인다(실제 사고).

### 검수 게이트

## 3. `@font-face` 스테이징 레시피

**서체는 리포에 넣지 않는다**(라이선스·용량). `~/Library/Fonts` 의 로컬 설치본을
빌드 디렉터리로 복사해서 상대 URL 로 물린다.

### 공용 함수 — `core/render_vivlio/stage.py`

```python
from core.render_vivlio import stage

stage.FONT_DIRS   # ["~/Library/Fonts", "/Library/Fonts", "/System/Library/Fonts"]
stage.find_font("Pretendard-Bold.otf")          # → 절대경로 or None
stage.stage_fonts(build_dir, fonts, log, required=True)   # build_dir/fonts/ 로 복사
```

`required=True` 면 하나라도 없을 때 예외(블랙북 정책 — 서체가 빠지면 판면이 통째로
달라진다). `False` 면 경고만(상일보카 정책). **신규 계열은 `True` 를 권장.**

### config → `@font-face` 생성 (계열 테마 생성기 패턴)

```jsonc
// config.json
"fonts": [
  { "family": "Pre", "file": "Pretendard-Regular.otf", "weight": 400 },
  { "family": "Pre", "file": "Pretendard-Bold.otf",    "weight": 700 },
  { "family": "HN",  "file": "HelveticaNeueLTStd-Lt.otf", "weight": 400 },
  { "family": "Kor", "file": "비트로 코어 OTF.otf", "as": "VitroCore.otf" }
]
```

```python
for f in cfg.get("fonts") or []:
    st = f" font-style: {f['style']};" if f.get("style") else ""
    fn = f.get("as") or os.path.basename(f["file"])     # ASCII 별칭 우선
    out.append(f'@font-face {{ font-family:"{f["family"]}"; '
               f'src:url("fonts/{fn}"); font-weight:{f.get("weight",400)};{st} }}')
```

### 함정

- ⚠ **한글·공백이 든 파일명은 NFD/NFC 때문에 `os.path.exists` 가 조용히 실패한다.**
  macOS 파일시스템은 NFD, config 는 NFC. 찾을 때는 정규화해서 찾고, 빌드
  디렉터리에는 config 의 `as` **ASCII 별칭**으로 놓는다
  (→ `series/vocaunit/__init__.py: _find_font()`).
- ⚠ **설치본에 기대한 굵기가 없을 수 있다.** 이번 검증에서 `HelveticaNeueLTStd-Roman.otf`
  는 없고 `-Lt/-Bd/-Hv/-Blk/-Th` 만 있었다. `@font-face` 를 쓰기 전에
  `ls ~/Library/Fonts | grep -i <이름>` 으로 **실제 파일명을 확인**할 것.
- ⚠ **Vivliostyle 출력의 서체는 전부 `Type3` 로 나간다.** 이번 검증에서도
  `get_fonts(full=True)` 가 `(5,'n/a','Type3','','F5','',0)` … 글리프마다 하나씩
  32개가 잡혔다. **서체 이름으로 하는 검사는 아무것도 못 찾고 조용히 통과한다** —
  크기(pt)·위치로 판정할 것.
- 복사는 mtime 비교로 변경분만(서체가 크다). `stage.stage_fonts` 가 이미 그렇게 한다.
- 서체 파일 자체는 `build/` 에 남으므로 `.gitignore` 대상.

## 4. 마진 박스 / 러닝 요소 — 사용법과 금지사항

### 쓰는 법

```css
@page {
  @top-left     { content: element(hdrL); vertical-align: top; }
  @bottom-left  { content: element(footL); vertical-align: top; }
  @bottom-right-corner { content: counter(page); font: 6pt/1 Noto; }
}
.hdr-l  { position: running(hdrL); width: 216mm; height: 20mm; }
.foot-l::before { content: counter(page); }
```

- 러닝 요소는 본문에 두고 `position: running(<이름>)` → 마진 박스에서
  `content: element(<이름>)` 으로 꺼낸다.
- 좌/우 면 구분은 `@page :left` / `@page :right` 에서 슬롯을 갈아 끼운다.
  꺼야 하는 슬롯은 `content: none`.
- 최소 예제에서 `@top-center` `@top-right` `@bottom-center` `@bottom-right-corner`
  **네 슬롯 모두 동작**(11.1.0 검증). 아래 "무시된다"는 사례는 **조건부**다.

### 금지·주의 (전부 실제로 데인 것)

| 하면 안 되는 것 | 무슨 일이 벌어지나 |
|---|---|
| `position: relative` | `position: running()` 이 덮여 **본문에 그대로 그려진다** |
| `transform: rotate()` | 무시된다 (마름모가 네모로 나옴) |
| `visibility: hidden` | 무시된다 → 감추려면 색·배경을 `transparent` 로 |
| 세로 음수 마진 | 잘린다. **가로 음수 마진 + 같은 크기 패딩**만 통한다 |
| 여백보다 큰 요소 | 잘린다 (13mm 여백에 16mm 탭 → 꼭짓점 소실) |
| 러닝 요소 높이 미지정 | 배경이 요소 상자 안에서만 그려져 **탭·로고 아래가 잘린다** → `height: <상단 여백>` 이 정답 |
| `@top-right` 에 넓은 요소 | 슬롯 폭이 좁아 잘린다 → 좌우 면 다 `@top-left` 슬롯을 쓰고 마진으로 민다(광문보카) |
| `@bottom-center` 의존 | 블랙북에서 **무시된 사례**가 있다. 쪽번호는 `@bottom-*-corner`(여백 밖으로 넘쳐도 안 잘림), 문구는 배경 이미지로 우회 |

**결론: 마진 박스 안의 도형은 예외 없이 배경 SVG.** 글자가 들어가는 것만
"배경 SVG(도형) + 러닝 요소(글자)"로 나눈다. 헬퍼는 `core/render_vivlio/svg.py`.

### 러닝 요소를 특정 면에서 끄기

```css
.hdr-l.off, .hdr-r.off { background: none !important; }
.hdr-l.off *, .hdr-r.off * { color: transparent !important; }
.foot-l.off::before { content: none; }
```

간지 면처럼 표식이 없어야 하는 면에서도 **러닝 요소 자체는 남는다** — 배경과
글자색을 지우는 방식으로 끈다.

## 5. Vivliostyle 함정 총목록

> 출처: `core/render_vivlio/*.py` 주석 · `themes/*.css` 머리주석 ·
> `docs/vivliostyle_엔진.md` · 블랙북 독립형 선례 · **이번 검증에서 새로 확인한 것**

### 5.1 배경 · 도형

- ⚠ **`@page` 배경은 층마다 position/size 를 명시**해야 한다. 안 하면 뒤 층이 앞 층
  크기를 물려받아 방패 뒤에 회색 띠 조각이 찍힌다.
- ⚠ **`repeating-linear-gradient` 는 주기가 어긋난다** → 줄을 하나씩 그린 SVG
  data URI 로 (`svg.hrules()`).
- ⚠ **얇은 괘선을 `linear-gradient` 의 색 정지점으로 그리면 72dpi 로 래스터화돼
  사라진다** → 단색 그라디언트를 **선 두께만 한 상자**로 (`svg.hairline()`).
- ⚠ **아래 괘선을 배경으로 깔면 페이지마다 3260×5px 래스터 이미지가 항목 수만큼
  나간다.** 광문보카에서 250여 개, 위 border(벡터)와 겹쳐 70곳이 165㎛ 대신
  198㎛ 로 보였다 → 흐름 상자에 `box-decoration-break: clone` 으로 두면 면마다
  한 번만 그려진다.
- ⚠ **배경 축약형에 `no-repeat` 를 두 번 쓰면 선언이 통째로 무시된다.**
  `svg.data_uri()` 는 이미 `no-repeat` 를 붙여 돌려준다 — 뒤에 또 붙이면
  CSS 파서가 그 배경을 버린다(도형이 조용히 사라진다).
- ⚠ **배경 SVG 안에는 CSS 변수를 못 쓴다** — 색이 파일에 구워진다. 팔레트를 바꾸면
  **반드시 생성기를 다시 돌릴 것**(안 그러면 띠·밴드만 옛 색으로 남는다 — 두 번 발생).
  `#` 는 data URI 안에서 프래그먼트로 잘리므로 `%23` (→ `svg.h()`).
- ⚠ **자산 PNG 는 팔레트를 따라가지 않는다.** 지면 색을 바꿔도 PNG 로고만 옛 색으로
  남는다 → 빌드마다 다시 굽는다(`series/vocaunit/assets.py: retint()`).
- ⚠ **좌표를 옮기면 박스(width/height)도 같이 키울 것.** 안 키우면 도형이 박스 밖에서
  잘린다(태그 바닥·접힌 꼬리가 실제로 사라졌다).
- ⚠ **`border-radius` 는 자식을 자르지 않는다** → 장식은 배경 SVG.
- ⚠ **`clip-path` + `filter: drop-shadow()` 를 같이 주면 요소가 통째로 사라진다.**

#### ✅ 이번 검증에서 새로 확인한 것 — 배경 종류별 PDF 산출물이 다르다

같은 색면을 세 방법으로 깔고 PDF 를 뜯어봤다.

| CSS | PDF 산출 | `get_drawings()` 에 보이나 | `prepress` 색 치환 대상인가 |
|---|---|---|---|
| `background-color:#0b5` | `rg` 채우기 (벡터) | **보인다** | **된다** |
| `linear-gradient(#b05,#b05)` | **PatternType 2 축 셰이딩** (`/P3 scn`) | **안 보인다** | **안 된다** |
| SVG data URI `<rect fill>` | `rg` 채우기 (벡터) | **보인다** | **된다** |

의미:

1. `verify.check_bleed_coverage()` · `check_box_cut()` 는 `probe.drawings_mm()`
   = `get_drawings()` 기반이다 → **그라디언트로 깐 색면·괘선은 게이트가 못 본다.**
   "도련 미달 0건"이 안전을 뜻하지 않는다.
2. `prepress.neutralize()` 는 콘텐츠 스트림의 `r g b rg` 를 치환한다. 그라디언트
   색은 `/Shading << /Function << /C0 [0 .7333 .3333] …` 안에 있어 **치환을 비껴간다**
   → 회색 띠를 그라디언트로 깔면 K 단색이 아니라 **ICC 4도**로 나간다.
3. 그래서: **색이 인쇄까지 정확히 가야 하는 색면은 `background-color` 또는
   SVG data URI 로.** `linear-gradient` 는 "배경 상자 크기를 지정하려는" 목적일
   때만 쓰고, 그 색은 `gray_map`/`cmyk_map` 으로 안 잡힌다는 걸 알고 쓴다.

### 5.2 페이지 · 나눔

- ⚠ **`@page :nth(N)` 은 `@page p-body` 같은 이름 규칙에 명시도로 밀린다.**
  이름과 **함께** 써야 먹는다: `@page p-body:nth(7), p-head:nth(7) { … }`
  (→ `paged.nth_rule()`). 빠뜨리면 "규칙을 넣었는데 안 먹는다".
- ⚠ **2열 항목을 flex 로 짜면 `break-inside: avoid` 가 마지막 항목에서 무시된다**
  (판면 아래 띠까지 넘침) → `display:table` + `table-cell`.
- ⚠ **`.x:first-of-type` 은 앞에 있는 같은 부모의 형제 때문에 안 맞는다** →
  `.x + .x` 인접 선택자.
- 강제 개면으로 생긴 빈 면은 `@page <이름>:blank` 로 잡는다(MEMO 면 처리).
- `break-before: left` 로 항상 왼쪽에서 시작시키면 흔들림이 그 경계를 못 넘는다 —
  2패스 수렴의 안전장치.

### 5.3 텍스트 · 마크업

- ⚠ **`text-indent` 는 inline-block 안까지 상속된다.** 뜻 문단 내어쓰기가 품사
  배지 안에서 또 걸려 글자만 상자 밖으로 밀렸다 → 배지에 `text-indent: 0`.
- ⚠ **테두리 있는 inline-block 에 `line-height:<상자 높이>` 를 주면 글자가
  내려앉는다**(줄 상자가 테두리 두께의 2배만큼 커진다) → `calc(높이 − 2×테두리)`.
- ⚠ **원고의 연속 공백은 의미 구분 간격이다** — HTML 은 공백을 축약한다. 보존할 것.
- ⚠ **렌더러에서 태그를 닫지 않으면 DOM 이 중첩돼 열 폭이 계속 좁아진다.**
- ⚠ **원고 주석 제거 정규식은 중첩 괄호에서 조용히 실패한다**
  (`(= judg(e)ment)`) → 여는 자리만 찾고 **닫는 자리는 깊이를 세어** 찾는다.
- ⚠ 2패스용 보이지 않는 마커에 `<u>` 를 쓰면 `text-decoration:none` 없이는
  **투명한 사각형 도형**이 남아 프리플라이트에 걸린다.
- 한국어 본문 기본값: `line-break: strict; hyphens: none; word-break: keep-all;
  overflow-wrap: break-word;`

### 5.4 "다시 조판" 두 가지 — 섞지 말 것

| | 2패스 면 지정 | 높이 측정 배치 |
|---|---|---|
| 쓰는 곳 | 단어장(vocabook/vocaunit) | 블랙북 |
| 재는 것 | 시작 면 **번호** (보이지 않는 마커) | 항목별 **자연 높이 mm** |
| 두 번째 패스가 바꾸는 것 | 마진 박스 **내용**과 `@page` 배경만 | 없음 — 잰 값으로 본 조판을 **한 번에** |
| 안전성 | **페이지 나눔 불변** = 덧칠 → 수렴 걱정 없음 | 한 번에 끝남 |

- ⚠ **여러 면에 걸치는 흐름을 반복 조판으로 수렴시키려 하면 발산한다**
  (블랙북 해설 실측 10→8→7). 높이를 재서 펼침면 용량으로 미리 나눌 것.
- 계약을 넘는 경우(vocaunit ②는 상단 여백도 5mm 내려간다)는 **고정점에 닿을 때까지**
  돌리고 최대 패스에 안 멎으면 **경고**를 남긴다(조용히 어긋난 면에 헤더를 그리는
  것보다 낫다).

#### 높이 실측 2패스가 도는 방식 (`measure.py`)

```
① 렌더러가 "항목마다 개면"인 측정용 HTML 을 쓴다 (measure.html)
② cli.run_build(measure.html → measure.pdf)
③ probe.ink_bottom(page, top, bottom) — 머리·꼬리를 뺀 띠 안에서
   텍스트 블록 + 도형의 **가장 아래 y(mm)**
④ 높이 = ink_bottom − top + pad,  빈 면(파리티)은 건너뛴다
⑤ 측정 면 수 ≠ 항목 수 → ValueError (침묵 유실 금지)
⑥ heights.json 저장 → 본 조판이 이 값으로 슬롯을 채운다
```

```python
from core.render_vivlio import measure
h = measure.measure(html_path, out_pdf, keys=nos,
                    top=31.5, bottom=279.0, pad=1.0, log=log)
measure.save(h, "heights.json", log)
```

`top` 은 높이의 원점이자 머리 영역 경계다. 블랙북 실측값이 `top=31.5`,
`bottom=279.0` (config `metrics.body_top` / `body_bottom`).

### 5.5 인쇄 원고 (CMYK)

- ⚠ **조판 결과는 무조건 DeviceRGB.** 순수 검정도 `0 0 0 rg` 다. 그대로 ICC 변환하면
  본문 먹이 **C80 M80 Y77 K60 리치블랙** → 7pt 본문이 핀 어긋남으로 뭉갠다.
  먹·회색은 **DeviceGray 로 미리 바꾼다**(`print.gray_map`) — Ghostscript 는
  DeviceGray 를 CMYK 로 변환하지 않고 그대로 둔다.
- ⚠ 이전 판과 색을 정확히 맞춰야 하는 것은 `print.cmyk_map` 으로 못 박는다.
- ⚠ **`-dSAFER` 는 입출력 밖 파일 읽기를 막는다** — ICC 가 시스템 폴더에 있으면
  Permission denied → `--permit-file-read=<icc>`.
- ⚠ **Ghostscript 는 TrimBox/BleedBox 를 흘려버린다** → 변환 뒤 다시 찍는다.
- ⚠ `color: transparent` 마커가 **완전 투명한 리치블랙 도형**으로 남는다. 지우되
  `/Gxx gs` 는 자기 q/Q 블록 안에 있지 않으므로 앞쪽 `q` 부터 지우면 **보이는 내용까지
  날아간다** → "색 지정 + gs + 바로 뒤 BT…ET" 만 지우고 **지우기 전후 렌더를 픽셀
  비교**해 다르면 되돌린다(`prepress._same_render`).
- ⚠ **인쇄 원고는 조용히 뒤처진다.** 조판본만 다시 뽑고 인쇄본을 안 돌리면 옛 색으로
  납품된다 → `all` 에 `print` 를 포함하고, `verify` 가 mtime 으로 결함 처리한다.

### 5.6 확인 · 운영

- ⚠ **`get_drawings()` 는 클리핑 전 bbox** 다 → "좌표는 맞는데 안 보이는" 상황.
  좌표 확인으로 끝내지 말고 **고해상도 렌더로 눈으로 볼 것**.
- ⚠ **결과 PDF 를 뷰어에 열어 둔 채 다시 빌드하면** 몇 면만 남고 흰 종이로 보인다.
  파일이 통째로 교체돼(inode 교체) 뷰어 캐시가 깨진 것 — 창을 닫았다 열 것.
- ⚠ **GDrive 원본(원고·간지 아트워크)은 절대 수정하지 않는다.** 로컬 복사본으로 작업.
- 검수는 PDF 계측이 indd 덤프 자리를 메운다:
  누락/순서 · 판면 넘침 · 빈칸 유실 · 상자 면 걸침 · 준-빈면 · TrimBox · 도련 미달.
- 원고 인식 게이트(`data` 단계)는 기대 수량과 어긋나면 **조판하지 않고 중단**한다.

## 6. 신규 계열: core 엔진에 얹기 vs 교재 폴더 독립형

### 6.1 core 엔진에 얹기 (3계층)

`series/base.Series` 의 **네 훅**만 채우고 `series/__init__.py` 에 한 줄 등록한다.

```
core/render_vivlio/
  series/myseries/
    __init__.py     MySeries(Series)  — build() 오케스트레이션
    data.py         원고 → data.json (인식 게이트 내장)
    render.py       data.json → index.html
    theme.py        팔레트/치수 → build/theme.css (선택)
    assets.py       자산 재생성 (선택)
  themes/myseries.css
```

```python
# series/myseries/__init__.py
from core.render_vivlio.series.base import Series

class MySeries(Series):
    name, display, theme = "myseries", "중등 내신 정규", "myseries"

    def gen_data(self, cfg, log): ...            # 원고 → data.json
    def gen_theme(self, cfg, log): ...           # 팔레트 → 테마 (없으면 생략)
    def build(self, cfg, log, **opts): ...       # data → HTML → cli.run_build → finish
    def verify(self, cfg, log, report): ...      # 계열 고유 검사만

# series/__init__.py 에 한 줄
def _myseries():
    from core.render_vivlio.series.myseries import MySeries
    return MySeries()
register("myseries", _myseries)
```

교재 폴더에는 **`config.json` + `원고/` 만** 둔다.

```jsonc
{
  "series": "myseries",
  "book":   { "id": "중2천재소L5", "title": "…", "school": "…", "period": "26-2-중간" },
  "page":   { "width": 210, "height": 297, "bleed": 3 },
  "output": { "dir": ".", "stem": "중2_천재소_L5_내지" },
  "manuscript": { "dir": "원고", "files": { "본문": "….docx" } },
  "fonts":  [{ "family": "Pre", "file": "Pretendard-Regular.otf" }],
  "palette": {...}, "metrics": {...},
  "finish": { "art_pdf": "${STUDIO}/…", "inserts": [...], "trim": { "bleed": 3 } },
  "verify": { "frame": { "inner":23,"outer":26,"width":167,"top":25,"bottom":277.5 },
              "skip_last": 3, "blank_ignore": "0123456789MEMO§DIV" }
}
```

경로 토큰: `${BOOK}`(config 폴더) · `${STUDIO}`(스튜디오 루트) · `~`, 상대경로는 책 폴더 기준.

**얻는 것**: `bin/viv <책> all` 한 줄 · 도련/TrimBox/간지 결합/파리티 마감 ·
2패스·높이 실측 · 공용 검수 게이트 7종 · CMYK 인쇄 원고 · git 이력·롤백 ·
책 목록 자동 발견(`bin/viv --list`) · 두 번째 책은 **config 만으로**.

**드는 것**: 원고 파서와 렌더러를 계층 규칙에 맞춰 써야 한다(계열이 직접
`subprocess`·TrimBox 를 만지면 안 됨). 첫 책에서는 "무엇이 책마다 다른지"를 모르니
config 화가 과하면 추측이 된다.

### 6.2 교재 폴더 독립형 (블랙북 납품 시점 선례)

`.../블랙북/26-2-중간/_backup/automation_납품시점_20260820/` 이 원형이다:
`gen_data.py` · `render.py` · `theme.css` · `build.py` · `verify.py` · `assets/`
— 한 폴더에 전부. CLI 경로·서체 목록·간지 페이지 번호가 전부 하드코딩이고,
`postprocess()` 안에 TrimBox·간지·파리티가 손으로 다시 쓰여 있다.

**얻는 것**: 리포를 안 건드리고 바로 시작. 실험·1회성에는 빠르다.
**드는 것**: **git 이 아니다.** 다음 책에 복사하는 순간 포크가 늘고 롤백이 안 된다.
실제로 상일보카·블랙북이 각각 도련·TrimBox·간지 결합·2패스를 **다른 코드로 두 번**
썼고, 그걸 합치는 것이 지금의 `core/render_vivlio` 다.

### 6.3 권고

> **탐색은 독립형으로, 확정되면 core 계열로.** 다만 독립형 단계에서도
> 공용 백엔드를 **import 해서** 쓴다 — 복사하지 않는다.

1. **1일차 — 형태 탐색**: 위 §1 최소 예제를 교재 폴더에 두고 디자인을 맞춘다.
   이 단계에서는 `index.html` 을 손으로 써도 된다.
2. **2일차 — 공용 백엔드 붙이기**(독립형인 채로):
   ```python
   import sys; sys.path.insert(0, os.path.expanduser("~/dev/yone-design-web"))
   from core.render_vivlio import cli, stage, bleed, probe, verify, measure
   cli.run_build(html, pdf, log=print)
   stage.stage_fonts(build_dir, FONTS, required=True)
   bleed.finish(pdf, {"trim": {"bleed": 3}}, log=print)
   ```
   여기까지만 해도 §5 함정의 절반은 자동으로 피한다.
3. **3일차 — 계열 승격**: 원고 형식과 디자인이 굳으면 `series/<이름>/` 로 옮기고
   `config.json` 만 교재 폴더에 남긴다. **판정 기준: 같은 계보의 책이 두 권째
   들어오는가.** 두 권째가 계약의 구멍을 알려준다.

**어느 쪽이든 지키는 것**

- 교재 폴더의 코드는 **납품 시점에 `_backup/automation_납품시점_YYYYMMDD/` 로 동결**한다
  (블랙북·상일보카가 그렇게 남아 있다 — 회귀 기준선이 된다).
- 계열 승격 시 **납품본과 대조**: 쪽수 · 쪽별 텍스트 · 텍스트 블록 좌표.
  기존 두 책은 좌표 차이 0.000mm 로 재현됐다.
- 계열 테마의 config 화 정도는 **책 수에 비례**한다. 한 권짜리 계열은 실측값을
  테마 CSS 에 그냥 둔다(블랙북). 넷이면 전부 뺀다(단어장).
