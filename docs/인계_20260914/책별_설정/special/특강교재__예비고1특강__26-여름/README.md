## 원고

`원고/예비고1_특강_합본_내지(수정2).docx` (GDrive 원본의 로컬 복사본).
검수를 거치며 두 번 개정됐다(2026-08-28). `(수정)` 은 정답·해석 오기,
`(수정2)` 는 **어법 문제의 밑줄**(고칠 자리 표시)을 넣은 판이다. 앞의 판들도
남겨 뒀다 — **`config.json` 이 가리키는 쪽이 조판본**이다.
**단락 스타일에 의미가 붙어 있는 원고**라 파서가 정규식을 쓰지 않는다 —
`Week제목`·`지문`·`해설항목` 같은 스타일 이름이 곧 구조다. 모르는 스타일이
나오면 조용히 버리지 않고 게이트로 세운다.

원고가 색으로 표시한 것(문항 번호 남색·출처 회색·정답 남색·품사 올리브)은
파서가 **이름**(`num`/`src`/`pos`)으로 바꿔 담는다. 조판 색은 테마가 정한다.

⚠ 낱말 예문의 출처(`26년 고1 6월`)는 원고에서 **흰 글자 6.5pt** 로 숨어 있다.
조판에서는 옅은 회색 꼬리표로 **보이게** 넣었다. 숨기려면 렌더러의 `r-src` 를
`color: transparent` 로.

## 디자인 — 위계로 읽히게

"덜 꾸몄는데 더 출판물처럼." 요소를 늘리지 않고 **크기·굵기·여백·위치**로 위계를
만든다. 색으로 모든 위계를 해결하지 않는다.

### 여백 눈금 4단계 · 그리드 하나

`--s1 2 / --s2 4 / --s3 9 / --s4 16mm` 넷 중 하나만 쓴다. 번호 거터 `--g 12mm` +
본문 162mm — 제목·문항 번호·작성 영역이 모두 이 두 열에 맞는다. 본문 시작 X 는
어느 면에서나 같다.

### 색 3단계

**주색과 보조색은 둘 다 부(部)마다 다르다.** 보조색은 그 주색과 **톤은 맞되 색상이
다른 짝**이다 — 같은 색의 채도만 바꾸면 2도 인쇄처럼 보인다. 보조색은 **밝은
판(`sub`)** 과 **짙은 판(`subd`)** 둘로 둔다 — 밝은 판은 머리 띠처럼 넓은 면에,
짙은 판은 글자·선 강조에. 공통색만 부와 무관하게 전권 공통이고, 어떤 주색과도
어울리는 중립 톤이다.

| 부 | 주색 | 보조색(밝은 판 / 짙은 판) |
|---|---|---|
| 어휘 | 머스터드 `#c08618` | 웜 아이보리 `#f2e7d3` / `#9a6a2a` |
| 구문·어법 | 버건디 `#96323f` | 뮤트 블루 `#d2dfe8` / `#3f6480` |
| 독해 | 올리브 `#6f7e2c` | 뮤트 핑크 `#f0d6d9` / `#a86271` |

공통색(`--n-1`~`--n-5`, 아이보리 `#fdfaf4` · 베이지 `#f4efe4` · 괘선 `#e2dccf` ·
웜그레이 `#a49c8d` · `#6b6459`)이 나머지 전부다.
한 면에서 강한 색이 나오는 자리는 2~3곳까지.

### 라벨은 셋뿐

작은 색 캡슐을 늘리지 않는다. 같은 위계의 라벨은 크기·자간을 모두 같게 쓴다.

| | 무엇 | 생김새 |
|---|---|---|
| A 대분류 | PART / WEEK / LESSON / EXAMPLE / ANSWERS | 글자만. 작고 자간 넓게, 상자 없음 |
| B 학습 포인트 | 필기 POINT · 어법 개념 · 핵심 구조 | 좌측 색 막대 + 굵은 글자 |
| C 작성 영역 | 해석하기 · 판단 포인트 · KEY POINT · NOTE | 작은 회색 글자 + **실제 줄** |

### 머리 띠 · 꼬리말

띠 바탕은 그 부의 **보조색 밝은 판**(높이 19mm)이다. 그 위에서 두 면이 지는 것이
다르다:

  · **왼쪽(짝수)** — 바깥 끝의 **각진 주색 면**(`WEEK`/`PART` + 번호) + 단원 표기
  · **오른쪽(홀수)** — 도형 없이 **책 이름 + 로고**만. 둘은 한 줄 안에서
    `vertical-align: middle` 로 **가운데를 맞춘다**(따로 앉히면 어긋난다).
    책 이름은 본문 서체가 아니라 **표시 서체(GmarketSans)** 로 — 본문체로 두면
    문서처럼 보인다.

⚠ 왼쪽 그래픽을 반전해 오른쪽에 쓰지 않는다. 단원 표기는 부마다 다르다 —
어휘 `VOCABULARY / 어근 | 뜻`, 구문·어법 `구문·어법 SYNTAX & GRAMMAR / N강 | 제목`,
독해 `READING / 유형 | 소재`.

**꼬리말**은 쪽번호 옆에 왼쪽 면은 **교재명**, 오른쪽 면은 **단원명**을 둔다
(`@bottom-left` 에 판면 폭짜리 러닝 요소). 머리와 같은 그리드에 맞는다.
머리 안의 글자는 띠 **아래쪽에 붙여** 앉힌다.

### 제목 — 번호를 떼어 세운다

`01` 을 별도 그래픽으로 왼쪽 거터에 놓고, `LESSON` 라벨 아래 제목이 중심이 된다.
제목 아래 긴 선에 기대지 않는다. 상자에 넣지 않는다.

### 부마다 다른 레이아웃 성격

  · **어휘** — 표제어가 지배한다. 시선은 표제어 → 뜻 → 어원 → 예문 → KEY POINT.
    `어근/접두사/접미사/다품사` 는 띠가 아니라 **구분선 + 라벨**로 면을 나눈다.
  · **구문·어법** — 위 절반이 개념(핵심 구조 요약이 가장 먼저), 아래가 필기 모눈.
    연습은 강마다 세 면(구문 6문항 한 면 · 어법 10문항 **5+5**).
  · **독해** — 지문 덩어리가 가장 무겁고 해석이 가장 가볍다.
    배경지식 노트는 이 교재의 특징 콘텐츠라 **독립 카드**(보조색 짙은 판 머리 +
    밝은 판 바탕)다.

우선순위: 지문+발문 > 선택지 > 학생 풀이 영역 > 배경지식 > 해석.

### 글리프 금지

원고의 `■ ● ✓ ❖ □ ❶❷` 는 전부 떼고 도형·색면·번호로 바꾼다(산출 HTML 에 장식
글리프 0개). 남은 것은 선지 `①~⑤` 와 다품사 `↔` 뿐 — 표식이 아니라 **내용**이다.

### 원고의 끊긴 지문은 이어 붙인다

지문 단락이 **소문자로 시작하면** 앞 단락이 원고에서 실수로 끊긴 것이다
(1차 산출물 p.111 의 (B) 가 '…placed from one' / 'to two miles apart…' 두 상자로
쪼개져 인쇄됐다). 영어 지문은 대문자나 `(A)`·번호로 시작하므로, 소문자로 여는
지문은 형식과 무관하게 **이어짐**이다(`_join_passages`). 전권에 1건 걸린다.

### 밑줄 — 두 번 사라졌다

어법 문제는 '밑줄 친 부분을 고치라'는 문제라 **밑줄이 곧 문제**다. 빈칸 추론의
빈칸도 밑줄이다. 이 둘이 두 번 통째로 사라졌고, 두 번 다 **전수 대조
1,978건이 그대로 통과했다** — 글자는 하나도 안 틀렸으니까.

  · `라벨 | 본문` 을 나누던 `kv_inline` 이 본문을 `esc(plain(...))` 로 내보내
    해설 쪽 19곳이 날아갔다. → 조각 목록을 `|` 에서 갈라 **뒤쪽은 `inl()` 로**.
  · 테마의 `u { text-decoration: none }` **한 줄**이 나머지 전부를 지웠다.
    산출 HTML 에 `<u>` 는 71개 멀쩡히 있었다.

원고는 밑줄을 다섯 군데 쓴다 — `기입선` 190 · `POINT` 60 · `문제` 30 ·
`해설영문` 30 · `지문`(빈칸) 11. 이 중 **`<u>` 로 오는 것은 문제·해설영문·빈칸
71곳뿐**이고, 기입 칸 250곳은 엔진이 직접 괘선으로 그리므로 `<u>` 로 오지
않는다. **즉 `u` 를 끌 이유가 애초에 없다. 끄지 말 것.**

**두께는 `--rule-u` 하나로 잡는다**(글자 밑줄 + 기입 괘선 4곳).
⚠ 렌더러가 선 두께를 **1/8px 격자로 내림 스냅**해서 `.5pt` 로 적으면 **0.47pt 로
나간다**(실측). 격자가 0.47 / 0.56 이라 **0.50pt 정확히는 안 나온다** — 0.5pt 이상
으로 앉는 첫 값이 `.6pt`(→0.56pt)다. 얇다는 지적이 나왔던 값이 0.47 이니
`.5pt` 로 되돌리지 말 것. 구분선·상자 테두리는 밑줄이 아니라 그대로 0.47pt 다.

`G-밑줄` 이 지킨다 — **PDF 에서 글자를 찾아 그 바로 아래 그어진 선을 확인한다.**
⚠ 이 게이트를 처음엔 산출 HTML 의 `<u>` 로 셌다가 두 번째 결함을 그대로
통과시켰다. **재는 곳은 언제나 최종 산출물이다.**

### 필기 모눈은 게이트가 지킨다

모눈은 판면 아래에 못박아 두는 요소라, 위 내용이 길어지면 **조판은 아무 소리
없이 성공하면서 본문 위로 겹쳐 인쇄된다**(1차 산출물 p.118). 넘침 검사도 대조
게이트도 못 잡는다 — 글자는 다 들어가 있기 때문이다. `G-모눈` 이 모눈 선 색으로
모눈을 찾아 그 위 본문 바닥과의 거리를 재고, **4mm 미만이면 결함**이다.
높이는 구문·어법 108mm · 독해 60mm — 최악 면 실측에서 나온 값이니 **줄이려면
게이트를 먼저 돌려 볼 것**.

⚠ 이 게이트를 짜면서 같은 실수를 두 번 했다. ① 측정창을 모눈 기준으로 자르면
**겹쳐 내려간 글자를 스스로 못 본다**(자르는 기준은 판면이다). ② 라벨이 본문 줄
바로 아래 붙으면 한 덩어리로 묶이므로 **덩어리가 아니라 줄로 재야 한다**. 그리고
라벨은 구문·어법이 `필기노트`, 독해가 `필기 노트` 로 **띄어쓰기가 다르다**.

자리**다 — 우선순위가 지문·선택지보다 아래다.

### 여기서 실제로 잡힌 것

- **`break-inside: avoid` 를 flex 컨테이너에 직접 걸면 그 덩어리가 사라진다.**
  어휘 Week 4 no.10(novel) 카드가 통째로 빠졌다. 뒤에 강제 나눔이 있고 남은
  자리에 안 들어갈 때 다음 면으로 밀리는 대신 없어진다(최소 재현 확인).
  → 두 단짜리 덩어리는 `display: table` 로 짠다.
- **본문 흐름 요소에 `position: relative/absolute` 를 주면 그 단락이 뒤 레이어로
  밀려** PDF 글자 추출 순서가 읽는 순서와 어긋난다. 처음엔 1,186건, 표식을 도형으로
  바꾸며 다시 걸려 1,939건 실패했다 → 표식은 **매달린 들여쓰기 + inline-block 도형**
  으로만 그린다.

## 뒤 간지 · 제본 파리티

책은 **뒤 간지**(`.endpage`)로 끝난다 — MEMO 면이 아니다. 전면 색면 + 브랜드 ·
교재명 · 각인Books 로고. `break-before: left` 라 **마지막 면이 언제나 짝수**다.

⚠ **음수 여백으로 판면을 넘기는 방식은 본문 맨 끝 요소에서는 통째로 비어 나온다**
(실측: 두 면이 빈 채로 나왔다). 마지막 면은 판면 높이만 차지하고, 도련까지 나가는
색면은 **절대 배치 레이어**(`.bg`)가 그린다 — PART 오프너와 같은 방식.

간지 펼침 앞에 백면이 생기면 빌드가 찾아 옅은 색면으로 채운다(`@page :nth()`
배경색 — 이미지가 아니라 도형 칠이라 인쇄에 안전하다).
