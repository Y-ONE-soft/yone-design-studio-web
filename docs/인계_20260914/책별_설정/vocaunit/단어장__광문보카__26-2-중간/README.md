# 광문보카 01 (광문고1 26-2-중간) — 내지 조판

**코드는 이 폴더에 없다.** 통합웹 리포의 Vivliostyle 엔진이 조판한다.
여기 있는 것은 `config.json`(책 1권치 설정) + `원고/`(GDrive 원본의 로컬 복사본) +
`_기준_…(샘플).pdf`(디자인 기준본) 뿐이다.

```bash
cd ~/dev/yone-design-web
bin/viv "…/단어장/광문보카/26-2-중간" data      # 원고 → data.json (+ 인식 게이트)
bin/viv "…/단어장/광문보카/26-2-중간" build     # 전권 → 광문1_광문보카01_내지.pdf
bin/viv "…/단어장/광문보카/26-2-중간" build --sample   # 견본(Unit 1개)
bin/viv "…/단어장/광문보카/26-2-중간" verify    # 검수 게이트
bin/viv "…/단어장/광문보카/26-2-중간" all       # data → build → **print** → verify
bin/viv "…/단어장/광문보카/26-2-중간" print     # 인쇄 원고(CMYK) → …_인쇄.pdf
```

- 계열 코드: `core/render_vivlio/series/vocaunit/` (**광문보카 계보 = `vocaunit`**,
  상일·배재보카의 `vocabook` 과 다른 계열이다 — 디자인도 원고 형식도 다르다)
- 계열 스타일시트: `core/render_vivlio/themes/vocaunit.css`
- 공용 백엔드: `core/render_vivlio/` (도련·TrimBox·2패스·검수)
- 설계·함정: `docs/vivliostyle_엔진.md`

## 짜임 — 대단원 4개 (2026-08-26)

원고가 **두 벌**이고 형식도 다르다. 어느 쪽인지는 시트를 열어 **구조로 판정한다**
(행당 채워진 칸: 블록형 1.5칸 / 표형 5.0칸 — 사이가 텅 비어 있어 3.0이 경계다).

| PART | 단원명 | 원고 | 형식 | 단원 | 낱말 |
|---|---|---|---|---|---|
| 1 | **어휘끝** | 어휘끝 고교기본 Unit 15~23 …xlsx | 블록형 | UNIT 15~23 | 270 |
| 2 | **올림포스** | 통합.xlsx `전체` 시트 | 표형 | Unit 01~08 | 405 |
| 3 | **교과서** | 통합.xlsx `교과서` 시트 | 표형 | Special Lesson 2 | 30 |
| 4 | **모의고사** | 통합.xlsx `모의고사` 시트 | 표형 | 2024년 9월 | 459 |

대단원마다 **간지 2면**(왼쪽 표지 · 오른쪽 차례)이 붙고 **지면 색**이 바뀐다.
큰 원 안에는 대단원명이 눈썹으로 얹히고(`어휘끝` / `UNIT` / `15`), 둥근 탭도
`어휘끝 15` 처럼 대단원명을 앞에 단다. 자리가 12mm 뿐이라 글자 크기는 **폭에
맞춰 자동으로 줄인다**(`fit_pt`) — `Special Lesson` 은 `LESSON` 으로 줄인다.

**표형 지면**은 발음기호도 파생어도 없어 한 줄짜리 항목이다(번호·회독칸·표제어 |
뜻). 소단원(`Analysis` · `1번` · `본문2` · `20번`)은 면색 알약 머리로 끊는다.

**예문은 묶음에 한 번만 싣는다.** 원고가 낱말마다 같은 문장을 되풀이해 적어
놓았다(894개 중 **468개가 바로 앞과 같은 문장**). 같은 문장이 이어지는 낱말을
한 묶음으로 보고, 그 문장을 묶음 끝에 한 번만 실으면서 **그 묶음의 낱말을 모두
강조**한다(굴절형까지 잡는다 — `individual` → `individuals`). 낱말들과 예문은
한 상자라 면이 갈려도 떨어지지 않는다.

## 이 책의 값 (config.json)

A5 148×210 + 도련 3mm(재단 154×216) · 어휘끝 고교기본 **Unit 15~23** ·
Unit 당 표제어 30개(총 270개) · 안쪽 여백 18mm / 바깥 15mm.

**색을 바꾸면 `palette` 만 고치면 된다** — 배경 SVG(띠·탭·큰 원·모눈·크레스트)도,
글자가 든 자산 PNG("2026" 알약·MEMO 탭)도 빌드마다 팔레트 색으로 다시 구워진다.

### 대단원 색 = 표지 핑크에서 **색상만** 돌린다

`parts[].hue` 하나가 그 대단원의 분홍 계열 전부를 정한다(띠·괘선·회독칸·모눈·
간지 바탕·번호·로고). **밝기와 최대채도 대비는 그대로 두고 색상각만 돌리므로**
네 단원이 같은 톤으로 읽힌다 — `core/render_vivlio/color.py`.

| PART | 색상각 | 느낌 | 포인트 | 띠 |
|---|---|---|---|---|
| 어휘끝 | **352** | 로즈(표지 색) | `#d06397` | `#efcfdc` |
| 올림포스 | **318** | 오키드 | `#b768cf` | `#e7d0ef` |
| 교과서 | **288** | 바이올렛 | `#8b82ce` | `#d7d6ee` |
| 모의고사 | **258** | 페리윙클 | `#648fce` | `#cddaee` |

**핑크→보라 구간만 쓴다.** 이 밝기(L 0.646)에서 최대채도가 큰 구간이 H285~30
이라, 그 밖(파랑·초록)으로 나가면 채도가 눌려 **칙칙해진다**. 버터(큰 원·둥근 탭)와
연하늘(크레스트·MEMO 탭), 예문 강조 주황, 무채색은 대단원이 바뀌어도 **그대로
둔다** — 그래야 "같은 책의 다른 단원"으로 읽힌다.

⚠ 배경 SVG 는 색이 파일에 구워져 들어가 **CSS 변수로 못 바꾼다**. 글자·괘선은
`.pN` 이 변수를 갈아끼워 따라오지만, 띠·모눈·MEMO 배경은 2패스가 **면마다 규칙을
따로 내야** 색이 바뀐다(`_write_pages_css`).

### 기준 색 = 버터 배경 + 쿨한 핑크 포인트 + 연하늘 보조 (2026-08-26)

| 역할 | 색 | 쓰이는 곳 |
|---|---|---|
| **배경** 버터 H98 | `#f6e7a2` · `#f4e187` | 큰 원 · 둥근 탭 |
| **면** 블러시 핑크 H352 | `#efcfdc` · `#edd0dc` · `#ebc3d3` · `#e8c9d5` | **위아래 띠 · 항목 괘선 · 회독칸 · 모눈** — 매 페이지에 반복돼 분홍 느낌을 만든다 |
| **포인트** 진한 핑크 H352 | `#d06397` · `#d23d8c` · `#db9bb6` | 번호 · 쪽번호 · ①②③ · UNIT 글자 · 큰 UNIT 번호 · 판권 로고 · "2026" 알약 |
| 간지 · 판권 바탕 H352 | `#f7e3eb` | 표지와 이어지게 분홍(버터 아님) |
| **보조** 연하늘 H235 | `#c9dce8` | 헤더 크레스트 · MEMO 탭 |
| 예문 강조어 | `#f68b62` | 최종본과 같은 색(인쇄 C0 M56 Y64 K0) |
| 무채색 | K100 · K70 · K50 | 본문 · 품사 배지 · 발음기호 |

**버터색은 채도로 결정된다.** H≈98 에서 **최대채도의 55~75%** 여야 버터로 읽힌다
— 실측 기준값 butter `#f5e8aa`(60%) · `#f9e8a0`(75%). 30% 언저리로 낮추면
**베이지**가 되고(2026-08-25 에 이 실수를 했다), 80% 를 넘기면 레몬으로 튄다.
지금은 65%. 버터 위에서는 **흰 글자가 약하다** — 헤더 글자는 `palette.headtxt`
(진한 핑크)로 뺐다.

**핑크의 색상은 표지가 정한다.** 표지(`광문1_광문보카_표지.pdf`)의 3D 글자·워드마크를
실측하면 **H≈352 의 쿨한 핑크**다(`#f49ec4` · `#d892b1`). 2026-08-26 에 내지 핑크를
전부 H≈5(따뜻한 코럴 쪽) → **H352** 로 돌렸다 — 밝기와 최대채도 대비는 그대로 두고
색상만 회전했다. 포인트는 **52%max 를 넘기지 말 것**: 그 이상은 표지에 없는
마젠타(`#d65d98`)로 튄다.

**분홍 느낌은 "면적"에서 나온다.** 버터 배경 + 핑크 글자만으로는 분홍이 사라진다
(글자는 면적이 없다). 그렇다고 큰 원·탭까지 핑크로 하면 포인트(진한 핑크)와 같은
계열이 돼 2도처럼 보인다. **매 페이지에 반복되는 중간 면**(위아래 띠·괘선·회독칸)
만 핑크로 두는 것이 균형점이다. 비교본 = `_핑크비중_A_B.png`
(A = 지금 값 / B = 큰 원·탭·간지까지 핑크).

**피해야 하는 배합**(사용자 지시):
`연핑크 배경 + 핫핑크 포인트`, `연보라 배경 + 찐보라 포인트` — 둘 다 안 쓴다.

색을 바꿔 온 이력(같은 길을 다시 걷지 않게):
① 강조어만 코랄→체리로즈→진보라→청록으로 바꿔서는 2도 느낌이 안 없어졌다.
   원인은 **면색과 포인트가 같은 계열**이었던 것.
② 면 라벤더 + 포인트 핫핑크 → 원래 완성본(연보라)과 너무 비슷.
③ 면 분홍 + 포인트 라벤더 → 채도가 낮아 칙칙, 포인트는 보라로 튐.
④ 솜사탕(밝은 분홍 + 라벤더 + 연하늘) → 채도를 올렸더니 유치.
⑤ 버터 배경 + 핑크 포인트 → 정리는 됐는데 **분홍 느낌이 사라졌다**(글자엔 면적이 없다).
⑥ 버터 배경 + 핑크 면 + 진한 핑크 포인트 + 연하늘 보조 → 방향은 맞았으나
   버터가 **채도 부족으로 베이지**, 핑크는 **따뜻한 쪽(H5)이라 표지와 어긋남**.
⑦ 지금 = ⑥ + **버터 65%max(H98)** + **핑크 전부 표지 색상 H352 로 회전**.

품사 배지는 **뜻·파생어 모두 무채색(K70)** 으로 통일했다. 글자색은 테두리색을
따라간다. 세로 정렬은 뜻(8.5pt)과 파생어(7pt)가 줄 높이가 달라 **따로 잡는다**
(`pos_va` / `pos_va_deriv`) — 같은 값을 쓰면 파생어에서 0.3mm 뜬다.

## 디자인 근거 — 기존 완성본에서 실측 이식

기준본은 `_기준_광문보카_내지(샘플).pdf`(= `…/단어장/광문보카/광문보카1_내지.indd`
출력물). 치수·색·세로 리듬을 **베이스라인 단위로 실측**해 옮겼다.

- 항목 괘선은 **전 334곳 0.165mm(≈0.5pt) 균일**이다. 한때 면마다 4~5곳이
  0.198mm 로 굵었는데, 아래 괘선이 래스터 이미지로 깔려 위 괘선(벡터)과 겹쳤기
  때문이었다. 지금은 아래 괘선을 흐름 상자에 `box-decoration-break: clone` 으로
  두어 면마다 한 번만 그린다.
- 항목 세로 리듬(괘선 기준 mm): 번호 3.95 · 표제어 9.03 · 발음기호 12.75 ·
  파생어 17.28(줄간 4.18) / 뜻은 8.90 을 축으로 위아래 가운데 · 예문 첫 영문 16.90 ·
  영문 줄간 3.39 · 영→한 4.27 · 한→다음 영 6.20
- 4면 헤더: ①Unit 시작(왼쪽)=모눈+큰 원+UNIT NN ②이어지는 오른쪽=모눈+로고
  ③이후 왼쪽=상단 띠+둥근 탭 ④이후 오른쪽=상단 띠+로고
- 크레스트(광문고 심벌)는 완성본에서 **벡터 패스로 추출**해 계열에 넣었다
  (`series/vocaunit/art.py`). "2026" 알약과 MEMO 탭만 PNG다 — 원본 서체
  `TTSupersizeBk` 가 이 기계에 없어서다(`core/render_vivlio/assets/vocaunit/`).

맨 뒤 **판권면**은 `광문1_광문보카_내지(수정).pdf` 66쪽에서 그대로 옮겼다
(로고는 벡터 추출, 좌표·글자 크기 동일). 색만 책 주색상을 따른다.

원본과 **의도적으로 다른 곳**은 둘뿐이다.

1. 원본은 오른쪽 열에 세로 균등배분(InDesign)이 걸려 있어 항목마다 간격이 ±1mm
   흔들린다. 여기서는 고정 간격을 쓴다.
2. 원본 MEMO 면의 모눈은 왼쪽 도련 3mm 에 안 깔려 있다(재단 사고 위험).
   여기서는 도련까지 채운다.

## 원고 → 조판 표기 (판단이 갈릴 수 있는 곳)

원고(`어휘끝 …xlsx`)에는 완성본 샘플에 없던 표기가 있어서 아래처럼 정했다.
**바꾸려면 `series/vocaunit/render.py` 의 `_paren()` 한 곳만 고치면 된다.**

| 원고 | 조판 | 근거 |
|---|---|---|
| `[명] [동] [형]` | **라인형 네모 배지** (가는 테두리 정사각 + 글자 하나) | 2026-08-25 지시 — 완성본은 대괄호였다 |
| `1. 2. 3.` | `① ② ③` (보조색) | 완성본과 같음 |
| `(과실의)` 같은 한글만 든 괄호 | 6pt 작은 글자 | 완성본과 같음 |
| `(= thoughtful)` `(↔ senseless 어리석은)` | **뺀다** (176건) | 2026-08-25 지시. `options.notes: "small"` 로 되돌리면 6pt 회색으로 표시된다 |
| `(split-split-splitting)` 같은 영문 괄호 | 본문 크기 그대로 | 유의어·반의어가 아니라 활용형 |

파생어 칸은 여러 파생어가 한 칸에 이어 붙어 온다(`sensitivity [명] … sensibility
[명] …`). `영단어 + [품사]` 를 경계로 잘라 줄을 나눈다 — `finance [명] 재정 [동]
자금을 대다` 처럼 한 파생어 안의 두 번째 품사는 자르지 않는다.

### 원고를 손댄 곳 (2026-08-26)

`원고/_원본_….xlsx` 가 손대기 전 원본이다. 원고를 다시 받아오면 **이 수정이
사라진다** — 아래를 다시 넣을 것.

| 위치 | 원고 | 조판 |
|---|---|---|
| Unit 17 · 017 `legal` 파생어 | `legally 법률적으로; 합법적으로` | `legally **[부]** 법률적으로; 합법적으로` |

같이 드러난 파서 사고: 파생어 판정이 **품사 대괄호가 있는 셀**만 파생어로 봤다.
품사가 없는 `legally …` 는 조용히 사라졌고(원고 전체에서 딱 1건), 게이트도 못
잡았다 — 품사 대괄호는 여러 파생어를 **자르는 경계**일 뿐 파생어의 조건이 아니다.
`data.py` 를 고쳐 **블록 시작 마커 행(B 열이 숫자가 아닌 채로 차 있음)만 건너뛰고
남은 C 열은 전부 파생어**로 읽게 했다. 고친 뒤 data.json 을 대조해 바뀐 항목이
`legal` 하나뿐임을 확인했다(270개 표제어 중 269개 무변화).

⚠ 화면용 RGB 본과 인쇄용 CMYK 본은 **색이 조금 다르게 보인다** — 정상이다.
CMYK 는 색 영역이 좁아 분홍·라벤더가 약간 차분해진다.

⚠ **인쇄본이 안 바뀐 것처럼 보일 때** — 두 가지뿐이다.
1. 뷰어가 옛 화면을 붙잡고 있다. 파일이 통째로 교체돼 캐시가 깨진 것이니
   창을 닫았다 다시 연다.
2. 진짜로 안 돌렸다. 이제 `all` 이 인쇄본까지 만들고, `verify` 가 **인쇄본이
   조판본보다 오래되면 결함**으로 잡는다("인쇄 원고 최신" 이 찍히는지 볼 것).

검수 게이트(`verify`)가 보는 것: 원고 인식 수량 · Unit 시작면 9개 · Unit 이 전부
왼쪽 면에서 시작 · 판면 넘침 · TrimBox 전면 · 도련 미달 색면 · 예상 밖 빈 면 ·
**빼기로 한 유의어·반의어 주석이 한 톨도 안 남았는지**(중첩 괄호 때문에 실제로
3건이 남았던 자리다).
