## 0. 한 문단 요약

교재팀 원고(docx·hwpx·xlsx, 일부 계열은 기존 렌더 플랜이나 코퍼스·분석본 PDF)를 **구조로 인식**해 `data.json`으로 만든다. 이것을 계열 렌더러가 **HTML + CSS(Paged Media)**로 바꾸고, **`@vivliostyle/cli` 11.1.0**(Node 별도 프로세스)이 PDF로 조판한다. 그 뒤 PyMuPDF가 **마감**(간지·MEMO 삽입, 짝수 면 맞춤, TrimBox)을 하고, `prepress`가 **CMYK 인쇄본**(`<stem>_인쇄.pdf`)을 만들며, `verify`가 **결과 PDF를 계측해 검수**한다.

InDesign 경로는 계속 남아 있다. 이 시스템은 그와 **나란히 도는 "코드 조판" 백엔드**다.
- 신규 계열은 이쪽으로 만든다. 단어장, 프리미엄북, 워크북, 파이널, 포켓북, 중등, 특강 등 12개 계열 59권이 `bin/viv --list`에 잡힌다.
- InDesign은 기존 책 재판·수정과 표지·목업 작업에 남는다(`docs/vivliostyle_인수인계.md` §3의 결정).
- 속도 차이의 근거는 파일럿 실측이다. 동형은 6초 대 191초, 워크북은 4초 대 437초였다(같은 문서 §2).
- 원리적 한계가 하나 있다. **엔진이 다르면 행 나눔이 달라서** InDesign 완성본을 줄 단위로 복제하지는 못한다. 신규 조판에는 해가 없다.

## 2. 빌드 파이프라인

```
원고(docx/hwpx/xlsx/렌더플랜)
  │ ① data   계열.gen_data  ── 인식 게이트(어긋나면 중단)
  ▼
data.json (+ edits.json을 읽을 때 얹음: edits.load_data)
  │ ② theme  계열.gen_theme ── 배경 SVG·생성 CSS(대개 build 안에서 매번)
  │ ③ build  계열.build
  │     ├ stage: fonts/ theme.css _base.css knobs.css overrides.css assets/ (grep.json)
  │     ├ (측정 계열) measure.html → cli.run_build(final=False) → measure.pdf → heights.json
  │     ├ render → build/index.html
  │     ├ cli.run_build(final=True) ── 직전에 grepstyle 적용 ── `vivliostyle build index.html -o <pdf>`
  │     ├ (2패스 계열) probe로 마커 면 찾기 → pages.css → 재조판
  │     └ bleed.finish(spec) ── 간지·MEMO·짝수 면·뒤 간지·TrimBox
  ▼
<output.dir>/<stem>.pdf              ← 조판본(DeviceRGB, 검수·미리보기용)
  │ ④ print  book.print_pdf → prepress.make → prepress.audit
  ▼
<output.dir>/<stem>_인쇄.pdf         ← 납품 파일(CMYK)
  │ ⑤ verify 공용 게이트 + 계열.verify + design_gate
  ▼
Report(결함 = rc 1)
```

### 2.1 data

- `book.gen_data` → `Series.gen_data`. 입력은 `manuscript` 절의 원고, 출력은 `data.json`(계열 `data_path`).
- 파서는 계열마다 다르다. import를 실측한 결과는 다음과 같다.
  - `openpyxl`: vocabook, vocaunit, vocacard, pocketbook/voca
  - `docx`: special, vocacard (whitebook·blackbook data는 `.docx` 문자열을 참조)
  - `hwpx`: vocabook·pocketbook에 참조가 있다
  - 포켓북은 `tools/pocket_harvest/analysis_pdf.py`로 분석본 PDF까지 읽는다
- 원칙은 **형식이 아니라 구조로 인식하고, 침묵 유실을 금지**하는 것이다(엔진 문서).

### 2.2 build

공통 뼈대(blackbook 기준, `series/blackbook/__init__.py:92`):
1. `data_mod.load(cfg)`. 내부적으로 `edits.load_data`가 편집 이력을 얹고 `refs.set_classes`를 넘긴다(`edits.py:321`).
2. 측정 계열이고 `--nomeasure`가 아니면 측정용 HTML을 쓰고, `measure.measure()`로 한 면에 한 항목씩 조판해 높이를 잰 뒤 `measure.save()`로 `heights.json`에 적는다.
   - 측정 조판 전 `_mute_page_effects`가 작업대의 "빈 면" 효과를 끈다. 켜 두면 항목 수와 면 수가 어긋나 멈춘다.
   - 면 수가 항목 수와 다르면 `ValueError`로 멈춘다(`measure.py:40`).
3. 본 HTML `build/index.html`을 쓰고 `_stage`를 한다.
4. `cli.run_build(html, out, extra=["-f","pdf"])`. 기본 timeout은 900초이고, 실패하면 stdout·stderr 끝 3000자를 남기고 `RuntimeError`를 낸다.
5. 견본(`--sample`)이 아니면 `bleed.finish(out, cfg.finish_spec())`.

CSS가 얹히는 **순서가 곧 우선순위**다(`stage.py:106`).

| 순서 | 파일 | 누가 쓰나 |
|---|---|---|
| 1 | `_base.css` | `@page` 골격 |
| 2 | `theme.css` | 계열 CSS(또는 계열이 생성한 것) |
| 3 | `knobs.css` | config 손잡이, styles, page_rules, 표·상자·목차·각주 CSS |
| 4 | `overrides.css` | **맨 마지막**이라 무엇이든 이긴다 |

두 가지 "다시 조판"을 **섞지 말 것**(엔진 문서 "두 가지 다시 조판").

| 방식 | 계열 | 무엇을 바꾸나 | 수렴 |
|---|---|---|---|
| 2패스 면 지정(`paged.py`) | vocabook | 마진 박스 **내용과 `@page` 배경만**. 페이지 나눔은 불변이라는 계약 | 덧칠이라 걱정 없음 |
| 2패스 + 여백 변경 | vocaunit | 시작면 다음 면의 상단 여백까지 | 고정점 확인 필요(최대 4패스) |
| 높이 측정 배치(`measure.py`) | blackbook, whitebook, final, pocketbook 등 | 잰 높이로 본 조판을 **한 번에** | 반복 조판으로 수렴시키려 하면 **발산**(10→8→7) |
| 당겨붙이기 측정(`workbook/fit.py`) | workbook | 넘친 1~2줄 덩어리의 자간·행간 | 두 바퀴로 제한. 바퀴마다 점수를 매겨 최선의 판을 보관 |

### 2.3 render (미리보기 전용)

- `book.render` → `Series.render_only`. `cli.skip_build()` 블록 안에서 build를 돌리다가 **`final=True`인 조판 호출에서** `RenderOnly(html_path)`로 멈춘다(`cli.py:157`).
- 측정 조판은 `final=False`라서 멈추지 않는다. 멈추면 측정용 HTML을 미리보기로 삼는 사고가 난다.
- stdout에 `RENDER_HTML=<경로>`를 찍는다. `watch`가 이 줄을 읽는다(`book.py:534`).

### 2.4 finish (`bleed.finish`, `bleed.py:168`)

순서는 고정이다.

| 순서 | 키 | 동작 |
|---|---|---|
| ① | `inserts: [{marker\|at, pdf?, page, mode:"replace"\|"insert", fit?, crop?}]` | 렌더러가 심은 마커(`§DIV1§` 등)나 쪽번호 자리를 아트워크로 교체·삽입. 인덱스가 밀리지 않게 **뒤에서부터** 처리 |
| ② | `blank_fill: {pdf?, page, ignore?}` | 빈 면을 MEMO 아트워크로 |
| ③ | `end_on_left: {pdf?, page}` | 마지막 면을 왼쪽(짝수)으로. 아트워크가 없으면 **빈 면**을 붙인다 |
| ④ | `append: [{pdf?, page, redact?, fit?, crop?}]` | 맨 뒤에 붙일 면 |
| ⑤ | `trim: {bleed}` 또는 `{rect}` | **반드시 마지막**에 전 면 TrimBox. MediaBox **원점 기준**(`_raw_box`, `bleed.py:50`) |
| – | `art_pdf`, `suffix` | 기본 아트워크 PDF / 산출 접미사(없으면 제자리 갱신) |

- 크기가 다른 아트워크(도련 없이 뽑힌 완성본)는 판형 한가운데 놓는다(`insert_page`, `bleed.py:94`). `fit:"cover"`는 비율을 유지해 판형을 덮는다.
- 저장은 항상 `<target>.tmp`에 쓴 뒤 `os.replace`로 바꿔친다. 교재 폴더는 클라우드 동기화 경로라 저장이 끊기면 납품본이 반쪽으로 덮이기 때문이다.
- 계열별로 간지를 구성하는 방식은 `.claude/rules/vivlio_print_spec.md` "간지" 표에 있다.

### 2.5 print (`book.print_pdf` → `prepress.make`, `prepress.py:544`)

`print` 절은 세 겹으로 합성된다(`book._print_section`).
1. 바닥값 `prepress.default_print()`: `out:"_인쇄"`, profile `JapanColor2001Coated.icc`, 기본 gray_map
2. 그 위에 `Series.print_defaults(cfg)`
3. 그 위에 책 `print` 절. `gray_map`·`cmyk_map`은 **칸 단위로** 덮는다

입력은 `cfg.out_pdf(print.suffix 또는 verify.suffix)`이고 출력은 `cfg.out_pdf(print.out)`, 즉 `<stem>_인쇄.pdf`다.

| 단계 | 함수 | 이유 |
|---|---|---|
| 0 | `_lift_notes` | Ghostscript가 검수 쪽지(Text 주석)를 10배로 키우므로 떼어 둔다 |
| 1 | `fix_tounicode`(`:400`) | ToUnicode `bfrange` 끝 바이트 넘침을 gs **전에** 쪼갠다(`대`→`눀` 사고) |
| 2 | `neutralize`(`:81`) | `rg/RG` 무채색을 DeviceGray(gray_map)로, 지정색은 고정 CMYK(cmyk_map)로 |
| 3 | `neutralize_patterns`(`:152`) | 양 끝 색이 같은 축 셰이딩(`linear-gradient(색, 같은 색)`)도 같은 처리 |
| 4 | `pin_flat_images`(`:214`) | "한 색 + 알파" 로고 그림을 CMYK 한 점 + SMask로 |
| 5 | `strip_invisible`(`:320`) | 투명 마커 잔재 제거. 전후를 `_same_render`로 픽셀 비교해 다르면 되돌린다 |
| 6 | `run_gs`(`:513`) | Ghostscript ICC 변환(`-dCompatibilityLevel=1.4 -dPDFSETTINGS=/prepress`, 서체 임베드, 다운샘플 없음, `--permit-file-read=<icc>`) |
| 7 | `_restore_notes`, `stamp_boxes`(`:645`), `add_output_intent`(`:473`) | gs가 흘린 BleedBox/TrimBox를 다시 찍고 OutputIntent(ICC)를 박는다 |
| 8 | 한글 음절 개수표 대조 | 조판본보다 **늘어난 글자**가 있으면 `_불량.pdf`로 떼어 내고 `RuntimeError`. 줄어든 글자는 경고만 |
| 9 | `audit`(`:656`) | 판형, TrimBox, BleedBox, 색 연산자, `rgb_left`, 서체 목록. `book.print_pdf`가 로그에 한 줄 찍는다 |

납품 규약과 코드의 대응, 아직 코드가 못 지키는 틈은 `.claude/rules/vivlio_print_spec.md`에 있다. 주요 틈은 다음과 같다.
- 면수 4의 배수 게이트가 없다
- 안전 여백 게이트가 없다
- 서체 임베드 여부와 이미지 해상도 게이트가 없다
- 유채색 `cmyk_map` 고정은 포켓북 등 일부 계열만 했다

### 2.6 verify (`book.verify`, `book.py:364`)

입력은 `cfg.out_pdf(verify.suffix)`다. 공용 게이트 → `_check_print_fresh` → 계열 `verify` → 디자인 게이트 순으로 돈다. 상세는 §7.

## 3. 명령어 치트시트

진입점은 `bin/viv`이며 실체는 `exec python3 -u -m core.render_vivlio.book "$@"`다. 리포 루트로 cd한 뒤 실행하고, `-u`로 버퍼링을 끈다.
`bin/viv` 머리 주석에는 `data|theme|build|verify|all`만 적혀 있지만, **실제로 지원하는 단계는 아래 표가 전부**다(`book.py:491` `main`).

| 명령 | 동작 |
|---|---|
| `bin/viv --list` (`-l`, `list`) | 교재 트리의 책 목록. `--json`이면 기계용(`books_json`: key = 스튜디오 상대경로) |
| `bin/viv <책>` | 단계를 생략하면 **`build`** |
| `bin/viv <책> data` | 원고 → data.json |
| `bin/viv <책> theme` | `gen_theme` |
| `bin/viv <책> render` | HTML까지만(`RENDER_HTML=` 출력) |
| `bin/viv <책> build` | 조판 → PDF → 마감 |
| `bin/viv <책> print` | CMYK 인쇄본 |
| `bin/viv <책> verify` | 검수. 결함이 있으면 rc 1 |
| `bin/viv <책> all` | `data → build → print → verify`. `print`는 `_print_section`이 비었을 때만 빠진다. `book.py` docstring의 "data → build → verify"는 옛 표기 |
| `bin/viv <책> watch [--port=13000] [--host=127.0.0.1] [--data]` | 라이브 미리보기. 다른 단계와 섞지 않는다 |
| `bin/viv <책> knobs [--json] [--set="k=v,k2=v2"] [--reset="k"]` | 손잡이 보기·쓰기(config.json 부분 치환 + `.bak`) |
| `bin/viv <책> variants --knob=<키> --values="a,b,c" [--pages=4]` | 시안 매트릭스 → `<책>/_시안_<키 끝>.pdf` |
| `bin/viv <책> sections [--json]` | 넣고 뺄 섹션 목록 |
| `bin/viv <책> select --exclude= --include= --limits="k=4" --order= [--clear]` | config `select` 쓰기(`data build`를 다시 돌려야 반영) |
| `bin/viv <책> css [--text=…\|--file=…\|--clear]` | `overrides.css` 쓰기·보기 |

- `<책>`에는 ① 실제 경로 ② `--list`가 찍는 스튜디오 상대경로 ③ **책 이름 일부**(예: `광문보카`)를 쓸 수 있다. 여러 권에 걸리면 후보를 보여 주고 멈춘다(`config.resolve_book`, `config.py:194`).
- 단계는 여러 개를 이어 쓸 수 있다(`data build`). 나머지 `--키`/`--키=값`은 그대로 계열 build에 넘어간다.
- 계열 옵션(코드 확인분): `--sample`(견본, 대부분 계열), `--nomeasure`(blackbook·whitebook·final·hankkeut: 이미 잰 heights를 쓴다), `--nomemo`(vocabook), `measure_pass`(pocketbook).

## 7. 검수 체계

### 7.1 `Report` (`verify.py:15`)

- `fail`: 결함. 하나라도 있으면 rc 1
- `warn`: 사람이 볼 것
- `note`: 정보
- `design(msg, s)`: `strict`면 fail, 아니면 warn

### 7.2 공용 게이트

`book.verify`가 자동으로 부르는 것:

| 게이트 | 함수 | 조건·내용 |
|---|---|---|
| 쪽수 기록 | `probe.page_texts` | 항상 |
| 판면 넘침 | `check_overflow(pdf, frame, skip_pages)` `:99` | `verify.frame`이 있을 때. 좌표는 **미디어(도련 포함) 기준** |
| TrimBox 전면 | `check_trimbox` `:138` | `page.bleed > 0`일 때. MediaBox 원점 기준인지 확인 |
| 도련 미달 색면 | `check_bleed_coverage` `:158` | `page.bleed > 0`일 때. 재단선에 딱 맞춰 끝난 색면을 결함으로 |
| 준-빈면 | `check_blanks` `:127` | 항상(`verify.blank_ignore`) |
| 인쇄본 최신 | `_check_print_fresh`(`book.py:404`) | print가 켜진 책. 인쇄본이 없거나 조판본보다 오래되면 **fail** |

`skip_pages`와 `skip_last`(끝에서 N면)는 판면·도련·디자인 검사에서 뺀다. 붙인 아트워크(간지·MEMO) 면을 뺄 때 쓴다.

계열이 가져다 쓰는 공용 함수:
- `check_sequence(texts, seq)` `:75`: 누락과 순서 어긋남
- `check_gaps(items, texts)` `:207`: 빈칸 유실(`count_gaps` `:196`)
- `check_box_cut(pdf, top, bottom)` `:226`: 테두리 상자가 면 위·아래에서 잘렸는지

### 7.3 디자인 게이트 (`design_gate.py`)

`verify`에서 자동으로 돈다. `verify.design.off: true`로 끄고, 게이트 자체가 예외를 내도 본 게이트를 막지 않는다(note만 남긴다).

| 검사 | 함수 | 기본 |
|---|---|---|
| G-크기: 본문 최소 글자 크기 | `check_min_size` `:240` | `min_pt: None` = **판정 안 함**(분포만 기록). A5 단어장 본문은 6pt라서 책이 바닥값을 정한다. A4 학습서는 7.0 권장 |
| G-대비: 글자와 그 자리 배경 | `check_contrast` `:285` | `contrast_hard 3.0` 미만이면 판정, 3.0~4.5는 참고 한 줄. 색 조합으로 묶어 보고 |
| G-색면: 면 유채색 면적 | `check_chroma` `:349` | `chroma_max 0.35`, `chroma_pages_skip` |
| G-글리프: 장식 글리프를 머리 기호로 | `check_bullets` `:370` | `BULLET_GLYPHS = "■□●○◎✓✔❖◇▪▫※·"`, `bullets_allow` |
| G-미러: 좌우 면 장식이 거울상인지 | `check_mirror` `:392` | `mirror_sim 0.93`, 경계선 밀도 `mirror_edge 0.02`로 장식이 있을 때만 |

- 판정 세기는 **기본 경고**다(`strict: False`). 기존 납품 교재의 지면을 바꾸지 않기 위해서다.
- **신규 조판은 `verify.design.strict: true`로 시작한다.** 웹 카드 `vivlio_book`은 새 책에 자동으로 켠다.
- 기타 설정(`DEFAULTS`, `design_gate.py:61`): `max_warn 8`, `dpi 72`, `running_frac 0.08`(frame이 없을 때 러닝 띠), `sample_pages`.
- 서체 **이름**으로 판정하지 않는다. 출력 서체명이 `Type3 (n 0 R)`이라 이름으로 찾는 검사는 조용히 통과해 버린다.

### 7.4 계열 게이트

각 계열의 `verify()`(일부는 `series/<계열>/verify.py`)가 맡는다. 예: vocabook Day 시작면 수, blackbook 대화문 바탕과 해설 펼침면, whitebook "문항 N은 (N-1)//4번째 면". **상세는 계열별 문서로 미룬다.**

### 9.1 조각화·흐름

| 함정 | 대응 |
|---|---|
| **flex 컨테이너에 `break-inside: avoid`를 걸면**, 뒤에 강제 나눔이 있고 자리가 모자랄 때 덩어리가 **통째로 사라진다**. 육안 검수로는 못 잡는다 | 두 단 덩어리는 `display:table; table-layout:fixed` + `table-cell`로 짠다 |
| flex 2열 항목에서 마지막 항목의 avoid가 무시돼 판면 밖으로 넘친다(vocaunit) | 같음 |
| `break-before: page`는 **면 머리에서 시작하는** 요소에 아무 일도 안 한다 | `verso` 등(workbook) |
| `.grid`에 height를 주면 면으로 쪼개지지 않고 판면 밖으로 흐른다 | 단 높이는 `@page` 여백에 맡기고 칸 높이만 준다 |
| 칸 높이를 단 높이와 똑같이 주면 반올림 때문에 옆 단이 비고 면이 늘어난다 | 1mm 덜 준다 |
| 반복 조판으로 흐름을 수렴시키면 **발산**한다(10→8→7) | 높이를 측정해 한 번에 조판 / 바퀴 수 제한 |
| `transform: scaleX()`는 줄바꿈에 반영되지 않는다(장평 대체 불가) | 자간(+`word-spacing`)으로. 값은 조판 결과를 최소제곱으로 푼다 |
| 크기가 다른 인라인이나 inline-block은 줄 상자를 키운다 | `line-height: 0`, `position:absolute` |
| `text-indent`가 inline-block 안까지 상속된다 | 배지에 `text-indent: 0` |
| 머리 기호를 `position:absolute`로 얹으면 PDF 글자 추출 순서가 어긋난다 | `text-indent` + `::before` |

### 9.2 마진 박스·@page

| 함정 | 대응 |
|---|---|
| **`@bottom-center`가 무시된다**(블랙북) | 쪽번호는 `@bottom-*-corner`, 문구는 배경 이미지로 |
| `@bottom-outside`(안·바깥)를 무시한다 | `:left`/`:right`로 갈라 적는다 |
| 마진 박스에서 `transform: rotate()`와 `visibility:hidden`이 무시되고, `position:relative`를 주면 러닝 요소가 본문에 그려진다. 세로 음수 마진은 잘리고, 여백보다 큰 요소도 잘린다 | 마진 박스 도형은 **전부 배경 SVG**로. 러닝 요소 높이는 상단 여백과 같게 |
| `@page :nth(N)`은 이름 있는 페이지 규칙에 **명시도에서 밀린다** | `paged.nth_rule`처럼 `이름:nth(N)`으로 함께 지정 |
| `@page 이름:nth(1)`은 그 이름 묶음의 첫 면이 아니라 **절대 쪽번호**다 | 흐름 안에 높이 0인 표식 |
| 계열이 이름 있는 면(`@page voca`)을 쓰면 "모든 면" 규칙이 먹지 않는다 | 이름 규칙에 적는다 |
| `string-set`/`string()`은 러닝 요소에서 빈 문자열이 된다 | 섹션마다 러닝 요소를 다시 선언 |
| `@page` 배경의 `repeating-linear-gradient`는 주기가 어긋나고, 배경 층마다 position/size를 명시하지 않으면 뒤 층이 크기를 물려받는다 | SVG data URI, 층별로 명시 |

### 9.3 도형·괘선·색

| 함정 | 대응 |
|---|---|
| `clip-path` + `filter: drop-shadow()`를 같이 쓰면 요소가 사라진다. `border-radius`는 자식을 자르지 않는다 | 배경 SVG |
| **얇은 괘선을 `linear-gradient` 색 정지점으로 그리면 72dpi로 래스터화돼 사라진다**. 배경으로 깔면 래스터 이미지로 나가 굵기가 들쭉날쭉해진다(광문보카 250여 개, 165㎛ 대 198㎛) | 선 두께만 한 상자에 단색으로 깔거나, `box-decoration-break: clone`인 border |
| 배경 SVG 안에서는 CSS 변수를 못 쓴다(색이 구워진다). 자산 PNG도 팔레트를 따라가지 않는다 | 팔레트를 바꾸면 생성기를 다시 돌린다(계열이 매 빌드 굽는다) |
| 배경 축약형에 `no-repeat`를 두 번 쓰면 선언 전체가 무시된다(`svg.data_uri`가 이미 붙인다) | 한 번만 |
| config 키 `_`와 CSS 변수 `-`가 어긋나면 색이 조용히 검정으로 떨어진다 | 프렐류드에서 변환 |
| `get_drawings()`는 **클리핑 전** bbox를 준다. 배경 선은 잡히지 않는다 | 고해상도 렌더로 눈으로 확인하거나 픽셀 한 줄을 읽는다 |

### 9.4 출력 PDF·인쇄

| 함정 | 대응 |
|---|---|
| **출력 서체명이 `Type3 (n 0 R)`**이다(가변 서체가 Type3 외곽선으로 들어간다). 이름으로 찾는 검사는 조용히 통과한다 | 크기(pt)와 위치로 판정. 인쇄에는 문제없다 |
| 출력은 무조건 **DeviceRGB**다(검정도 `0 0 0 rg`). 그대로 ICC를 태우면 본문이 리치블랙이 된다 | gray_map → DeviceGray → gs가 K 단색으로 유지 |
| **gs 통과 후 Type3 ToUnicode가 깨진다**(`대`→`눀`, 딱 0x100 차). 인쇄 모양은 멀쩡하고 검색·복사만 틀린다 | `fix_tounicode` + 글자층 대조(`_불량.pdf`). 2026-09-11에 닫혔다. 수리 전 인쇄본은 `print`를 다시 돌린다 |
| gs가 TrimBox/BleedBox를 흘리고, Text 주석을 10배로 키우며, OutputIntent가 없다. CMYK는 1/256 단위로 적는다 | `stamp_boxes`, `_lift/_restore_notes`, `add_output_intent`. 잉크 대조는 ±0.005 |
| `-dSAFER`가 시스템 폴더 ICC 읽기를 막는다 | `--permit-file-read=<icc>` |
| 투명 마커가 투명한 리치블랙 도형으로 남는다. `/Gxx gs`는 자기 q/Q 블록 밖에 있다 | 색 + gs + 바로 뒤 BT…ET만 지우고 렌더를 비교 |
| `set_cropbox`를 먼저 부르면 TrimBox가 되돌아간다. Chromium PDF는 **MediaBox 원점이 0이 아닐 수 있다**(재단선 0.24mm 밀림) | `_raw_box`로 원본 좌표를 읽어 TrimBox만 찍는다 |
| 완성본 간지가 도련 없이 뽑혀 있는 경우가 흔하다 | `insert_page`로 가운데 배치 또는 `fit:"cover"` |

### 9.5 DOM·작업대

| 함정 | 대응 |
|---|---|
| Vivliostyle은 조판 결과 DOM에 **임의 속성(`data-ref`)을 옮기지 않는다**. `id`도 남지 않는다(자립화 문서 "①`id`는 조판 결과에 안 남는다"). **class는 남는다** | 자리표는 `vrefN` 클래스 + `refs.json` |
| 자리표를 붙이면서 원래 없던 클래스를 얹었더니 줄바꿈이 바뀌었다(블랙북 26·61면) | `refs.mark(base=원래 클래스 그대로)`. 회귀 대조로만 잡힌다 |
| 앱 CSS(`*{box-sizing:border-box}`)가 조판에 얹혀 단 폭이 167mm에서 118mm로 줄었다 | 지면을 딴 문서(`/book-studio/frame`)로 격리 |
| 작업대 뷰어 빈 화면의 원인 넷: CSP frame-ancestors, 뷰어 번들의 eval, `src=` URL 인코딩, 키의 슬래시 | 경로 한정 CSP, 인코딩하지 않음, sha1 bid |
| `vivliostyle preview`의 stdout을 비우지 않으면 파이프가 차서 서버가 멈춘다. 주소를 직접 조립하면 판이 바뀔 때 깨진다 | 데몬 스레드로 비우고 `Preview URL:` 줄을 읽는다 |
| `--sample`이 블랙북에서 파일명만 바꾸고 전권을 조판해 브라우저가 멈췄다. 견본 측정값이 전권 `heights.json`을 덮었다 | 진짜 견본 + `heights_견본.json` |

### 9.6 운영

| 함정 | 대응 |
|---|---|
| **결과 PDF를 뷰어에 열어 둔 채 다시 빌드하면** 몇 면만 남고 흰 종이로 보인다(inode 교체로 뷰어 캐시가 깨짐) | 창을 닫았다 연다 |
| 교재 폴더는 클라우드 동기화 경로라 큰 저장이 `Operation timed out`으로 끊긴다 | 임시 파일 + `os.replace`(finish, prepress) |
| **동시 세션**: 워킹트리 하나에 클로드 세션이 여럿 붙는다. `checkout -b`를 하면 남까지 끌려가고, autosync의 `git add -A`가 남의 미완성 편집을 커밋한다. 다른 세션의 재빌드가 기준선을 1분 만에 무효로 만든 일도 있다 | §10 워크트리 격리. 남이 만지는 책은 작업에서 뺀다 |
| 원고·간지 원본은 GDrive에 있다 | 원본은 수정 금지, 로컬 복사본으로 작업 |
