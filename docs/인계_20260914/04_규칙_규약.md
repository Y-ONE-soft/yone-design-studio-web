## 1. 인쇄 납품 규약

**전제**: 사용자가 따로 말하지 않으면 모든 비블리오 조판은 오프셋 인쇄 납품용이다 (CLAUDE, feedback_vivlio_print_default 2026-09-11).
- 조판본(RGB PDF)은 검수·미리보기용 중간 산출물이다.
- 사용자가 "이건 인쇄용 아니야"라고 한 책만 인쇄본을 뺀다.

| 규약 | 값·규칙 | 코드 대응 위치 |
|---|---|---|
| 도련 | 사방 3mm. 도련은 요소를 옮기는 것이 아니라 **늘리는 것**이다. 재단선에 닿는 색면·괘선·이미지는 3mm 더 그린다. 요소 위치는 재단선 기준 그대로 둔다 (CLAUDE) | `config.json` → `page.bleed: 3`. `config.py` 기본값이 3이다(2026-09-11, `p.setdefault("bleed", 3.0)` 확인). 미디어 = 판형+6mm, 재단 원점 (3,3). `bleed.py` 머리 주석, `verify.check_bleed_coverage` (SPEC) |
| 재단선 마크 | 넣지 않는다. 인쇄소가 문서로 요구할 때만 넣는다 (CLAUDE) | 해당 코드 없음. 인쇄소는 TrimBox로 재단한다 (SPEC) |
| TrimBox·BleedBox | 전면에 지정한다 (CLAUDE) | `prepress.stamp_boxes`(변환 후 다시 찍음), `verify.check_trimbox`. Ghostscript가 상자를 흘리므로 변환 **후**에 찍는다. `set_cropbox`를 먼저 부르면 TrimBox가 되돌아간다 (SPEC) |
| 안전 여백 | 글자·번호·러닝헤드 등은 재단선에서 최소 3mm, 권장 5mm 안쪽 (CLAUDE) | **게이트 없음.** `verify.frame` 판면 검사가 간접적으로만 막는다 (SPEC) |
| 색 | CMYK. 무채색은 K 단색이다. 본문 먹 K100, 회색은 K%만, 흰색 K0. 본문 리치블랙 금지 (CLAUDE) | `prepress.make` = `neutralize`(gray_map) → `neutralize_patterns` → `pin_flat_images` → `run_gs` (SPEC) |
| DeviceRGB | 납품 PDF에 연산자 0개 (CLAUDE) | `prepress.audit()["rgb_left"]`. print 로그에 "[경고] DeviceRGB 연산자가 N개 남았다"가 뜨면 납품 금지 (SPEC) |
| 무채색 표 | 팔레트의 무채색 전부를 `print.gray_map`에 등록한다 (CLAUDE) | 계열 기본표 `series/<계열>/__init__.py`의 `PRINT_GRAY`(+`print_defaults`). pocketbook은 `theme.PRINT_GRAY`/`PRINT_CMYK`. 빠진 회색은 ICC를 타서 4도 리치그레이가 된다 (SPEC) |
| ICC | Japan Color 2001 Coated. 다른 프로파일은 인쇄소가 지정할 때만 쓴다 (CLAUDE) | `config.print.profile` / `prepress.DEFAULT_PROFILES` (SPEC). `prepress.add_output_intent`가 OutputIntent를 박는다 (feedback_print_pdf_cmyk) |
| 이전 판 유채색 고정 | `print.cmyk_map`으로 못 박는다(ICC 변환 안 탐). 값은 완성본 PDF에서 직접 읽는다 (CLAUDE) | `config.print.cmyk_map {"#hex":[C,M,Y,K]}`. 완성본 내용 스트림의 `k` 연산자를 읽는 방법이 가장 정확하다 (SPEC, 엔진 "화이트북" 절) |
| 선·글자 최소치 | 선 0.25pt 이상, 반전(흰) 선 0.5pt 이상, 흰 글자 7pt 이상. 작은 글자·가는 선에 4도 혼합색 금지 (CLAUDE) | SPEC 대응표에 해당 게이트 기재 없음. 확인 필요 |
| 이미지 | 300dpi 이상. 로고·아이콘은 벡터. 다운샘플 없음(무손실 Flate) (CLAUDE) | `run_gs`의 `-dDownsample*Images=false`와 FlateEncode. 300dpi 미만 원본을 거르는 게이트는 없다 (SPEC) |
| 서체 | 전부 임베드(서브셋). 임베드 금지 라이선스 서체 사용 금지 (CLAUDE) | `run_gs -dEmbedAllFonts -dSubsetFonts`. `audit()["fonts"]`는 목록만 내고 임베드 여부는 검사하지 않는다 (SPEC) |
| PDF 버전 | PDF 1.4, PDF/X-1a 태그 없음. 요구 시 별도 (CLAUDE) | `run_gs -dCompatibilityLevel=1.4 -dPDFSETTINGS=/prepress` (SPEC) |
| 인쇄본 최신 | 조판본을 다시 뽑으면 인쇄본도 다시 뽑는다 | `book._check_print_fresh`: 인쇄본이 조판본보다 오래되면 verify 결함 (SPEC) |
| 인쇄본 항상 생성 | config에 `print` 절이 없어도 인쇄본을 만든다 (CLAUDE) | `book._print_section` = 책 `print` 절 ⊕ `Series.print_defaults(cfg)` ⊕ `prepress.default_print()` 바닥값. 끄는 방법은 `"print": false` 또는 `{"off": true}`뿐 (SPEC) |
| 글자층 보존 | 인쇄본의 텍스트 검색·복사가 조판본과 같아야 한다 | `prepress.fix_tounicode`가 gs **전에** ToUnicode `bfrange`를 쪼갠다. `make()` 끝에서 한글 음절 개수표를 조판본과 대조하고, 늘어난 글자가 있으면 `_불량.pdf`로 떼고 멈춘다 (SPEC, feedback_print_pdf_cmyk 2026-09-11) |
| 검수 쪽지 | 인쇄본에서도 원래 크기를 유지한다 | `prepress._lift_notes/_restore_notes`. Ghostscript가 Text 주석을 10배로 키우기 때문이다 (feedback_print_pdf_cmyk) |
| 웹 작업대 | CLI와 같은 규칙을 적용한다 | `engines/vivlio_book/engine.py`(build 뒤), `routes/book_studio.py`(kind=press) (SPEC) |

### 1-1. 면 구성·제본

| 규칙 | 출처 |
|---|---|
| 낱장 1-up, 첫 면 오른쪽, 마지막 면 왼쪽(짝수) | CLAUDE |
| **제본 기본 = 무선제본 → 총 면수는 짝수만 맞춘다.** 중철·스프링은 사용자가 말할 때만 적용한다. 보고에서 제본을 미결 항목으로 올리지 않는다 | feedback_binding_default_perfect (2026-09-14) |
| 4의 배수는 **중철일 때만**. 스프링도 짝수 | CLAUDE, feedback_print_pdf_cmyk |
| 부족한 면은 MEMO·빈 면으로 채운다. 자동 게이트가 없으니 직접 센다 | CLAUDE |
| 코드: `config.finish.end_on_left` → `bleed.finish` ③. **finish 절이 없는 책은 홀수로 끝날 수 있다.** hankkeut는 `finish.multiple`(기본 2, `series/hankkeut/__init__.py::_parity` 확인) | SPEC, feedback_binding_default_perfect |

제본 가정을 잘못한 사례: 한서끝을 중철로 가정해 56면(MEMO 3면)으로 뽑았다가 "메모 3장이나 넣은 이유는?"이라는 지적을 받았다 (feedback_binding_default_perfect).

### 1-2. 절차·납품 파일

1. `bin/viv <책> all`을 돌린다. data → build → **print** → verify 순서이고, verify 결함이 0이어야 한다 (CLAUDE, SPEC).
2. print 로그의 audit 한 줄을 확인한다 (SPEC).
   - 판형 = 판형+6mm
   - 재단 = 사방 3mm 안쪽
   - `rgb_left` 0
   - 서체 목록에 낯선 이름이 없는지
3. 면수를 센다. 1-1절 규칙을 따른다.
4. 완성본(이전 판)이 있으면 색·괘선 굵기를 나란히 대조한다 (SPEC).
5. **납품 파일은 `<stem>_인쇄.pdf` 하나다. 조판본(RGB)은 납품하지 않는다** (CLAUDE).

그 밖의 규칙:
- **표지는 별도다**(cover 엔진/InDesign). 책등 두께는 면수가 확정된 뒤에 잡는다 (CLAUDE).
- **화면용 예외**: 화면용(열람·태블릿)이 명시된 때만 RGB·도련 0으로 만들고, 파일명에 `_화면`을 붙인다 (CLAUDE).

### 1-3. 새 책 config 최소 요건 (SPEC)

기본으로 `page.bleed: 3`만 확인하면 된다. `print` 절은 적지 않아도 계열 기본표가 깔린다. 적으면 계열 표 위에 **칸 단위로** 덮인다.

`print` 절을 적는 경우는 셋이다.
1. 이전 판과 색을 못 박아야 할 때 → `cmyk_map`
2. 팔레트를 바꿔 무채색이 늘었을 때 → `gray_map` 칸 추가
3. 화면용일 때 → `"print": false`

### 1-4. 문제로 삼지 말 것

- **판형·서체 형식**: 154×216(도련 3mm) 판형과 Type3 본문으로 상일보카·블랙북이 이미 무사히 인쇄됐다. 인디자인 파일 하나만 보고 "기존 납품본은 도련 없음"이라고 했다가 지적받았다 (feedback_print_pdf_cmyk).
- **Type3 서체**: Vivliostyle/Skia는 가변 서체를 Type3 외곽선으로 심는다. 인쇄에는 문제없다 (SPEC).
- **CMYK 대조 오차**: Ghostscript는 CMYK를 1/256 단위로 적는다. 잉크 대조는 ±0.005로 본다 (feedback_print_pdf_cmyk).

- **참조 구현은 `series/hankkeut`**: `render.front_html` 1P, `divl_html`+`divr_html` 2P, 뒤 1P. 표지 돌 바탕 `palette.stone` + 이중 괘선 `rule_motif` + 워드마크.
- 계열별 현황:
  - pocketbook: 앞 1P + 마지막 P. `cover.ink_from_cover`가 학교 표지 PDF에서 색을 읽는다.
  - final: 크레딧이 계열 자산이다.
  - blackbook: **코드로 그린다**(2026-09-15, `series/blackbook/art.py` → `build/art.pdf` 4면: 앞·MEMO·뒤·정답 간지).
    인디자인 완성본 면을 빌리던 방식은 `finish.art_pdf` 를 적으면 아직 된다(옛 책). 학교 이름은 config `cover`.
  - whitebook: 인디자인 아트워크 PDF 면을 교체해 넣는다 — 디자인 폴더 `참고/` 안의 파일.
  - vocabook: 별도 제작 PDF를 쓴다.
  - vocaunit: 팔레트 손잡이로 표지 색을 대입한다.
- 새 계열은 hankkeut 구조를 그대로 따른다.

## 5. 디자인 게이트 — 기계가 잡는 것 / 사람이 봐야 하는 것

### 5-1. 기계가 잡는 것

**`design_gate.py`** (GATE). 기본은 경고이고 `strict`면 결함이다. 전부 **결과 PDF**에서 잰다.

| 검사 | 무엇 | 기본값·한계 |
|---|---|---|
| G-크기 | 본문 최소 글자 크기 | `min_pt: None`(**기본 끔**). 책마다 바닥값을 정한다(A4 학습서 7.0 권장). 판면 밖 러닝 요소는 제외한다(frame이 없으면 위아래 8%) |
| G-대비 | 글자 ↔ 그 자리 배경 대비 | 3.0 미만은 경고, 3.0~4.5는 참고 한 줄. 색 조합으로 묶고 상위 8개만 편다 |
| G-색면 | 면 유채색 면적 비율 | `chroma_max 0.35`. 간지는 `chroma_pages_skip`으로 뺀다. 문서상 기준은 학습면 3~8%, 문제면 1~3% |
| G-글리프 | 장식 글리프를 머리 기호로 쓴 줄 | `■□●○◎✓✔❖◇▪▫※·`. ★◆▣는 중등부가 뜻을 담아 써서 기본 목록에서 뺐다(책이 추가 가능) |
| G-미러 | 좌우 면 장식 유사도 | `mirror_sim 0.93`. 경계선 밀도로 장식이 실제로 있을 때만 판정한다(평평한 색 띠는 제외) |

**`verify` 공용 게이트** (엔진 "검수", SPEC):
- 원고↔PDF 누락·순서 어긋남
- 판면 넘침, 빈칸 유실, 상자 면 걸침, 준-빈면
- TrimBox 전면 지정, 도련 미달 색면
- 인쇄본 최신 여부
- 인쇄본 ToUnicode 한글 개수 대조(`prepress.make`)
- 계열별 게이트: 단어장 Day 시작면, 블랙북 대화문 바탕, 포켓북 G-P1~P13 등

### 5-2. 사람이 봐야 하는 것

기계가 못 잡거나, 게이트가 없다고 문서에 적힌 것들이다.

| 항목 | 이유·출처 |
|---|---|
| 색 3계층 구성, 금지색, 표지와 간지의 느낌 일치 | 해당 게이트 없음. G-색면은 면적만 잰다 (GATE 검사 목록) |
| 좌우 면에 "무엇을 넣는지"가 다른가 | G-미러는 이미지 유사도만 잰다. 위치만 바꾼 미러링 판정은 사람 몫 (feedback_no_mirrored_page_art 기준, 확인 필요) |
| 기준 완성본과의 구조·색·괘선 굵기 대조 | 납품 전 점검 4번, 수동 (SPEC) |
| 안전여백(3/5mm) | 게이트 없음 (SPEC) |
| 서체 임베드 여부, 이미지 300dpi | 게이트 없음 (SPEC) |
| 면수(짝수, 중철 4의 배수) | "자동 게이트가 없으니 직접 센다" (CLAUDE). hankkeut·pocketbook은 build가 맞춘다 (SPEC) |
| 선 0.25pt·흰 선 0.5pt·흰 글자 7pt 최소치 | SPEC 대응표에 게이트 기재 없음. 확인 필요 |
| 게이트는 통과했는데 글자가 있어 육안으로만 보이는 결함 | 예: 회차 배지가 제목에 눌러앉음(중등부 2권 개정 원고, "게이트 셋 다 통과"). 대응은 콘택트 시트로 전 면을 훑는 것 (project_middle_regular_gachisaegim, project_gwanggyo_prehigh1_special) |
| 색을 바꾼 뒤의 렌더 결과 | 표지 워드마크가 뒤표지로 넘어갔는데 빌드는 성공했다 → 렌더해서 눈으로 본다 (project_gwanggyo_prehigh1_special) |
| `get_drawings()` 좌표 | 클리핑 전 bbox라 좌표는 맞는데 안 보이는 경우가 있다 → 고해상도 렌더로 확인 (엔진 "확인·운영") |
