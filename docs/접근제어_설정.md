# yonestudio.com 접근 제어 설정 가이드 (C3-13)

> 대상: yonestudio.com — Cloudflare Tunnel → localhost:5010 (Flask).
> 이 문서는 Cloudflare **대시보드에서 수동으로** 수행하는 절차다. API 토큰이
> 없어 코드로 자동화하지 못한 부분을 사람이 1회 설정한다. 소요 약 15분.

## 0. 현재 앱 레벨 방어 현황 (코드에 이미 구현됨)

| 계층 | 내용 | 위치 |
|---|---|---|
| 로그인 | 세션 기반 로그인 필수 (`/login`, `/logout`, `/api/health`, `/static/` 외 전 경로). API는 401 JSON, 페이지는 리다이렉트 | `routes/auth.py` `check_auth` |
| 역할 분리 | 조교(assistant)는 목업/채팅 경로 차단 (403) | `routes/auth.py` |
| 비밀번호 | 환경변수(`YONE_ADMIN_PASSWORD` 등) 주입 — 저장소에 평문 없음 | `data/users.json` + `core/webdata.py` |
| **시도 제한 (C3-13)** | (클라이언트IP, 아이디) 기준 **실패 5회 → 10분 잠금**. 잠금 중엔 정답도 거부, 잠금 연장 없음. 성공 시 초기화. 실패/잠금 시도는 stdout 로그로 남음 (`~/Library/Logs/yonestudio-flask.log`) | `routes/auth.py` 로그인 시도 제한 블록 |
| 클라이언트 IP 식별 | Cloudflare Tunnel 뒤라 `remote_addr`은 항상 로컬 — **`CF-Connecting-IP` 헤더**를 우선 사용 (로컬 접속은 remote_addr 폴백) | `routes/auth.py` `_client_ip` |
| 보안 헤더 | CSP, HSTS, X-Frame-Options DENY, nosniff, Referrer/Permissions-Policy, COOP/CORP/COEP 등 전 응답 적용 | `routes/auth.py` `add_no_cache` |

앱 레벨 방어는 "비밀번호가 뚫리기 어렵게" 하는 것이고, 아래 Cloudflare Access는
**로그인 화면 자체를 인터넷에서 숨기는** 바깥 겹이다. 둘을 함께 쓰는 것이 목표.

## 1. Cloudflare Zero Trust Access — 이메일 OTP 게이트 (권장)

효과: yonestudio.com 접속 시 Flask에 닿기 **전에** Cloudflare가 이메일 인증
화면을 먼저 보여준다. 허용 목록에 있는 이메일로 1회용 코드(OTP)를 받아야만
통과 → 그 다음에야 기존 Flask 로그인 화면이 나온다. 무료 플랜(50석)으로 충분.

### 1-1. 팀 도메인 생성 (최초 1회)

1. https://one.dash.cloudflare.com 접속 → yonestudio.com이 있는 계정으로 로그인.
2. 좌측 메뉴 **Zero Trust** 클릭. 처음이면 온보딩이 뜬다:
   - **팀 이름(team domain)** 입력 — 예: `yonestudio` → `yonestudio.cloudflareaccess.com`이 된다. (인증 화면 주소일 뿐, 서비스 주소와 무관)
   - 플랜 선택에서 **Free** 선택 (결제수단 등록을 요구할 수 있으나 과금 없음).
3. 기본 로그인 방식은 **One-time PIN**(이메일 OTP)이 자동 활성화되어 있다.
   확인: Zero Trust → **Settings → Authentication → Login methods**에
   "One-time PIN"이 있는지. 없으면 **Add new → One-time PIN** 추가.

### 1-2. Access Application 추가

1. Zero Trust → **Access → Applications → Add an application**.
2. 유형: **Self-hosted** 선택.
3. 설정:
   - **Application name**: `Y.ONE STUDIO 조판웹`
   - **Session Duration**: `24 hours` (하루 한 번 OTP — 조교 사용 패턴에 적당)
   - **Public hostname**: Domain에서 `yonestudio.com` 선택, Path는 비움(전체 보호).
     - www 등 서브도메인도 서비스 중이면 **Add public hostname**으로 각각 추가.
4. **Next**로 정책 화면으로 이동.

### 1-3. 정책: 특정 이메일만 허용

1. **Policy name**: `허용 이메일`
2. **Action**: `Allow`
3. **Include** 규칙:
   - Selector: **Emails**
   - Value: 허용할 이메일을 나열 — 예: `yungienglish.lab@gmail.com`, 조교 지메일들.
   - (팀원이 모두 같은 도메인 메일이면 **Emails ending in** `@회사도메인`도 가능)
4. **Next → Add application**으로 저장.

> 주의: **Everyone**이나 **Bypass**를 넣지 말 것 — 그러면 게이트가 무의미해진다.

### 1-4. 터널 연동 확인 + 동작 검증

Access는 DNS가 Cloudflare 프록시(주황 구름)를 거치기만 하면 터널과 자동으로
함께 동작한다 — cloudflared 쪽 설정 변경은 불필요. 확인 절차:

1. Cloudflare 대시보드 → yonestudio.com → **DNS**: 해당 레코드가 **Proxied**(주황 구름)인지 확인. (터널 라우트로 만든 CNAME은 기본 Proxied)
2. **시크릿 창**에서 https://yonestudio.com 접속 → Cloudflare Access 이메일 입력 화면이 나오면 성공.
3. 허용 목록의 이메일 입력 → 메일로 온 6자리 코드 입력 → 통과 후 기존 Flask 로그인 화면이 나오는지 확인.
4. 허용 목록에 **없는** 이메일로도 시도 — "That account does not have access" 류 거부가 나와야 한다.
5. 로컬 확인: `http://localhost:5010`은 터널을 안 거치므로 Access와 무관하게 기존처럼 동작한다 (Mac에서의 작업 흐름 불변).

### 1-5. 조교 온보딩 시 이메일 추가

1. Zero Trust → **Access → Applications** → `Y.ONE STUDIO 조판웹` → **Edit** → **Policies** 탭.
2. `허용 이메일` 정책 클릭 → Include의 **Emails** 값에 새 조교 이메일 추가 → **Save**.
3. 조교에게: "yonestudio.com 접속 → 본인 이메일 입력 → 메일로 온 코드 입력" 안내.
   그 다음 Flask 로그인은 기존처럼 assistant 계정 사용.
4. 퇴사/교체 시 같은 화면에서 이메일 제거 (Access 세션은 최대 24시간 내 만료).

## 2. 대안: WAF IP 제한 (Access 대신 또는 보조)

Cloudflare 대시보드 → yonestudio.com → Security → WAF → Custom rules에서
"IP가 허용 목록에 없으면 Block" 규칙 하나로 끝나는 가장 단순한 방법이다.
장점은 설정 1분·사용자 경험 무변화(허용 IP에선 아무 것도 안 뜸)·무료라는 점,
단점은 **고정 IP 전제**라는 점이다 — 가정용 회선·휴대폰 테더링은 IP가 수시로
바뀌어 조교가 갑자기 차단되고, 그때마다 대시보드에서 IP를 갱신해야 한다.
또 IP는 "사람"이 아니라 "회선"을 식별하므로 카페 와이파이 같은 공유 IP를
허용하면 그 회선의 모든 사람이 통과한다. 사무실 고정 IP + 관리자 1인 환경이면
충분하지만, 조교가 여러 장소에서 접속하는 현 운영 형태에는 이메일 OTP(1장)가
맞다. 절충으로 "한국 외 국가 차단"(Country not in KR → Block) 규칙만 WAF에
추가하고 Access를 본 게이트로 쓰는 조합도 좋다.

## 3. 자동화하려면 (나중에)

이 문서의 절차를 코드/CLI로 자동화하려면 Cloudflare **API 토큰**이 필요하다:

- 발급: Cloudflare 대시보드 → My Profile → **API Tokens → Create Token**.
- 필요 권한 스코프: **Account → Access: Apps and Policies → Edit**
  (조회만 필요하면 Read). 계정 범위는 yonestudio.com이 속한 계정으로 한정.
- 토큰이 있으면 `cloudflared` 또는 REST API(`/accounts/{id}/access/apps`)로
  Application/Policy 생성·이메일 추가를 스크립트화할 수 있다.
- 토큰은 저장소에 커밋하지 말고 `.env`(예: `CF_API_TOKEN`)로 주입할 것.
