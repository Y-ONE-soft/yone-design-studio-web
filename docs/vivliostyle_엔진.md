# Vivliostyle 조판 엔진 — 설계와 함정 (2026-08-20)

InDesign 대신 **HTML/CSS → @vivliostyle/cli → PDF** 로 책을 내는 경로.
상일보카(A5 단어장 259p)와 블랙북(A4 교과 문제집 116p) 두 권이 이 엔진으로
납품됐고, 계열은 앞으로 계속 늘어난다.

이 문서 하나로 이어받을 수 있게 쓴다. **먼저 "왜 3계층인가"를 읽고, 새 계열을
붙일 때는 "계열 붙이기"만, 조판 중 이상하면 "함정"만 보면 된다.**

---

## 왜 3계층인가

상일보카는 교재 폴더의 `automation/` 안에서 완성됐다. 그 폴더는 **git 이 아니다.**
다음 책에 복사하는 순간 포크가 늘고 롤백도 안 된다. 그런데 거기서 나온 것 중
대부분은 책과 무관한 공용 자산이었다 — 도련 계산, TrimBox, 간지 결합, 2패스 면
지정, PDF 계측 검수. 블랙북에서도 **같은 것을 다시 썼다**(다른 코드로).

그래서 셋으로 나눈다. 경계의 기준은 "무엇이 달라지면 여기가 바뀌는가"다.

| 계층 | 위치 | 바뀌는 이유 |
|---|---|---|
| ① 공용 백엔드 | `core/render_vivlio/` | Vivliostyle·PDF 자체의 성질이 바뀔 때 |
| ② 계열 | `core/render_vivlio/series/<이름>/` | 디자인 계보·원고 형식이 바뀔 때 |
| ③ 책 1권 | 교재 폴더의 `config.json` + `원고/` | 책마다 |

교재 폴더에는 **코드를 두지 않는다.** 지금 상일보카·블랙북 폴더에는
`config.json`·`원고/`·산출 PDF·README 뿐이다(납품 시점 코드는 `_backup/` 에 보존).

## 실행

```bash
cd ~/dev/yone-design-web
npm --prefix core/render_vivlio ci     # 최초 1회 (CLI 설치)

bin/viv --list                          # 교재 트리의 Vivliostyle 책 목록
bin/viv "<책폴더>" data                 # 원고 → data.json (+ 인식 게이트)
bin/viv "<책폴더>" build                # 조판 → PDF → 마감(간지·TrimBox)
bin/viv "<책폴더>" verify               # 검수 게이트
bin/viv "<책폴더>" all                  # data → build → verify

bin/viv "<책폴더>" watch                # ★ 라이브 미리보기 — 고치면 바로 보인다
bin/viv "<책폴더>" render               # 조판 직전까지(HTML만). watch 가 쓰는 것
```

계열 옵션은 그대로 흘러간다: `--sample`(견본), `--nomemo`(단어장, 메모면 없는 판),
`--nomeasure`(블랙북, 높이 재측정 생략).

### 라이브 미리보기 — `watch`

값 하나를 바꿔 보려고 전권 조판(20~50초)을 돌리고 PDF 뷰어를 다시 열던 왕복을
없앤다. **재렌더는 0.4초**고, 브라우저가 스스로 새로 그린다.

```bash
bin/viv "<책폴더>" watch                # 주소를 찍어 준다. 브라우저로 열어 두고 작업
bin/viv "<책폴더>" watch --port=13100   # 포트가 겹칠 때
bin/viv "<책폴더>" watch --data         # 원고부터 다시 뽑고 시작
```

- **완전히 오프라인**이다. `@vivliostyle/cli` 와 뷰어가 `node_modules` 에 이미 있다.
- `--no-open-viewer` 라 Playwright 브라우저를 띄우지 않는다 — 쓰던 브라우저로 연다.
- 지켜보는 것: 책 `config.json`·`data.json`·`overrides.css`, 계열
  `series/<계열>/*.py`, `themes/<계열>.css`·`_base.css`, 공용 백엔드 `*.py`.
- ⚠ **편집 지점은 `build/` 가 아니다.** `build/theme.css`·`index.html` 은 렌더마다
  덮어써지는 사본이라 거기 고친 것은 다음 렌더에 사라진다.
- ⚠ 렌더는 **자식 프로세스**로 돈다(`bin/viv <책> render`). 계열 `.py` 를 고쳐도
  늘 새 코드로 돌게 하기 위해서다(`importlib.reload` 는 조용히 어긋난다).
- ⚠ 주소를 직접 조립하지 말 것 — 뷰어는 `/__vivliostyle-viewer/index.html`, 문서는
  `/vivliostyle/…` 이고 해시에 `src=` 가 붙는다. CLI 가 찍는 줄을 읽는다.
  그리고 **preview 의 stdout 을 안 비우면 파이프가 차서 서버가 멎는다**(데몬 스레드).

**"조판을 건너뛴다"는 최종 조판에만 걸린다.** 블랙북은 본 조판 전에 높이 측정용
PDF 를 두 번 굽는데, 거기서 멈추면 **측정용 HTML 을 미리보기로 삼는 사고**가 난다
→ `cli.run_build(..., final=False)` 로 내부 패스를 표시하고, 블랙북은
`render_opts = {"nomeasure": True}` 로 측정 자체를 건너뛴다(이미 잰 `heights.json`
을 쓴다. 원고가 바뀌었으면 `build` 를 한 번 돌려 갱신할 것).

CLI 는 이제 **리포 소유**다(`core/render_vivlio/package.json`). 예전 파일럿 설치
(`pilot/vivliostyle/node_modules`)는 폴백으로만 남는다.

## ① 공용 백엔드 — 무엇이 여기 있나

| 모듈 | 하는 일 |
|---|---|
| `cli.py` | CLI 위치 탐색·실행. **경로의 단일 소스** (예전엔 세 곳에 복사돼 있었다) |
| `stage.py` | 서체·테마·자산을 빌드 디렉터리에 배치. 서체는 리포에 넣지 않고 로컬 설치본을 복사 |
| `probe.py` | PDF 계측 원자 — 텍스트·마커·잉크 바닥·도형·상자. **전부 mm 로 돌려준다** |
| `paged.py` | 2패스 면 지정 — 마커로 면을 찾고 `@page :nth()` 규칙을 만든다 |
| `measure.py` | 자연 높이 실측 — 한 면에 한 항목만 조판해 바닥 잉크까지를 잰다 |
| `bleed.py` | 도련·TrimBox·간지 삽입·빈 면 채우기·파리티 마감 |
| `verify.py` | 검수 게이트 — 누락/순서, 판면 넘침, 빈칸 유실, 상자 걸침, TrimBox, 도련 미달 |
| `svg.py` | 배경 SVG 헬퍼 (도형을 그리는 **유일하게 안전한 방법**) |
| `config.py` `book.py` | ③ 스키마와 빌드 오케스트레이션 |

### 두 가지 "다시 조판"이 있다 — 섞지 말 것

둘 다 "조판 → PDF 계측 → 다시 조판"이지만 **계측하는 것이 다르고, 안전성이 다르다.**

- **2패스 면 지정**(단어장) — 1패스로 조판해 Day 시작 면 번호를 알아낸 뒤,
  그 면에만 `@page :nth()` 로 배경/마진 박스 내용을 바꾼다.
  **페이지 나눔이 불변**이라는 계약이 핵심이다. 재조판이 아니라 덧칠이므로 수렴을
  걱정할 필요가 없다.
- **높이 측정 배치**(블랙북) — 항목을 한 면에 하나씩 조판해 자연 높이를 재고,
  그 값으로 본 조판을 **한 번에** 끝낸다.
  ⚠ 여러 면에 걸치는 흐름(해설)을 **반복 조판으로 수렴시키려 하면 발산한다**
  (실측: 10→8→7). 높이를 재서 펼침면 용량으로 미리 나누는 편이 한 번에 끝난다.

### 도련은 옮기는 게 아니라 늘리는 것

판형 148×210 + 도련 3mm → 페이지 154×216, 재단선 원점 (3,3).
**본문 위치는 재단선 기준으로 그대로** 두고 여백만 도련만큼 더한다(20/19/11 →
23/22/14). 재단선에 닿는 **색면만 3mm 더 그린다**.

- 요소를 페이지 끝에 붙이면 재단 후 폭이 3mm 줄어든다 — 측면 라벨에서 실제로 발생.
  옮기지 말고 **오른쪽 패딩에 +3mm**.
- 배경 SVG 의 **박스(width/height)도 같이 키울 것.** 안 키우면 도형이 박스 밖에서
  잘린다 — 태그 바닥(높이 부족)과 접힌 꼬리(폭 부족)가 실제로 사라졌다.
- ⚠ `set_cropbox` 를 먼저 부르면 **TrimBox 가 되돌아간다.** TrimBox 만, 그리고
  MediaBox 원점 기준으로 찍는다(원점이 0 이 아닐 수 있다).
- 마감 저장은 항상 임시 파일 → `os.replace`. 교재 폴더는 클라우드 동기화 경로라
  큰 저장이 `Operation timed out` 으로 끊길 수 있는데, 목적지에 직접 쓰면
  **납품본이 반쪽짜리로 덮인다**(실제로 한 번 겪었다).

## ② 계열 붙이기

`series/base.Series` 의 네 훅만 채우고 `series/__init__.py` 에 한 줄 등록한다.

```python
class MySeries(Series):
    name, display, theme = "myseries", "…", "myseries"   # themes/myseries.css
    def gen_data(self, cfg, log): ...    # 원고 → data.json (인식 게이트 내장)
    def gen_theme(self, cfg, log): ...   # 팔레트/자산 재생성 (필요 없으면 생략)
    def build(self, cfg, log, **opts): ...   # data.json → HTML → CLI → 마감
    def verify(self, cfg, log, report): ...  # 계열 고유 검사만
```

조판 실행·서체 배치·패스 관리·PDF 마감·공용 검수는 **백엔드가 한다.** 계열이
직접 `subprocess` 로 CLI 를 부르거나 TrimBox 를 찍으면 그건 계층을 넘은 것이다.

### 지금 있는 계열

| 계열 | 책 | 성격 |
|---|---|---|
| `vocabook` | 상일·(배재)보카 | A5 단어장. 섹션(표제어/파생어/more with/vs)+워크북 합본. 헤더 4면 체계 · 2패스 면 지정 |
| `vocaunit` | 광문보카 | A5 단어장. Unit 하나가 표제어 30개짜리 한 흐름, 항목은 2열(왼쪽 표제어·오른쪽 뜻/예문) |
| `blackbook` | 프리미엄북 블랙북 | A4 교과 문제집. 높이 측정 배치 · 펼침면 단위 해설 흐름 · 완성본 아트워크 결합 |
| `whitebook` | 프리미엄북 화이트북 | A4 어휘 실전문제집. **사분면 고정**(한 면 4문항) · Day 하나 = 5면 · 정답은 뒤에 몰아서 |

`vocabook` 과 `vocaunit` 은 **둘 다 A5 단어장이지만 계열이 다르다.** 나눈 기준은
판형이 아니라 "무엇이 달라지면 코드가 바뀌는가"다 — 디자인 계보(마름모 탭 vs
모눈+둥근 탭)와 원고 형식(시트 4개짜리 섹션 xlsx vs Unit 시트별 블록 xlsx)이 다르고,
겹치는 것은 백엔드(도련·TrimBox·2패스·검수)뿐이다. 헤더 4면 체계라는 **아이디어**는
같지만 그리는 도형이 전부 달라 공유할 코드가 없다.

**계열 테마의 config 화 정도는 책 수에 비례한다.** 단어장은 책이 넷이라 서체·팔레트·
판형·치수를 전부 config 로 뺐고(`themes/vocabook.css` 의 `/*@PRELUDE@*/`·
`/*@GENERATED@*/` 자리에 `series/vocabook/theme.py` 가 끼운다), 블랙북은 아직 한 권이라
`themes/blackbook.css` 에 실측값이 그대로 있다. **무엇이 책마다 다른지는 두 번째 책이
알려준다** — 두 번째 책이 오기 전에 미리 빼는 것은 추측이다.

## ③ 책 config.json

```jsonc
{
  "series": "vocabook",
  "book":   { "id", "title", "brand", "subject", "school", "period" },
  "page":   { "width": 148, "height": 210, "bleed": 3 },
  "output": { "dir": ".", "stem": "상일1_상일보카01_내지" },
  "manuscript": { "dir": "원고", "files": {…} },   // 또는 "pattern"/"lessons"
  "fonts":   [{ "family", "file", "weight" }],      // 파일명만 — 로컬 설치본을 복사
  "palette": { "common": {…}, "sections": {…} },
  "metrics": {…},                                   // 계열 기본값을 덮어쓴다
  "finish":  {…},                                   // 간지·MEMO·파리티·TrimBox
  "verify":  {…},                                   // 판면 프레임·건너뛸 면
  "options": {…}                                    // 계열 고유
}
```

경로에는 `${BOOK}`(config 가 있는 폴더)·`${STUDIO}`(스튜디오 루트)·`~` 를 쓸 수 있고,
상대경로는 책 폴더 기준이다.

`finish` 는 마감 순서를 그대로 나타낸다 — 간지 삽입(마커 `§DIV1§` 또는 쪽번호
`at`) → 빈 면을 MEMO 로 → 마지막 면을 왼쪽으로 → 뒤 간지 → **마지막에** TrimBox.

## 인쇄 원고 — `bin/viv <책> print`

조판 결과는 **무조건 DeviceRGB** 다(Vivliostyle/Skia 는 순수 검정도 `0 0 0 rg`).
`core/render_vivlio/prepress.py` 가 CMYK 인쇄 원고를 만든다.

```bash
bin/viv "<책폴더>" print        # config 의 `print` 절을 따른다
bin/viv "<책폴더>" all          # data → build → **print** → verify
```

⚠ **인쇄 원고는 조용히 뒤처진다.** 조판본만 다시 뽑고 인쇄본을 안 돌리면 옛 색
그대로 납품될 수 있다(실제로 겪었다). `print` 절이 있는 책은 **`all` 이 인쇄본까지
만들고**, `verify` 가 **인쇄본이 조판본보다 오래됐으면 결함**으로 잡는다.
⚠ 결과 PDF 를 뷰어에 **열어 둔 채** 다시 만들면 파일이 통째로 교체돼(inode 교체)
뷰어가 옛 화면을 붙잡는다 — 파일이 안 바뀐 게 아니다. 창을 닫았다 열 것.

⚠ **그냥 ICC 로 넘기면 본문 먹이 C80 M80 Y77 K60 리치블랙이 된다.** 7pt 본문에
4도 먹을 쓰면 핀 어긋남으로 글자가 뭉갠다. 실제 납품본(InDesign)은 본문 **K100**,
회색 **K70·K50** 단색이다. 그래서 두 단계로 나눈다.

1. 먹·회색만 **DeviceGray 로 미리 바꾼다**(`print.gray_map`). Ghostscript 는
   DeviceGray 를 CMYK 로 변환하지 **않고 그대로 둔다** — RIP 에서 K 단색으로 나간다.
   화면 표기값(#231f20)과 인쇄값(K100)이 다르므로 자동 판정하지 않고 표를 명시한다.
2. 나머지(유채색·이미지·그러데이션)는 Ghostscript 가 ICC 로 변환한다.

그 밖의 함정:

- 이전 판과 **색을 정확히 맞춰야 하는 것**(브랜드색·전 학기 강조색)은 ICC 를
  태우면 값이 미묘하게 달라진다 → `print.cmyk_map` 에 넣어 CMYK 로 못 박는다.
- ⚠ `-dSAFER` 는 입출력 밖 파일 읽기를 막는다 — ICC 가 시스템 폴더에 있으면
  "Permission denied" 로 죽는다. `--permit-file-read=<icc>` 로 그 파일만 열어 준다.
- ⚠ **Ghostscript 는 TrimBox/BleedBox 를 흘려버린다** → 변환 뒤 다시 찍는다.
- ⚠ `color: transparent` 인 2패스 마커가 **완전 투명한 리치블랙 도형**으로 남는다.
  잉크는 안 나가지만 색 점검에 잡히고 투명도를 끌고 온다 → 지운다. 단 `/Gxx gs` 는
  자기 q/Q 블록 안에 있지 **않아서**, 앞쪽 `q` 를 찾아 통째로 지우면 같은 블록의
  보이는 내용까지 날아간다. "색 지정 + gs + 바로 뒤 BT…ET" 만 지우고, **지우기 전후
  렌더를 픽셀 비교**해 다르면 되돌린다.
- ⚠ **얇은 괘선을 `linear-gradient` 배경으로 깔면 래스터 이미지로 나간다.**
  광문보카에서 항목 아래 괘선이 면마다 3260×5px 이미지 4~5개씩, 총 250여 개가 됐다.
  벡터인 위 border 와 겹쳐 **70곳이 165㎌ 대신 198㎌** 로 보였다(사용자가 "어디는
  굵어 보인다"고 지적한 것의 실체). 위아래 border + 음수 마진도 반올림 때문에 정확히
  겹치지 않는다 → **아래 괘선은 흐름 상자에 `box-decoration-break: clone` 으로**
  두면 면마다 한 번만 그려진다(전 334곳 165㎌ 균일 확인).

## 함정 (두 책에서 실제로 데인 것)

### 마진 박스(러닝 요소)
- `position: relative` 를 주면 `position: running()` 이 덮여 **본문에 그대로 그려진다**
- `transform: rotate()` 무시 (마름모가 네모로 나옴), `visibility: hidden` 무시
  → 감추려면 색·배경을 `transparent` 로
- 세로 음수 마진은 잘린다. **가로 음수 마진 + 같은 크기 패딩**만 통한다
- 박스 높이(= 페이지 여백)를 넘는 요소는 잘린다 — 13mm 여백에 16mm 탭 → 꼭짓점 소실
- `@bottom-center` 는 무시된다(블랙북). 쪽번호는 `@bottom-*-corner`
  (여백 밖으로 넘쳐도 잘리지 않는다), 나머지 문구는 배경 이미지로
- **결론: 마진 박스 안의 도형은 전부 배경 SVG**(feDropShadow 포함)

### 본문·공통
- `clip-path` + `filter: drop-shadow()` 동시 사용 시 **요소가 통째로 사라진다**
- `border-radius` 는 자식을 자르지 않는다 → 장식은 배경 SVG 로 구울 것
- `@page :nth(N)` 은 `@page p-head` 같은 **이름 규칙에 명시도로 밀린다**
  → `@page p-head:nth(N), p-deriv:nth(N), …` 처럼 이름과 함께 지정
  (빠뜨리면 헤더 밴드의 둥근 모서리로 배경이 비쳐 보인다)
- `@page` 배경의 `repeating-linear-gradient` 는 주기가 어긋난다 → SVG data URI
- `@page` 배경은 **층마다 position/size 를 명시**해야 한다. 안 하면 뒤 층이 앞 층의
  크기를 물려받아 방패 뒤에 회색 띠가 조각으로 찍힌다
- 얇은 괘선을 `linear-gradient` 의 색 정지점으로 그리면 **72dpi 로 래스터화돼 사라진다**
  → 단색 그라디언트를 **선 두께만 한 상자**로 깔 것
- 배경 SVG 안에는 CSS 변수를 못 쓴다 → 색이 구워져 들어간다. 팔레트를 바꾸면
  **반드시 생성기를 다시 돌릴 것**(빼먹으면 띠·밴드만 옛 색으로 남는다 — 두 번 발생).
  지금은 빌드마다 자동으로 다시 굽는다
- 렌더러에서 태그를 닫지 않으면 DOM 이 중첩돼 열 폭이 계속 좁아진다
- 원고의 **연속 공백은 의미 구분 간격**이다 → 보존할 것(HTML 은 공백을 축약한다)
- `.vunit:first-of-type` 은 앞에 있는 같은 부모의 요소 때문에 맞지 않는다 → `+` 인접 선택자

### 확인·운영
- ⚠ `get_drawings()` 는 **클리핑 전 bbox** 다 → "좌표는 맞는데 안 보이는" 상황이 생긴다.
  좌표 확인으로 끝내지 말고 **고해상도 렌더로 눈으로 볼 것**
- **미리보기로 결과 PDF를 열어 둔 채 다시 빌드하면** 몇 면만 남고 나머지가 흰 종이로

  아니다 — 창을 닫았다 열거나 확인용 사본을 따로 둘 것
- 원고·간지 원본은 **GDrive 원본을 절대 수정하지 않는다.** 로컬 복사본으로 작업

## 광문보카(`vocaunit`) — 세 번째 계열에서 드러난 것

기존 완성본(`광문1_광문보카_내지(샘플).pdf`)을 기준으로 **베이스라인 단위 실측**해
옮겼다. 자를 대고 눈으로 맞추지 말고, `origin` (베이스라인)으로 상수를 뽑아
CSS 값을 역산할 것 — bbox 윗변은 글리프마다 달라 ±2mm 씩 흔들린다.

- **완성본 도형은 벡터로 뽑아 온다.** 크레스트는 `get_drawings()` 의 items 를
  SVG path `d` 로 변환해 `series/vocaunit/art.py` 에 넣었다(색·크기만 바꿔 헤더와
  간지에 같이 쓴다). 서체가 없는 글자(`TTSupersizeBk` 의 "2026", MEMO 탭)만
  고해상도 PNG 로 떠서 `assets/vocaunit/` 에 뒀다.
- ⚠ **배경 축약형에 `no-repeat` 를 두 번 쓰면 선언이 통째로 무시된다.**
  `svg.data_uri()` 는 이미 `no-repeat` 를 붙여서 돌려준다 — 뒤에 `/ 크기 no-repeat`
  를 또 붙이면 CSS 파서가 그 배경을 버린다(도형이 조용히 사라진다).
- ⚠ **러닝 요소의 배경은 요소 상자 안에서만 그려진다.** 높이를 상단 여백만큼
  잡지 않으면 탭·크레스트의 아래쪽이 잘린다. 여백보다 크게 잡으면 이번엔 마진
  박스가 자른다 → `height: <상단 여백>` 이 정답.
- ⚠ **2열 항목을 flex 로 짜면 `break-inside: avoid` 가 마지막 항목에서 무시된다.**
  판면 아래 띠까지 넘쳤다(Unit 19). `display: table` + `table-cell` 로 바꾸면
  조각화가 제대로 걸린다. 음수 마진으로 괘선을 겹치는 대신 아래 괘선을
  **배경 상자**로 깔면 다음 항목의 `border-top` 과 정확히 겹친다.
- config 키의 밑줄(`cover_mark`)과 CSS 변수의 하이픈(`--c-cover-mark`)이 어긋나면
  **색만 조용히 검정으로 떨어진다** — 프렐류드에서 `_` → `-` 로 바꿔 넣을 것.
- ⚠ **`text-indent` 는 inline-block 안까지 상속된다.** 뜻 문단의 내어쓰기
  (`text-indent: -3.75mm`)가 품사 배지 안에서 또 걸려 **글자만 상자 밖으로**
  밀려났다. 배지 같은 inline-block 에는 `text-indent: 0` 으로 끊을 것.
- ⚠ **테두리 있는 inline-block 에 `line-height: <상자 높이>` 를 주면 글자가 내려앉는다.**
  줄 상자가 내용 상자보다 테두리 두께의 두 배만큼 커진다 → 품사 배지의 글자가
  아래로 밀렸다. `calc(상자 높이 - 2 × 테두리)` 로 맞출 것.
- ⚠ **원고 주석을 빼는 정규식은 중첩 괄호에서 조용히 실패한다.** `(= judg(e)ment)`
  · `(↔ uncertainty … 불확실(성))` — `\(...[^()]*\)` 로는 이 셋이 그대로 남는다.
  여는 자리만 찾고 **닫는 자리는 깊이를 세어** 찾을 것. 뺀 뒤 PDF 전문에 한 톨도
  안 남았는지 게이트로 확인한다.
- ⚠ **자산 PNG 는 팔레트를 따라가지 않는다.** 배경 SVG 는 빌드마다 다시 구워지지만
  PNG 는 색이 파일에 박혀 있어, 지면을 연보라→분홍으로 바꿨을 때 로고의 "2026"
  알약만 보라로 남았다. `series/vocaunit/assets.py` 가 "바탕색 한 가지 + 흰 글자 +
  알파" 구조를 이용해 **빌드마다 팔레트 색으로 다시 굽는다**(흰색 쪽 섞임 비율을
  커버리지로 재서 바탕색만 교체 → 글자·안티에일리어싱 보존).

### 2패스 계약이 한 발 넘어간 자리 (알고 넘는다)

②(Unit 시작면 다음 오른쪽 면)는 배경만이 아니라 **상단 여백도 5mm 내려간다**
(완성본이 그렇다). 여백이 바뀌면 페이지 나눔이 바뀔 수 있으므로, `vocaunit` 은
시작 면 목록이 **고정점에 닿을 때까지** 다시 조판한다(최대 4패스, 안 멎으면 경고).
Unit 마다 `break-before: left` 가 걸려 있어 흔들림이 Unit 경계를 넘지 못하므로
실제로는 한 번 더 돌면 멎는다. 배경만 바꾸는 `vocabook` 의 2패스와 달리 이쪽은
**수렴을 확인해야 하는 패스**라는 점을 섞지 말 것.

## 한 책에 원고 형식이 둘 — `vocaunit` 대단원(part) 구조 (2026-08-26)

광문보카 26-2-중간에 **부교재 통합 원고**가 붙으면서, 한 책이 원고 두 벌·형식
두 가지·대단원 네 개가 됐다. 여기서 굳힌 것:

**형식은 시트를 열어 구조로 판정한다.** 파일 이름도 머리글 문구도 보지 않는다.
지표는 *행당 채워진 칸 수* 하나다 — 블록형(한 표제어가 여러 행) 1.5칸,
표형(한 행이 한 낱말) 5.0칸. 사이가 텅 비어 있어 3.0을 경계로 두면 시트가 몇
줄뿐이어도 흔들리지 않는다.

**표형의 열 역할도 값의 성질로 가른다**(`No/word/단원/meaning/예문` 이라는
머리글에 기대지 않는다): 가장 긴 열 = 예문, 가장 덜 다양한 열 = 단원, 거의 다
정수 = 번호, 남은 영문 중 짧은 쪽 = 낱말, 한글이 있는 열 = 뜻. 머리글 행은
"역할에 맞지 않는 행"으로 저절로 빠지고, **몇 줄을 버렸는지 반드시 로그로 남긴다.**

**색은 색상각 하나로 돈다.** `parts[].hue` 가 그 대단원의 분홍 계열 전부를
정하고, `core/render_vivlio/color.py` 가 **밝기와 최대채도 대비를 지킨 채 색상만**
돌린다(OKLCH). HSL 로 돌리면 같은 S·L 이라도 노랑이 밝고 파랑이 어두워 톤이
무너진다. 쓸 수 있는 구간은 그 밝기에서 **최대채도가 큰 곳** 뿐이다 — L 0.646
에서는 H285~30(보라~로즈~코럴). 밖으로 나가면 채도가 눌려 칙칙해진다.

**배경 SVG 는 CSS 변수로 못 바꾼다.** 색이 data URI 안에 구워져 들어가기
때문이다. 그래서 대단원 색은 두 갈래로 간다 —
글자·괘선·회독칸은 `.pN { --c-*: … }` 로 **상속**시키고,
띠·모눈·MEMO 배경은 2패스가 **면마다 `@page p-body:nth(N)`** 을 낸다.
면이 어느 대단원인지는 간지에 심은 보이지 않는 `PARTOPEN` 마커로 안다
(`DAYOPEN` 과 같은 수법). 빈 면(MEMO)인지도 조판 결과의 글자 유무로만 알 수 있어,
2패스는 시작 면 목록뿐 아니라 **면 텍스트 전체**를 받는다.

**되풀이되는 예문은 묶음으로 접는다.** 표형 원고는 낱말마다 같은 문장을 다시
적어 놓는다(894개 중 468개가 바로 앞과 같은 문장). 같은 문장이 이어지는 낱말을
한 묶음으로 보고 문장을 **한 번만** 실으면서 그 묶음의 낱말을 모두 강조한다.
낱말들과 예문은 한 상자(`break-inside: avoid`)라 면이 갈려도 떨어지지 않는다 —
안 묶으면 "누구 예문인지 모를 문장"만 다음 면 맨 위에 남는다.

## 화이트북(`whitebook`) — 네 번째 계열에서 드러난 것 (2026-08-31)

1권(인디자인 완성본)의 **실전문제 면만** 실측 이식해 2권(400문항·120면)을 냈다.
같은 원고를 이 엔진으로 조판해 완성본과 대조하면 기준선·좌우 끝이 **±0.2mm** 안이다.
블랙북과 대비되는 성격이 이 계열의 정체다 — 블랙북은 높이를 재서 **가변 배치**하고,
화이트북은 **사분면 고정**이라 높이 측정을 배치가 아니라 **넘침 검사**에만 쓴다.

**사분면은 `column-fill: auto` + 고정 높이로 짠다.** 판면 높이를 칸 두 개보다 조금
크게(122.5×2 + 1) 잡고 `.q { height: 122.5mm }` 를 두 단에 흘리면 한 면에 정확히
넷이 앉고 다섯째가 다음 면으로 간다. 반올림 때문에 딱 245mm 로 잡으면 둘째 칸이
밀려난다.

**머리 장식의 좌우 오프셋은 판면 기준으로 잡으면 저절로 미러링된다.** 안쪽/바깥쪽
여백 차(3mm)를 장식 위치가 그대로 물려받으므로, 판면 왼쪽에서 `-9.75mm` 하나로
왼쪽 면·오른쪽 면이 모두 맞는다(Day 가 어느 쪽에서 시작해도 된다).

### 인디자인의 **장평**을 CSS 로 옮기는 법

완성본은 장평(가로 비율) 95% 다. CSS 에는 장평이 없다. 넷을 재 보면 —

- **글자 크기를 줄이면 안 된다.** 세로까지 줄어 지면이 달라진다.
- `transform: scaleX()` 는 **줄바꿈에 반영되지 않는다**(레이아웃 폭은 그대로).
- 서체를 가로로 눌러 다시 구우면 정확하지만, Noto CJK 6.5만 자를 매번 굽는 값이 크다.
- 남는 것은 **자간**이다. 글자 폭이 일정한 한글은 거의 정확하고(장평 95% ≡ 자간
  -0.05em), 폭이 제각각인 로마자는 ±0.2mm 오차가 남는다.

여기서 두 가지를 배웠다.

1. **자간은 서식마다 다르게 잡는다.** 한 값으로 밀면 한글 줄이 1mm 넘게 벌어져
   선지가 한 줄씩 더 접힌다. 크기·서체가 다른 조각(빈칸 표기·머리기호·원문자)은
   자간을 0 으로 끊고 **여백(padding)으로** 자리를 맞춘다.
2. **공백은 자간만으로 안 맞는다.** 한글 낱말 사이 공백은 0.22em 인데 자간 -0.046em
   을 그대로 먹으면 20% 가 깎인다 → `word-spacing` 으로 되돌린다.
   (이 보정 하나로 한글 선지 오차가 1.35mm → 0.3mm 로 줄었다.)

**자간 값은 글꼴 표가 아니라 조판 결과로 정한다.** `letter-spacing: 0` 으로 한 번
굽고, 완성본과 **같은 글줄**의 폭을 비교해 최소제곱으로 푼다. 글꼴 advance 표로
계산하면 렌더러가 실제로 쓰는 폭과 어긋나 값이 통째로 틀린다(원문자 하나 때문에
0.5em 이 어긋났다).

### 그 밖에 덴 것

- ⚠ **한글에서 넘어온 docx 는 모든 런에 `<w:u w:val="none"/>` 을 붙인다.**
  태그 유무로 밑줄을 판정하면 **문서 전체가 밑줄**이 된다(`data.py` 의 `_on()`).
  블랙북 파서도 같은 코드를 쓰고 있었다 — 고친 뒤 data.json 바이트 동일 확인.
- ⚠ **크기가 다른 인라인은 줄 상자를 키운다.** 8.63pt 빈칸 표기 하나 때문에 지문
  셋째 줄만 0.57mm 벌어졌다 → 그런 조각은 `line-height: 0` 으로 끊는다.
- ⚠ **인라인 블록은 더 심하다.** 문항 번호(11pt)를 `display:inline-block` 으로 두면
  그 상자 높이가 줄 상자를 키워 발문 둘째 줄이 밀린다 → 흐름 밖(`position:absolute`)
  으로 뺄 것. 같은 이유로 기준선 보정은 `vertical-align` 말고 `position: relative`.
- ⚠ **같은 발문이 400번 되풀이되는 교재**에서는 공용 `check_sequence` 가 못 쓴다.
  전권을 한 줄로 이어 놓고 찾으므로 위치가 앞뒤로 튀어 **순서 어긋남 3,692건** 같은
  거짓 경보가 난다. 면 범위를 Day 로 좁히고, 순서 대신 **"문항 N 은 (N-1)//4 번째
  면"** 이라는 계약을 본다(공용 `check_gaps` 도 같은 이유로 계열 것으로 바꿨다).
- ⚠ **PDF 글자 추출 순서는 조판 흐름이 아니다.** 사분면 배치는 흐름이 ①→②(왼 단)
  →③→④(오른 단)인데 추출은 좌표 순(①→③→②→④)이다. 순서 검사를 그대로 걸면 늘 깨진다.
- 판면 검사(`verify.frame`)의 좌표는 **미디어(도련 포함)** 기준이다. 재단 기준으로
  적으면 전 면이 넘침으로 잡힌다.
- `end_on_left` 에 아트워크가 없으면 예전에는 **조용히 아무것도 안 했다** — 간지를
  안 쓰는 계열이 홀수로 끝날 수 있었다. 이제 빈 면으로 맞춘다.
- 서체가 없는 글자(`AcademyEngravedStd` 의 `WHITE BOOK`)는 완성본에서 뜨되,
  **권 번호(`VOL.N`)는 같이 뜨면 안 된다** — 2권에 1권 표기가 나간다. 앞부분만
  떠 오고 번호는 빌드 때 Elice 로 그려 붙인다(`series/whitebook/assets.py`).
