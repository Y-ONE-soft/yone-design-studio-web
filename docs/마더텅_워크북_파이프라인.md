# 마더텅 N강 워크북 파이프라인

강 번호 하나로 워크북(가로) 완성까지 가는 단일 진입점.
`scripts/mt_pipeline.py`

```
강 번호 → 엑셀에서 코드 조달 → 코드별 세로 완성본 유무 판정
  → 있는 것: 세로결합 / 없는 것: 원고로 세로 조판 → 세로중간본
  → 가로 변환 + 후처리(정리·재스레드·지문번호)
  → 세로↔가로 전문 대조 → 손실 0 아니면 실패로 중단
```

부품(엔진)은 전부터 있었지만 묶는 곳이 없어서, 2026-08-24 13강은 임시
스크립트 10여 개를 손으로 이어 붙여 돌렸다. 이 파이프라인은 **그때 실제로
통했던 절차 그대로**를 코드로 고정한 것이다.

## 쓰는 법

```bash
cd ~/dev/yone-design-web
export PYTHONPATH="/Users/nhj/Library/Python/3.9/lib/python/site-packages"

# 1) 계획만 본다 — InDesign 무접촉, 1초 이내
/usr/bin/python3 scripts/mt_pipeline.py --gang 13 --school 한영1 \
    --exam-period 26-2-중간 --plan-only

# 2) 전 과정 실행 (계획에서 나온 run 을 이어서)
/usr/bin/python3 scripts/mt_pipeline.py --run mt13_b0f7e7

# 처음부터 한 번에 돌릴 수도 있다
/usr/bin/python3 scripts/mt_pipeline.py --gang 13 --school 한영1 \
    --exam-period 26-2-중간 --split 16 --workbook-start 2
```

주요 옵션

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `--gang` | 마더텅 강 번호 | (필수) |
| `--school` / `--exam-period` | 출력 폴더·파일명에 들어간다 | (필수) |
| `--grade` | 학년 | `고1` |
| `--split` | 권당 문항 수 (`0` = 분권 없음) | `16` |
| `--workbook-start` | 워크북 번호 시작 | `2` → `워크북02` |
| `--plan-only` | 코드 조달·유무 판정까지만 | off |
| `--run` | 기존 run 이어서 | — |
| `--from` | 그 단계부터 강제 재실행 | — |
| `--repair` | 대조 유실을 페이지 복구로 메움(최후 수단) | off |

결과 파일명은 `{학교}_워크북{NN}(마더텅{G}강_{a}~{b})_내지` — `a~b` 는
마더텅 지문번호 범위다.

## 단계

| # | 단계 | 하는 일 | 쓰는 부품 |
|---|---|---|---|
| 1 | `codes` | 지문 출처 엑셀에서 강별 코드 + 마더텅 지문번호 | `workbook_select/motherteng.py` |
| 2 | `survey` | 코드별 세로 완성본 유무 판정 | `mockexam_sero_merge.probe_sources` |
| 3 | `sero_new` | 완성본 없는 코드를 원고에서 세로 조판 | `workbook_sero` |
| 4 | `sero_merge` | 권별 세로결합 → 세로중간본 | `mockexam_sero_merge` |
| 5 | `v2h` | 가로 변환 + 후처리 3종 | `vert_to_horiz` |
| 6 | `verify` | 세로↔가로 전문 대조 | `scripts/v2h_content_diff.compare` |

각 단계는 끝날 때 `jobs/mt{강}_{id}/state.json` 에 기록된다. 다시 돌리면
**완료된 단계는 건너뛴다.** 한 단계가 수 분~수십 분이므로, 중간에 죽어도
`--run` 으로 이어서 가면 된다.

실측 소요(2026-08-24, 13강 32문항 2권): 세로 신규조판 1~3분/건,
세로결합 4분/권, 가로변환+후처리 5~10분/권, 대조 3~5분/권.

### 2단계 — 세로 완성본 유무 판정

`인디자인 파일/워크북/모의고사/고N/` 에서 `고N_YY년_M월_세로.indd` 를 찾는다
(리터럴 매칭 → 숫자 토큰 폴백). 못 찾은 회차 = 신규 조판 대상.
13강 실측: 32문항 중 27개는 완성본 있음, 5개(16년6월·17년9월·19년9월·
21년9월 2개)는 없음.

### 3단계 — 없는 것만 원고로 세로 조판

원고 폴더를 두 규칙으로 찾는다.

1. **회차 폴더가 있으면** 그 회차 원고
   `모의고사 작업/고N/고N YY년(3,6,9,10,11월)/고N YY년 M월/워크북/…`
   연도 묶음 폴더도 뚫고, `36-37번 워크북` 처럼 한 단계 더 들어간 폴더도
   따라간다(`_find_manuscript_dir` + `_descend_to_manuscripts`).
2. **회차 폴더가 없는 옛 기출**(16·17·19년 등)은 마더텅 N강 보충 폴더로
   몰아서 한 번에 조판
   `모의고사 작업/고N/*마더텅*기출*/{강}강 */워크북/`

조판 뒤 `content_meta.json` 의 사이클 코드로 **요청한 코드가 실제로 들어갔는지**
확인한다. 빠지면 그 자리에서 중단한다(조용히 넘어가면 결합 결과에 구멍이 난다).

### 4단계 — 세로결합

권별로 `mockexam_sero_merge` 를 돌린다. 3단계에서 새로 만든 세로본은
`source_override` 로 코드별 소스를 직접 지정해 섞는다 — 이 통로가 없으면
"세로 완성본을 찾지 못한 회차" 로 parse 가 죽는다.

### 6단계 — 대조 검수 (이게 유일한 진짜 검수)

세로→가로는 내용 보존 변환이다. 세로중간본에 있던 문단은 가로에 전부 있어야
한다. 조판 로그의 "오버셋 0 / 슬롯 검수 OK / 빈칸대조 일치"는 **전부 통과인데
지면은 잘려 있을 수 있다** — 프레임 매칭에서 빠진 내용은 조용히 사라진다
(2026-08-25 실측: STEP3 문항이 선지 중간에서 끊기고 문장배열 상단 카드가 소실.
로그는 전부 정상이었다).

유실이 하나라도 있으면 파이프라인은 **실패로 끝난다.** 그 상태의 가로
결과물은 납품하지 않는다.

대조는 두 종류를 제외한다. 둘 다 **개수를 로그와 완료 보고에 남긴다** —
조용히 0으로 만들지 않는다.

1. **세로에서 인쇄되지 않는 문단** — 덤프가 `OVF`(오버셋) / `PB`(붙임 영역)로
   찍는다. 세로에서도 안 나오는 걸 가로에 요구할 수 없다. 다만 세로 쪽
   오버셋은 **세로 자체의 문제**일 수 있으니 수를 보고 판단할 것.
2. **템플릿 잔재** — 세로결합은 템플릿 위에 내용을 얹으므로, 원고가 없는
   자리에는 템플릿의 샘플 문장이 그대로 남는다(실측: "All experimental
   equipment must be handled with care." 가 세로중간본 p123·p223 에 잔존 —
   13강 지문과 무관한 일반 어법 예문이고, `[원본]워크북(세로)_내지.indd`
   안에 그대로 있다). 가로는 trim_unused 가 그 미사용 페이지를 지우므로
   없는 게 정상이다. 판정 기준은 **템플릿을 직접 덤프**해서 얻는다
   (mtime 기준 캐시). CLI 는 `--template` 로 지정.

`--repair` 를 주면 유실 페이지를 세로 페이지째 가로에 넣어 메우고 재대조한다
(`engines/vert_to_horiz/jsx/repage_recover.jsx`). 넣은 페이지는 세로판
레이아웃 그대로이므로 **반드시 눈으로 확인**해야 한다.

## STEP3 유실의 원인과 수리 (2026-08-25)

첫 시운전에서 대조가 유실을 잡아냈다(1권 7/3244, 2권 5/2901). 추적 기록 —
같은 증상이 다시 나오면 여기부터 볼 것.

1. **재스레드가 범인일 것** → **반증**. `rethread_step3.jsx` 를 빼고 돌리니
   유실이 5개 → 12개로 **늘었다**. 재스레드는 잘린 내용을 되살리고 있었다.
2. **세로 원본의 오버셋일 것** → **반증**. 유실 문단이 있는 프레임은
   `overflows=false`, 전부 정상 인쇄 상태였다.
3. **페이지를 한 장씩 복제해서 스레드가 잘린다** → **확정**. 세로 p14~16 을
   두 방식으로 복제해 원본과 대조:

   | 방식 | 결과 |
   |---|---|
   | 한 장씩 `page.duplicate()` | 76문단 중 **2개 유실** |
   | 범위째 `pages.itemByRange(...).duplicate()` | **유실 0** |

   실전 페이지의 텍스트는 여러 프레임에 걸친 **하나의 스레드 스토리**다
   (실측: 6프레임 13,200자). 그 일부만 떼어 복제하면 **프레임 경계에 걸친
   문단이 잘린다**. 유실된 2문단은 정확히 `frame4` 끝 ↔ `frame3` 시작이었다.

**수리**: `run.jsx` 의 `lesson_all` 분기에서, 세로 페이지와 가로 슬롯이
**둘 다 연속일 때만** 범위째 복제한다. 아니면 종전 한 장씩으로 가고,
범위 복제가 실패해도 한 장씩으로 폴백한다(기존 동작 보존).
수리 후 같은 권 대조: 유실 5개 → **1개**(그 1개도 붙임 영역이라 대조 제외
대상). 원본은 `run.jsx.bak_before_rangedup`.

**최종 검증(13강 32문항 2권)**: 두 권 모두 **유실 0** 으로 통과.

| 권 | 대조 문단 | 유실 | 제외(인쇄 안 됨 / 템플릿 잔재) |
|---|---|---|---|
| 워크북02 (1~16) | 3238 | **0** | 6 / 6 |
| 워크북03 (17~32) | 2885 | **0** | 16 / 0 |

⚠ 워크북03 의 오버셋 16개는 **세로 쪽 상태**다. 가로 변환의 결함은 아니지만
세로중간본(=기출 세로 완성본)에 인쇄되지 않는 텍스트가 있다는 뜻이므로,
따로 살펴볼 가치가 있다.

## 검수에서 드러난 것들 (2026-08-25, 13강)

완주 뒤 산출물을 검수하자 **대조가 통과했는데도 지면이 잘못된** 경우가 나왔다.
아래는 그 원인과 대책이며, 후처리에 모두 반영돼 있다.

### 1. 대조가 "존재"만 보고 "인쇄"를 안 봤다 (가장 컸다)

세로 문단이 가로 파일에 **있기만** 하면 통과였다. 프레임에 안 들어가 지면에
안 나오는 텍스트도 "있다"고 셌다. 인쇄면 기준으로 다시 재니 **2885개 중
546개(19%)** 가 안 나오고 있었다.

→ `compare()` 가 가로 쪽도 인쇄되는 문단만 대조 집합에 넣는다.

### 2. 오버셋 = 조용한 유실

가로 프레임이 세로 내용을 못 담으면 꼬리가 숨는다. 문자수 검수도 내용 대조도
통과한다. 실측: 주제 문항 **선지 ①~⑤ 통째 소실**, p186·p195·p202 는 한 장에
270~320줄이 갇혀 지면이 거의 백지.

→ `overflow_relief.jsx` — 넘친 프레임 뒤에 페이지를 잇는다. 지면은 늘지만
   내용은 전부 나온다(실측 1권 +1장, 2권 +66장).

### 3. STEP3 프레임 경계 잘림

실전 페이지를 한 장씩 복제하면 여러 프레임에 걸친 스레드 스토리의 **경계
문단이 잘린다**. 범위째 복제하면 유실은 0이지만 담을 프레임이 부족해 오버셋이
대량 발생한다 — **오버셋 해소와 함께 써야** 성립한다(순서 중요).

| 조합 | 인쇄면 누락 |
|---|---|
| 한 장씩 + 재스레드 | 9개 |
| 한 장씩 + 오버셋 해소 | 4개 |
| **범위째 + 오버셋 해소** | **0개** |

`repage_recover`(페이지째 삽입)는 다른 내용을 덮어써 **역효과**였다(4→5개).

### 4. 지문번호는 마더텅 번호로 (사용자 확정)

`fix_passage_numbers` 는 코드 뒤 2자리(원 문항번호 36/37)를 썼다. 마더텅
작업은 **어떤 경로로 진행하든 마더텅 지문번호**여야 한다.

→ `settings.sources_list`(그 강 코드의 마더텅 번호 순서)로 매핑. 두 가지를
   함께 고쳤다:
   - **그 강에 없는 코드는 제외** — 섞여 들어온 코드 하나 때문에 지문이 하나 더
     잡혀 번호가 통째로 밀렸다(실측: `01,02,03,38,04…`). 제외한 코드는 경고로
     남긴다(실측 240938 — 세로중간본에 다른 회차가 섞였다는 신호).
   - **마커 인식 확장** — 회차에 따라 `{YYMMQQ}` 가 아니라 중괄호 없이 6자리만
     있다(실측 250936·250937). 6자리를 모두 긁되 그 강 코드와 일치하는 것만
     채택하므로 오탐은 없다.

### 5. 간지 라벨

가로 템플릿에 `"고2 모의고사"` 가 박혀 있어 고1 워크북에 그대로 인쇄됐다.

→ `fix_cover_label.jsx` — `"마더텅 13강, 17~32번"` 으로 교체.
   ⚠ 만들면서 두 번 틀렸다. 문서 전체 `findGrep` 은 **본문 발문까지** 바꿨고
   (`[2017 9월 고1 모의고사 36번]` 훼손), GREP 치환의 `~` 가 특수문자로
   해석돼 `"17~32번"` 이 `"17 2번"` 이 됐다. 지금은 **마스터 페이지를 포함해
   문단 단위 완전 일치**일 때만 `contents` 로 바꾼다.


## ⚠ 신규 조판은 **가로 직접**(workbook_select)이다 — 세로 경로 금지

세로 완성본이 없는 문항을 원고로 새로 조판할 때, **원고→세로(`workbook_sero`)로
가면 안 된다.** 그 경로는 문장배열 배치가 어긋난다.

실측(2026-08-25, 13강 신규 5문항):

| 경로 | 문장배열 결과 |
|---|---|
| 원고→세로 (`workbook_sero`) | 상단에 **템플릿 잔재**({20}·{21}·{22})가 남고 우리 지문이 하단으로 밀림, 하단 넘침 |
| 원고→가로 (`workbook_select`) | 상단=순서배열 / 하단=순서삽입 **정상**, 오버셋 0 |

가로 워크북 JSX 에는 하단 전용 스타일이 있다
(`S1_C1_BTM` = "STEP 01/C1_문장 배열 하단", `S1_C1_BTM_T` = 하단 지문).
`workbook_sero` 는 이 로직을 빌려 쓰지만 슬롯 배치가 맞지 않는다.

```bash
python3 scripts/wbsel_build.py --codes 170936,210937 --gang 13 \
    --grade 고1 --school 한영1 --exam-period 26-2-중간 --name "..."
```
⚠ `--gang` 을 함께 줘야 한다. 회차 폴더가 없는 옛 기출(17년 9월 등)은 마더텅
N강 보충 폴더에서 원고를 찾는데, 강 번호가 없으면 그 탐색을 생략해
"원고 폴더를 찾지 못한 회차" 로 죽는다.

### 이 오진에 이르기까지 — 같은 실수를 반복하지 않기 위해

문장배열 하단이 비어 있는 것을 보고 **원고 결손이라고 두 번 잘못 진단**했다.
- 1차: `Step1 C1 문장배열.docx` 한 파일만 열고 "순서삽입 문항이 원고에 없다" 고 단정.
       → 폴더에 `Step3`, 분석본 `.indd` 등이 더 있었다.
- 2차: 두 번째 블록에 "(A)(B)(C) 보기가 없다" 고 단정.
       → 그 블록은 **주어진 문장 + 지문 안 ①~⑤ 삽입 표시** 형식의 순서삽입
         문제였다. 원고는 처음부터 완전했다.

교훈: 조판 결과가 비면 **원고를 폴더째** 확인하고, 형식을 단정하기 전에
정상 동작하는 다른 경로(여기서는 가로 조판)로 같은 원고를 넣어 볼 것.
