# 워크북(가로) 섹션별 지면 규칙

조판 결과가 "맞는지" 판정하는 기준. 텍스트가 다 있어도 **상단/하단 배치가
어긋나면 불합격**이다. 사용자 확정(2026-08-25, 마더텅 13강 검수).

## 본문정리

| 위치 | 내용 |
|---|---|
| **상단** | 본문의 **주제·제목 정리** (카드) |
| **하단** | 주제·제목 **문제** (발문 + 선지) |

주제·제목이 이 섹션에 들어가는 것 자체는 맞다. 문제는 **순서**다.
세로 원본이 `지문 → {주제}카드 → {제목}카드 → 발문 → 선지` 순서이므로
가로도 상단 카드 / 하단 문제로 가야 한다.

## 문장배열

| 위치 | 내용 |
|---|---|
| **상단** | **순서배열** 문제 |
| **하단** | **순서삽입** 문제 |

## 검수 시 확인

- 칸이 비어 있지 않은가
- 프레임이 겹치지 않는가
- 상단/하단 내용이 뒤바뀌지 않았는가

⚠ 텍스트 대조(`v2h_content_diff`)는 **이걸 못 잡는다.** 내용이 전부 있어도
자리가 틀리면 통과한다. 지면 검수는 PDF 로 눈으로 보거나, 프레임 y좌표와
내용을 함께 덤프해 확인할 것.


## 오버셋 처리 — 페이지를 끼우지 말 것

가로 프레임이 세로 내용을 못 담을 때, **넘친 프레임 뒤에 페이지를 삽입하면
안 된다.** 오버셋은 없어지지만 "한 지문 = 상단/하단 짝" 구조가 깨진다
(2026-08-25 실측: 66장 삽입 후 문장배열 상단이 비고 다음 장 하단이 빈 채로
밀림). 그 방식으로 만든 `overflow_relief.jsx` 는 **쓰지 않는다.**

대신 `overflow_fit.jsx` — **프레임 크기도 페이지 구성도 그대로 두고** 그 안에서
담기게 한다. 눈에 덜 띄는 순서로: 문단간격 → 자간(-20) → 행간(-8%) → 장평(96%).
필요한 만큼만 쓰고, 어떤 수단을 어디까지 썼는지 프레임별로 로그에 남긴다
(인쇄 밀도가 달라 보일 수 있으므로 조판자가 확인할 수 있어야 한다).
후처리는 페이지 수가 변하지 않았음을 스스로 검증한다.

## 세로 완성본의 규격 — 본문정리는 2프레임

본문정리 페이지는 **상단(y32~155) / 하단(y155~277) 2프레임**이 규격이다.
통짜 1프레임(y28~277)이면 가로 상단 칸에 통째로 밀려들어가 넘치고 선지가
잘린다.

실측(2026-08-25): `고1_22년_9월_세로.indd` 만 본문정리 18페이지 전부가
1프레임이었다. **같은 22년의 3·6·11월본은 2프레임**이므로 연도별 규격 차이가
아니라 그 파일 하나의 예외였다. 18페이지를 모두 2프레임으로 분할해 규격을
맞췄다(문단 5007→5007, 유실 0, 페이지 밀림 0, 백업
`~/Backups/sero_원본_백업_20260828_165301/`).

→ 새 회차 세로본을 만들 때도 이 규격을 지킬 것. 어긋나면 그 회차를 쓰는
   모든 강에서 같은 유실이 반복된다.

## 남는 한계 — 실전(STEP3) 스레드 경계

실전 페이지의 텍스트는 여러 페이지에 걸친 **하나의 긴 스토리**다(실측 4~7
프레임, 6천~1만 3천 자). 이건 정상 구조다. 페이지를 한 장씩 복제하면 문단이
페이지 경계에 걸친 지점에서 잘린다.

범위째 복제하면 유실은 0이 되지만 담을 프레임이 부족해 오버셋이 대량 발생하고
(실측 954개 미인쇄), 소요 시간도 8분 → 45~60분으로 늘며 타임아웃이 잦다.
`repage_recover`(페이지째 삽입)는 다른 내용을 덮어써 역효과였다(4→5개).

**결론: 경계 잘림 소수는 조판자 수동 보정이 현실적이다.** 13강 2권차 실측으로
2885문단 중 3개였다.
