# 원고 자리 규약 (초안 v1 — 2026-10-08)

> 원고가 들어가는 글상자는 모두 이 규약을 따른다. 편집기 재현(`절차.md`)의 단위도 이 규약대로 만든다.

## 왜 — 디자인은 바깥으로 나간다

우리 디자인(틀)은 **바깥 시스템**(Y.OS contents 등)으로 나간다. 바깥에서 디자인을 고르고 콘텐츠를 고르면, 그 자리에서 콘텐츠가 틀에 맞춰 들어가 결과가 나온다. 그래서 틀은 처음부터 이렇게 만든다.

```
디자인(틀) = 자리 + 스타일 + 임시 글   ──내보내기──▶   바깥 시스템
                                                      콘텐츠 고르기
결과 ◀── 자리 이름대로 글만 바뀐다(스타일은 틀 그대로) ──┘
```

손으로 친 글로 모양만 맞춘 틀은 이 길을 검증하지 못한다. 원고가 들어갈 곳에 글을 직접 치지 않는다.

## 넷으로 나눈다

| 층 | 무엇 | 누가 정하나 | 인디자인에서는 |
|---|---|---|---|
| 자리 | 글상자에 붙는 이름 — 바깥 시스템과 약속하는 칸 | 틀을 만드는 사람 | 태그 프레임(XML 태그) · 데이터 병합 필드 |
| 스타일 | 서체·크기·행간·자간·정렬·양끝·GREP 스타일 | 틀 | 단락·문자·GREP 스타일 |
| 임시 글 | 스타일을 매길 때 쓰는 가짜 글 — 그 자리에 올 글의 꼴을 흉내 낸다 | 편집기가 채워 준다(고칠 수 있다) | 자리 표시자 텍스트로 채우기 |
| 원고 | 바깥에서 오는 실제 글 — 자리 이름별로 | 바깥 시스템 | XML 가져오기 · 데이터 병합 |

원고는 **글만** 바꾼다. 스타일·자리·상자는 틀이 가진다.

## 자리 이름

- 자리 이름은 콘텐츠의 구조를 따른다 — `docs/참고자료/교재_블록_지도/` 의 블록(B1~B11)과 그 필드가 기준. 예: 변형지문(B7)의 본문·변형 마크, 문항(B6)의 발문·선지, 원문지문(B1)의 지문 번호.
- 편집기의 지금 목록(지문 본문·지문 번호·발문·선지 …)은 정답이 아니다. 블록 지도에 맞춰 **더하고 다시 나눠도 된다**. 새 이름은 편집기의 「직접 적기」로 바로 쓸 수 있고, 쓰임이 굳으면 목록에 올린다.
- 한 이름 = 한 뜻. 모양이 달라도 같은 콘텐츠면 같은 이름(예: 어휘선택 지문과 어법선택 지문은 둘 다 「변형지문 본문」, 변형 종류는 따로).
- 고정 글(머리·쪽번호의 「STEP BY STEP」 같은 것)은 자리가 아니다. 책·단원 이름처럼 책마다 바뀌면 자리(`sys.*` 또는 책 자리).

## 원고 형식 — 자리마다 글을 어떻게 보내나

자리마다 바깥 시스템과 약속한다. 스타일이 알아볼 수 있게.

| 규칙 | 이유 |
|---|---|
| 문단은 줄바꿈(`\n`) | 단락 간격·들여쓰기는 틀이 |
| 강조·선택 표시는 약속한 꼴로 — 예: 선택지 `[ ⓐ … / ⓑ … ]` | GREP 스타일이 그 꼴을 찾아 서식을 입힌다(원고에 서식을 싣지 않는다) |
| 번호는 숫자만 — `01` 같은 꼴은 틀이 | 번호 매기기·서체는 틀 |
| 줄 끝을 정하는 줄 나눔은 원고에 넣지 않는다 | 줄 끝은 편집기가 정한다(단락 컴포저 — 진행표 「나중에 할 보편 기능」) |
| 윗주·옆 메모는 약속 표시로 — `{본문|아래 윗주}` · `{본문^위 윗주}` · `{본문^위|아래}` · `[[옆 메모]]` | 글상자 「원고 표시 읽기」를 켠 자리만 읽어 윗주(인디자인 윗주)·옆 메모(고정 개체) 조각으로 바꾼다 — 들어온 뒤에도 편집기에서 고칠 수 있다. 윗주 없는 `{글}` 은 건드리지 않는다(다른 약속) |
| 글자 꾸밈(형광·색·물결 밑줄)은 약속 표시 + GREP | GREP 규칙이 그 표시를 찾아 브랜드의 **문자 스타일**을 입힌다(2026-10-11 — 꾸밈 값은 문자 스타일에, GREP 은 「패턴 → 문자 스타일」만) |

자리 목록과 각 자리의 원고 형식은 디자인과 **함께 내보낸다**(바깥 시스템이 무엇을 보내야 하는지 안다).

## 만드는 순서 (작업자)

1. 글상자를 그리고 **자리**를 고른다(없으면 직접 적는다).
2. **임시 글 채우기** — 자리에 맞는 가짜 글이 들어온다(예: 변형지문이면 `[ ⓐ … / ⓑ … ]` 가 섞인 영어 문단).
3. 임시 글을 보며 **스타일**을 매긴다 — GREP 스타일도 임시 글의 꼴로 확인.
4. 원고를 넣어 본다 — 글만 바뀌고 모양은 그대로인지.

## 확인 (편집기 재현 단위마다)

| # | 확인 | 기준 |
|---|---|---|
| ① | 견본(원본 글)을 자리에 넣은 상태가 원본과 같다 | `절차.md` 합격 기준(위치·크기·모양) |
| ② | 원본 원고를 **바깥 시스템처럼 API 로** 넣은 결과가 ①과 같다 | 줄 끝 차이는 단락 컴포저 전까지 따로 보고 |
| ③ | 다른 원고를 넣어도 스타일이 유지되고, 길면 상자가 자라거나 넘침 경고 | 스타일·자리 그대로 |

### 흐름 틀 — 문항 수·길이가 바뀌어도 단·쪽을 넘어 흐른다 (인디자인 스토리)

고정 틀(문항마다 상자를 원본 자리에)은 문항 길이가 바뀌면 넘치고 겹친다. 흐름 틀은 인디자인처럼 만든다.

| 편집기에서 | 인디자인에서는 |
|---|---|
| 글상자 하나에 자리를 여럿 — `번호+발문+보기+지문+요약문+선지+진술+조건머리+조건+답칸` (「직접 적기」) | 한 스토리 안의 단락들 |
| 글상자 「글 잇기」 — 새 이야기 → 다음 상자들은 같은 이야기 | 텍스트 프레임 연결 |
| 쪽 「넘치면 이어 갈 면」을 두 면이 서로 가리키게(왼쪽 ↔ 오른쪽) | 스마트 텍스트 리플로(쪽 추가, 마스터 A/B 번갈아) |
| 자리마다 단락 스타일(글상자 속성의 자리 줄 「스타일」) | 단락 스타일 |
| 번호 자리 「앞에 붙이기」 + 폭 | 번호 뒤 탭(발문 첫 줄 앞) |
| 단락 스타일 칸 — 단락 앞·뒤(더한다), 같은 스타일 사이, 다음과 함께, 쪼개지 않기, 처음·마지막 N행, 바탕·테두리(잇닿은 같은 바탕은 한 상자), 바탕 위·아래, 기준선 내림, 균등 배치(낱말·자간) | 단락 간격 · 분리 옵션 · 단락 음영/테두리 · 균등 배치 |

원고 꼴 — 흐름 자리 이름에 **문항 목록**을 보낸다. 문항 = `[[자리, 글], …]`(문항 안 차례 그대로) 또는 `{자리: 글}`.

```json
{"번호+발문+보기+지문+요약문+선지+진술+조건머리+조건+답칸": [
  [["번호", "01"], ["발문", "다음 글의 주제로 가장 적절한 것은?"], ["지문", "…"], ["선지", "① …\n② …"]],
  [["번호", "02"], ["발문", "…"], ["보기", "…"], ["지문", "…"]]
]}
```

모자라면 덧쪽이 저절로 생기고(왼쪽·오른쪽 번갈아), 남으면 빈 덧쪽은 지운다. 확인 — 원본(14 d1 48~56쪽)과 구조 비교 `tests/e2e/flow_check.py <PDF> 48 9`:
문항 안 요소 사이 간격 54/80 같음(0.3mm 안) · 문항 시작 쪽·단 31/38. 다른 원고(차례 바꿈·길게·짧게) 넘침·겹침·잘림·면 밖 0.

알고 있는 차이(원본 인디자인과) — 고치지 않는다:
- 2줄 발문 뒤 지문이 원본보다 0.92mm 아래(인디자인이 그 자리에서만 간격을 줄인다 — 규칙으로 못 찾음).
- 단 첫 줄 높이가 원본과 1mm 안팎 다르다(원본은 단마다 30.6 / 31.5).
- 줄 끝이 원본과 93% 같다 — 한 줄 차이가 뒤 문항을 다음 단으로 밀어 문항 시작 자리가 7개 다르다.

### 틀 만들 때 지킬 것 — 원고가 길어져도 안 깨지게

| 지킬 것 | 왜 |
|---|---|
| 글상자 높이는 **그 자리 글의 줄 수만큼** 그린다(넉넉히 그리지 않는다) | 상자 높이 = 최소 높이다. 상자를 크게 그리고 그 아래 빈 곳에 해석·번호·»를 두면, 원고가 길어질 때 상자 **안에서** 자라 덮는다(밀리지 않는다 — 07·11·12·12P 에서 겪음) |
| 글에 따라 움직여야 하는 것(O/X 상자 · 끝 기호)은 「글 끝에 붙이기」 | 고정 자리에 두면 글 길이가 바뀔 때 글을 덮는다(03 에서 겪음) |
| 두 단 면은 「여백 및 단」에 단 수를 준다 | 원고를 문항 순서로 받는다 |
| 틀을 다 만들면 `swap_check.py` 로 다른 원고를 넣어 본다 | 「영역 안」·겹침이 0 이어야 한다 |

- ☐ 임시 글 채우기 버튼 — 지금은 작업자가 임시 글을 친다
- ☐ 바깥 시스템 연결 — 인증·디자인 목록·결과 보관(지금 입구는 편집기 서버 안)

## 꾸밈 조각 원고 — 윗주 · 문자 스타일 · 옆 메모 (2026-10-11, 광문 분석본)

꾸밈이 든 글은 **조각 목록**으로 보낸다. 글만 보내는 쪽은 약속 표시(`{본문|아래}` · `{본문^위}` · `[[메모]]`)도 된다(글상자 「원고 표시 읽기」).

```json
[ "1 ",
  {"t": "Cuju,", "ruby": {"t": "단 S", "pos": "above"}}, " ",
  {"t": "holds", "cs": ["파랑 글자", "형광 민트"], "ruby": {"t": "V 단", "pos": "below"}},
  {"t": "It", "ruby": [{"t": "Cuju", "pos": "above"}, {"t": "S", "pos": "below"}]},
  {"t": "", "side": "* let이 사역동사로 쓰여 …\n분사구문으로 쓰인 following은 …"} ]
```

| 조각 칸 | 뜻 |
|---|---|
| `cs` | 문자 스타일 이름(브랜드에 같은 이름) — 하나 또는 여럿(글자색 + 형광 띠, 차례로 겹쳐 입힌다) |
| `ruby` | 윗주 — `{t, pos: above\|below}` 하나 또는 [위, 아래] 둘. 모양·거리는 글상자의 윗주 기본값 |
| `side` | 옆 메모(고정 개체) — 그 자리 줄 높이의 옆 칸에. `\n` 은 메모 안 문단. `t` 는 빈 글 |

한 글상자 여러 자리(`문장+해석`)에는 레코드마다 `{"문장": [조각 …], "해석": "글"}`. 글 하나 자리에 조각을 보낼 땐 `[[조각 …]]`(바깥 목록 = 자리 차례).

### 광문 스텝업 분석본 — 자리 표 (편집기 제작 카드)

| 면 | 자리 | 원고 꼴 |
|---|---|---|
| 간지 | `학교` | 「2026 광문고1」 — 앞 네 자리 연도는 GREP 이 「연도 굵게」 |
| 간지 | `권번호` | 「2」 |
| 간지 | `교재명+강제목` | 레코드 목록 `[{"교재명": …, "강제목": …}, …]` — 쌍 수는 책마다 |
| 분석 펼침면(원고마다) | `강` · `회차` · `지문제목` | 글 — 「7강」 · 「분석」/「1번」/「서술형 Practice」 · 지문 제목. 오른쪽 꼬리 `강+회차` 는 이 둘을 이어 쓴다(따로 보내지 않는다) |
| 〃 | `문장+해석` | `[{"문장": 조각 목록(맨 앞 「번호 」 — GREP 이 「번호 배지」), "해석": 글}, …]` |
| 〃 | `주제` · `요약` | 글 |
| 〃 | `발문+문제지문+선지` | `[{"발문": 글, "문제지문": 글(문단 \n), "선지": "① …\n② …"}]` |
| 〃 | `답` | 「답: ⑤」 |
| 〃 | `어휘` | 줄마다 「낱말<탭>뜻」(\n) — 3단으로 첫 단부터 14줄씩 |

원고마다 면은 문서 원고 `{"분석 펼침면": [레코드, …]}` — 레코드 하나 = 지문 하나 = 펼침면 한 벌.

`source.data = {"format": "yos-analysis-v1", "book": {"title"}, "analyses": [TypesetDoc, …]}` 로 `/api/v1/renders` 에 보낸다.

## 포켓북 원고 — `yos-pocketbook-v1` (2026-10-12, 배재1 포켓북 · 시험용 초안)

contents 에 포켓북 저장소가 아직 없다(관리 표 「포켓북은 아직 저장소가 없어」). 그때까지 원본 PDF 에서 뽑은 원고 한 벌로 원고 넣기 · 책 만들기 검사를 한다
(`tests/e2e/replay/배재포켓북/원고_뽑기.py` → `원고.json` · `그림/`). 자리 이름은 contents 의 분석본 조판 문서(TypesetDoc)와 워크북 빈칸 꼴에 맞췄다 —
나중에 contents 가 포켓북을 보낼 때 그 재료를 그대로 묶으면 된다.

```json
{"format": "yos-pocketbook-v1", "book": {"title": "배재1 포켓북", "책이름": "POCKET BOOK 배재1"},
 "원고": [
  {"출처": "능률(오) 1과 본문1", "지문": [조각 …], "해석": "글", "그림": "그림/p044.png", "단원": "교과서 1과", "구분": "교과서"},
  {"흐름": [{"제목": "도입", "글": "…\n→ …"}, …], "주제": "글", "요약문": "글",
   "동반의어": [{"낱말": "impressive", "뜻": "인상적인", "동의어": "striking, remarkable", "반의어": "ordinary, dull"}, …], "단원": "…", "구분": "…"},
  {"암기지문": "… an 1[impressive] meaning …", "단원": "…", "구분": "…"} ]}
```

- **원고 = 덩어리 목록, 원본 차례 그대로.** 덩어리마다 그 자리를 가장 많이 담는 면에 들어간다(절차 6단계). 노트 · 암기가 없는 지문은 그 덩어리가 없다.
- 지문 조각: 글자색 → `cs`(빨강 글자 · 파랑 글자), 낱말 바로 아래 회색 글(S · V · O · C …) → 아래 윗주, 바로 위 → 위 윗주.
- 암기지문: 「번호[답]」(contents 빈칸 꼴). 암기 TEST + 정답 2쪽 면이 한 덩어리를 받는다 — TEST 쪽은 답을 숨기고 정답 쪽은 보인다(스타일로).
- 그림: 있을 때만. 그림이 있으면 그림 자리를 가진 분석 면(삽화 있음)이 골라진다.
- 단원 · 구분: 오른쪽 면 바닥 글 · 옆 탭. 책 · 단원 자리(덩어리마다 실어 보낸다).
- 줄 끝 꺾임은 원고에 없다(편집기 컴포저가 정한다). 원본 작업자가 손으로 친 줄 나눔(133% 넘게 벌린 줄인데 다음 낱말이 들어가는 줄)만 `\u2028` 로 싣는다(원고_뽑기 `forced_breaks`).
- **편집기에 넣는 꼴** — `{"원고": [레코드 …]}`, 레코드 = 자리 이름 → 값(지문 · 해석 · 흐름제목+흐름글 · 낱말+뜻+동의어+반의어 · 암기지문 · 단원 · 구분). 편집기가 레코드마다 자리가 가장 많이 맞는 「원고마다」 면을 고른다 — 같으면 면 설정 「구분」, 그다음 같은 자리 개수 = 목록 길이(흐름 3개 → 3칸 면). (`core/units/content._faces_by_chunk`)
- `_원본쪽`: 시험용 — 그 덩어리가 원본 몇 쪽에서 나왔나(책 만들기 검사에서 차례 맞대기).
