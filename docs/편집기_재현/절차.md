# 편집기 재현 — 절차 (초안 v1)

> 이 문서가 정본이다. 스킬·명령·다른 세션은 모두 이 문서를 따른다. 규칙을 바꿀 땐 여기만 고친다.

## ★ 템플릿 등록 — 네 단계 (2026-10-20 사용자 확정 · 이 절이 아래 모든 절보다 앞선다)

> 이의1보카 · 명일1 파이널에서 하루가 갔다 — 사용자 「프로세스 재정립, 빨리할 수 있는 방법으로」 →
> 같은 날 다시 확정: 「템플릿 만들기는 사람이 만드는 것처럼 직접 해 봐야 한다 · 책 만들기는 기능 테스트로 사람이 할 수 있는지 판단」.
> 아래 옛 10단계는 세부 참고 — 서로 다르면 이 절을 따른다.

1. **면 가르기** — 원본 PDF 를 관리 폴더에 올리고(`bin/register-design`), **펼침면 그림**으로 면 목록을 보인다(판정 결과와 기대 면 나란히, Downloads HTML).
   사용자 확인 1번(「ㅇㅇ」) → `faces.json` · `구성.json`. 왼쪽 · 오른쪽 쪽이 늘 짝이면 펼침면 하나, 같은 모양에 색만 다르면 한 면.
2. **템플릿 만들기 — 사람처럼 직접** — 면마다 대본(`make.py`)을 짜 편집기를 사람처럼 조작해 만든다(`replay.py <책>@<면> check`, 사람 조작).
   값은 원본에서 재고 서체는 `fontmatch.py`. 빠르게 하는 장치:
   - **처음 쓰는 동작은 먼저 1~2분 시험** — 대본을 다 돌리기 전에, 처음 쓰는 조작(고정 개체 · 그룹 · 새 칸 …)만 작은 문서에서 사람 조작으로 돌려 본다. 되면 면 전체 판.
   - **실패하면 그 면만 · 원인 하나만** 고쳐 다시. 같은 원인 두 번이면 멈추고 보고.
   - **사람이 못 만들면 편집기 문제** — 그 자리에서 고친다(기능기록 · 인디자인 · regcheck 규칙 그대로). 템플릿을 만드는 데 필요 없는 것은 「편집기 고칠 목록」.
   - 검사 서버는 구성 미리 계산 없이 몇 초에 뜬다(`YONE_WARM=0`). 다른 세션 검사와 동시에 여러 판을 돌리지 않는다.
3. **템플릿 시험하기 — 원본과 맞대기** — 면 판정(고정 0.3mm · 원고 들어감)과 등록 뒤 맞대기. 글이 겹치거나 빠진 것 · 모든 쪽에 되풀이되는 차이(스타일 값)만 템플릿에서 고친다.
4. **책 만들기 — 기능 테스트로** — 원고 전체로 원본과 똑같은 책을 맞추지 않는다. 원고 넣기 · 넘쳐 이어 가기 · 다른 길이 원고 · 편집기에서 손보기가
   사람이 할 수 있는지 기능별로 시험해 판단한다(예: `swap_check.py` · 원고 넣기 보고 · 편집기로 열어 고쳐 보기). 세부(특수 짜임 · 몇 mm · 한 쪽만)는 실제 책에서 사람이 손본다.

- **나눔 기준**: 모든 쪽에 되풀이되는 차이 = 템플릿에서 고친다 · 한 쪽에만 있는 차이 = 실제 책에서 손보기.
- **반영** — main 머지 · 배포는 여러 권 모아서. 편집기 코드를 고쳤을 때만 regcheck. 끝나기 전 `attach_origin.py --check` (로컬 · 배포서버).
- **관리에는 편집기 제작 템플릿만 남긴다**(2026-10-26 사용자 확정) — 1단계에 올린 PDF 카드는 면 가르기용 임시다. 편집기 템플릿에 원본을 붙인 뒤
  (`attach_origin.py`) 그 PDF 카드는 지운다 — 리포(`git rm`)와 배포서버(`DELETE /api/catalog/design/<틀>/<카드>`) 둘 다. 확인한 면 목록은 대본 폴더 `구성.json` 에 남는다.
- **묻는 것** — 면 목록 확인 · 처음 쓰는 기능이 인디자인에 없을 때 허락. 그 밖은 묻지 않는다.

## 목적

관리 페이지에 이미 있는 결과물(원본)을 「만들기」 편집기의 **있는 기능만으로** 똑같이 다시 만들 수 있는지 확인한다.
안 되는 곳이 버그·빠진 기능이다. 사용자 허락을 받아 고친다.

## 말

| 말 | 뜻 |
|---|---|
| 원본 | 사용자가 관리 페이지에서 지정한 기존 결과물 |
| 단위 | 원본을 나눈 한 덩어리. 디자인이면 디자인 상세 「구성」 카드 하나 = 카드에 보이는 두 면. 이름 = `NN-구성이름` (예: `02-A어휘선택`) |
| 대본 | 내가 편집기를 조작하는 순서(클릭·끌기·입력). 대본을 쓰는 것 = 편집기로 만드는 것 |
| 비교 | 내가 만든 지면과 원본을 요소별(위치·크기·색·글)로 맞대고 일치율(%)을 내기 |
| 녹화 | 다 맞은 대본을 처음부터 다시 돌리며 찍는 영상. 사용자 확인용 |
| 막힘 | 편집기 기능이 없거나 고장 나서 만들 수 없는 상태 |

## 시작 — 작업 지시를 받으면

1. 사용자가 관리 페이지의 원본을 지정한다.
2. 원본을 단위로 나눠 진행표(체크박스 목록)를 만든다 — `진행표양식.md`.
3. 진행표를 보이고 확인받은 뒤 첫 단위부터.

## 단위 하나의 순서

```
1 만들기(대본, 녹화 없음) → 2 비교 ─ 다름 → 1 로 (같아질 때까지)
                             └ 같음 → 3 녹화(빠르게) → 4 보고 → 사용자 확인 → 체크
막힘 → 멈추고 보고 → 허락 → 고침 → 1 로
```

단계는 이 넷뿐이다. 진행을 알릴 때도 이 번호·이름 그대로 쓴다 — **「대본 쓰기」를 따로 단계로 세지 않는다**(대본 쓰기 = 만들기).

1. **만들기** — 대본을 쓰며 편집기로 직접 만든다. 빠르게 돌리고 녹화하지 않는다. 값은 원본 데이터에서 가져온다(눈대중 금지). 실제 화면 조작만 쓴다(js 로 값 꽂기 금지).
2. **비교** — 만든 지면과 원본을 맞댄다. 다르면 대본을 고쳐 1을 다시. 같아질 때까지 되풀이.
3. **녹화** — 다 맞으면 같은 대본을 처음부터 돌리며 녹화한다. **확인용이라 빠르게**(기본 8배속, `REC_SPEED`). 영상에는 성공한 한 번만 담긴다.
4. **보고** — `보고양식.md` 대로: 일치율 · 다른 점 · 막힘 · 영상. 사용자가 확인하면 진행표에 체크하고 다음 단위.

**단위가 다 돼야 다음 단위로.** 막힘이 남은 채로 넘어가지 않는다.

### 만들기의 규칙 (단위 01·02 에서 정한 것)

- **빈 데이터로 시작** — `replay.py` 가 단위마다 편집기 데이터를 비운다(판형 정의와 빈 브랜드 「기본 (브랜드 없음)」 하나만). 시드의 블록·지면·문서가 화면에 섞이지 않고, 영상에는 대본이 만든 것만 남는다. 빈 브랜드는 그림(로고)을 올릴 자리다.
- **원고가 들어가는 글상자는 `원고자리_규약.md`** — 아래 「원고가 있는 면」 순서대로(글을 직접 치지 않는다). 02B 부터.
- **블록 없이 그리기만** — 면·선·원·도형·글상자·그림 도구와 속성 칸. 로고 같은 그림은 그림 틀에 파일을 올린다.
- **글 자리 = 기준선 공식** — 원본 PDF 의 기준선에서 「반 행간 + 서체 윗높이(서체 파일 hhea)」를 빼서 글상자 위 끝을 정한다(`mkpage.top_of`). 자간은 원본 글 폭과 서체 글자 폭의 차이로 계산한다.
- **측정 보정으로 덮지 않는다** — 만들고 재서 어긋난 만큼 빼는 보정은 원인을 숨긴다(2026-10-08: 보정이 편집기의 1mm 반올림 버그를 덮고 있었고, 버그를 고치자 단위 01 이 무너졌다). 어긋나면 원인(편집기 버그·서체·측정 칸)을 찾아 고친다. 남겨도 되는 건 원인을 밝힌 것뿐이고 그 이유를 대본 주석에 쓴다.
- **굵기는 재서 정한다** — 원본 서체가 Type3(윤곽)이라 굵기 이름이 없으면, 브라우저에서 굵기 100~900 의 잉크 양을 재서 원본과 맞는 굵기를 고른다(눈대중 금지).
- **서체 이름은 브라우저에서 확인** — 같은 집 안 굵기를 브라우저가 잘못 고를 수 있다(「Gmarket Sans」+500 → Bold). 비교의 모양 검사가 잡는다.
- **서체가 없으면 설치** — 편집기 서체 목록(시스템 서체)에서 먼저 찾고, 없으면 공식 배포처에서 받아 `~/Library/Fonts` 에. 예전 작업자 폴더(`core/render_vivlio` · `engines`)는 보지 않는다(지킴 훅이 막는다).
- **서체 이름이 PDF 에 없으면**(Type3 윤곽 — 예전 코드(Vivliostyle)로 뽑은 판) — 글자 모양을 후보 서체와 겹쳐 고른다(`fontmatch.py`, 겹침 0.9+).
  후보 = 편집기 시스템 서체. 같은 책의 인디자인 판(교재 폴더 `참고` · `_기준_…(샘플)`)이 있으면 거기 적힌 서체 이름을 후보 맨 앞에 둔다 — 이름만, 값(크기 · 자리 · 색)은 목표 PDF 에서(2026-10-19).
  고른 서체는 **시스템 서체로만** 쓴다 — 로컬 · 배포서버 같은 묶음. 목록에 없으면 「＋ 서체」로 등록해 두 곳 다 쓰게 한다(사용자 2026-10-19 「시스템 자체에 서체가 등록되고 그 기능을 사용」).

### 원고가 있는 면 — 만드는 순서 (표지·간지처럼 고정 글만 있는 면과 다르다)

원고가 들어갈 글상자(지문·번호·발문·선지 …)는 `원고자리_규약.md` 대로. 견본 대본: `tests/e2e/replay/02B-원고자리/make.py`.

1. 글상자를 그리고 **임시 글**을 친다 — 올 원고의 꼴을 흉내 낸 글(지문이면 `[ ⓐ … / ⓑ … ]` 가 섞인 영어 문단, 번호면 `00`). 원본 글을 치지 않는다.
2. **자리 이름**을 붙인다 — `mkpage.slot("지문")` (편집기 「원고 자리 → 직접 적기…」). 이름은 그 면의 콘텐츠 구조대로 새로 정해도 된다.
3. 임시 글을 보며 **스타일**을 매긴다 — 서체·자간·양끝맞춤·GREP 스타일. 줄 끝은 단락 컴포저가 고른다(손 줄 나눔 안 친다).
4. 다 그린 뒤 **원고 넣기** — `mkpage.put_content({"지문": [...], "지문번호": [...]})`. 원고 = 원본 PDF 에서 읽은 글(줄 나눔 없이). 편집기 보고 「찬 자리 N」이 자리 수와 같아야 한다.
5. 단위 `상태.json` 에 `"fill": true` — 비교 PDF 가 원고를 넣은 결과로 나온다.
6. 합격 = 원고를 넣은 결과가 원본과 같다(위의 합격 기준). 지문은 문단 기준(겹침 0.80).

### 판을 돌리는 법

- 한 판 = 빈 편집기에서 단위 전체를 처음부터(약 5분). **한 판이 끝나면 틀린 것을 모두 분석하고 모두 고친 뒤** 다음 판 — 하나 고치고 돌리고를 되풀이하지 않는다.
- 편집기 코드를 고치면 앞서 끝낸 단위도 다시 돌려 깨지지 않았는지 본다(다른 포트로 같이).
- 단위마다 같이 돌린다 — 서버 · 크롬 포트는 도구가 빈 것을 고른다(2026-10-19, 정하려면 `REPLAY_PORT` · `REC_PORT`).

## 합격 기준 — `replay.py` 가 요소마다 자동으로

| 항목 | 기준 |
|---|---|
| 배치 | 요소마다 위치·크기 오차 0.3mm 이내 (같은 색 잉크 상자) |
| 글 모양 · 굵기 | 원본과 잉크 양 ±12% 이내 · 겹침(0.17mm 너그럽게) 0.90 이상 — 문단은 0.80 (양끝맞춤 단어 자리 차이) |
| 색 | 같은 값 (#hex) |
| 글 | 내용·크기(pt) 같음 |

위치·크기만 재면 굵기·서체가 달라도 통과한다(2026-10-08 단위 01·02 에서 실제로 놓침). 그래서 글은 모양까지 잰다.

끝까지 못 맞추는 차이가 있으면 녹화 전에 **차이 보고**: 일치율, 다른 항목, 이유, "허락할지" 칸. 허락하면 녹화.

## 막힘 — 멈추고 묻는다

1. 그 자리에서 멈춘다. 우회(js 주입, 책 전용 꼼수)하지 않는다.
2. 사용자에게 알린다 — **한 줄씩**: `문제 → 기능 추가 / 기능 수정(버그)`. 예: `문단 안 일부 글자만 굵은 파랑 불가 → 기능 추가: GREP 스타일`.
3. **허락을 받은 뒤** 고친다. 다른 책에도 쓸 수 있는 보편 기능으로.
4. `tests/e2e/canvas_audit.py` 로 다른 곳이 안 깨졌는지 확인.
5. 1(만들기)부터 다시.

## 다시 하기 — 그 단위만 지운다

단위에 문제가 생겨 처음부터 다시 할 때만 `replay.py <단위> reset`.
지우는 것: 그 단위의 데이터 폴더(편집기 문서) · 그림 · 영상 · 보고. 대본은 남긴다(고쳐서 다시 쓴다). 다른 단위는 건드리지 않는다.

## 명령

```sh
python3 tests/e2e/replay.py <단위> check     # 만들기(녹화 없음) → 결과 지면
python3 tests/e2e/replay.py <단위> compare   # 만들기 + 원본과 비교·일치율
python3 tests/e2e/replay.py <단위> rec       # 녹화 (REC_SPEED 기본 8)
python3 tests/e2e/replay.py <단위> reset     # 그 단위만 지우기
```

## 작업 순서 — 확정 (2026-10-10, 정본 실패 뒤)

> 이 절은 다른 절보다 앞선다. 바꾸려면 사용자 승인부터.

**목적**: 원본 PDF 를 보고 편집기로 **손수** 만든다. 만들면서 모자란 기능·버그를 찾아 고치고 점검해 편집기가 좋아지는 것이 목적이다.
결과물만 빨리 맞추는 자동 변환(PDF 를 분해해 그대로 찍기 등)은 이 목적에 맞지 않는다 — 쓰지 않는다.

**언제** — 사용자가 PDF 를 주거나, 이미 등록된 원본 PDF(관리 카드)를 지정하면 이 순서를 돈다.
입력 = PDF · 등록할 폴더 · 문서 이름. 예전에 만든 결과는 쓰지 않는다.

**단계** (2026-10-11 사용자 확정 골자 — 정본에서 하루 넘게 걸린 뒤 다시 정함)

1. **원본 올리기**
   - 원본 PDF 를 관리 폴더에 올린다(관리 폴더 ＋ → PDF 등록, 또는 `bin/register-design <PDF> <폴더> <이름>`).
   - 관리에 원본 카드가 생기고, 서버가 구성을 계산해 둔다.
2. **면 나누기** (2026-10-12 사용자 확정 — 배재1 포켓북: 지문마다 붙는 면이 2·3·4면으로 달라 되풀이 묶음으로는 못 나눴다)
   - 쓰는 것: PDF 등록이 돌리는 판정(`routes/catalog.py` 의 `design_layouts`). 원본 카드 「지면 보기」에 결과가 나온다.
   - **만드는 단위 = 면 하나**(인디자인의 상위 페이지). 서로 다른 면 모양마다 하나씩, 한 번만 나와도 면이다. 같은 면은 한 번만 만든다.
   - 판정이 면 모양을 가르는 기준: 머리·바닥의 구성 이름표 · 맨 위 큰 제목이 있나 · 삽화 갈래. 글이 적은 면은 그림 배치·글상자 배치·글자 수.
     면마다 글이 다른 머리표(지문 출처 · 번호)는 원고라 이름표가 아니다.
   - **되풀이 묶음(2면·4면…)은 만들지 않는다** — 지문마다 어떤 면이 몇 장 붙는지는 원고가 정한다(인디자인도 차례·패턴을 따로 적지 않고, 원고를 보며 쪽을 붙이고 상위 페이지를 고른다).
     판정이 찾은 묶음은 「원본 차례 견본」 — 7번 책 만들기 검사에서 같은 차례가 나왔는지 맞대는 데만 쓴다.
   - 두 쪽이 늘 한 벌로 나오는 펼침면(워크북 유형 2쪽, 분석본 지문 2쪽 등)은 펼침면 하나를 면 하나로 친다.
   - **만드는 면 = 확인받은 면 목록 그대로** (2026-10-19 사용자 확정 — 광문보카 「그냥 나눈 면만 템플릿으로 하면 되는 거 아니야?」).
     모양이 같고 색만 다른 면(파트 · 단원마다 띠 색)도 따로 만들지 않는다 — 첫 견본 쪽의 색으로 한 장. (2026-10-12 「색별로 따로」는 배재1 포켓북에만 남는다.)
   - **펼침면부터 본다 · 본문 꼴이 다르면 다른 면** (2026-10-19 사용자 확인 — 상일보카: 쪽을 하나씩 떼어 보다 4·5쪽 펼침면을 둘로 가르고,
     본문 꼴이 다른 구간(표제어 항목 · 파생어 목록 · 워크북 문제 · 정답)을 「원고가 흐를 뿐」이라며 한 면으로 묶었다가 두 번 되돌림).
     ① 왼쪽 · 오른쪽 쪽을 붙인 그림(머리 확대)으로 띠 · 바탕이 두 쪽에 이어지는지 보고, 이어지면 첫 면이든 본문이든 2쪽 면 하나로.
     펼침면 반쪽만 오는 곳(DAY 끝 MEMO 앞 왼쪽 쪽 등)은 그 면의 반쪽을 쓴 것으로 적는다.
     ② 띠 · 번호표가 같아도 본문 꼴(단 · 상자 · 항목 꼴)이 다르면 자리가 달라 다른 면. 구간 안에서 색만 다른 것은 나누지 않는다.
   - **면마다 설정을 갖는다** — 편집기 쪽 패널에 두고 면 목록에도 보인다.
     ① 크기: 1쪽 면 / 2쪽 한 벌(펼침면) ② 이어짐: 넘치면 어느 면으로 이어 갈지(「넘치면 이어 갈 면」, 없으면 넘침 없음)
     ③ 놓이는 곳: 맨 앞 · 맨 뒤 고정 / 원고 따라(원고 덩어리의 자리가 맞으면 찍힘 — STEP 간지처럼 이름만 바뀌는 면도 원고 따라).
     ④ 구분: 자리가 같은 면이 여럿일 때 고르는 원고 「구분」 값 — 이미 있는 배재1 포켓북 템플릿용. 새 책은 색 갈래를 만들지 않으니 쓰지 않는다.
   - 「지면 보기」와 「PDF에서 보기」로 원본과 대조하고, 면 목록을 사용자에게 보여 확인받는다.
3. **대본 짜기** (구성마다 — `tests/e2e/replay/<책>/make.py`)
   - 원본에서 요소(띠·선·글상자·아이콘)의 위치·크기·색·서체·글 크기·행간·자간을 읽는다.
   - 요소마다 편집기의 어떤 기능으로 만들지 정한다. 없는 기능이 나오면 보고하고 만든다(이미 있는 기능을 먼저 찾는다).
   - 고정 부분과 원고 부분을 가른다 — 같은 구성의 여러 회차를 맞대 회차마다 바뀌는 것은 원고, 늘 같은 것은 고정(아래 「합격 기준」의 구분).
   - 원고 자리에는 **임시 글**을 넣고 자리 이름을 붙인 뒤, 스타일(서체·크기·행간·자간·색·바탕)을 칸으로 정한다.
     **틀 하나로 여러 책을 찍으므로 틀에는 책 글을 두지 않는다** — 원고 자리의 틀 글은 마지막에 모두 「«자리 이름»」으로(문서 패널 「자리 글 → «자리 이름»」 단추,
     인디자인 데이터 병합의 자리 표시). 견본 원고는 「보기: 원고」(미리보기)로만 본다 — 견본 글·임의 임시 문장을 틀 글로 두면 원고가 빠진 자리에 그 글이 찍혀 나간다(2026-10-11).
     스타일은 「보기: 원고」를 켠 채 글상자 칸·단락 스타일로 정한다(틀 글과 상관없다).
   - 자리 이름과 원고 꼴은 **외부 연동**(바깥 시스템이 보내는 원고)을 기준으로 정하고 적어 둔다.
   - 조작 순서로 적는다. 전에 해 본 구성과 같은 모양이면 그 대본에 값만 새로 넣는다.
   - **면마다 구성 이름을 면 이름으로 붙인다**(쪽 패널 「이름」). 같은 구성은 같은 이름(STEP 간지 세 장 = 「STEP 간지」), 펼침면 오른쪽 면은 이름 없이 왼쪽 면을 따른다.
     관리 「지면 보기」가 편집기 제작 카드의 구성을 이 이름 · 「원고마다」 · 「넘치면 이어 갈 면」으로 묶는다(`routes/catalog.editor_layouts`). (2026-10-11 — 이름이 없으면 PDF 생김새로 짐작해 STEP 간지가 갈라졌다)
4. **가르기**
   - 짠 대본의 동작을 「해 본 동작 목록」과 맞대 「처음 보는 종류 / 검증한 종류」로 가른다.
     동작 = 「무엇을 어디에 했나」(칸 입력 · 목록 고르기 · 단추 · 파일 올리기 · 그리기) — 넣은 값은 보지 않는다. 목록에 없는 동작이 하나라도 있으면 처음 보는 종류.
   - 결과를 사용자에게 보여 확인받는다.
   - 도구: `python3 tests/e2e/actions.py split <steps.json>` — 목록은 `tests/e2e/replay/해본동작.json`(사람 조작 검사를 통과한 판에서 `actions.py build` 로 모은다).
5. **만들기 + 검사** (구성마다 — 여러 구성을 동시에 돌려도 된다)
   - 처음 보는 종류: 빈 편집기에서 사람처럼 조작해 만들고 원본과 맞댄다(`replay.py <책>@<구성> check`, 녹화 없음). 통과하면 쓴 동작을 해 본 동작 목록에 더한다.
   - 검증한 종류: 빠르게 만들고 같은 기준으로 맞댄다(`REC_DIRECT=1 replay.py <책>@<구성> check` — 같은 대본을 마우스 이동·한 글자씩 치기 없이, 결과는 「~바로」 폴더). 걸린 부분은 사람 조작으로 돌린다.
     바로 넣기 판은 해 본 동작 목록에 더하지 않는다. 사람 조작 판이 통과하면 `actions.py build` 로 목록을 새로 쓴다.
   - 기준(아래 「합격 기준」):
     - 고정 부분 — 원본과 0.3mm, 글자 모양까지 정확히.
     - 원고 부분 — 완전 일치가 아니다. 들어가나, 넘치지 않나, 스타일을 칸으로 정하고 바꿀 수 있나. 기능이 있고 설정이 되면 약간의 차이는 넘어간다.
       원본의 쪽별 차이는 따라 하지 않고 구성마다 스타일 하나로 통일한다.
     - **판정 뒤 그림 확인 = 「기능이 되나」만** (2026-10-12 사용자 확정 — 배재1 포켓북). 원고 부분 판정은 일부러 느슨해서 원고 쪽 기능이
       망가져도 통과한다(윗주가 기준선에 붙음 · 빈칸 번호 높이 단위 착각 — 둘 다 그림에서 잡았다). 그래서 대조 그림에서 꾸밈 종류마다
       「나오나 · 제자리 근처인가」(윗주 · 형광 · 물결 · 빈칸 감추기 · 그림 칸 · 서술형 표시 …)를 본다. 원고의 줄 끝 · 몇 mm 차이 · 시험용 원고의
       작은 틀림은 고치지 않는다(원고를 원본과 똑같이 맞추지 않는다).
     - **원고 자리 작은 글 높이는 도구가 본다** (2026-10-12 사용자 승인). 윗주 · 위첨자 번호 · 구문 표기처럼 본문보다 작은 글이
       주인 글자에서 떨어진 높이를 원본과 0.3mm 로 맞댄다(`replay.py` `deco_check`) — 원고가 바뀌어도 그대로인 관계라서.
       위 두 사고(윗주 붙음 · 번호 높이)를 이제 판정이 실패로 잡는다. 그림 확인은 이 검사가 못 보는 꾸밈(형광 · 물결 · 그림 칸 …)만.
       바탕 그림의 방향 · 그러데이션도 그림으로 본다 — 색 차가 작아 「목록 밖 차이」에 안 걸린다(배재1 포켓북 앞·뒷면 바탕이 상하 뒤집힌 채 통과).
     - 판정 측정이 원본을 잘못 재면(가는 세리프가 바탕과 섞여 색으로 안 잡힘 등) 600dpi 로 직접 재 확인하고, 그 요소의 측정 값(ctol 등)만
       근거를 주석으로 적어 바꾼다. 통과 기준(0.3mm · 모양)은 바꾸지 않는다.
   - 기능이 안 되면: 편집기 기능을 고치고, 그 구성 결과를 지운 뒤(`replay.py <책>@<구성> reset`) 그 구성만 처음부터 다시 돌린다. 만들던 결과에 덧대지 않는다.
   - 대본이 틀렸으면: 대본을 고치고 그 구성만 다시 돌린다.
   - 다시 돌리기는 한 원인에 한 번. 또 실패하면 멈추고 보고한다.
   - **새 서체는 돌리기 전에 원본과 대 본다** (2026-10-12 사용자 확정 — 배재1 포켓북 앞·뒷면이 짐작한 서체·굵기·광학 크기로 5판 돌았다).
     대본에 처음 넣는 서체마다 `tests/e2e/fontmatch.py` 로 원본 글자와 겹쳐 서체·굵기를 고르고, 가변 서체는 광학 크기도 글자 하나로 맞대 본다.
     겹침이 0.9 미만이면 고르지 않고 「맞는 서체 없음」으로 보고한다. 판정에는 손대지 않는다(처음 넣는 값만).
   - **실패하면 실패한 요소를 처음부터 전부 잰다** (같은 날 사용자 확정). 600dpi 이상으로 잉크 끝 · 글자 겹침 · 바탕 색을 한 번에 재 두고
     「실제 차이 / 측정 문제」를 요소마다 적는다. 고치기는 그대로 원인 하나씩 — 같은 요소에 수정 둘을 한 판에 섞지 않는다
     (바탕 색이 원인인데 굵기를 바꿔 헷갈린 일). 자동 진단은 넣지 않는다 — 「측정 문제」가 허용치 넓히기의 핑계가 되지 않게.
6. **원고 넣기** (면 하나씩)
   - 외부 연동 꼴(자리 이름 → 글)로 원본 원고를 「원고 넣기」로 넣어, 임시 글이 원고로 바뀌는지 본다.
   - 길이가 다른 원고를 넣어 잘림·넘침·겹침이 0인지 본다(`swap_check.py <책>@<구성> rotate`).
   - **면은 자리의 집합, 원고는 자리 덩어리의 차례** — 원고 덩어리(지문 분석 · 노트 · 암기 문제 · STEP 이름 …)를 순서대로 받아
     덩어리마다 그 자리를 가장 많이 담는 면을 골라 찍는다. 그 내용이 없는 지문은 그 면이 안 붙는다. 「중간에 올 수 있는 면」 목록 · 구간 되풀이는 두지 않는다.
     맨 앞 · 맨 뒤 고정 면은 그 자리에. 지금의 「원고마다」(면 묶음을 원고 수만큼)는 그대로 쓴다(워크북 · 분석본 카드).
     자리 이름은 contents 기준 — 디자인마다 같은 이름을 쓴다. 틀에 없는 자리의 원고는 원고 넣기 보고의 「틀에 없는 자리」로 알린다.
7. **잇기 · 책 만들기 검사**
   - 통과한 면 문서들을 편집기 「문서 파일 가져오기 → 이 문서 끝에」로 이어 한 문서로 만든다.
   - **원본 원고 전체를 넣어 책을 만들고 원본 PDF 와 쪽마다 맞댄다** — 쪽 수 · 쪽 차례(2번의 원본 차례 견본) · 면 모양이 같아야 통과. 패턴을 따로 만들지 않고 이 결과로 확인한다.
   - 정본 예: `python3 tests/e2e/replay/<책>/join.py` — 내보내기 → 가져오기로 잇기 → 면 이름 → 견본 원고 → 관리에 등록 → 맞대기까지 한 번에.
8. **편집기 제작 등록**
   - 구성마다 견본 원고 하나를 넣고 문서 패널 「관리에 등록」으로 같은 관리 폴더에 올린다(카드 라벨 「편집기 제작」 — 구성 견본 한 벌씩, 원본 전체 쪽수가 아니다).
   - **원본 PDF 를 템플릿에 붙인다** — `python3 tests/e2e/attach_origin.py <틀>/<템플릿> <원본 PDF | 1단계 원본 카드 id>` (템플릿 폴더 `참고/원본.pdf`).
     원본 카드를 나중에 지워도 템플릿에 남는다. 도구가 바로 템플릿 보기를 열어 두 칸(아래 9)을 확인한다(2026-10-13 사용자 확정).
9. **맞대기**
   - 등록 PDF 의 견본 쪽을 구성마다 쓰던 요소 목록으로 다시 판정하고, 결과를 사용자에게 보여 확인받는다.
   - 등록된 카드 = 관리 폴더에서 누르면 **템플릿 보기 — 두 칸**: 「상위 페이지」(편집기 문서에서 읽은 만드는 단위 · 1페이지/펼침면)와
     「원본 페이지 차례」(붙인 원본 PDF 를 PDF 등록과 같은 판정으로 — 원본에서 상위 페이지가 어떤 차례로 되풀이됐나, 확인용).
     두 칸을 사용자에게 보여 확인받는다. 거기서 「편집기에서 편집」으로 편집기에서 연다(넣어 둔 견본 원고 모습으로).
     등록한 뒤 고칠 때도 이 길로 열어 고치고 다시 「관리에 등록」 — 같은 카드를 다시 그린다(정본 예: `rename.py <틀>/<카드>`).
10. **반영**
   - main 머지 → push → `deploy/fly-deploy.sh` → 상태 확인.
   - 배포는 **새 카드만** 배포서버로 옮긴다. 이미 있던 카드를 고쳤으면 배포서버에서도 9번 길(「편집기에서 편집」 → 고침 → 「관리에 등록」)로 다시 등록한다(`RENAME_BASE=https://yos-studio.fly.dev rename.py …`).
     있던 템플릿에 원본을 처음 붙였으면 배포서버에도 붙인다(`attach_origin.py <틀>/<템플릿> <원본> --base https://yos-studio.fly.dev` — 배포는 있던 템플릿에 새 파일을 안 옮긴다).
   - **끝났다고 말하기 전에** 로컬과 배포서버 템플릿 보기를 `python3 tests/e2e/attach_origin.py --check [--base https://yos-studio.fly.dev]` 로 본다 —
     편집기 템플릿마다 「상위 페이지」 · 「원본 페이지 차례」 두 칸이 나와야 끝(2026-10-13 — 포켓북을 「끝」이라 했는데 관리 화면은 옛 「구성」 한 칸이었다).
   - 배포서버 서체는 `deploy/fly-deploy.sh fonts`(사용자가 터미널에서 — `fly ssh` 는 클로드가 못 쓴다). 서체가 없으면 등록 PDF 맞대기에서 글자가 걸린다.

**합격 기준** (도구 판정 — `replay.py` 끝 줄 「판정: 통과/실패」)
- 대본 오류 0. 원본 쪽마다 만든 지면이 있다.
- 맞댈 요소 목록(`elems.json`)이 **있다** — 없으면 실패. 고정 부분(띠·제목·탭·선·쪽번호·그림·고정 글)은 **전부** 넣는다(흐르는 쪽도 고정 부분은 같다).
- 고정 요소는 0.3mm 안 · 글은 모양까지.
- **고정 / 원고 구분** (2026-10-10 사용자 확정) — 같은 구성의 여러 회차를 맞대 회차마다 바뀌는 것 = 원고(지문·번호·발문·선지·주제·주석·회차 제목 …),
  모든 회차에 같은 것 = 고정(머리·탭·꼬리표·아이콘·선·쪽 번호 자리). 있다 없다 하는 것 = 원고(한 줄기 흐름 — 원고에 없으면 문단이 안 생긴다 · 접기 묶음은 2026-10-14 지움). 한 번만 나오는 구성은 책마다 바뀌는 글(교재명 등)만 원고.
  원고를 따라 움직이는 것(원고 바탕·테두리·O/X 칸)도 원고 쪽.
- **고정** 요소: 원본과 0.3mm 안 · 글은 모양까지(위 표).
- **원고** 요소(`"원고": true`): 원본과 위치·크기·모양을 맞대지 않는다. **「바꿀 수 있는가」** (2026-10-10 사용자 확정) —
  ① 자리에 원고가 들어감(그 둘레 8mm 안에 있음) ② 넘침 없음(편집기 경고) ③ 원본 글 모양(서체·크기·행간·자간·자간 축소·색·정렬·바탕)을 글상자 칸으로
  정하고 바꿀 수 있음(대본이 그 칸에 원본 값을 쳐서 오류 0) ④ 다른 원고(swap_check)에도 안 깨짐. 이것이 되면 원본과의 약간의 차이는 넘어간다.
  원본의 쪽별 차이(같은 구성인데 쪽마다 다른 크기·서체·손 흔적)는 따라 하지 않는다 — 구성마다 글상자 스타일 하나로 통일하고, 다른 값은 「그 칸으로 바꿀 수 있음」만 보고에 적는다.
- 판정만 다시: `replay.py <단위>@<구성> judge` — 지난 판의 결과로 판정만(다시 만들지 않는다).
- 요소 목록 밖에서 원본과 다른 곳이 없다(빠뜨린 요소를 잡는다).
- 예외는 사용자가 확정한 것만 `상태.json` 「허용」에 이유와 함께.
- **원본 손 고침** (2026-10-14 사용자 확정) — 원본은 인디자인 템플릿으로 찍은 뒤 사람이 손으로 고친 곳이 있을 수 있다
  (정본 187쪽 지문 번호 「6」 앞 간격만 2.6mm — 같은 자리 다른 12곳은 9.7mm). 판정에서 한 쪽만 걸리면 먼저 **같은 구성의 다른 회차 쪽들과 같은 자리를 잰다**:
  ① 다수가 같은 값이고 그 쪽만 다르면 「손 고침 후보」 — 템플릿은 다수(표준) 값 그대로 두고, 그 쪽을 맞추려 템플릿을 바꾸거나 예외 템플릿을 만들지 않는다.
  ② 사용자에게 다른 회차 값과 함께 보여 확인받고 `상태.json` 「원본_손고침」 {"p쪽:요소" 또는 "p쪽:요소:작은 글": "이유"} 에 적는다 —
  검사(replay.py · join.py)는 판정에서 빼되 결과에 「원본 손 고침 N곳」으로 늘 보인다(「허용」과 따로 — 「허용」은 그 밖의 사용자 확정 예외).
  ③ 그런 곳은 책을 만든 뒤 사용자가 편집기에서 그 자리만 고친다(인디자인과 같은 흐름 — 템플릿 → 원고 → 손보기. 「원고 들어간 문단 하나만 서식 바꾸기」는 다음 할 일).
  다수가 없으면(회차마다 다 다르면) 손 고침이 아니라 원고 차이다 — 원고 판정(「바꿀 수 있는가」)으로 본다.

**돌리는 방식** (2026-10-10 사용자 확정 — 병렬로 돌리며 공용 부분을 고치다 실패가 섞이고 되풀이됐다)
- 구성은 **하나씩** 차례로. 동시에 돌리지 않는다(바빠지면 화면이 늦게 바뀌어 조작이 어긋난다).
- 검사가 도는 동안 공용 부분(편집기·조작 도구 rec.py·공용 대본 함수)을 고치지 않는다. 실패하면 원인 하나를 밝히고 그것만 고친 뒤 그 구성을 다시.
- 조작 도구를 고치면 그 고친 조작을 쓰는 구성을 한 번 돌려 통과를 본다(사람보다 빠른 순서 한 번이면 된다 — 2026-10-10 사용자).
- 맨 끝에 모든 구성을 처음부터 다시 만드는 「책 전체 판」은 **하지 않는다**(2026-10-10 사용자 — 3시간 걸리고, 구성 통과 뒤 바뀐 것이 기능 추가뿐이면 얻는 것이 없다).
  대신 7~9번 「잇기 → 편집기 제작 등록 → 맞대기」. 다만 구성이 통과한 뒤 **있던 조작을 바꾸거나 없앤** 편집기 변경이 있으면, 그 조작을 쓰는 구성만 다시 검사한다.
- 실패 → 고침 → 다시 돌리기는 한 원인에 **한 번**. 두 번째도 안 되면 멈추고 사용자에게 보고한다(끝없이 돌리지 않는다).
- 맞댈 요소 목록은 **늘 새 원본에서 새로 읽는다**(이전 대본·이전 책에서 가져오지 않는다) — 다시 쓰는 대본이 새 책의 요소를 빠뜨리거나 값이 틀리면 판정에서 걸린다.
- 다시 쓰는 대본(공용 대본 함수)에서 문제가 나오면 그 함수를 고치고, 그 함수를 쓰는 다른 책들을 같은 판정으로 다시 확인한다.

**조작은 사람과 같게** (2026-10-10 — 다르면 사람이 쓸 때 생길 버그를 놓친다)
- 마우스는 이어서 움직여 누르고 끈다. 칸은 눌러 키보드로 친다 — 한글은 입력기 조합(자모 → 음절), 긴 글은 붙여넣기(⌘V).
- 목록은 눌러 편집기 화면 안 목록을 펼치고 화살표·Enter 로 고른다(운영체제 목록 창은 쓰지 않는다 — 편집기 `.selmenu`).
- 화면 밖은 휠로 굴리고, 접힌 칸은 머리를 눌러 편다. 묻는 창엔 글을 쳐서 확인(`{"answer": …}`), 파일은 단추를 눌러 뜬 파일 창에서 고른다.
- 누르기 전에 화면이 다 바뀌었는지 본다(그려진 요소 수 · 서버와 주고받는 중 `window.__busy`). 속도는 빨라도 된다.
- 코드로 값을 넣거나 화면 요소를 건드리지 않는다(`js` 단계는 결과 읽기·확인만).

**서체는 시스템 서체만** — 편집기 서체 칸은 시스템 서체(`core/units/fonts.system_fonts` — 묶음 서체 + 올려 등록한 서체)에서만 고른다.
없으면 글상자 「＋ 서체」로 올려 등록한 뒤 쓴다. 그리기·PDF 는 그 파일을 직접 부른다(컴퓨터에 깔린 서체에 기대지 않는다).
검사는 등록 안 된 서체·없는 굵기를 쓰면 실패. 등록한 서체는 문서 묶음(units.json)에 실려 서버로 같이 간다.

**하지 않는 것** (반복된 실수)
- 예전 단위·예전 문서의 **결과물**을 가져다 합치기(짜깁기). 만드는 방법·도구 함수는 써도 되지만 값은 목표 PDF 에서 새로 잰다.
- 쪽·구성마다 검사 기준을 바꾸기, 「이 쪽은 특별하다」며 요소 목록을 빼기, 낮은 수치에 그럴듯한 설명을 붙여 넘기기.
- 승인 없이 방식 바꾸기(손작업 → 자동 생성 등). 바꾸고 싶으면 먼저 묻고, 정해지면 이 절에 먼저 적은 뒤 따른다. 진행 중에 그 자리에서 방식을 바꿔 끼우지 않는다.
- 「됐다」 보고 전에 목표와 맞대지 않기 — 보고는 판정 결과로.

| 나눌 것 | 방법 |
|---|---|
