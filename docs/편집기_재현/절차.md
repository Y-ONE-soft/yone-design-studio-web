# 편집기 재현 — 절차 (초안 v0)

> 이 문서가 정본이다. 스킬·명령·다른 세션은 모두 이 문서를 따른다. 규칙을 바꿀 땐 여기만 고친다.

## 목적

이미 만들어진 결과물(기준)을 「만들기」 편집기의 기능만으로 **똑같이** 다시 만든다.
못 만들면 그 자리에서 멈추고 편집기 기능을 고친다. 버그를 찾고 기능을 채우는 것이 목적이다.

## 말 (이 말만 쓴다)

| 말 | 뜻 |
|---|---|
| 기준 | 똑같이 만들어야 할 결과물 (PDF 쪽, 그림 등) |
| 단위 | 한 번에 만들고 확인받는 덩어리. 보통 지면 한 장. 이름 = `pNN-이름` (예: `p03-단원표지`) |
| 작업 지시 | 사용자가 주는 것: 기준 + 단위 목록 + 요청 |
| 대본 | 녹화기가 따라 하는 조작 목록 (`steps.json`), 대본 생성기 `make.py` 가 만든다 |
| 빠른 검사 | 녹화 없이 대본만 돌려 결과 지면을 뽑기 (30초) |
| 비교 | 기준과 결과를 나란히 · 차이 · 수치로 맞대기 |
| 녹화 | 커서·클릭·끌기·키 입력이 보이는 영상 |
| 막힘 | 편집기 기능이 없거나 고장 나서 대본으로 만들 수 없는 상태 |

## 단위 하나의 순서 (늘 같다)

```
1 기준 수치 → 2 대본 → 3 빠른 검사 → 4 비교 ─(합격)→ 5 녹화 → 6 보고·확인
                          ↑            │(불합격·대본 문제)
                          └────────────┘
                                       │(막힘) → 멈춤 → 기능 수정 → 3 부터
```

1. **기준 수치** — 기준에서 면·선·글의 위치(mm)·색·크기·서체·글 내용을 뽑는다. 대본의 모든 값은 이 수치에서 온다. 눈대중 금지.
2. **대본** — `make.py` 에 조작을 쓴다. 실제 화면 조작(마우스·키보드)만 쓴다. js 로 값을 꽂지 않는다.
3. **빠른 검사** — `replay.py <단위> check`. 녹화와 **같은 대본**을 돌리므로 여기서 맞으면 녹화도 맞는다.
4. **비교** — `replay.py <단위> compare`. 합격 기준(아래)을 모두 넘으면 5로. 아니면 2로.
5. **녹화** — `replay.py <단위> rec`. 합격한 대본만 녹화한다. 녹화는 단위당 한 번이 원칙.
6. **보고** — `보고양식.md` 대로 보고를 쓰고 비교 그림 + 영상을 보인다. 사용자가 확인하면 진행표에 체크.

## 합격 기준 (초안 — 값은 돌려 보며 정한다)

| 항목 | 기준 |
|---|---|
| 배치 | 요소마다 위치·크기 오차 0.5mm 이내 |
| 색 | 같은 값 (#hex) |
| 글 | 내용·크기(pt) 같음 |
| 화면 일치율 | 98% 이상 (기준과 겹쳐 같은 화소 비율) |

못 넘는 항목이 있으면 녹화하지 않는다. 대신 **차이 보고**를 쓴다:
일치율, 다른 항목, 이유(서체 없음 / 기능 없음 / 기준 측정 한계 …), "허락할지" 칸. 사용자가 허락하면 녹화로 간다.

## 막힘 — 바로 멈춘다

1. 대본 진행을 멈춘다. 우회(js 주입, 책 전용 꼼수)하지 않는다.
2. 사용자에게 한 줄로 알린다: 어느 단위 · 어느 조작 · 무엇이 안 됨.
3. 편집기 기능을 고친다. 다른 책에도 쓸 수 있는 보편 기능으로.
4. 기존 검사(`tests/e2e/canvas_audit.py`)로 다른 곳이 안 깨졌는지 확인한다.
5. 3(빠른 검사)부터 다시 한다.

## 다시 하기 — 그 단위만 지운다

단위에 문제가 생겨 처음부터 다시 할 때만 지운다. `replay.py <단위> reset`.
지우는 것: 그 단위의 데이터 폴더(편집기 문서), 검사·비교 그림, 영상, 보고. **대본 생성기 `make.py` 는 남긴다**(고쳐서 다시 쓴다 — 지우라고 하면 지운다).
다른 단위는 건드리지 않는다.

## 파일 자리

| 무엇 | 어디 | 커밋 |
|---|---|---|
| 절차·양식 | `docs/편집기_재현/` | O |
| 단위 대본·보고·상태 | `tests/e2e/replay/<단위>/` (`make.py` · `steps.json` · `보고.md` · `상태.json`) | O |
| 진행표 | `tests/e2e/replay/<작업>.md` (진행표양식) | O |
| 그림·영상 | `~/Downloads/편집기재현/<단위>/` (`check.png` · `side.png` · `diff.png` · `<단위>.mp4`) | X |
| 단위 데이터 폴더 | `~/.cache/yone-replay/<단위>/catalog` (편집기 저장 데이터) | X |

단위마다 **데이터 폴더를 따로** 쓴다(`YONE_CATALOG_DIR`). 그래서 지우기가 그 단위에만 미치고, 병렬로 돌려도 서로 안 지운다.

## 병렬 (여러 세션)

| 나눌 것 | 방법 |
|---|---|
| 코드 | 세션마다 워크트리 |
| 서버 포트 | 세션마다 다르게 — `REPLAY_PORT=5101` (5101, 5102 …) |
| 크롬 포트 | `REC_PORT=9471` (9471, 9472 …) |
| 데이터 | 단위별 데이터 폴더 (위) |
| 같은 단위 동시 작업 | `상태.json` 의 `session` 이 있으면 다른 단위로 간다 |
| 기능 수정 | **미정** — (가) 한 세션만 고친다 / (나) 각자 고쳐 각자 머지 |

다른 세션이 기능을 고쳐 main 에 머지했으면 다음 단위 시작 전에 main 을 받는다.
