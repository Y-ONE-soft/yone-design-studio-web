# 디자인 단위 스키마 v1

> 스키마: `core/schema/units.schema.json` · 작성 2026-09-21
> 원칙: 작은 단위로 큰 단위를 만든다. 콘텐츠는 필드(bind)로만 들어온다. 색·서체는 토큰 이름으로만 적고 값은 옷이 준다.

## 단위

| 단위 | 역할 | 안에 드는 것 |
|---|---|---|
| 원자 `atom` | 인디자인 오브젝트 하나. `text` `line` `rect` `ellipse` `image` | 치수(mm)·토큰·bind |
| 부품 `part` | 원자 묶음. 콘텐츠 자리는 원자의 `bind` | 원자 |
| 블록 `block` | 유형 1개. 필드 스키마 + 모양(부품) 1개 이상. **콘텐츠 연동 단위** | 필드·모양→부품 |
| 지면 `page` | 칸(zone) 배치 + 고정 부품(러닝헤드·쪽번호). **PDF 한 면 = 지면 하나** | 칸·chrome→부품 |
| 구간 `section` | 지면 반복 규칙 + 앞 간지. STEP·PART·DAY·회차 | 지면 |
| 틀 `plan` | 구간 순서 + 앞뒤 면 + 규격. 라인업 이름 | 구간·spec |
| 규격 `spec` | 판형·도련·제본·도수 | 값 |
| 옷 `skin` | 토큰 값 + 블록별 모양 선택 + 이미지 교체 | 값 |
| 세트 `set` | 콘텐츠가 오는 단위(지문 1개 + 딸린 블록). contents 는 이것만 보낸다 | 블록 id + 필드 값 |

- 부품 안에 부품 없음, 블록 안에 블록 없음. 반복은 **세트**(블록 여러 개)와 **구간**(지면 여러 번) 두 곳에서만.
- **묶기·풀기(인디자인의 그룹)**: 원자 여럿 → 묶기(Ctrl+G) → 부품 → 풀기(Ctrl+Shift+G) → 원자. 부품 → 올리기(콘텐츠 자리 이름표 = 글상자의 bind 가 필드) → 블록 → 풀기 → 부품(지금 옷의 모양). 캔버스의 떠 있는 도구와 오른쪽 사슬에 버튼.
- `bind` 이름 = 블록 필드 이름. `sys.page_no` `sys.section` `sys.title` 은 책이 채운다.
- 토큰은 `$이름`. 옷의 `tokens.color` / `tokens.font` 에서 값을 찾는다. 없으면 조판 중단(조용히 넘기지 않는다).

## 화면 · 코드

- 캔버스 `/units` (`templates/units_canvas.html`) — Canva 식이되 **왼쪽 세로 탭이 인디자인 순서의 단위**: ①원자(오브젝트) · ②부품(그룹) · ③블록(콘텐츠 자리, 「설명으로 만들기」) · ④지면(페이지 목록·흐름 설명) · ⑤틀(책 구성) | 👕옷(색·서체·모양) · 📝세트(콘텐츠, 「이 지면의 블록 자리로 세트 만들기」). 가운데 ④지면(위에 뜬 도구: 이름·옷·복제·지우기), 아래 지면 띠(번호·끌어 순서·끝의 +). 오른쪽은 고른 것의 **단위 사슬**(블록→모양→부품→원자 / 부품→「블록으로 만들기」 / 원자 속성 편집). 원자를 Shift+클릭으로 여럿 고르고 「부품으로 묶기」 → 부품 → 「블록으로」 = 단위가 올라가는 길. 자유 배치 요소 `page.items` = `[{block|part|atom, x, y, w?}]`. 깊은 링크 `/units?tab=atoms#pair`.
- 캔버스의 문서 = **틀(plan)**. `/units` 는 틀 목록(시작 화면: 「＋ 새 틀」, 틀 카드) → `/units?plan=<id>#<page>` 로 한 틀을 편다. 아래 지면 띠·＋·←/→·지우기·순서는 그 틀의 지면 순서(`planIds`: front → sections(divider, pages) → back) 위에서 움직이고, 바꾸면 틀을 한 구간으로 다시 써 저장한다. 지면은 라이브러리(공유)에 있어 다른 틀이 쓰는 지면은 라이브러리에 남긴다. 위 도구: ← 틀 · 틀 이름 · 지면 이름 · 옷 · 📖 책 미리보기(세트를 끼운 전체) · ⬇ PDF(`/api/units/pdf?plan=`, `core/units/pdf.py` 크로미움 인쇄, `--user-data-dir` 는 이 맥에서 멎으니 금지) · ⧉ · 🗑. 빈 틀엔 3단계 안내.
- 캔버스 조작(디자인 툴 표준): 클릭 고르기 · Shift+클릭 더 고르기 · 빈 곳 끌기 = 영역 선택 · 끌어 옮기기(여럿 함께, 다른 요소 가장자리·가운데·여백선에 붙는 안내선, Alt 로 끄기) · 손잡이 폭(E)·높이(S, 원자)·둘 다(SE) · 화살표 0.5mm(Shift 5) · Ctrl+Z/Shift+Z 되돌리기(지면마다 50) · Ctrl+C/V · Ctrl+D 복제 · Ctrl+A · Delete · Ctrl+]/[ 맨 앞·뒤 · 정렬 6종(여럿 골랐을 때) · 글상자 더블클릭 = 글 고치기 · Ctrl+G 묶기 / Ctrl+Shift+G 풀기 · Esc. 헤드리스 시험: scratchpad `cdp.py`(stdlib 로 Chrome DevTools) + `canvas_steps.json`.
- 라이브러리 `/units/library` (`templates/units.html`): 왼쪽 라이브러리·분해(PDF·그림·프롬프트), 가운데 미리보기(SVG), 오른쪽 JSON 편집. 깊은 링크 `/units/library#plans/workbook_mini`.
- 라이브러리 `catalog/_units/<kind>.json` (`core/units/store.py`) — 배포에선 볼륨이 정본, 리포는 시드(`deploy/catalog_sync.py` 가 없는 폴더만 보탠다).
- 그리기 `core/units/render.py` — 부품·블록·지면·틀을 같은 코드로. 글은 `<foreignObject>` 로 브라우저가 감고, 높이는 글자 수로 어림해 아래 원자를 민다. 부품 폭은 칸 폭에 맞춘다(가로 비례). 없는 토큰은 자홍색 + 경고.
- 분해 `core/units/decompose.py` — PDF 는 PyMuPDF(도형 → 그림 → 글 순서, 줄을 단락으로 합침, 재단선 안으로 자름), 이미지·프롬프트는 클로드(`YONE_ASSIST_MODEL`, JSON 글로 받는다).
- 시험 `tests/test_units.py`.

## 원고가 들어오면 — 워크북 엔진이 하던 일과 대응

| 워크북 엔진(render_vivlio/series/workbook)이 하던 것 | 단위 시스템에서 | 상태 |
|---|---|---|
| 원고(docx) 단락 스타일 → 역할(roles) → data.json | 📝 세트 `{kind, id, blocks:[{block, fields}]}` — 캔버스 「이 지면의 블록 자리로 세트 만들기」로 손으로, 실제는 contents 가 보냄 | 파서 없음(다음) |
| 지문마다 반복(groups) | 틀 section.pages `repeat: each_set` — 슬롯 모드: 세트마다 한 면, 자리에 값 | 있음 |
| STEP 간지 자동 | 틀 section.divider | 있음 |
| 러닝헤드·쪽번호·단계 표시 | system 블록 + `sys.*` (page_no·section·title·tag) | 있음 |
| 글이 길면 아래로 밀림·넘침 | 자리가 자라면 아래 요소를 민다(가로 겹치는 것만, system 은 고정). 면 아래로 넘치면 경고 | 다음 면으로 흘리기 없음 |
| 하단 문제 붙임(step2_a1_btm) | 세트 안 블록 순서 | 있음 |
| 정답지 분리 | 세트의 answer 필드 → 정답 지면 | 없음 |
| 넘침·누락 검수 게이트 | warnings | 일부 |

## 입력 → 분해 → 목록

| 입력 | 분해기 | 출력 |
|---|---|---|
| PDF 한 면 | PyMuPDF: 벡터(선·면)·글(span)·이미지가 이미 오브젝트 | `decomposed` — 원자 목록 + 잰 토큰(색·서체) + 부품 후보 |
| 이미지 | 클로드가 보고 원자로 그린다 | 같은 형식 |
| 프롬프트 | 클로드가 원자로 그린다 | 같은 형식 |

분해 결과는 라이브러리에 **후보**로 들어간다. 사람이 고르고 이름 붙이면 부품이 되고, 필드를 붙이면 블록이 된다.
