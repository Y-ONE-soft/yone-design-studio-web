> **파일럿 완료.** 계열 `final` 신설, 5개 학교 10권이 게이트를 전부 통과했다.

> 자세한 결과는 §8. 아래 §1~§7 은 착수 전 정찰 기록이며 결론은 그대로 유효하다.

이 문서의 §1~§7 은 **착수 전 정찰**이다.
근거는 전부 실측이다 — 납품 완성본 PDF(광문2 26-1-기말 Vol1 40p / Vol2 62p),

다음 면으로 흘리는 것이 CSS Paged Media 의 기본 동작이기 때문이다. 난도의 무게
중심이 렌더에서 **소스**로 옮겨간다.

## 0. 결론 먼저

1. **렌더 병목은 Vivliostyle 이 통째로 없앤다.** InDesign JSX 3,759줄이 하던 일
   (오버플로우 감지 → 페이지 추가 → 프레임 확장/축소 → 폰트 축소 → 페이지 스왑)의
   9할은 CSS 가 공짜로 한다. 광문2 Vol1 의 `오버플로우: 7개` 같은 결함은 개념 자체가
   사라진다.
2. **그러나 사용자가 말한 병목의 본체는 렌더가 아니라 소스 수집이다.**
   Vivliostyle 은 그것을 자동으로 고쳐 주지 않는다. 다만 전환은 그것을 고칠
   **유일한 기회**다 — 렌더를 새로 쓰는 김에 소스 계약도 새로 그을 수 있다.
3. **핵심 제안: 워크북 `.indd` 역수확(InDesign 패스 #1)을 원고 직독으로 갈아탄다.**
   §4 에서 실물로 확인했다 — 파이널이 워크북에서 긁어 오는 모든 섹션이
   같은 이름의 원고 docx 로 존재한다. 이 하나가 지금까지 나온 조판 결함의
   **대부분**의 근원이다.

공통점이 둘이다.

- **전부 "헤더·개수·순서는 정상인데 내용만 틀린" 류**다. 눈으로 안 잡히고, 카운트

- **원고에는 애초에 없던 문제**다. 라벨 오귀속·프레임 분할·파일 중복은 전부
  *조판 결과물*의 성질이지 원고의 성질이 아니다.

### 1-3. 시간·의존 비용

- InDesign 패스가 **두 번**이다: ① 워크북 4개(각 20~30MB)를 열어 추출 →
  ② Vol1/Vol2 조판 + vocab 별도 패스.
- 그래서 조판 머신이 InDesign 을 점유한다. 동시 세션 충돌, 사용자 작업 문서 보호,
  `pgrep osascript` 대기 같은 규율이 전부 여기서 나온다.
- 한 시험기간에 **학교 18곳 × 2권 = 36권**. 이 왕복이 36번 돈다.

## 2. Vivliostyle 이 없애는 것과 못 없애는 것

### 없애는 것 (렌더)

| 지금 JSX 가 하는 일 | Vivliostyle |
|---|---|
| 오버플로우 감지 → `pages.add` → 마스터 상속 → 프레임 복제 | 그냥 흐른다 |
| 프레임 하단 확장/축소, 폰트 축소, 페이지 스왑 | 불필요 (§3-3 의 슬롯 정책만 정하면 됨) |
| 스토리 시작 페이지를 **런타임 스캔**으로 찾기 | 문서 순서가 곧 배치 |
| `>>내용요약` 좌우 baseline 동기화 (JSX 가 좌우 스토리 높이를 재서 맞춤) | 표 한 행이면 구조적으로 맞음 |
| 화살표 GraphicLine 앵커 복제, pasteboard 고아 정리, rulerOrigin 강제 | 없음 |
| 마스터·섹션마커·문자스타일 이름 의미론 | CSS 클래스 |
| 산출이 `.indd` 라 PDF 를 따로 뽑아야 함 | PDF 가 1급 산출 |

### 못 없애는 것 (그래서 따로 설계해야 하는 것)

1. **소스 수집·라벨 부여·정렬** — §4.
2. **구글시트 두 개**(시험범위·중요어휘). 이건 병목이 아니라 정당한 진실의 출처다.
   다만 fetch 시점 의존이라 **스냅샷 고정**이 필요하다(재현·회귀용).
3. **슬롯 넘침 정책** — 인디자인은 런타임에 폰트를 줄였다. CSS 에서는 "그냥 흘리면"
   4칸 격자가 깨진다. 정책을 명시적으로 정해야 한다(§3-3).

### 3-4. 사분면 넘침 정책 — 유일하게 새로 정할 것

화이트북이 이미 답을 갖고 있다: `column-fill: auto` + 고정 높이 칸.
파이널은 지문 길이가 들쭉날쭉하므로(현 InDesign 은 넘치면 폰트를 줄인다) 셋 중
하나를 **명시적으로 고른다.**

1. 칸에 `overflow` 를 두지 않고 **자연 높이대로 흘린다** → 격자가 깨진다(현 완성본과 다름).
2. **칸 높이를 지키고 넘치면 그 지문만 폰트를 단계적으로 줄인다**
   (`core/render_vivlio/measure.py` 로 자연 높이를 재서 축소율을 미리 계산).
   → 현 완성본과 가장 가깝다. **권고안.**
3. 넘치는 지문만 **두 칸(세로 반쪽 2개)을 쓰게 한다**.

권고는 2번이되, **몇 %까지 줄였는지 검수 리포트에 남긴다**(침묵 축소 금지).
현 InDesign 이 몇 개나 줄이고 있는지는 `typeset_log.txt` 의 `오버플로우: N개` 로
이미 셀 수 있다(광문2 Vol1 = 7).

## 4. 소스 통일 — 원고 직독이 가능한가 (검증함)

### 4-1. 원고 폴더의 모양이 **모든 출처에서 같다**

교과서·올림포스·모의고사가 전부 같은 파일 이름을 쓴다.

```
<교재 폴더>/… 워크북/
    Step1 C1 문장배열.docx        ← 파이널 ① 문장배열 + 문장삽입(하단)
    Step1 C2 빈칸어휘.docx        ← 고3 ② 중요어휘
    Step2 A1 어법선택.docx
    Step2 C2 영작배열.docx        ← 파이널 ④ 서술형영작
<교재 폴더>/… 직전보충/
    …_어법수정_문제지.docx        ← 파이널 ③ 어법수정 (이미 원고를 직접 읽는다)
```

실물 확인:
- 교과서 `교과서 작업/영어Ⅰ/영어Ⅰ 미래엔(김)/영어1 미래엔(김) 4과/… 4과 워크북/`
- 올포 `EBS 작업/올림포스 독해기본1/올림포스 독해기본1 12강/12강 워크북/`
- 모의 `모의고사 작업/고2/고2 25년 3월/고2 25년 3월 워크북/`

### 4-2. 내용이 실제로 일치한다 (대조함)

광문2 Vol1 문장배열 첫 블록 `교과서4과 본문1` (완성본 p2 왼쪽 위)과
`영어1 미래엔(김) 4과 워크북/Step1 C1 문장배열.docx` 의 `1. L4-본문1(p.94)` 블록:
**(A)~(I) 아홉 문장이 순서까지 완전히 같다.**

라벨도 원고가 더 낫다 — `1. L4-본문1(p.94)` 는 **원고가 스스로 말하는 라벨**이라
`L4 → 4과`, `본문1 → 본문1` 로 결정론적으로 옮겨진다. 반면 지금은 지면 순서로
번호를 매겨서 상일1 올포 12강 같은 오라벨이 났다.

### 4-3. 하단 문제(문장삽입)도 같은 파일에 있다

`engines/workbook_v2/plan.py` 의 C1 슬롯 배치(W70·W73)가 근거다 — 워크북의
C1 지면은 **한 원고 파일**에서 상단(배열 카드)과 하단(순서·삽입)을 갈라 넣는다.
원고에 `02  문장삽입  주어진 문장 다음에 이어질…` 같은 유형 표기가 붙어 있고,
워크북 v2 는 이미 그 구조를 읽는다.

### 4-4. 시트로 남아야 하는 것 (원고에 없음)

- **중요어휘(고1·고2)** — 워크북 `Step1 C2 빈칸어휘.docx` 는 같은 지문에 빈칸을
  29개 뚫는데, 파이널 완성본은 15개다. **선생님이 고른 부분집합**이라 원고에서
  유도할 수 없다. 시트가 정본이다. (고3 은 워크북 빈칸어휘를 그대로 쓴다.)
- **요약문** — 중요어휘 시트에 같이 실려 온다.
- **시험범위·제외·에디션** — 시트가 정본.

### 4-5. 그래서 남는 위험 하나

원고에 없고 **`.indd` 에만 있는 수정**이 있을 수 있다(조판 후 손으로 고친 것).
전환 첫 판에서는 **원고본과 현행 추출본을 나란히 놓고 문장 단위로 대조**하는
일회성 검사를 돌려, 차이가 나는 지문만 목록으로 뽑는다. 차이가 0 이면 그대로 가고,
있으면 그 지문만 예외 처리한다. 이 대조는 `extracted.json` 이 과거 job 에 남아
있으므로 InDesign 없이 오프라인으로 가능하다.

   응답을 그대로 저장.

### C. 확인이 필요한 것 (사용자 결정)

1. **`.indd` 에만 있는 손수정이 있는가** — §4-5 대조 결과에 따라 갈린다.
2. **넘침 정책** — §3-3 의 2번(폰트 축소, 현행과 동일)으로 가도 되는지.
3. **산출 형식** — 지금은 `.indd` 를 폴더에 두고 사용자가 직접 연다.
   Vivliostyle 은 PDF 만 낸다. **조판 후 손으로 고치는 일이 있는지**가 핵심이다.
   있다면 "수정은 원고에서" 로 작업 방식이 바뀐다.

## 7. 리스크

1. **소스 전환이 진짜 일이다.** 렌더는 화이트북 선례가 있어 예측 가능하지만,
   라벨 정규화(`L4-본문1`/`p2-no.20`/`Unit12`)는 출처마다 방언이 있다.
   워크북 v2 가 이미 겪은 길이라 자산은 있으나, **정규식 화이트리스트로 가면 안 된다**
   (반복 피드백: 형식이 아니라 구조로 판정할 것).
2. **B3~B5 를 먼저 하고 B6 을 나중에** 하는 순서를 지킬 것. 렌더와 소스를 같이
   갈아 끼우면 어느 쪽이 깨졌는지 알 수 없다.
3. **시트 fetch 시점 의존** — 스냅샷 없으면 회귀 검증이 블라인드가 된다.
4. **인쇄 원고** — 전권 무채색이라 `print.gray_map` 만으로 K100 이 나온다.
   대신 `verify` 가 "인쇄본이 조판본보다 오래됨"을 잡도록 켜 둘 것.
5. **`.indd` 납품 관행** — §5-C-3. 여기가 정리 안 되면 전환해도 두 경로가 공존한다.

### 실측 대조 (광문2 26-1-기말)

| | 완성본(InDesign) | Vivliostyle |
|---|---|---|
| Vol1 | 40p | **40p** |
| Vol2 | 62p | **62p** · 면별 지문 배치 **62/62 일치** |

6배 크다 — 인디자인 단락스타일의 트래킹이다). 빈칸 밑줄 폭은 완성본 227개에서
글자수별 최솟값이 일정해 **정답 글자 수 × 0.684em** 으로 굳혔다.

### 완성본에 없던 것을 되찾았다

- **리딩파워 15강 Ex02 의 항목 (E)(F)(G)(H) 네 개가 납품본에 없다.** 지문이
  사분면 한 칸(126mm)보다 47% 길어 인디자인이 지면 밖으로 흘렸고, 그만큼이
  PDF 에서 잘렸다. 원고에는 있다. Vivliostyle 판은 이 지문에 **두 칸**을 주어
  전부 싣는다(§ 넘침 정책).
- **되읽기 잔재(하이픈 넣기) 42건** — `lim-ited`·`bet-ter` 처럼 조판된 지면을
  역수확하며 생긴 것이 그대로 인쇄돼 있다. 원고에는 없다. 지금은 검수가 세어
  경고로 알리고, **원고 직독(B6)으로 바꾸면 사라진다.**

### 넘침 정책 (사용자 확정 + 한 단계 더)

칸을 넘는 지문은 ① 활자를 단계적으로 줄이고(하한 7.0pt), ② 그래도 안 되면
**두 칸**을 주고, ③ 한 단보다 긴 지문(어법 321mm)은 **흘린다**. 셋 다 검수
리포트에 남는다 — 조용히 줄이거나 자르지 않는다. 광문2 Vol1 은 축소 6 · 두 칸 2.

### 남은 것

1. **B6 소스 전환** — 지금은 파이널 엔진의 `content.json` 을 그대로 먹는다.
   워크북 `.indd` 역수확을 원고 직독으로 바꾸는 일은 이 계열 **바깥**에서
   일어나고, 계열은 그때도 그대로다(§6 의 순서를 지킨 이유).
2. **줄바꿈 자리** — 인디자인은 단락 컴포저(전역 최적화)와 낱말 사이 압축을
   쓰고 CSS 는 앞에서부터 채운다. 글줄 폭은 0.012mm 로 맞지만 **어디서
   꺾이는지는 다를 수 있다**(어법 901줄 → 949줄). 지면 구조·쪽수는 같다.
3. **섹션 첫 면이 홀수일 때** 장 탭을 흰 상자로 덮는다 — 글자는 PDF 에 남는다.
   `@page <이름>:nth(1)` 은 Vivliostyle 에서 절대 쪽번호를 세므로 못 쓴다(실측).
4. **통합웹 카드** — 지금은 CLI 다. `engines/final_viv` 로 감싸 웹에서 돌리려면
   config 합성만 얹으면 된다(`scripts/final_viv_book.py` 가 그 원형).
