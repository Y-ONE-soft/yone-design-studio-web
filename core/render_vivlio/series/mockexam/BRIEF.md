# 동형모의고사 학교별 조판규칙 — 심층 작업 지시서

한 학교·학년(예: `한영2`) 하나를 맡아 **그 학교의 조판 규칙 전부**를 실제 기출
시험지에서 뽑아 프로파일로 확정한다. 얕게 훑고 끝내지 말 것 — 한 학교를 깊게.

## 0. 대전제

- **정본은 실제 학교 기출 시험지다.** 완성된 InDesign 파일도, 지금까지 나간 동형
  산출물도 정본이 아니다. 둘이 어긋나면 기출이 옳다.
- **정본 회차 = 직전 회차.** 조판 시점이 26-2-중간이므로 직전은 **26-1-기말**.
  없으면 `_reference_manifest.json` 의 fallback 회차를 쓰되, 그 사실을 프로파일
  `reference.fallback` 과 보고서에 반드시 남긴다.
- **큰 틀은 잘 안 바뀌고 세부만 가끔 바뀐다.** 그래서 세부(마무리 문구·배점 괄호·
  화살표 글리프·범위 구분자 …)는 **직전 회차에 맞춘다**. 회차별로 다른 값을
  발견하면 버리지 말고 `variants` 에 전부 기록한다.
- **직전 회차에 없는 요소는 그 요소가 나오는 가장 최근 회차에서 가져오고,
  해당 필드에 `src: "<회차>"` 를 붙인다.** (예: 직전 회차에 서답형이 없으면
  서답형 규칙은 직전-1 회차에서.)
- **판형은 제품 상수 B4 257×364mm**(도련본 263×370). 학교 기출이 A4여도 판형은
  안 따른다. 대신 모든 치수를 **B4 환산치**로 적고, 괄호에 정본 실측치를 남긴다.
  환산 계수 = 257 / (정본 지면 폭 mm). `rolemeasure` 가 자동으로 두 벌 다 낸다.
- **MediaBox 를 곧이곧대로 믿지 말 것.** 세종1 정본은 MediaBox 가 B4(257.2×364.1)인데
  내용 스트림 첫 클립 패스가 597.36×846.12pt = **A4** 였다(한글 A4 문서를 B4 용지로
  인쇄해 A4 판면이 B4 캔버스 좌상단에 얹힘). 그대로 믿었으면 환산 계수를 1로 잡아
  글자 크기를 22% 작게 낼 뻔했다. 텍스트 bbox 범위와 클립 패스를 같이 확인하라.
  스캔본이면 종이 가장자리를 찾아 이미지 픽셀 비율로 판면을 잡는다.

## 1. 입력

| 무엇 | 어디 |
|---|---|
| 정본(기출) 캐시 | `~/Documents/작업/Y.ONE STUDIO/조판/교재/동형모의고사/기출정본/<학교키>/` |
| 정본 지정표 | `core/render_vivlio/series/mockexam/profiles/_reference_manifest.json` |
| 동형 원고(1·2회) | `~/Documents/작업/Y.ONE STUDIO/조판/교재/동형모의고사/원고/` |
| 현행 동형 산출물 | `~/Documents/작업/Y.ONE STUDIO/조판/교재/동형모의고사/고{N}/<시험기간>/<학교>/` |
| 스키마 | `profiles/_schema.json` |
| 기준례 | `profiles/배재1.json` — **이 깊이·형식을 그대로 따를 것** |

기출DB 원본(Google Drive `내 드라이브/콘텐츠 관리/내신대비/학교기출DB`)은 **읽기
전용**이다. 절대 수정·이동·삭제하지 않는다. 필요한 파일은 캐시로 복사해 쓴다.

## 2. 도구 (이미 있음 — 새로 만들지 말 것)

```bash
cd ~/dev/yone-design-web && set -a && source .env && set +a
# 표기 방언·상자·마무리·글리프 증거
PYTHONPATH=. python3 core/render_vivlio/series/mockexam/refscan.py "<정본.pdf>"
# 역할별 서체·크기·행간·들여쓰기 (텍스트층 PDF 전용, B4 환산 포함)
PYTHONPATH=. python3 core/render_vivlio/series/mockexam/rolemeasure.py "<정본.pdf>"
# 원고 규칙 census
PYTHONPATH=. python3 core/render_vivlio/series/mockexam/msscan.py "<원고.hwpx>"
```

정본이 **스캔본**이면 `rolemeasure` 가 못 쓴다. 그때는 페이지를 PNG 로 렌더해
직접 눈으로 읽고(`fitz` `get_pixmap`, 긴 변 2000px), 치수는 **이미지 픽셀 비율로
환산**해 근사값을 적고 `typography.approx: true` 를 둔다. 최소 4쪽(첫 쪽·서답형이
있는 쪽·묶음이 있는 쪽·마지막 쪽)은 반드시 눈으로 본다.

같은 학교의 **텍스트층 있는 다른 회차**가 캐시에 있으면 수치는 그쪽에서 실측하고
표기·문구는 직전 회차에서 가져온다(어느 회차에서 왔는지 필드마다 `src` 로 표시).

## 3. 반드시 채울 13가지

1. **정본 확정** — 어느 PDF·어느 회차·왜. 직전 회차가 없으면 사유.
2. **지면 골격** — 본문 좌/우/상/하, 단 수·단 원점·단 폭·단 간격, 단 괘선 유무와
   두께·길이, 쪽 테두리 상자 유무, 상·하단 가로 괘선.
3. **러닝 요소** — 저작권 문구 **원문 그대로**·위치·크기, 쪽번호 형식과 위치,
   머리표(매 쪽인지 1쪽만인지, 표면 몇 행 몇 열이고 각 칸이 무엇인지, 칸 글자
   크기), 감독 확인란, 첫머리 안내문 줄들, '다음 쪽에 계속' 문구·글리프·위치.
4. **단락 역할별 수치** — 발문/지문/선지/보기/조건/요약/답란/서답형 라벨 각각의
   서체·크기·행간·앞여백·들여쓰기·내어쓰기·정렬·볼드.
5. **문제 유형별 차이** — 어휘·빈칸·순서·삽입·요약·장문·안내문·서답형에서
   들여쓰기나 배치가 달라지는 지점. 다르지 않으면 "균일"이라고 명시할 것.
   (다르지 않은 것을 확인한 것도 결과다.)
6. **보기/조건/요약/주어진문장 렌더 방식** — 맨줄인지, 테두리 상자인지, 캡션이
   테두리 선에 걸친 상자인지, 표인지, 반전 칩인지. 테두리면 두께·안여백·정렬까지.
   학교마다 **전부 다르다** — 이걸 대충 적으면 이 작업의 의미가 없다.
7. **문항 묶음 표기** — 정확한 문자열 템플릿. 괄호 종류, 안쪽 공백, 범위 구분자
   (`-` `~` `–`), 선택형+서답형 혼합 표기, 지시문이 같은 줄인지 다음 줄인지,
   묶음 안 개별 문항이 발문을 되풀이하는지 번호만 갖는지.
8. **서답형/서술형 라벨** — 정확한 템플릿(`[서답형 1]` / `서술형1.` / 반전 칩 +
   유형칸 + 배점칸 3칸 표 …), 번호가 선택형과 연번인지 별도인지, 위치.
9. **배점 표기** — 괄호 종류(코드포인트까지), 소수 자릿수, 정수일 때 표기,
   붙는 자리(발문 끝/지문 끝/우측 별행), 앞 공백 유무, 서답형 꼬리말
   (`부분점수 없음` 등), 소문항 부분배점, 머리표 총점 칸.
10. **마무리** — 정확한 문자열(공백·마침표까지), 정렬, 서체, 크기.
    회차별로 다르면 전부 `ending.variants_seen` 에.
11. **기타 글리프** — 요약 화살표 코드포인트, (A)(B)(C) 짝 선지 구분자,
    문장삽입 자리 표시 형태, 밑줄 관행, 원문자 종류.
12. **원고 규칙** — 이 학교 원고가 주는 것/안 주는 것(번호·서답형 표시·묶음
    표시), 머리 메타 줄 형식, 선지 마커 종류, 정규화 필요 항목(➀→①, 악센트 …),
    출처 태그 처리, 답란 표기.
13. **현행 산출물과 정본의 차이** — 지금 나가는 동형 PDF를 열어 정본과 항목별로
    대조하고, 다른 지점을 `diff_vs_current` 에 **구체적으로** 적는다.
    (사용자가 지적하기 전에 우리가 먼저 찾아 두는 목록이다.)

## 4. 산출

1. `core/render_vivlio/series/mockexam/profiles/<학교키>.json`
   — `_schema.json` 구조, `배재1.json` 깊이. 값마다 실측 근거(쪽·좌표·표본 문자열)를
   같이 남긴다. 모르면 지어내지 말고 `gaps` 에 "무엇이 왜 부족한지"를 적는다.
2. `docs/동형_학교별_조판규칙/<학교키>.md`
   — 사람이 읽는 요약. 13개 항목을 순서대로, 표본 문자열과 실측치를 인용해서.
   마지막에 **"현행과 달라 고쳐야 할 것"** 과 **"자료가 없어 못 정한 것"** 두 절.

## 5. 지켜야 할 것

- 파일은 **자기 학교 것만** 쓴다. 다른 학교 프로파일·공용 도구·엔진 코드는
  건드리지 않는다(여러 작업이 같은 워킹트리를 공유한다).
- `git commit` / `git push` 하지 않는다.
- Google Drive 원본은 읽기만.
- InDesign 을 실행하지 않는다.
- 추정한 값에는 반드시 그렇게 표시한다. **정본에서 확인 안 된 값을 확정값처럼
  적지 않는다.**
