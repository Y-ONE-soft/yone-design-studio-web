# SlimBuild.jsx — 워크북 슬림버전 원샷 변환

`Slim_Ver.jsx`(섹션 삭제) + `Slim_Merge.jsx`(본문 O/X 병합) + `Slim_Merge2.jsx`(문장 배열 병합)를
하나로 합치고 검증까지 내장한 스크립트. 세 개를 순서대로 돌릴 필요 없이 한 번에 끝난다.

## 쓰는 법

### 수동 (InDesign Scripts 패널)
1. 변환할 워크북 .indd 를 InDesign에서 연다 (다른 문서는 닫아두는 것이 안전).
2. Scripts 패널에서 `SlimBuild.jsx` 더블클릭.
3. **대상 문서 경로 확인 다이얼로그**가 뜬다 — 파일 경로가 맞는지 확인하고 확인.
4. 끝나면 요약 알림. 문서는 저장된다(Cmd+Z 불가, 사본으로 작업할 것).

> 이 스크립트는 `app.activeDocument`를 쓰지 않는다. 실행 중 창을 전환해도 대상이 바뀌지 않는다.

### 자동화 (배치)
`__SETTINGS_PATH__` 를 JSON 경로로 치환한 사본을 실행한다.

```json
{
  "doc_path": "/절대/경로/대상.indd",
  "log_path": "/절대/경로/slim.log",
  "save": true
}
```

실행기 예시: `/Users/Shared/slim_build/run_slim.py` (원본을 출력 경로로 복사 후 in-place 변환 → 원본 무접촉)

## 하는 일

| 단계 | 내용 |
|---|---|
| 1 | 파스트보드의 "단원" 문자스타일 마커로 섹션 경계 자동 인식 |
| 2 | `delete_sections` 섹션 통째 삭제 (기본: 어휘 선택 2 / 본문 정리 / 내용 종합 / 어법 O/X / 빈칸 어법) |
| 3 | `merge_half_sections` 반쪽 병합 (기본: 본문 O/X) — 2p→1p, 상단/하단 절반 |
| 4 | `merge_stack_sections` 적층 병합 (기본: 문장 배열) — 하단 부가문제(문장삽입) 프레임 삭제 후 다음 페이지 문항을 적층, 2p→1p |
| 5 | 섹션 첫 페이지 마스터 좌우 보정 (A↔B, C↔D) — 슬림으로 페이지가 밀려 섹션 시작이 오른쪽 페이지가 되면 헤더 탭이 있는 마스터로 자동 교체 |
| 6 | **간지 스프레드 정렬** — 간지 블록이 (왼쪽,오른쪽) 2P 구성이 되도록 메모 페이지 삽입 (아래) |
| 7 | 검증 — 오버셋 스토리 수, 누락 링크 수, 최종 섹션 목록을 로그에 기록 |

### 간지 스프레드 정렬 (`fix_divider_spreads`)

간지 블록 = **마스터가 [없음]인 페이지의 연속 런**.

- 왼쪽 페이지 = 스프레드 전체를 덮는 배경 사각형 (STEP 표지)
- 오른쪽 페이지 = 단원 제목 — **흰 글자라서 배경이 없으면 아무것도 안 보인다**

슬림 변환으로 앞 섹션이 왼쪽 페이지에서 끝나면 이 블록이 한 칸 밀려, 배경이 pasteboard로
반쯤 나가고 제목이 흰 배경에 흰 글씨로 얹힌다. 뒤따르는 간지·메모·판권면까지 전부 어긋난다.

→ 블록의 **마지막 페이지가 왼쪽이면 블록 앞에 메모 페이지(M-마스터)를 1장 삽입**한다.
메모 페이지는 빈 페이지에 M-마스터만 적용하면 된다 (MEMO 글자·도트 그리드는 마스터 제공).
문서 앞에서 뒤로 순회하며 삽입할 때마다 재평가하므로, 한 장 넣어 뒤쪽이 전부 해결되면
불필요한 삽입을 하지 않는다.

**`pages.add(BEFORE, ...)` 금지** — facing pages 셔플 때문에 한 칸 앞(콘텐츠 페이지 사이)에
끼어 문항 순서를 깨뜨린 사례가 있다. 앞 페이지를 `getElements()`로 실체 참조로 잡아
`pages.add(AFTER, prevRef)` 로 넣고, 삽입 후 `앞=콘텐츠 마지막 / 뒤=간지 첫 페이지`
인접성을 검증한다. 어긋나면 삽입을 되돌리고 중단한다.

### 이미 만든 파일만 보정하기 (`skip_slim`)

슬림 변환은 끝났는데 간지 정렬만 필요하면 settings 에 `"skip_slim": true` 를 주면
삭제·병합·파리티 보정을 건너뛰고 간지 정렬만 수행한다. 페이지 1장 삽입 외에는
문서를 건드리지 않으므로 수동 수정본에 증분 적용해도 안전하다.

**섹션 목록을 바꾸려면** 스크립트 상단 `CFG` 의 배열만 고치면 된다 (또는 settings JSON으로 덮어쓰기).

## 설계상 지켜지는 것

- **스레드 해제는 Adobe SplitStory 방식** (`duplicate()` → 원본 `remove()`).
  `nextTextFrame = NothingEnum.nothing` 은 뒤 프레임 텍스트를 앞 프레임 오버셋으로 빨아들일 수 있어 쓰지 않는다.
- **좌표는 페이지 원점 기준**(`rulerOrigin = PAGE_ORIGIN`)으로 통일 → 좌/우 페이지 파리티에 무관.
  적층 프레임은 host 프레임의 x를 그대로 상속하므로 안쪽여백(좌 20 / 우 22)이 자동으로 맞는다.
- **섹션 처리는 뒤에서 앞으로** → 앞 섹션의 페이지 오프셋과 좌우 파리티가 변하지 않는다.
- **간지/백지 보호** — 삭제 범위 끝에 `[없음]`·M·간지 마스터 페이지가 걸리면 삭제하지 않는다.
- **페이지 개체는 통째로 이동** — 텍스트 프레임만이 아니라 그 페이지의 모든 최상위 개체를 같은 delta로 옮긴다.

1. `Slim_Merge`의 위험한 스레드 해제 방식 → SplitStory 방식으로 교체
2. `Slim_Merge2`의 하드코딩 좌표(`[160.25, 20, 404.75, 188]`) 제거.
   기존 방식은 좌/우 안쪽여백 판정을 페이지 side가 아니라 "삭제 누적 보정한 페이지번호 짝수"로 해서
   **문장배열 병합 페이지마다 아래 블록이 위 블록과 x가 2pt 어긋났다** (광문2 정본에서 실측 확인).
   또 프레임 하단이 404.75(페이지 297 밖)까지 뻗었다 → 실제 필요 높이로 산출 후 오버셋 시에만 확장.
3. 마스터 좌우 변형(A↔B, C↔D) 자동 보정 추가 — 기존에는 수동 처리였다.
4. `app.activeDocument` 제거 (사용자가 창 전환 시 남의 파일을 건드리는 사고 방지)

### 어법 선택 → 어법 수정
두 경로 모두 **"어법 선택 → 어법 수정으로 교체"** 체크박스가 있다.

- **표기**: 단원 마커를 바꿔 러닝헤더가 `A1 어법 선택` → `A1 어법 수정`이 된다.
- **내용**: **조판 단계**에서 켜고 어법수정 원고를 원고 목록에 함께 올리면
  STEP2 A1 슬롯 원고가 자동으로 교체된다 (`core/grammar_swap.py`).
  기존 `Step2 A1 어법선택.docx`는 조판에서 빠지고, 어법수정본이 그 슬롯 이름을
  물려받는다 — 헤더 체계(`N. p2-no.20`)가 같아 기존 파서가 그대로 처리한다.
  완성본 후처리(경로 1)에서는 표기만 바뀐다.

어법수정 원고는 폴더가 계열마다 달라 파일명도 완전히 일치하지 않는다.
정규화 후 **`어법수정` + `문제지`** 를 포함하거나 **`직전 보충 자료`** 면 인식한다
(해설지·정답지는 제외):

| 계열 | 위치 | 파일명 |
|---|---|---|
| 모의고사 | 회차 폴더 루트 | `고2_2026_06월-읽기영역(18~45번)_어법수정_문제지.docx` |
| 모의고사 | 회차 폴더 > `... 직전보충` | `고2_2022_09월(인천시)...어법수정_문제지.docx` |
| 교과서 | 과 폴더 루트 | `공통영어2_NE능률민병천-Lesson1...._어법수정_문제지.docx` |
| 교과서 | 과 폴더 > `... 직전보충` | `공통영어1_YBM김은형-LESSON1...._어법수정_문제지.docx` |
| 올포 | 강 폴더 루트 | `올림포스...Unit07..._어법수정_문제지.docx` |
| 수특라이트 | 강 폴더 루트 | `* 직전 보충 자료.docx` (이름에 '어법수정' 없음) |

> 어법선택 **정답지**가 원고 목록에 남아 있으면 지문(어법수정)과 불일치하므로
> 로그에 경고가 뜬다. 정답지 자동 교체는 하지 않는다 — 필요하면 어법수정
> 해설지로 직접 바꿔 올릴 것.

## 남은 작업 (별개 단계)

1강+2강을 한 권으로 합치는 것은 이 스크립트의 범위가 아니다 (`MergeTextbook.jsx` 등 기존 합본 절차).
합본 시 각 강의 앞부속 백지/판권지 정리가 필요하다 (정본 광문2는 2강 앞 백지 2p를 뺐다).
합본 후 SlimBuild를 한 번 돌려도 되고(섹션이 강별로 반복돼도 정상 처리), 강별로 돌린 뒤 합쳐도 된다.
