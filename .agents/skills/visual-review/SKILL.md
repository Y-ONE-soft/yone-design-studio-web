# 시각 검수 절차 (2층)

1층(기계 검사, `core/visual_inspect`)은 오버셋·지오메트리·픽셀 이상만 잡는다.
이 스킬은 그 위에서 **에이전트가 이미지를 직접 보고** 사람 검수를 대행한다.
텍스트 덤프 게이트(G1~G30)와 달리, 여기서는 "보이는 것"만 믿는다.

## 준비 (검토 폴더가 없으면)

```bash
python3 scripts/visual_review.py <job_dir 또는 산출.pdf> [--dump typeset_dump.json]
```

→ `data_corpus/visual_review/<이름>/` 에 `pages/*.png`, `visual_report.json`(1층),
`review_queue.json`(의심 페이지 큐)가 생긴다.

## 검수 수행

1. `review_queue.json` 을 Read — `layer1` 요약과 `queue`(페이지+사유) 파악.
2. 큐의 각 페이지 PNG를 **Read 도구로 직접 열어** 아래 체크리스트로 본다.
   플래그 페이지는 반드시 **앞뒤 페이지도 함께** 열어 맥락 비교(같은 마스터의
   정상 페이지와 나란히 보면 어긋남이 드러난다).
3. 큐가 전부 정상이어도 최소 6장(첫/가운데/끝 + 무작위)은 봐야 "통과" 판정 가능.

### 체크리스트 (페이지마다 전부 확인)

| # | 항목 | 보는 것 |
|---|---|---|
| C1 | 텍스트 잘림 | 프레임 끝에서 문장이 중간에 끊김, 마지막 줄 반토막, 단어 절단 |
| C2 | 프레임 겹침/어긋남 | 본문·발문·박스가 서로 침범, 다른 페이지와 정렬 불일치 |
| C3 | 번호 연속성 | 문항/지문 번호가 순서대로인가, 중복·건너뜀 없나 |
| C4 | 스타일 일관성 | 같은 역할(발문/선지/해설)의 글꼴·크기·배경이 페이지 간 동일한가 |
| C5 | 여백/빈 공간 | 본문 중간의 비정상 공백, 반쯤 빈 페이지, 콘텐츠가 여백 침범 |
| C6 | 간지/머리말 | 간지 제목·머리말·쪽번호가 해당 단원과 일치하는가 |
| C7 | 이미지/아이콘 | 깨짐, 저해상, placeholder(X 박스), 어긋난 인라인 아이콘 |
| C8 | 좌/우 마스터 | 좌우 페이지 여백 방향·단 구성이 마스터와 맞는가 |

### 판정 등급

- **fail**: 인쇄 나가면 안 됨 (잘림, 겹침, 번호 오류, 내용 손상)
- **suspect**: 사람이 최종 확인 필요 (의도인지 결함인지 이미지로 확정 불가)
- **pass**: 결함 없음

## 리포트 작성

검토 폴더에 `review_result.json` 을 쓴다:

```json
{
  "reviewer": "Codex-visual-review",
  "date": "YYYY-MM-DD",
  "source": "<검수한 PDF/indd>",
  "pages_reviewed": [1, 2, 17],
  "verdict": "pass | suspect | fail",
  "findings": [
    {"page": 17, "grade": "fail", "check": "C1",
     "detail": "STEP2 마지막 발문이 프레임 하단에서 절단 — '...it was' 이후 소실"}
  ],
  "notes": "전반 소견 (양품과의 비교 근거 포함)"
}
```

- `findings` 는 **페이지·체크 항목·증거를 특정**해서 쓴다 ("이상해 보임" 금지).
- verdict 는 findings 최고 등급을 따른다 (fail>suspect>pass).
- 마지막으로 사용자 보고에는: 판정 + fail/suspect 페이지 목록 + 근거 이미지 경로.

## 철칙

- 이미지를 열어보지 않고 1층 리포트만으로 pass 판정 금지 — 1층은 후보 추출기다.
- 실서비스 산출 폴더의 파일을 수정하지 않는다 (검토 폴더는 data_corpus 전용).
- InDesign이 필요한 경로(.indd만 있는 흐름)는 사용자 문서 무접촉 — 열려 있는
  문서를 닫지 말고, `core.visual_inspect.render_indd_pages`(읽기 전용) 사용.
